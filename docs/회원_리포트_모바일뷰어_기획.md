# 회원 리포트 모바일 뷰어 + 데스크톱 보기 — 기획안

> 상태: 기획 초안 (승인 대기) · 시안: `designs/member-report-mobile-viewer/mockup.html`

## 1. 문제
- 회원 리포트는 모바일 기준으로 설계됐다(회원 대부분이 모바일에서 열람).
- 화면 폭이 넓어지면 그래프(추이선·막대)가 가로로 늘어나 읽기 어렵고, 지표 카드가 2열로 퍼져 모바일 의도와 달라진다.
- 상담사 검토 화면(분할 패널)도 같은 본문을 쓰므로 폭이 좁아졌다 넓어졌다 하며 모양이 흔들린다.

## 2. 목표
1. 회원용 리포트는 **어떤 화면에서든 모바일 폭(최대 430px)의 한 컬럼 뷰어**로 보인다.
2. 넓은 화면에서는 **'데스크톱 보기' 버튼**으로 현재의 넓은 레이아웃을 팝업(모달)으로 따로 제공한다.
3. 회원 화면·상담사 검토 화면·메일 토큰 열람 페이지가 **같은 뷰어**를 쓴다(이미 진행 중인 본문 통일 작업과 연결).

## 3. 범위
| 화면 | 기본 | 데스크톱 보기 |
|---|---|---|
| 회원 앱 리포트 상세(모달/페이지) | 모바일 뷰어 | 버튼 → 팝업 |
| 상담사 검토 패널(회원용 리포트) | 모바일 뷰어(회원이 보는 그대로) | 버튼 → 팝업 |
| 메일 토큰 열람 페이지 | 모바일 뷰어 | 버튼 → 팝업 |
| 상담사용 리포트(type counselor) | 변경 없음(넓은 레이아웃) | 해당 없음 |

제외: 모바일 실기기(≤560px)는 현재와 동일하게 전체 폭, 버튼 비노출.

## 4. 동작 정의
- **폭 규칙**: 컨테이너 `max-width: 430px`, 가운데 정렬. 뷰포트 ≤ 560px면 전체 폭.
- **데스크톱 모습 프레임**: 폭 ≥ 561px에서 뷰어를 기기 프레임 느낌의 카드(둥근 모서리, 옅은 그림자, 보라 크림 배경)로 감싸 "모바일로 보는 중"임을 명확히 한다.
- **'데스크톱 보기' 버튼**: 뷰어 상단 우측(헤더 줄). 폭 ≥ 561px에서만 표시. 클릭 시 기존 넓은 레이아웃(사이드 목차 + 2열 지표)을 `dialog` 모달(최대 1240px, ESC·바깥 클릭·닫기 버튼으로 닫기)로 연다. 모달 안에서는 '모바일로 보기'로 돌아가는 보조 버튼 제공.
- 그래프: 모바일 뷰어 안에서는 `max-height: 210px` 규칙(기존 ≤560px 규칙)을 그대로 적용해 퍼짐 방지.
- 상태 기억: 선택은 저장하지 않는다(항상 모바일 뷰어로 시작) — 단순화.
- 접근성: 모달은 native `dialog`(포커스 트랩·ESC), 버튼 라벨 "데스크톱 보기"/"모바일로 보기", 터치 타깃 44px.

## 5. 구현 방향 (기술)
- `ClientReportBody`를 감싸는 `MemberReportFrame`(신규) 컴포넌트: 폭 제한 + 데스크톱 보기 버튼 + 모달.
- CSS는 `narrative-sections.css`의 ≤560px 규칙을 컨테이너 쿼리(`.member-report-frame` 기준 `container-type: inline-size`)로 바꿔 뷰포트가 아니라 **프레임 폭**에 반응하게 한다. (현재 미디어쿼리는 뷰포트 기준이라 프레임만 좁혀서는 모바일 스타일이 켜지지 않음 — 핵심 작업)
- 모달 안은 프레임 제한 없이 기존 스타일(뷰포트 기준) 유지.
- 렌더 지점: ClientReportViewer, ReportDetailView(회원용), ReportViewPage(회원용)에서 `MemberReportFrame` 사용.
