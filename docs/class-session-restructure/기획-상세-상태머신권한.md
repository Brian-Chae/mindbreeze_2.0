## 1. 상태 머신

공통 원칙: ① 이력은 append-only 이벤트로 남긴다(`class_member_events`, `counseling_relationship_events`, `session_host_history`) ② 삭제는 숨김(`hidden_at`) = 보존 전환 ③ 금지 전이는 서버가 409 로 막고 같은 사유 문구를 돌려준다 ④ 상태 값 이름은 영문 소문자(DB), 화면 문구는 해요체(R8 §4).

### 1.1 클래스 (`classes.status`)

| 상태 | 의미 | 세션 행 | 새 회차 추가 | 멤버 모집 |
|---|---|---|---|---|
| `draft` | 편성 중. 회차 표를 `draft_schedule`(JSONB)에 보관, 진행 강사 미정 허용 | 없음 | — | 불가 |
| `active` | 공개됨. 회차 존재, 모집·진행 | 있음 | 가능 | 가능 |
| `completed` | 고정형: 마지막 정규 회차가 끝남 / 정기형: 지도사가 마무리 | 있음 | 고정형만 가능(→ `active` 복귀) | 불가 |
| `cancelled` | 클래스 전체 취소(예정 회차 일괄 취소) | 있음 | 불가 | 불가 |
| `archived` | 보관(읽기 전용, 기본 목록 숨김) | 있음 | 불가 | 불가 |

| # | 전이 | 조건 | 주체 | 부수 효과 |
|---|---|---|---|---|
| C1 | ∅ → `draft` | 편성 마법사 "나중에 이어서" | 개설자 | `draft_schedule` 저장, 알림 없음 |
| C2 | ∅ → `active` | 마법사 완료. 모든 회차 진행 강사 지정, 강사 ≥1, 주강사 ≥1 | 개설자 | 세션 행 N개 생성(한 트랜잭션), 리마인더 예약, 클래스 코드 1개 발급, 초대 알림 **클래스 단위 1통** |
| C3 | `draft` → `active` | C2 와 같은 검증 | 주강사·센터 관리자 | 동일 |
| C4 | `draft` → 삭제 | 세션·멤버 없음이라 물리 삭제 허용(유일한 예외) | 개설자 | — |
| C5 | `active` → `completed` | 고정형: 마지막 정규 회차가 `completed`/`cancelled` 이고 `open`/`in_progress` 회차 없음 → **자동**. 정기형: 수동 "마무리" 또는 종료일 도래 | 시스템·주강사 | 남은 `scheduled` 회차는 취소(정기형 수동 종료 시), 멤버십 `active`→`completed`, 클래스 코드 무효화, 완료 알림 |
| C6 | `active` → `cancelled` | `open`/`in_progress` 회차 없음 | 주강사·센터 관리자 | 예정 회차 일괄 취소 + 멤버 알림(1통), 코드 무효화, 완료된 회차 데이터 유지 |
| C7 | `completed`/`cancelled` → `archived` | 수동(기본) | 주강사·센터 관리자 | 목록에서 숨김, 열람 가능 |
| C8 | `archived` → `completed`/`cancelled` | 보관 해제(원래 상태 복원) | 주강사·센터 관리자 | — |
| C9 | `completed` → `active` | 고정형에서 회차 추가 / 정기형 "이어서 하기" | 주강사 | 코드 재활성화, 멤버십은 `completed` 유지(이어서 참여하려면 새로 가입 — 같은 행 되살림 아님) |

금지 전이: `draft` → `completed`/`cancelled`/`archived` · `active` → `archived`(종료 선행) · `cancelled` → `active`(새 클래스로 복제) · `archived` → `active` · `open`/`in_progress` 회차가 있는 상태의 C5/C6 · 숨김(삭제)된 클래스의 모든 전이.

클래스 **삭제**(숨김 = 보관): `completed`·`in_progress` 회차가 하나라도 있으면 삭제 불가, `archived` 만 가능(현행 "ready/scheduled/cancelled 일 때만 삭제" 규칙 `R9 §6.1` 을 클래스로 확장). 삭제 가능 조건과 문구는 `D-17`.

### 1.2 세션(회차) (`sessions.status` — 현행 유지)

현행 상태 6종 `ready · scheduled · open · in_progress · completed · cancelled` 와 전이표(`TRANSITIONS`)를 **그대로 쓴다**(엔진 공유, `R2 §3.1`). 열기·시작·종료·취소의 출발 상태 세부는 구현 때 `TRANSITIONS` 원문으로 재확인(이 문서는 R4 §5 에 인용된 취소(`in_progress` 포함)만 확정 사실로 취급).

새로 붙는 축 3개(상태가 아니라 속성):

| 속성 | 값 | 의미 |
|---|---|---|
| `session_kind` | `regular` / `makeup` | 정규 회차 / 보강 회차. 보강은 진행률 분모(N)에 포함하지 않는다 |
| `host_state` | `assigned` / `pending_ack` / `needs_reassign` | 진행 강사 상태(§1.3). `host_id` 는 항상 NOT NULL |
| `seq` | 정수 | 부모 안 회차 번호. **취소돼도 재사용하지 않는다**(알림·리포트 참조 안정) |

세션 수준 금지: `needs_reassign` 인 회차의 열기·시작 · 취소된 회차의 어떤 전이 · 종료된 회차의 `host_id` 변경(귀속 정정 경로 제외).

### 1.3 진행자 배정 (`sessions.host_state`) — 명상 클래스 (`R9 §6.2`)

상담은 "관계의 상담사 1명 = 진행자"라 배정 단계가 없다(§1.6 의 교체/이관만).

| 상태 | 설명 |
|---|---|
| (초안) 미정 | `draft` 클래스의 `draft_schedule` 안에서만 존재. 세션 행 아님 → NOT NULL 불변식 유지 |
| `assigned` | `host_id` 지정 완료, 수락 필요 없음 또는 수락 완료 |
| `pending_ack` | 임박(시작 60분 이내) 긴급 변경에서 새 강사 수락 대기. `host_id` 는 **현 진행자 유지** |
| `needs_reassign` | 진행자가 정지·삭제·클래스 제거 등으로 유효하지 않음. `host_id` 는 이전 값 유지, 열기·시작 차단 |
| (파생) `locked` | 회차 `open`/`in_progress` — 변경 불가 |
| (파생) `finalized` | 회차 `completed`/`cancelled` — 귀속 정정만 |

| # | 전이 | 조건·주체 | 부수 효과 |
|---|---|---|---|
| H1 | (초안) → `assigned` | 편성 시 주강사·센터 관리자가 **active 클래스 강사** 지정 | 충돌 경고 표시, 공개(C2/C3) 시 배정 알림 |
| H2 | `assigned` → `assigned`(변경) | 시작 60분 초과 전 즉시. 주강사·센터 관리자(진행 강사 본인은 "양도 요청") | 이전·신규 강사 알림, `session_host_history` 기록, 새 강사 기준 충돌 재검사, 채팅방 방장·리마인더·AI 비서 범위 동기화, 회원 알림은 `D-29` 기준 |
| H3 | `assigned` → `pending_ack` | 시작 60분 이내 긴급 변경 요청 | 새 강사에게 수락 요청, 회원 즉시 알림은 **수락 확정 뒤** |
| H4 | `pending_ack` → `assigned` | 새 강사 수락 → `host_id` 교체 | H2 의 부수 효과 실행 |
| H5 | `pending_ack` → `assigned`(유지) | 거절·타임아웃(시작 15분 전) | 요청자·센터 관리자 알림, 기존 진행자 유지 |
| H6 | `assigned`/`pending_ack` → `needs_reassign` | 진행자 계정 정지·삭제·클래스에서 강제 제거 | 주강사·센터 관리자 알림, 시작 72h/24h 전 재알림 |
| H7 | `needs_reassign` → `assigned` | 주강사·센터 관리자 재배정 | H2 와 동일 |
| H8 | `assigned` → `locked` | 진행 강사만 열기 | 이후 변경 불가(인계는 후속, `D-23`) |
| H9 | `locked` → `finalized` | 종료/취소 | 리포트 소유·승인 주체 확정 |

금지: 미정·`needs_reassign` 회차의 열기·시작 · `open`/`in_progress` 중 변경 · 진행자가 클래스 강사가 아닌 사람(대체 규칙 §2 의 임시 등록 경유 없이) · 진행자 2명 · `pending_ack` 중 또 다른 변경 요청(먼저 해소).

완료 후 귀속 정정: **리포트 승인 전**에만 가능(사유 필수, `session_host_history` 에 이전·이후·사유·실행자·시각). 승인 후에는 `host_id` 를 바꾸지 않고 "표시 진행 강사" 정정 메모만 허용(`D-24`).

### 1.4 멤버십 (`class_members.status`) (`R4 §9.1`)

값: `invited` · `waitlisted` · `active` · `completed` · `left` · `removed` · `declined`. (휴회 `paused` 는 후속 — 범위 제외, `기획.md` §2.4)

| # | 전이 | 조건 | 주체 | 부수 효과 |
|---|---|---|---|---|
| M1 | ∅ → `active` | 코드 입장(정원 여유) / 지도사 직접 추가 / 이전(`migration`) | 본인·지도사·시스템 | 합류 이후 예정 회차에 출석 `expected` 생성, 지난 회차 행 **만들지 않음** |
| M2 | ∅ → `waitlisted` | 정원이 찼거나 앞선 대기자 존재 | 본인·지도사 | 끝 순번 부여 |
| M3 | ∅ → `invited` | **현행 동작 유지**: 지도사 초대는 수락 없이 즉시 등록이라 이 전이는 쓰지 않음 | — | `D-14` 에서 수락 도입을 결정할 때만 사용 |
| M4 | `waitlisted` → `active` | 정원 여유 + 순번 | 시스템(행 잠금) | `class_waitlist_promoted` 알림 |
| M5 | `waitlisted` → `left` | 대기 취소 | 본인 | 행 삭제 금지, 재대기 시 같은 행 복구·끝 순번 |
| M6 | `active` → `left` | 본인 이탈 | 본인 | 미래 `expected` → `withdrawn`, 정원 반환·대기자 승격, 지도사 알림 |
| M7 | `active` → `removed` | 지도사 제외 | 지도사 | M6 과 동일 + 사유 이력 |
| M8 | `active` → `completed` | 클래스 `completed`(C5) | 시스템 | 이력 불변 |
| M9 | `left` → `active`/`waitlisted` | 재가입(코드 재입장·초대) | 본인·지도사 | 같은 행 되살림, 이탈 중이던 회차 행은 만들지 않음 |
| M10 | `removed` → `active` | **지도사 복구만** | 지도사 | 코드 자가 재입장은 차단(`D-13`) |
| M11 | `invited` → `active`/`declined` | 수락/거절/만료 | 본인·시스템 | M3 사용 시에만 |

금지: `removed` → (코드로) `active` · `completed` → `left`/`removed` · `declined` → `active`(새 초대 필요) · `waitlisted` → `completed` · 클래스가 `cancelled`/`archived` 일 때의 신규 전이 · `active` → `invited` · 이력 삭제.

### 1.5 출석 (`session_participants.attendance_status`) (`R4 §9.2`)

값: `expected` · `attended` · `absent` · `excused` · `withdrawn`. 회차 자체의 취소는 세션 상태에서 파생(별도 값 없음). 현행 `ParticipantLogState`(READY/STARTED/COMPLETED)는 세션 상태 파생이라 혼동 방지를 위해 출석은 별도 필드명으로 노출한다.

| # | 전이 | 조건 | 주체 |
|---|---|---|---|
| A1 | ∅ → `expected` | 멤버 활성화(미래 회차) / 회차 생성(활성 멤버 전원) / 보강 추가 | 시스템·지도사 |
| A2 | `expected` → `attended` | 회차 입장 성공(`entered_at` 최초 기록) | 본인 |
| A3 | `expected` → `excused` | 사전 결석 통보(회차 시작 전까지) | 본인·지도사 |
| A4 | `excused` → `expected` | 취소 통보 + 회차 정원 여유 확인 | 본인·지도사 |
| A5 | `expected` → `absent` | 회차 종료(`end`) 후 `entered_at IS NULL` 확정. **취소된 회차는 확정 제외** | 시스템 |
| A6 | `expected`/`excused` → `withdrawn` | 멤버가 `left`/`removed` | 시스템 |
| A7 | `absent` ↔ `excused` | 사후 정정(사유 인정) | 지도사만 |
| A8 | `absent` → `attended` | 사후 정정(오기록), 감사 이벤트 | 지도사만 |

금지: `attended` → `absent`/`excused`/`withdrawn`(지도사 정정 이벤트 제외) · `withdrawn` → 임의 값(재가입 로직이 미래 행 복구) · 종료된 회차에 `expected` 잔존(확정 훅이 해소) · 본인이 `absent` 직접 설정 · 취소 회차의 `absent` 확정.

파생(저장 안 함): **보강 대기** = 결석/사전 결석 행이 있고 이를 대체하는 `makeup` 출석이 없음 · **보강 완료** = `makeup` 출석이 `attended`. 진행 중에 취소된 회차는 입장자 `attended` 유지, 나머지는 확정하지 않음(`D-10` 하위).

### 1.6 상담 관계 (`counseling_relationships.status`) (`R1 §10`, `R10 §2.5`)

값: `pending` · `active` · `closed` · `archived`. (R10 의 `ended` 는 현행 `client_counselor_links.ended` 가 "상담사 접근 차단"이라는 반대 의미를 가져 혼동되므로 `closed` 로 통일한다. 일시중지 상태는 두지 않는다 — `휴면`은 표시 라벨, `D-45` 하위.)

| 상태 | 새 회차 예약 | 입장 | 목록 노출 |
|---|---|---|---|
| `pending` | 가능(첫 상담 동시 예약) | 첫 입장 시 `active` | "초대 중" |
| `active` | 가능 | 가능 | 기본 |
| `closed` | **불가**(재개 먼저) | 불가 | "마무리한 상담", 읽기 전용 |
| `archived` | 불가 | 불가 | 기본 숨김, 검색으로 열람 |

| # | 전이 | 조건 | 주체 | 부수 효과 |
|---|---|---|---|---|
| R1 | ∅ → `pending` | 비회원/미가입 내담자 초대. 이메일 필수 | 상담사 | 관계 코드 발급(§상담 상세), 초대 메일 |
| R2 | ∅ → `active` | 회원 내담자와 시작(마법사) | 상담사 | 첫 회차 `seq=1`(반복이면 N개) |
| R3 | `pending` → `active` | 내담자 첫 입장 + 동의 완료 | 내담자 | 자격 발급 |
| R4 | `active` → `closed` | **`in_progress` 회차가 있으면 409**. 예정(`ready`/`scheduled`/`open`) 회차는 확인 후 일괄 취소 | 상담사 + 내담자(회원)(`D-44`) | `closed_by/closed_at/close_reason`, 관계 코드·비회원 자격 폐기(`reentry_ver`+1), 반복 규칙 정지, 직접 채팅 읽기 전용, 내담자 알림(선택) |
| R5 | `closed` → `active` | 재개. 기본 = **같은 관계 재개** | 상담사. 내담자가 종결한 건은 내담자 단독 재개, 상담사가 종결한 건은 상담사 승인(`D-46`) | `reopened_count`+1, `seq` 이어서, 관계 코드 새로 발급 |
| R6 | `closed` → `archived` | 종결 후 N일 자동(기본 365, `D-47`) 또는 수동 | 시스템·상담사 | UI·권한만 변경, **데이터 삭제 없음** |
| R7 | `archived` → (재상담) | **새 관계** + `predecessor_relationship_id` 연결 | 상담사 | 새 상담사 화면에 "이전 상담 기록 N건" |
| R8 | 이관(교체) | `active` → `closed`(reason=`counselor_transfer`) + 새 상담사와 새 관계 | 센터 관리자·상담사 | 과거 세션 `host_id` 불변, 새 상담사의 과거 열람은 `D-58` |

금지: `archived` → `active`/`closed` · `closed` → `pending` · `active` → `archived` 직행 · `pending` → `closed`(세션 없는 종결은 의미 없음 → 삭제 가능: 세션·개인정보 0건일 때만) · `closed`/`archived` 에서 세션 생성 · 진행 중 세션이 있는 종결 · 물리 삭제(플랫폼 관리자의 원본 삭제 경로 제외, 감사 기록).

### 1.7 비회원 신원 (`counseling_guests`) — 상담 영역 (`R1 §11`, `R10 §6`)

| 상태 | 설명 |
|---|---|
| `registered` | 상담사가 이름·이메일로 등록. 코드 입장 전 |
| `verified` | 첫 입장: 코드 + **등록 이메일 일치** + 개인정보·보관 동의 완료 (이메일 OTP 는 SDD-209 D-1 에서 제외 확정이라 쓰지 않음) |
| `credentialed` | 관계 단위 재방문 자격 발급(마지막 사용 후 90일 슬라이딩) |
| `expired` | 자격 만료/기기 변경 → 코드 + 이메일 + 생년월일 재확인으로 재발급 |
| `revoked` | 종결·상담사 초기화·`reentry_ver` 증가로 폐기 |
| `claimed` | 회원 가입 후 기록 연결 완료(`claimed_user_id`). 자격은 폐기, 회원 로그인으로 통일 |
| `scrubbed` | 보관 기간 후 개인정보 스크럽(`pii_scrubbed_at`). 행·세션·리포트 참조는 유지 |

전이 요약: `registered`→`verified`→`credentialed`⇄`expired`(재확인)·`credentialed`→`revoked`·(`credentialed`|`expired`|`revoked`)→`claimed`·(`registered` 외 모두)→`scrubbed`. 금지: `scrubbed` → 어떤 상태(복구 불가, 재상담은 새 등록) · `claimed` → 되돌리기(이력 보존만, 오연결 정정은 플랫폼 관리자 경로).

명상 클래스의 비회원은 이 테이블을 쓰지 않고 `class_members(kind='guest')` + 클래스 단위 장기 자격으로 표현한다(`R4 §7`, `D-16`).

### 1.8 리포트 (현행 유지 + 보강) (`R6 §5.3`)

```
pending_analysis ──생성 성공──▶ pending_review ──승인──▶ completed
        │                         │  ▲                    │
        └──생성 실패/타임아웃──▶ error ◀─ 재생성 ─────────┘(재생성해도 completed 유지)
```

- 승인축 4값(`pending_analysis`/`pending_review`/`completed`/`error`) × 생성축 4값(`pending`/`processing`/`ready`/`partial`). "발송"은 별도 상태가 아니라 `sent_at`(앱 노출) + 참여자 메일 상태(`report_email_status`)의 조합.
- 신규: `approved_by_user_id`, `approved_at`(추가형 nullable). 기존 completed 행은 NULL 유지(사실을 지어내지 않음).
- 금지: `pending_analysis`/`error` → 승인 · `completed` → `pending_review` 되돌림 · 승인된 건의 재생성이 승인을 취소(재생성해도 `completed` 유지).
- 결석 회원은 리포트 **행 없음**(0점·빈 리포트 만들지 않음). 제외 참여자는 모든 파생물(추이·분포·일괄 발송)에서 제외.

## 2. 권한 매트릭스

## 3. 알림 규칙

원칙: ① 이벤트 키(`session_*`)는 유지(구 앱 호환) ② payload 에 `area`·`class_id`/`counseling_relationship_id`·`seq` 가산, `target_id`(세션 id)·레거시 `session_id` 유지(`R2 §6.1`, `R7 §6.3`) ③ 일괄 생성은 **회차마다가 아니라 클래스 단위 1통** ④ 확정되지 않은 상태(미정·`pending_ack`·`needs_reassign`)는 회원에게 알리지 않는다(불안 유발 금지, 불변식 I20) ⑤ 문구는 영역별 용어 사전(`R8 §4`).

| `makeup_offered` | 신규 | 결석 회원 | 보강 회차 추가·합류 안내 | `놓친 3회차를 보강으로 채울 수 있어요` |
| `class_completed` | 신규 | 활성 멤버 | 클래스 `completed` | `MBSR 봄 클래스를 마쳤어요` (점수·평가 표현 금지) |
| `report_ready` | 기존 | 회원(승인 시), 승인 대기는 승인자 | 승인 | `3회차 리포트가 준비됐어요` |
| `counseling_invited` | 신규 | 회원/비회원 내담자 | 상담 관계 생성 | `{상담사}님이 상담에 초대했어요` |
| `counseling_closed` | 신규 | 내담자(선택, 기본 켬) | 종결 | `{이름} 상담을 마무리했어요. 지난 기록은 그대로 보관돼요` |
| `counseling_reopen_requested` | 신규 | 상담사 | 상담사 종결 건을 내담자가 재개 시도 | `{이름} 님이 상담을 다시 시작하고 싶어 해요` |
| `counseling_claim_completed` | 신규 | 상담사 | 비회원이 가입 후 기록 연결 | `{이름} 님이 가입해 상담 기록이 연결됐어요` |

수신자 선정 규칙: 대기열·호스트 제외(현행)에 더해 **멤버십 기준**으로 바꾼다(결석 예고 회원 제외 여부는 `D-06`). 알림 설정 UI 는 이벤트 키 단일 사전(≈35키)을 유지하고 영역별 분리 UI 는 만들지 않는다(기본값 — 알림 설정을 영역별로 쪼개는 것은 후속).

리마인더(`R5 §2.3`): 회차별 Celery ETA(오프셋 수 × 회차 수) + OS cron 스윕 안전망 유지. 수신자 = 활성 멤버 − 해당 회차 사전 결석자. 정기형은 롤링 생성 시점에 예약. 비회원 리마인더 메일은 입장 시 별도 동의가 있을 때만(`D-15`). 상담사 본인에게 가는 사전 안내는 현행에 없으므로 "오늘 일정" 요약은 홈의 Action Queue 로 대체(알림 신설은 후속).

## 4. 데이터 보존·삭제 규칙 (SDD-209 R4/R5 정합)

SDD-209 의 보관 3층 구조(`R10 §8.1`)를 **그대로 유지**하고 단위만 클래스·관계로 확장한다.

| 층 | 대상 | 규칙 | 상위(클래스·관계) 종료·종결의 영향 |
|---|---|---|---|
| ① 영구층 | 상위 개체·세션 메타·리포트 본문·기록지 요약·지표 요약·상담사 메모·계정 | 삭제 대상 아님(SDD-209 N-2). 삭제 요청은 운영 접수 → 플랫폼 관리자 | 종결·보관은 이 층을 **지우지 않는다** |
| ② 기간 삭제층 | EEG raw·음성·영상·STT 원문 | 세션 종료일 + `RETENTION_RAW_DAYS`(90일). 연구 동의 건은 ack 전 보류. 스위프 최초 활성화는 dry-run 후 승인(`RETENTION_SWEEP_ENABLED`) | 종결·보관과 무관(앞당기거나 미루지 않음). 상담만 다르게 할지는 `D-49` |
| ③ 개인정보 스크럽층 | 비회원 PII(이름·성별·생년월일·이메일) | 90일 후 스크럽, 행·참조는 유지. **기준일 재정의**: 명상 멤버십 = "마지막 출석 회차 종료일 또는 멤버십 종료일 중 늦은 날 + 90일", 상담 비회원 = "종결일(없으면 마지막 세션 종료일) + 90일" | 멤버십/관계 + 출석 사본을 **같은 실행 단위**에서 스크럽(한쪽만 스크럽하는 실수 방지). `counseling_guests` 를 스위프 대상에 **추가해야 함** |
| ④ 연구 DB | 동의 건의 비식별 번들 | ack 후 기본 DB 삭제 허용. 가명 ID(이름+생년월일 HMAC)는 회차·클래스·관계를 넘어 동일 | 영향 없음. 상담 비회원 회원 전환 후에도 동일 ID 유지 |

삭제·보관 사건별 규칙:

| 사건 | 규칙 |
|---|---|
| 일반 삭제(클래스·세션·참여자) | 숨김(`hidden_at` / `removed_at`) = 보존 전환. ORM 필터가 모든 조회에서 제외하므로 **새 부모 모델(`classes`, `counseling_relationships`)에도 같은 필터를 적용**. 이탈한 회원의 **과거 출석 행에는 `removed_at` 을 쓰지 않는다**(리포트 접근이 행 존재로 판정되므로) |
| 계정 삭제(회원) | 멤버십 `left`(system), 출석·리포트 보존. 상담 관계는 `closed`(reason=`account_deleted`), 기록은 상담사 쪽에 보관됨을 탈퇴 안내에 고지 |
| 계정 삭제(강사·상담사) | 미래 회차를 **숨기지 않고** `needs_reassign` 로 보존(현행 일괄 숨김 폐지). 상담 관계는 `closed`(reason=`counselor_left`) 후 이관 대기, 상담 세션은 숨김 제외 |
| 플랫폼 관리자의 기간 전 원본 삭제 | 현행 유지(`original_deletion_audits` 에 대상·실행자·시각·사유, FK 없이 UUID 보관). 클래스·관계 단위 일괄 삭제는 만들지 않는다 |
| 연구 동의 철회 | 현행 경로 유지(운영팀 → 플랫폼 관리자). 동의 효력은 **회차 스냅샷**(`research_consents` 는 회차 단위 유지), 입력 UI 만 가입 시 1회 받아 미래 회차 행에 복사 |
| 비회원 스크럽 후 재방문·리포트 재발송 | 불가(이메일 없음). 사전 고지 필요: `개인정보 보관 기간이 지나 다시 보낼 수 없어요` |

보관 **기간 숫자**(종결 후 자동 보관 일수, 영구층 상한, 상담 원본 기간, 비회원 PII 삭제 시점)만 `결정-필요.md` 에 둔다(`D-47`~`D-50`).
