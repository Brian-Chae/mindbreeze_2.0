### 1.4 필드별 실제 용도

| 필드 | 실제 용도 | 새 구조 |
|---|---|---|
| `run_id` | "같은 행의 재실행 표식"(`new-run` 이 같은 행의 `run_id` 만 교체). 소비처: 직렬화뿐, 프론트 호출 0건 | **회차 개념이 아님.** 값 보존, 신규 사용 중단, `new-run` 호환 유지 후 폐기 후보 (Phase 8) |

| `type` | 라벨·검증·직렬화. **엔진이 type 으로 갈라지는 곳은 3종뿐**(STT 화자 프롬프트, 요약 템플릿, 정원 정규화) | 값 유지. 영역은 부모 FK 로 표현 |

### 4.3 이전 규칙 (단일 분류 함수 — 백필과 `POST /sessions` shim 공유)

| 순서 | 조건 | 상위 | 규칙 코드 |

| 1 | `type='meditation'` | 명상 클래스 | C1 |

| 5 | 〃 활성 참여자 = 0 | 상담 관계(내담자 미상 placeholder, 상담사당 1) | R3 (`D-57`) |

- 정원(`max_participants`)으로 그룹/1:1 을 판정하지 않는다(기본 정원이 10 이라 상담도 10 일 수 있음). 활성 참여자 = 호스트 본인·제거·대기·대기취소 제외.
- 명상 이전: `classes` 1행(새 uuid; `created_by`←`host_id`, `title`, `description`←`notes`, `schedule_mode='fixed'`, `planned_session_count=1`, `origin='migrated'`, `status`←completed/cancelled/active, 설정 기본값 복사, 코드·숨김·생성시각 복사) · 세션은 `class_id`+`seq=1` 만 채움(**기존 컬럼은 건드리지 않음**) · `class_instructors(host_id,'lead','active')` 1행(세션 갱신 **전에** INSERT) · 참여자마다 `class_members` 1행 + `member_id` 연결.
- 참여자 상태 백필: `removed_at` → 멤버십 `removed` / 출석 `withdrawn`, `waitlist_cancelled_at` → `left`/`withdrawn`, `is_waitlisted` → `waitlisted`/`expected`, `entered_at` 있음 → `attended`(세션 completed 면 멤버십 `completed`), 입장 정보 없음 → **`absent` 로 단정하지 않고 `expected` 유지 + 표시**.
- 상담 이전: 회원 1명짜리는 `(host_id, 회원)` 쌍으로 묶음(`seq` = `coalesce(scheduled_at, started_at, created_at)`, `created_at`, `id` 순), 비회원은 세션당 `counseling_guests` 1행(참여자 개인정보 **복사**, `email_verified_at=NULL`, `origin='migrated'`, 스크럽된 행은 `pii_scrubbed_at` 도 복사) + 관계 1행. 링크는 **생성하지 않고** 있으면 `link_id` 연결, `ended` 이면 관계 `closed`.
- 예외: 숨김 세션도 이전(원시 SQL, ORM 필터 우회) · 취소 세션 이전 + `seq` 부여 · 기관 NULL 은 NULL 그대로 · 테스트 데이터(개발용 계정 3개)도 삭제하지 않음 · 분류 불가는 `unclassified` 보고 후 중단 · 비활성 호스트의 미래 세션은 `needs_reassign` 후보로 보고만.
- 모든 이전 행은 `session_migration_map(session_id PK, parent_kind, parent_id, rule, flags)` 에 기록 — 멱등 키 겸 역방향 근거.
