## 1. 한 줄 결론

- 프론트는 "서버가 주는 세션 1건 = 화면의 클래스 1건"으로 목록·홈 히어로·상세·만들기·입장·알림 라우팅까지 **한 타입(`SessionDto`)** 에 걸려 있다. 타입을 쪼개는 순간 영향이 번지는 구조다.
- 반대로 **진행 화면(플레이어)·입장 준비 마법사·대기실·종료·리포트 진행**은 이미 "세션 1건 단위"로 닫혀 있어 새 모델에서 "세션=회차"로 그대로 쓸 수 있다. 재사용 비중이 크다.
- 회원 "내 클래스"에 해당하는 화면은 **현재 없다**. 하단 탭 "클래스"는 세션(회차)을 4구역으로 나눈 평평한 목록이다(§7).
- 상담사 만들기 마법사는 5단계이고 **한 번에 세션 1건만** 만든다. 반복 일정·회차 일괄·강사 배정·기수 복제 입력이 없다(§8).

### 5.2 "내 클래스"에 해당하는 현행 화면 — **없음**

- 클래스(프로그램) 개념이 없어 "참여 중·완료·보강 대기·이탈" 구분, 3/8 진행, 결석 회차·보강 안내, 클래스 단위 변화 서사에 해당하는 화면/데이터가 모두 없다.

- 홈 요약 타일의 "완료 클래스"(`ClientHomePage.tsx:92`)는 완료 **세션 수**.
- 비회원(4자리 코드)은 앱 셸에 진입하지 않는다 — 입장 화면 흐름(`/join`→`/class/:id/enter`)만 있고 "내 …" 목록이 없다. 입장 자격은 `sessionStorage` 탭 단위(`class-flow.ts:241-264`)라 새로고침 외 재방문 시 클래스 이력이 남지 않는다.

### 5.3 이름 충돌 주의
- 상담사 홈 `DashboardPage.tsx:489-504` 에 이미 **"내 클래스" 섹션**이 있다(= 내가 진행한 세션 목록). 회원 "내 클래스"(프로그램)와 이름이 겹친다. 상담사 쪽은 "내 클래스"를 프로그램 목록으로 의미를 맞추거나 "최근 세션"으로 바꿔야 한다(R8 §4).
