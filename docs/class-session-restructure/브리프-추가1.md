# 브리프 추가 1 — 범위 확대 (Brian 2026-10-17, `브리프.md` 에 더해 적용. 충돌하면 이 문서가 우선)

## A. 범위: "전체 Phase 우선 기획"
- 이번 문서는 **MVP 한 조각이 아니라 전체 로드맵(Phase 0~N)** 을 먼저 그린다. 각 Phase 에 목표·포함 기능·선행 조건·백엔드/프론트 규모(S/M/L)·롤백·출시 단위를 적고, **각 Phase = 후속 SDD 한 건**으로 쪼갤 수 있는 단위로 나눈다. (구현은 이 문서 승인 후 별도.) 맨 앞에 **Phase 개요 1페이지 표**(Phase, 한 줄 목표, 의존, 규모, 사용자 체감 변화)를 둔다.
- 서비스 구조 전반을 **세밀한 부분까지** 기획한다: 개체별 속성·불변식(invariant), 상태 머신(클래스·세션·멤버십·출석·강사 배정 각각 상태와 전이 가능 조건·금지 전이), 권한 매트릭스(역할 × 동작), 엣지 케이스 표(상황 → 시스템 동작 → 사용자에게 보이는 문구), 알림 규칙, 데이터 보존·삭제 규칙(SDD-209 R4/R5 정책과 정합).

## B. 신규 확정 요구사항 (그대로 반영, 뒤집지 말 것)
1. **강사(지도사)**: 한 클래스에 **강사는 1명 이상**. 한 **세션의 진행 강사는 반드시 정확히 1명**(0명·2명 이상 불가).
   - 예: 강사 2명이 번갈아 진행 → 클래스 강사 2명, 세션별 진행 강사 1명씩.
   - **세션별 진행 강사 배정은 클래스 편성 단계에서 만든다**(회차별 지정, 번갈아/요일별/일괄 규칙 제안 포함) **그리고 중간에 수정할 수 있어야 한다.**
2. **상담사(강사) 입장에서 편하게**: 클래스 편성과 세션 편성이 쉬워야 한다 — 마법사 단계 수 최소화, 반복 일정 일괄 생성, 템플릿/복제("지난 기수 그대로"), 한 화면에서 회차 일괄 편집(일정·강사·장소/방식), 충돌 즉시 표시(강사 시간 충돌·장소 충돌), 드래그 없이도 되는 대체 입력, 모바일 상담사 사용 가능 여부.
3. **리포트는 클래스 단위로 관리**: 클래스 상세에서 회차별 리포트 목록·승인 상태·발송 상태를 한눈에 보고 일괄 처리(승인/발송/재생성) 가능, 클래스 단위 추이·출석 요약. 회원별 리포트 열람 권한(강사 교체돼도 유지), 리포트의 "작성자/승인자"가 세션 진행 강사와 어떻게 연결되는지.
4. **회원이 참여한 클래스를 확실히 보게**: 회원 홈/탭에 **"내 클래스"** 를 일급 개념으로 — 참여 중·완료·보강 대기·이탈한 클래스 구분, 클래스별 회차 진행(3/8), 다음 세션(강사·일시), 결석 회차와 보강 안내, 지난 세션 리포트 접근, 클래스 단위 변화 서사(점수 환원 금지). 비회원(4자리 코드) 참가자가 클래스 멤버가 될 때의 노출 범위 제안.

## C. 강사 모델에서 반드시 다룰 세부 (각각 기본값 제안 + 결정 필요 항목은 `결정-필요.md`)
- 데이터: `클래스–강사`(역할: 주강사/보조? — 단 세션 진행자는 항상 1명) 와 `세션.진행 강사`(필수, 클래스 강사 중 1명)의 관계, DB 제약(NOT NULL·FK·복합 제약으로 "세션 진행자는 해당 클래스 강사여야 함" 강제 가능한지)과 앱 레벨 검증, 현행 `sessions.host_id` 와의 관계(이름·의미 매핑, 이전 방안).
- 편성 UX: 회차 일괄 생성 시 강사 배정 방식(전부 한 명 / 번갈아 / 요일별 / 회차별 개별 지정), 미배정 상태 허용 여부(편성 중 임시) vs 열기/시작 시 필수 검증, 배정 규칙 시안(표 형태 UI 개념).
- **수정 규칙**: 미래 세션 진행자 변경(누가 변경 가능? 해당 강사 동의/알림?), 시작 임박·진행 중·완료 세션 변경 가능 여부(완료 후 리포트 귀속 정정은?), 대체 강사(대강)가 **클래스 강사가 아닌 사람**일 때(임시 대체 허용? 클래스에 먼저 추가?), 강사 한 명 클래스 이탈/계정 비활성/퇴사 시 미래 세션 처리(자동 미배정+알림? 대체 요청?), 클래스 강사 추가/제거 시 기존 세션과의 정합.
- 충돌: 같은 강사가 같은 시각 두 세션 진행 불가(검사 단위, 다른 클래스·개인상담 포함), 장소 충돌, 소속 기관(센터) 간 강사 공유 시 권한(org_admin·membership 현행 모델 `user_org_membership` 과의 관계).
- 권한 매트릭스: 클래스 개설자/주강사/보조 강사/해당 세션 진행 강사/타 강사/센터 관리자/회원 × (클래스 편집, 강사 추가·제거, 세션 진행자 변경, 세션 열기·시작·종료, 리포트 승인·발송, 회원 초대/제거, 클래스 삭제·보관). 세션을 진행하지 않는 클래스 강사가 참관/열람 가능한지(기본값 제안).
- 알림: 배정·변경·취소 시 대상 강사 알림, 회원에게 "진행 강사 변경" 안내 기준.
- 리포트·분석: 회차 비교는 진행 강사가 달라도 클래스 단위로 이어지는지, 강사별 통계는 만들지 말지(평가·순위화 위험 — 기본값은 "만들지 않음", 근거 명시).
- 현행(1세션=host 1명) 데이터 이전: 기존 `host_id` → 클래스 강사 1명 + 세션 진행 강사로 자동 매핑하는 단계 계획.
