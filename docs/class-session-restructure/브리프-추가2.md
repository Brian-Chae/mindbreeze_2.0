# 브리프 추가 2 — 명상 클래스 / 상담 분리 (Brian 2026-10-17, 추가1 위에 적용. 충돌하면 추가2가 우선)

## 확정
1. **제품·메뉴를 둘로 분리한다**: **명상 클래스**(명상 지도사) / **상담**(심리 상담사). 지금 만든 클래스 마법사는 곧 **명상 클래스 마법사**이고, **상담 세션 마법사는 새로 만든다.** 이유: 리포트 성격과 진행 방식이 완전히 다르다.
2. **역할 구분 없이 모두에게 메뉴를 연다.** 명상 지도사도 상담을 할 수 있고, 상담사도 명상을 할 수 있다(상담사 재량). **기관(센터) 단위 on/off 설정은 만들지 않는다.** 한 계정이 두 메뉴를 모두 보고 언제든 원하는 쪽을 만들어 쓴다. (→ 역할/자격 게이트가 있다면 현행 `counselor` 역할 모델과 `qualification`/`credential`/`onboarding` 이 이를 막는지 조사하고, 필요한 변경만 제안.)
3. 주 고객은 명상 센터 → 화면 용어는 명상 쪽이 "클래스", 상담은 별도 "상담"(상담 세션). (이전 확정 5가지는 유지: 결석·보강·중간 합류·이탈, 고정형+정기형, 기존 단회차→클래스1+세션1 이전.)

## 구조 제안(기획에서 검증·보완할 것)
| | 명상 클래스 | 상담 |
|---|---|---|
| 상위 단위 | 클래스(프로그램) | **상담 관계**(내담자 1명 + 상담사 1명) — 기존 `client_counselor_link` 활용 여부 조사 |
| 하위 단위 | 세션(회차), 진행 강사 정확히 1명 | 상담 세션(회차) |
| 강사 | 클래스 강사 1명 이상, 세션별 1명 배정(추가1) | 상담사 1명(관계 단위). 상담사 교체/이관은 별도 시나리오로 다룸 |
| 마법사 | 현행 클래스 마법사 | **새 상담 세션 마법사**(내담자 선택, 일정, 방식, 반복 상담 예약, 녹음 동의, 단순화) |
| 정원·대기열·비회원 4자리 코드·강사 번갈아 | 있음 | 없음(1:1). 비회원 내담자 상담 가능 여부는 결정 필요 항목으로 분리 |
| 리포트 | 클래스 단위 추이·서사+변화량(점수 환원 금지) | 상담사용+내담자용, 기록지·승인 흐름(현행 유지·강화) |
| 회원 쪽 | **내 클래스** | **내 상담** |
- **공유 엔진**: 진행 화면(SDD-208), 입장 전 흐름(SDD-209), 뇌파, 녹음·STT·요약 파이프라인, 리포트 생성 엔진, 알림. 영역별로 달라지는 것은 상위 단위, 마법사, 리포트 화면, 목록·상세·홈 IA.
- 기존 세션 `type`(clinical·hypnosis·meditation·custom)을 새 구조에 매핑: meditation→명상 클래스 / clinical·hypnosis→상담 / custom→분류 필요(결정 필요 항목 또는 기본값 제안). 이전 규칙과 dry-run 검증 쿼리 포함.
- SDD-209 가 만든 것 중 상담에서 단순화·제외되는 것(정원 스텐퍼, 대기열, 4자리 코드 입장, 비회원 이메일 초대, 리포트 반영 선택 등)을 표로 정리하고, 상담에서 필요한 대체 동작(예: 내담자 동의, 리포트 자동 승인 정책)을 제안.
