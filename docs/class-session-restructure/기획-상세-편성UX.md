> 근거: `조사/R5-회차운영.md`(현행 생성 경로·충돌·리마인더·`is_template`·`run_id`, 화면별 초안), `조사/R3-프론트영향.md` §8·§10(현행 5단계 마법사·모바일 현황), `조사/R9-강사모델권한.md`(배정·충돌), `조사/R10-상담분리.md` §5(SDD-209 단순화).

## 0. 설계 원칙 (두 마법사 공통)

1. **단계 수 최소화**: 한 단계 한 화면, 하단 주 버튼 고정, 몰입형(앱 셸 없음). 현행 명상 마법사 5단계(+완료) → **4단계(+완료)**, 상담 마법사 **3단계(+완료)**.
2. **드래그 없음**: 날짜·시각·순서·횟수는 모두 스텝퍼/입력/버튼/셀렉트. 표 UI 는 모바일에서 카드 + 편집 시트로 바뀌며 **같은 데이터 모델·같은 검증 함수**를 공유한다.
3. **서버가 권위**: 충돌·회차 목록 미리 보기는 서버 `preview-schedule` 응답을 그대로 표시한다(현행은 서버와 프론트가 따로 계산해 어긋날 수 있음 — `R5 §2.2`).
4. **충돌은 즉시 표시, 차단하지 않음**(소프트): `겹쳐요` 칩 + 사유 시트. 만들기는 허용.
5. **기본값 우선**: 필수 입력은 이름·일정·(강사)뿐이고 나머지는 접힌 `고급 설정`.
6. 일괄 생성 알림·초대는 회차마다가 아니라 **클래스 단위 1통**.
7. 모든 미리 보기는 "변경 전 → 후"를 보여준 뒤 `적용`으로 저장한다.

현행 사실(요약): 마법사는 5단계(유형·방식 / 기록 / 일정 / 초대 / 확인)이고 **세션 1건만** 만든다. 날짜는 오늘~+13일 스텝퍼 1개, 시각 07:00~22:00(5분), 소요 5~480분. 반복 일정·회차 일괄·강사 배정·기수 복제 입구가 없고, 템플릿 저장은 있으나 "템플릿에서 시작" 입구는 마법사에 없다(`R3 §8`, `R5 §2.1·2.4`).

### 1.2 화면별 입력·검증·오류 문구

| 화면 | 입력 (기본값) | 검증 | 오류·안내 문구 |
|---|---|---|---|
| **S0 시작 방법** | 카드 2개: `처음부터 만들어요` / `지난 클래스 그대로 시작해요` → 내 클래스 목록 시트(최근 종료순, 이름·회차 수·요일) | 선택 필수 | `아직 지난 클래스가 없어요. 처음부터 만들어 볼까요?` |
| **① 기본 정보** | 클래스 이름(필수) · 진행 방식(온라인/오프라인, 기본 온라인) · 오프라인이면 주소(기관·프로필 주소로 기본 채움) · 정원 스텐퍼(기본 10, 최소 2, 온라인 ≤50 · 오프라인 ≤100) · `고급 설정`(접힘): LINK BAND 사용 안 함/선택/필수(기본 선택), 음성 녹음(기본 켬), 영상 녹화(온라인만), 채팅 | 이름 1~200자, 정원 범위, 오프라인 주소 필수 | `클래스 이름을 입력해 주세요` · `정원은 2명부터 설정할 수 있어요` · `온라인 그룹은 최대 50명까지예요` · `대면 클래스는 영상 녹화 없이 진행해요` |
| **② 일정** | 진행 형태 `정해진 횟수` / `계속 이어져요`(정기) · 시작 날짜(달력 + 스텝퍼, 기본 다음 주) · 요일 칩(복수) · 시작 시각(5분 스텝퍼, 07:00~22:00) · 소요(5분 스텝퍼, 기본 60) · 횟수 스텝퍼(고정형, 기본 8) · 건너뛸 날짜(선택) · 리마인더(끔/하루 전/1시간 전/둘 다, 기본 하루 전) | 요일 ≥1, 시작 날짜 ≥ 오늘, 시각 범위, 횟수 2~52(기본값·임의) | `요일을 하나 이상 골라 주세요` · `시작 날짜는 오늘 이후로 정해 주세요` · `횟수는 2회에서 52회 사이로 정해 주세요` · 정기형 안내 `처음 4주 분량의 회차를 먼저 만들어 두고, 이후 회차는 자동으로 이어서 만들어요` |
| **③ 회차·강사 확인** (핵심) | 상단: 강사 구성(클래스 강사 칩, `강사 추가` = 같은 센터 상담사 검색, 개설자 자동 주강사) · 배정 방식 4종 세그먼트(`모두 한 분이 맡아요` / `번갈아 맡아요` / `요일마다 달라요` / `회차마다 직접 정해요`) · 번갈아 순서(위/아래 버튼) · 요일별 지정. 아래: 회차 일괄 편집 표(§1.3), 충돌 즉시 표시 | 모든 회차 진행 강사 1명(미정은 `나중에 이어서` 저장 시에만 허용 — `D-19`), 강사 ≥1, 주강사 ≥1 | `진행 강사가 없는 회차가 있어요. 강사를 정해 주세요` · `강사를 한 분 이상 추가해 주세요` · 충돌 칩 `겹쳐요` |
| **④ 초대·확인** | 위: 요약(이름·총 N회 또는 정기·첫 회차 일시·요일/시각·강사 구성·정원·방식·밴드·녹음, 충돌 건수). 아래: 초대(회원 검색·선택, 이메일 초대(비회원), CSV) — `나중에 초대할게요` 건너뛰기 | 이메일 형식, 정원 초과, 충돌은 경고만 | `이메일 형식을 확인해 주세요` · `정원을 넘어서 더 초대할 수 없어요` · `겹치는 일정이 2건 있어요. 그대로 만들 수 있어요` · 제출 실패 `클래스를 만들지 못했어요. 잠시 뒤 다시 시도해 주세요` · 코드 소진 `지금은 새 클래스 코드를 만들 수 없어요. 잠시 후 다시 시도해 주세요` |
| **완료** | 클래스 코드(큰 글자·복사, `코드는 참가자에게만 전달하세요`) · 초대 결과(`초대했어요` / `메일 발송을 요청했어요` — 전달 단정 금지) · 주 CTA `첫 회차 보러 가기`(클래스 상세) · 보조 `지난 기수 템플릿으로 저장` | — | 초대 일부 실패 `일부 초대를 보내지 못했어요. 다시 보낼게요`(재시도) |

- ③에서 `나중에 이어서`를 누르면 `classes.status=draft` 로 저장하고(`draft_schedule` JSONB), 클래스 목록에 `편성 중` 칩으로 보인다. 공개(=완료)할 때 전 회차 진행 강사가 있어야 한다.
- ④에서 만들기를 누르면 **한 트랜잭션**으로 클래스 + 회차 N행 + 클래스 강사 + 리마인더 예약 + 코드 1개를 만든다. 초대 알림은 클래스 단위 1통이다.

### 1.3 회차 일괄 편집 표 (③ 및 클래스 상세 `회차` 탭 공용)

| 열 | 입력 방식 (드래그 없음) |
|---|---|
| 선택 | 체크박스(헤더 전체 선택) |
| 회차 | `1회차 … 8회차`. 보강은 `보강`, 취소는 `취소` 칩 |
| 날짜 | 날짜 입력 + `−1일`/`+1일` 버튼 |
| 시작·소요 | 5분 스텝퍼 |
| 방식·장소 | 온라인/오프라인 토글, 오프라인 주소는 클래스 기본값 상속 |
| 진행 강사 | 셀렉트(클래스 active 강사만; 대체는 `다른 강사 찾기` → 같은 센터 임시 등록) |
| 충돌 | `겹쳐요` 칩(탭하면 사유 시트: `11/5(수) 19:00 상담 · 채용욱 상담 4회차와 겹쳐요`) |

- 일괄 동작 바(선택 시 노출): `시각 한꺼번에 바꾸기` · `강사 한꺼번에 바꾸기` · `한 주 밀기` · `선택 회차 취소`. 각 동작은 변경 전→후 미리 보기 후 `적용`.
- 행 편집 범위: `이 회차만`(기본) / `이 회차부터 모두`.
- **모바일**: 표 대신 회차 카드 목록 + `회차 편집` 바텀 시트(같은 필드·같은 검증 함수), 일괄 동작은 상단 `선택` 모드. 몰입형 마법사의 "390×844 에서 스크롤 0" 합격 기준은 **이 단계의 회차 목록 영역 내부 스크롤만 허용**으로 재정의해야 한다(기본값).
- 모바일 상담사 사용: 현행 상담사 셸·마법사는 모바일 합격 기준이 있으나 **실기기 검증은 `미확인`**(SDD-209 summary 대기). 회차 표·일괄 편집은 신규라 모바일 합격 기준(4개 뷰포트)에 포함해야 한다.

### 1.4 고정형 · 정기형 생성 규칙

**고정형(총 N회)**
- 입력: 시작 날짜, 요일(복수), 시각, 소요, 총 횟수 N, 건너뛸 날짜, 리마인더.
- 서버: `POST /classes`(클래스 + 회차 N행 한 트랜잭션) · 사전 확인 `POST /classes/preview-schedule`(저장 없음, 회차 목록 + 충돌 반환)가 **같은 규칙 함수**를 쓴다.
- 알고리즘(제안): 시작일부터 하루씩 전진하며 `weekday ∈ weekdays` 이고 `skip_dates` 가 아니면 후보. `interval_weeks > 1` 이면 기준 주(월요일 시작)에서 `(주 차이 % interval_weeks == 0)` 만 채택. 후보가 N개 차면 중단. `Asia/Seoul` 벽시계로 만든 뒤 UTC 로 저장(`scheduled_at` aware).
- 공휴일: 한국 공휴일 데이터 소스가 코드에 **없음**(`미확인`). 자동 건너뛰기 없음 + 표에서 직접 이동/제외, `건너뛸 날짜` 입력 제공.
- 코드: 회차마다 코드를 발급하면 8회 = 8코드를 점유(코드 공간 10,000)하므로 **클래스 단위 코드 1개**가 전제다.

**정기형(끝 없음) — 롤링 생성**
- 이유: 리마인더 ETA 예약, 충돌 검사, 회원 일정 노출, 코드 공간이 모두 "회차 행이 이미 있음"을 전제하므로 무한 생성이 불가능하다.
- 기본값: 항상 **앞으로 4주(`rolling_window_weeks=4`)** 분 회차를 유지. 방법 2중: ① 클래스 상세 진입 시 부족하면 on-demand 보충 ② 일 1회 cron(기존 `*_cron.py` 패턴 — celery beat 없음, `R5 §2.3`). 멱등: `UNIQUE(class_id, seq)` + "마지막 `seq`+1 부터 규칙 투영".
- 생성 시 강사 배정: 저장된 `assignment_rule` 을 적용, 규칙에 비활성 강사가 포함되면 해당 회차는 `needs_reassign` 로 만들고 알림.
- 롤링 생성 중 충돌: 충돌 회차도 만들되 표시(소프트). 상담사 홈에 "이번 주 겹치는 일정 N건" 배너 후보.
- 종료: `이번 회차를 마지막으로 마쳐요` 또는 종료일 지정. 종료 시 미래 `scheduled` 회차 취소 + 멤버 알림 (`D-08`).

**규칙 저장**: `recurrence_rule` 예 `{"weekdays":[1,3],"time":"19:00","duration_min":60,"start_date":"2026-11-03","interval_weeks":1,"tz":"Asia/Seoul","skip_dates":["2026-12-25"]}`. 이미 생성된 회차에는 규칙을 소급하지 않는다.

### 1.5 지난 기수 그대로

- S0 에서 클래스 선택 → ① 값 채움(이름 입력란 포커스, `(복사)` 접미사 없음) → ② **원본 `recurrence_rule` 투영**: 시작 날짜만 새로 입력하고 요일·시각·횟수·소요 유지 → ③ 원본 `assignment_rule` 승계, 비활성 강사는 `미정`.
- 멤버·초대 복사는 기본 꺼짐(`지난 회원을 함께 초대해요` 토글, `D-18`). 클래스 코드는 새로 발급.
- 오류: `{이름} 강사는 더 이상 이 센터에 없어요. 다른 강사를 정해 주세요`.
- 재사용: 현행 `_COPYABLE_CONFIG_FIELDS` 13개(`type`·`duration_min`·`max_participants`·`location_*`·`participant_mode`·`linkband_mode`·`sfu_enabled`·`record_*`·`chat_enabled`·`reminder_offsets`)는 클래스 설정 복사 대상으로 승계. 현행 `duplicate_session` 은 일정 1개만 받으므로 `POST /classes/{id}/duplicate`(새 이름·시작일·멤버 복사 여부·패턴 그대로 여부)가 신규다. 원본에 보강·취소·일정 이동이 섞여 있어도 복제는 **원래 패턴(`recurrence_rule`)** 만 쓰고 개별 예외는 복사하지 않는다.
- `is_template` 행(유형 설정 저장본)은 회차가 아닌 세션 행으로 남아 필터(`is_(False)` 20곳 + 분기 4곳)를 계속 요구한다 → 이전 대상에서 제외하고 contract 단계(Phase 8)에서 `class_templates` 로 이사한다. "템플릿 입구"는 "지난 기수 그대로"로 대체된다.

## 2. 회차 변경 · 취소 · 보강 회차 추가

| 동작 | 대상 | 규칙(기본값) | 현행 재사용 |
|---|---|---|---|
| 일정 변경(한 회차) | `scheduled`/`ready` | 과거 일시 불가, 충돌 검사(진행 강사 기준), 리마인더 revoke → 재예약, 멤버 알림 | `update_session` 거의 그대로(완료·취소는 400) |
| 이후 회차 같이 이동 | 선택 회차~끝 | "이 회차만 / 이 회차부터 모두". 모두 선택 시 시각·요일 이동분 적용, 충돌 일괄 검사 후 한 번에 저장 | 신규(서버 일괄 API) — 클라이언트 N회 호출 금지 |
| 한 주 밀기(휴강) | 선택 회차 이후 | +7일, `skip_dates` 기록. 고정형은 총 횟수 유지(마지막 회차가 뒤로 밀림) | 신규 |
| 진행 강사 변경 | 미래 회차 | `기획-상세-강사모델.md` §6.1 | 신규 |
| 회차 취소 | `ready`/`scheduled`/`open`/`in_progress` | `cancelled`, `seq` 유지(재사용 금지), 멤버 알림, 리마인더 revoke | `TRANSITIONS` 의 취소 |
| 취소 후 보충 | — | 고정형은 총 횟수가 줄지 않음(취소 회차는 "취소" 표시로 남음). 자동 보충 없음, 필요하면 `회차 추가`/`보강 회차 추가` (`D-09`) | 신규 |
| 회차 추가 | 고정형 | 끝에 `seq` 이어서 추가(총 횟수 +1). 정기형은 롤링이 담당 | `POST /classes/{id}/sessions` |
| 보강 회차 추가 | 정규 회차가 `completed`/`cancelled` 뒤 | `session_kind='makeup'`, 대상 멤버 지정(기본 = 결석자), **분모(N)에 포함하지 않음**, 표시 `보강` | 신규. 출석 행은 `기획-상세-회원내클래스.md` §3 |
| 삭제 | `ready`/`scheduled`/`cancelled` | 현행 삭제=숨김 규칙 유지, 클래스 안 마지막 정규 회차 삭제는 확인 시트 | `delete_session` |

- 서버 문구 정리 제안: `종료된 세션은 수정할 수 없습니다` → `끝났거나 취소된 회차는 바꿀 수 없어요`, `시간이 겹치는 세션이 있습니다` → `시간이 겹치는 일정이 있어요`(영역 공통 중립어). 서버 `detail` 문구를 일괄 치환하는 대신 **프론트가 상태 코드·에러 코드로 문구를 정하고** 서버 `detail` 은 로그·API 계약으로 유지한다(`R8 §4.3`).
- 알림 폭주 방지: ETA 태스크 수 = 오프셋 수 × 회차 수(8회 × 2 = 16, 브로커 부담 작음). 일정 일괄 이동은 서버가 루프로 revoke → 재예약한다.

## 3. 시간 충돌 — 클래스·상담 통합

단위·강도·일괄 검사·응답 형태는 `기획-상세-강사모델.md` §7. UX 표시:

- 회차 표 행: `겹쳐요` 칩 + 펼치면 `11/5(수) 19:00 상담 · 채용욱 상담 4회차와 겹쳐요`.
- 마법사 요약: `겹치는 일정이 2건 있어요. 그대로 만들거나 시간을 바꿀 수 있어요.`
- 상담 마법사: `같은 시간에 '{제목}'이 있어요. 겹쳐도 만들 수 있어요.`(현행 문구 승계)
- 열기·시작: `다른 일정을 진행 중이에요. 그 일정을 먼저 마쳐 주세요.`(경고 후 확인, `D-33`)
- 내담자(회원) 충돌은 **같은 상담사의 다른 회차**와 겹칠 때만 표시하고, 타 상담사·타 클래스와의 겹침은 노출하지 않는다(타 상담 존재 노출 금지).

## 4. 새 상담 세션 마법사

전제: 상담 = 내담자 1명 + 상담사 1명인 **상담 관계** 아래의 상담 세션. 정원·대기열·강사 번갈아·공용 4자리 코드 입장 스텝퍼 UI 없음. 엔진(진행 화면 SDD-208, 입장 전 SDD-209)은 공유.

### 4.1 설계 원칙

- **3단계 + 완료**: ① 누구와 만나요? → ② 언제, 어떻게 만나요? → ③ 확인·동의.
- 관계가 이미 있는 내담자에게서 시작하면(상담 상세·내담자 상세의 `다음 상담 잡기`) ①을 건너뛴다.
- 제외: 유형 4종 선택 화면(상담 유형은 ②의 칩 하나), 인원(1:1 고정 — 서버가 `participant_mode=one_on_one`·`max_participants=1` 강제), 정원, 대기열, 이메일 CSV 초대. LINK BAND·영상은 `고급 설정` 접이식.
- 같은 내담자의 지난 회차 `일시·방식·소요`를 ②에 prefill(요일·시각·방식·소요 그대로 +1주).

### 4.2 화면별 입력·검증·오류 문구

| 화면 | 입력 (기본값) | 검증 | 오류·안내 문구 |
|---|---|---|---|
| **A. 내담자 선택** | 탭 `기존 내담자` / `새 내담자`. (기존) 이름·이메일 검색, 최근 상담순 목록(회원 검색 재사용), 행 우측 `상담 N회 · 마지막 11/3`. (새) 이름(필수), 이메일(필수 — 리포트 전달·초대 메일), 휴대폰은 받지 않음(개인정보 최소화 기본값) | 이름 1~50자, 이메일 형식, 이메일 재입력 확인 1회 | `이름을 입력해 주세요` · `이메일 형식을 확인해 주세요` · **이미 회원**: `이 이메일로 가입한 회원이에요. 회원으로 연결할까요?`(`연결해요`/`비회원으로 만들어요`) · **같은 상담사·같은 이메일 관계가 이미 있음**: `{이름}님과의 상담이 이미 있어요. 이어서 다음 상담을 잡을까요?` · **종결된 관계**: `마무리한 상담이 있어요. 이어서 다시 시작할까요, 새로 시작할까요?` |
| **B. 일정·방식** | 일정: `지금 바로` / `날짜·시간 정할게요`(기본). 날짜(달력 + 스텝퍼), 시작 시각(5분), 소요(기본 50분 — 현행 기본값), 방식 온라인/오프라인(오프라인이면 주소 기본 채움), 상담 유형 칩(`임상심리상담`/`최면심리상담`/`기타`+이름), **반복 상담 예약** 토글 | 과거 불가, 시각 범위, 충돌 즉시 표시 | `지난 시간으로는 잡을 수 없어요` · `같은 시간에 '{제목}'이 있어요. 겹쳐도 만들 수 있어요.` |
| **B-1. 반복 상담 예약** (토글 on 시 펼침) | 주기 `매주`/`격주`/`직접 고르기`(요일 칩), 요일·시각은 첫 상담에서 자동, 끝 조건 `N회 먼저 잡기`(기본 4, 2~12) / `끝 없이 이어가요`(정기형: 앞으로 4주씩 자동 생성), **회차 미리 보기**(최대 8행 + `더 보기`, 각 행 `11/10(월) 19:00 · 2회차 · 겹쳐요?`, 체크 해제로 제외) | 횟수 범위, 첫 회차 필수 | `횟수는 2회에서 12회 사이로 정해 주세요` · `끝 없이 이어가면 앞으로 4주 분량만 먼저 잡아 두고 이후는 자동으로 이어서 잡아요` |
| **C. 확인·동의** | 요약(내담자·일정·방식·반복). `상담 기록`: 음성 녹음(켬 기본)·AI 기록(켬), 영상 녹화(온라인, **상담은 기본 꺼짐** 제안 — 현행 기본은 켬). `고급 설정`: LINK BAND(`사용`/`사용 안 함` 2택, 기본 사용 — 필수 모드는 어차피 차단하지 않으므로 제외), 리마인더(기본 하루 전). **녹음 동의**: 상담사가 대신 체크하지 않고 `내담자에게 동의 안내를 함께 보내요`(안내문 미리 보기 링크) | 없음(경고만) | 동의 거부 시 처리 문구는 `D-02` 결론에 따름: `동의하지 않으면 녹음 없이 직접 기록해요`(수동 기록) 또는 `동의하지 않아도 상담은 진행할 수 있어요`(고지형) |
| **완료** | `{이름} 상담을 시작해요` 카드, 첫 상담 일시, 안내 전달 상태(`초대했어요`(회원 인앱) / `메일 발송을 요청했어요`(비회원) — 전달 단정 금지), 비회원이면 **상담 코드**(4자리, 큰 글자 + 복사, `코드는 내담자에게만 전달하세요`), CTA: 즉시면 `상담 열러 가기`, 예약이면 `상담 목록 보기` | — | `상담을 만들지 못했어요. 잠시 뒤 다시 시도해 주세요` · 부분 실패 `상담은 만들었지만 안내 메일을 보내지 못했어요. 다시 보낼까요?` |

|---|---|---|

| 필수 입력 | 유형·방식·인원·(정원)·일정·이름 | 내담자·일정(기본값 있음) |
| 클릭 수(기존 내담자 · 다음 주 같은 시각) | 해당 없음 | 내담자 선택 1 → 다음 1 → 확인 1 → 만들기 1 = **4**(목표) |

### 4.4 비회원 내담자 (확정 반영, 상세는 `기획-상세-상담.md` §4)

- 상담사가 이름 + 이메일(필수, 재입력 확인)로 관계를 만든다. 비회원 정보는 `counseling_guests` 한 곳에 두고 회차 참여자 행에는 `guest_client_id` 참조만 둔다(한쪽만 스크럽하는 실수 방지).
- 입장·본인 확인: **관계 단위 4자리 코드 + 등록 이메일 일치 + 상담사 대기실 승인**. 코드는 메일 본문에만 싣는다(URL 에 싣지 않음).
- 재방문: 관계 자격(마지막 사용 후 90일 슬라이딩) + 분실 시 코드 + 이메일 + 생년월일 재확인. 상담사 화면에 `코드 다시 만들기`(기존 코드 즉시 무효).
- 리포트는 승인 후 등록 이메일로 발송.

### 4.5 마법사 진입점

`/counseling/new`(상담 메뉴 `새 상담 시작`) · `/counseling/:relationshipId` 의 `다음 상담 잡기`(A 건너뜀) · 홈 빠른 액션 · 상담 직후 종료 화면의 `다음 상담 잡기` 한 줄. 기존 `/sessions/new` 는 영역을 구분해 `/classes/new` 또는 `/counseling/new` 로 보낸다.

## 5. 상담 관계 흐름 — 계속 추가 · 종결 · 재개

| 종결 후 열람 | 상담사: 읽기 전용(기록·리포트·메모) / 내담자: 지난 리포트 열람 | 새 회차 생성 불가, **삭제 아님**. 원본(EEG·음성·영상)은 SDD-209 스위프(90일)가 별개로 적용 — 범위는 `D-49` | 카드 `마무리한 상담 · 11/3 종료` |
| 재개 | 종결된 상담 상세 `다시 시작하기` / 마법사 A 에서 같은 내담자 선택 | **기본값: 같은 관계 재개**(`active`, 이벤트 기록, 관계 코드 새로 발급, `seq` 이어서). `새로 시작해요`를 고르면 새 관계. 보관(`archived`) 후에는 새 관계 | `다시 시작할까요? 이전 기록과 이어져요` · `새 상담으로 시작해요`(이전 기록과 분리) |
| 이관(상담사 교체) | 센터 관리자 (`기획-상세-상담.md` §6) | 기존 관계 `closed` + 새 상담사와 새 관계 | |

## 6. 리마인더 (편성 UX 관점)

- 현행: 회차별 Celery ETA(시점 5분~14일, 한 회차 최대 5개) + OS cron 스윕(향후 48시간, 상태 `scheduled`/`ready`/`open`). 수신자 = 회원·비대기(비회원 제외). 별도 AI 비서 사전 안내(3시간·1시간 전)는 1:1 예약 세션만.
- 변경: 수신자 = 활성 멤버 − 해당 회차 사전 결석자(회차 출석 행이 없는 멤버도 수신). 메일 문구에 클래스명·`N회차` 추가(`[MIND BREEZE] MBSR 봄 · 3회차 안내 (하루 전)`), 합니다체 → 해요체로 정리.
- 상담: 비회원 내담자는 현행 두 경로 모두 제외 → **입장 시 별도 동의가 있을 때만** 이메일 리마인더(`D-15`).
- 상담사 본인에게 가는 사전 안내는 현행에 없으므로 홈 Action Queue(`곧 열 회차·상담 — 15분 전부터 열기`)로 대체한다.
