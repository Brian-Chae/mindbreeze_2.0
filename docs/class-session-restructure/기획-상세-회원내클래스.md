# 기획 상세 — 회원 "내 클래스" · "내 상담" 정보 구조 / 멤버십·출석 모델

> 2026-10-17 · Phase 1(서비스 기획) 초안 · 승인 대기. 본문 `기획.md` §6·§7 의 상세 편.
> 근거: `조사/R4-회원참여모델.md`(멤버십·출석·정원·동의·비회원), `조사/R3-프론트영향.md` §5·§6.2(현행 회원 홈·탭), `조사/R8-용어IA.md` §5·§7.4(표기·홈·메뉴), `조사/R6-리포트분석.md` §6·§8(변화 서사 범위·금지), `조사/R10-상담분리.md` §6·§8(내 상담).
> 확정(브리프-추가1 §B-4): 회원이 참여한 클래스를 **일급 개념**으로 — 참여 중·완료·보강 대기·이탈 구분, 클래스별 회차 진행(3/8), 다음 세션(강사·일시), 결석 회차와 보강 안내, 지난 세션 리포트 접근, 클래스 단위 변화 서사(점수 환원 금지), 비회원 노출 범위 제안. 추가2: 회원 쪽은 **내 클래스 / 내 상담**.

## 1. 한 장 요약

1. 현재 회원 쪽에는 "내 클래스"에 해당하는 화면이 **없다**. 하단 탭의 `클래스`는 회차(세션)를 4구역(입장 가능 / 초대받은 / 예정 / 지난)으로 나눈 평면 목록이고, 홈의 `완료 클래스` 타일은 완료 **세션 수**다(`R3 §5.2`). 클래스(프로그램) 개념이 없어 진행률·결석·보강·이탈 구분에 해당하는 데이터도 없다.
2. 새 IA: 회원 홈 → **내 클래스** 목록(프로그램 카드) → **클래스 상세**(회차 타임라인) → 세션(회차) 입장. 상담은 **내 상담** 목록 → 상담 상세 → 상담 입장. 두 영역 모두 항상 노출한다(기관 단위 on/off 없음 — 데이터가 없으면 빈 상태 화면이 안내).
3. 회원 쪽 상태 4종(**참여 중 · 완료 · 보강 대기 · 이탈**)은 저장하는 값이 아니라 멤버십 상태 × 출석 × 클래스 상태에서 **파생**한다(§3.2).
4. 변화 서사는 **본인 데이터만, 방향·변화량·서사**로 표현한다. 그룹 평균·순위·±델타·종합점수·타인 대비 수치는 회원 화면에 두지 않는다(SDD-208 합의 #5).
5. 비회원(4자리 코드)은 앱 셸이 없다. 입장 자격이 있는 기기의 **한 화면**(다음 일정 · 내 출석 요약 · 본인 리포트 링크)으로 한정하고, 타 멤버 정보는 어떤 경우에도 노출하지 않는다.

## 2. 멤버십 + 회차별 출석 모델 (`R4`)

### 2.1 구조 결정 (기술 기본값)

| 옵션 | 내용 | 판정 |
|---|---|---|
| **A 확장형 (채택)** | `class_members`(멤버십) 신설 + `session_participants` 를 **회차 출석 행**으로 유지(`member_id` FK + `attendance_*` 컬럼 추가) | 출석 행 id 불변 → EEG·리포트·연구 동의·입장 자격(JWT `sub`)·FK 4곳(`eeg_records`·`eeg_raw_chunks`·`reports`·`eeg_feature_windows`, 모두 CASCADE) 무변경. 추가형(nullable→백필) |
| B 완전 분리 | `class_members` + 신규 `session_attendances`, FK 4곳 이전 | FK 4곳 + 연구 3테이블 + JWT 클레임 + 27개 서비스 파일 수정 — 롤백 트랩 대비 위험이 크다 |
| C 파생 | 멤버십 테이블 없이 "어느 회차에든 출석 행이 있으면 멤버" | 중간 합류·결석·이탈·대기·수료를 표현 못 해 요구 불충족 |

- 현행 참여자 "상태"는 단일 enum 이 아니라 플래그·타임스탬프 조합(`is_waitlisted`·`removed_at`·`waitlist_cancelled_at`·`entered_at`)이다. 멤버십·출석에 **명시적 status 컬럼을 신설**하고 기존 플래그는 출석 쪽에서 호환 유지한다.
- 이름 충돌 주의: 현행 `membership_service.py` 는 **상담사의 기관 소속**(`user_org_memberships`)이며 클래스 멤버십과 무관하다.
- **이탈 표현에 `removed_at` 을 쓰지 않는다**: `removed_at` 이 있는 행은 모든 ORM SELECT 에서 숨겨지고 회원의 리포트 접근이 "참여자 행 존재"로 판정되므로, 이탈한 회원의 지난 출석·리포트가 사라진다. 이탈은 멤버십 status 로만 표현하고 과거 출석 행은 가시 상태로 둔다.

### 2.2 `class_members`

`class_id` FK(RESTRICT) · `user_id` FK NULL(비회원) · `kind`(`member`/`guest`) · `status`(`기획-상세-상태머신권한.md` §1.4) · `joined_via`(`host_invite`/`code`/`email_invite`/`waitlist_promotion`/`migration`) · 비회원 개인정보(`guest_name`·`gender`·`birth_date`·`report_email`·`pii_scrubbed_at`, 클래스당 1회 입력) · `waitlist_position` · `joined_at`/`activated_at`/`left_at`/`removed_at`/`completed_at` · `first_session_id`(중간 합류 기준 회차) · `report_included_default`(기본 false) · `notice_ack_at`/`notice_version` · `entry_ver` · `UNIQUE (class_id, user_id)`(NULL 허용 — 비회원 다중). 재가입은 같은 행을 되살린다(현행 `_revive_removed_participant` 패턴 계승). 이벤트는 `class_member_events`(append-only).

### 2.3 `session_participants` 추가 컬럼 (추가형, nullable → 백필)

`member_id` · `attendance_status`(`expected`/`attended`/`absent`/`excused`/`withdrawn`) · `attendance_kind`(`regular`/`makeup`/`guest_pass`) · `makeup_for_session_id` · `attendance_marked_by`(`system`/`host`/`self`) · `absence_reason`(선택 — 개인정보 최소화, 필수 아님) · (상담용) `guest_client_id`.

### 2.4 결석·보강·중간 합류·이탈 — 데이터 표현

| 상황 | 멤버십 | 출석(해당 회차) | 비고 |
|---|---|---|---|
| 정상 참석 | `active` | `expected` → 입장 시 `attended` + `entered_at` | |
| 무단 결석 | `active` | 회차 `completed` 후 `expected` 이면서 `entered_at IS NULL` → `absent`(`system`). 취소 회차는 확정 제외, 분모에서도 제외 | 확정은 `end` 전이 후 훅(`research_export_service.on_session_completed` 와 같은 종료 훅 자리) |
| 사전 결석 통보 | `active` | `excused`(`self`/`host`) + 선택 사유 | 회차 정원에서 빠져 자리를 반환 |
| 보강(별도 회차) | `active` | 새 회차(`session_kind='makeup'`)에 출석 행 `attendance_kind='makeup'`, `makeup_for_session_id`=결석 회차, 최초 `expected` | 원 결석 행은 그대로 유지(기록 보존) |
| 보강(기존 회차 합류) | `active` | 같은 클래스의 다른 정규 회차에 `makeup` 행 추가 | 데이터 구조는 동일, 회차를 새로 만드는지만 다름 (`D-06`) |
| 보강 대기(파생) | `active` | 결석 행이 있고 이를 대체하는 `makeup` 출석이 없음 | "내 클래스" 의 `보강 대기` 배지 근거 |
| 중간 합류 | 새 멤버 `active`(정원이면 `waitlisted`), `first_session_id`=합류 직후 첫 예정 회차 | 합류 이후 예정 회차에만 `expected`. **지난 회차 행 없음**(결석 아님) | 지난 회차 열람 범위 `D-07` |
| 이탈(본인) | `active` → `left` | 미래 `expected` → `withdrawn`(숨김 아님), 과거 행 유지, 진행 중 회차는 끝까지 | 지도사에게 `class_member_left` 알림 |
| 이탈(지도사 제외) | `active` → `removed` | 위와 동일 | **멤버십 제외**와 **한 회차만 내보내기**를 구분(`D-13`) |
| 재가입 | `left` → `active` | 이후 예정 회차에 `expected` 재생성 | 같은 행 되살림, 이력은 `class_member_events` |
| 클래스 종료 | `active` → `completed` | 남은 `expected` 없음 | 정기형은 클래스 종료 시 일괄 |
| 회차 취소 | 변화 없음 | 행 유지, 상태 변경 없음(`absent` 아님) | 보강 필요 여부는 지도사가 "대체 회차 추가"로 처리 |

### 2.5 정원·대기열 — 혼합 (기본값, `D-11`)

| 옵션 | 정원 | 대기열 | 위험 |
|---|---|---|---|
| A 클래스 단위 | 활성 멤버 수 ≤ 정원 | 클래스 대기열 | 보강 참석자가 정원 밖 추가 인원이 되어 장소 초과 가능 |
| B 회차 단위 | 회차별 출석 `expected+attended` ≤ 정원 | 회차 대기열(현행) | 코호트에서 "내 자리"가 보장되지 않음 |
| **C 혼합 (기본값)** | **멤버 정원(클래스)** + **회차 상한**(`sessions.max_participants`, 기본 = 클래스 정원) | 멤버 모집·승격은 클래스 대기열, 회차 상한 초과(보강·드롭인)는 회차 대기열(현행 로직 재사용) | 로직이 두 겹 — 회차 쪽은 현행 코드 그대로 |

- 회차 정원 카운트 = `attendance_status ∈ {expected, attended}`(`excused`·`absent`·`withdrawn` 제외 → 사전 결석이 자리를 비워 보강자가 들어올 수 있음).
- 정기형(상시 모집)은 멤버 정원을 비워 둘 수 있고(무제한), 그때 정원은 회차 상한이 담당한다.
- 대기열 승격 규칙은 현행 유지(순번 순, 취소자 제외, 새치기 방지, 행 잠금). 승격 알림은 클래스 대기열용 `class_waitlist_promoted` 신규.
- 정원을 활성 멤버 수보다 낮춰도 기존 멤버를 강등하지 않고 **신규 입장만 대기로** 보낸다(현행 `update_session` 동작과 동일).
- 클래스 코드는 활성 코드 공간(10,000)을 아끼기 위해 **클래스 단위 1개**. 정기형은 코드 노출 기간이 길어져 재발급 UI 의 우선순위가 올라간다(Phase 4 범위 후보).

### 2.6 동의 시점 — 혼합 O3 (기본값, `D-01`)

| 종류 | 현행 단위 | O3 처리 |
|---|---|---|
| ① 수집 고지 확인(녹음·AI 기록·뇌파·영상, N일 후 삭제) | 참여자 행(=회차) | **회차마다** 한 줄 요약 + `확인`(체크 강제 없음, 증빙은 출석 행에 기록) — "세션 시작 전" 고지 원칙 유지 |
| ② 리포트 반영 선택(기본 제외) | 참여자 행 | **가입 1회** 기본값(`report_included_default`) → 출석 행 생성 시 **복사**, 입장 준비에서 `이번 회차 바꾸기` 링크 |
| ③ 연구 목적 데이터 활용 동의(기본 미동의) | 참여자 행 | **가입 1회** 입력을 미래 회차 행에 복사. 효력은 **회차별 스냅샷**(회차 종료 후 그 회차 동의는 확정) |

- `research_consents`·`report_scope`·내보내기 배치는 **회차 단위 그대로**이므로 검증이 끝난 SDD-209 코드를 건드리지 않는다. 변경은 "입력 시점·기본값 복사"에 한정된다.
- 클래스 기본값 변경은 **미래·미종료 회차 출석 행에만 전파**한다(종료 회차 불변). 화면 문구 `다음 회차부터 적용돼요`.
- 쟁점: 연구 동의를 가입 1회로 받아 미래 회차에 자동 적용하는 것이 "명시적 동의" 요건에 맞는지는 코드로 확인할 수 없다 → **법무 판단 필요**(`미확인`). 안전 변형 O3-s = 연구 동의만 회차마다 재확인(기본값 = 가입 시 선택).
- 정책 정합: 선택은 모두 분리 저장, 어느 선택도 입장·수집을 막지 않는다, 리포트 제외는 기본 제외에서 시작하여 명시 선택 시에만 포함(`policy-revision-r4.md` 정책 2·RV2). 상담에서는 기본값이 달라진다(`기획-상세-상담.md` §5, `D-02`·`D-03`).

## 3. 내 클래스 (회원)

### 3.1 메뉴·홈 (`R8 §7.4`)

- **사이드바(데스크톱)**: 홈 · 내 클래스 · 내 상담 · 채팅 · 리포트 · 알림 · 설정 (현행 6 → 7).
- **하단 탭(모바일)**: 홈 · 내 클래스 · 내 상담 · 리포트 · 더보기 (현행: 홈·클래스·채팅·리포트·더보기). 채팅은 ① `내 상담` 상세의 `상담사와 대화` ② 홈 `최근 대화` ③ 더보기. 채팅 미읽음 배지는 `내 상담` 탭 점에 합산. (탭 구성안은 UX 기본값이며 비즈니스 결정이 아니다 — 최종 확정은 시안 단계.)
- **홈 구성**

| 순서 | 섹션 | 내용 |
|---|---|---|
| 1 | 다음 일정 히어로 | 영역 무관 가장 임박 1건. `MBSR 봄 · 3회차` / `김하늘 상담사와 상담 · 4회차` |
| 2 | 초대받은 일정 | 클래스 초대 / 상담 초대 |
| 3 | **내 클래스** | 프로그램 카드(이름·진행 `3/8`·다음 회차·상태 칩). 점수·순위 표현 금지(횟수만) |
| 4 | **내 상담** | 관계 카드(상담사·마지막 상담·다음 상담·`상담사와 대화`). 종결된 상담은 접힌 `마무리한 상담` |
| 5 | 이번 주 일정(통합) | 현행 `이번 주 클래스` 구역을 영역 칩 포함 일정 목록으로 |
| 6 | 코드로 입장하기 | 유지 |
| 7 | 내 리포트 | 유지, 영역 칩 |
| 우측 레일 | 요약 타일 4(`다음 일정까지 · 새 리포트 · 이번 주 일정 · 마친 …`) / 담당 상담사 / 최근 대화 / 새 알림 | 타일 라벨의 `클래스` → `일정` |

- 빈 상태: 내 클래스 0 → `참여 중인 클래스가 없어요 · 코드로 입장하거나 지도사에게 신청해 보세요`. 내 상담 0 → `아직 상담이 없어요 · 상담사에게 신청해 보세요`. 현행 신청은 상담사에게 채팅 메시지 전송이라 영역별 문구(`클래스 신청하기` / `상담 신청하기`)로 분기한다.
- 상담사 홈의 기존 `내 클래스` 섹션(= 내가 진행한 세션)은 회원 "내 클래스"(프로그램)와 이름이 겹치므로 `진행 중인 클래스`로 개칭한다.

### 3.2 상태 4종 — 파생 규칙 (저장하지 않음)

| 회원 화면 상태 | 판정 |
|---|---|
| **참여 중** | 멤버십 `active` **이고** 클래스 `active`. 정원 대기는 `대기 중`(별도 칩, 4종 밖) |
| **보강 대기** | 참여 중이면서 "결석/사전 결석 출석 행이 있고 이를 대체하는 `makeup` 출석이 없음". 배지로 **참여 중에 덧붙는다**(구역은 참여 중에 남고 카드에 `보강 대기 1` 표시) |
| **완료** | 멤버십 `completed`(클래스 `completed`) |
| **이탈** | 멤버십 `left` 또는 `removed`. 기본 접힘 구역. `removed` 는 사유 비노출(`지도사가 제외했어요` 같은 문구 쓰지 않고 `참여가 종료됐어요`) |

목록 구역 순서: 참여 중 → 완료 → 이탈(접힘). 카드 정렬은 다음 회차가 가까운 순(참여 중), 종료일 최근순(완료).

### 3.3 내 클래스 카드

```
MBSR 봄 클래스                      [참여 중] [보강 대기 1]
김지수 지도사
8회 중 3회차 진행 중
다음 · 11월 17일(월) 오후 7:00 · 온라인
내 참석 2회 · 결석 1회
```

| 요소 | 규칙 |
|---|---|
| 진행 표기 | 고정형 `8회 중 3회차 진행 중`(분자 = 완료된 정규 회차 수 + 진행 중, 분모 = 취소 제외 정규 회차 수, 보강 제외). 정기형은 분모 없이 `3회차`만(칩 없음) |
| 내 참석 | **사실 표기만** — `내 참석 2회 · 결석 1회 · 보강 완료 1회`. 분자 = `attended`(정규+보강), 분모 = 합류 이후 취소 아닌 정규 회차. 출석률(%) 등급·정렬 금지 |
| 다음 세션 | 일시·방식·**진행 강사** (확정된 `assigned` 1명만 표시, 미정·`pending_ack` 강사명은 노출하지 않음 — I20) |
| 상태 칩 | 현행 키 재사용: 준비·예정·곧 열림·입장 가능·진행 중·완료·취소·초대 (`class-labels.ts`) |
| 접근성 | `aria-label="MBSR 봄 클래스 8회 중 3회차"` |
| 이름 없음 | `이름 없는 클래스 · 3회차` |

### 3.4 클래스 상세 (회원)

| 영역 | 내용 |
|---|---|
| 헤더 | 클래스명 · 지도사 · 진행 `3/8` · 상태 칩 |
| 다음 회차 | 일시·방식·진행 강사·`입장하기` CTA(현행 입장 상태 머신), 곧 열림 안내(`30분 뒤에 회차가 열려요`) |
| 회차 타임라인 | 회차별 한 줄: `1회차 · 11/3 · 참석` / `2회차 · 11/10 · 결석` + `보강 신청` / `3회차 · 11/17 · 예정` / `4회차 · 취소` / 합류 전 회차 `참여 전`(흐리게) / 보강 `보강 · 2회차 대신`. 취소 회차는 결석이 아님(분모 제외) |
| 결석·보강 안내 | 결석이 있으면 상단 카드 `놓친 회차가 1개 있어요. 보강으로 채울 수 있어요` + 보강 가능 회차 목록(`makeup_offered` 알림과 연결). 보강 대상이 없는데 신청하면 `보강할 결석 회차가 없어요` |
| 지난 세션 리포트 | 참석한 회차의 **본인 리포트**만(승인 후). 결석·합류 전 회차는 리포트 없음 표기(`이 회차는 결석이에요`, `합류 전 회차예요`). 이탈한 뒤에도 본인 지난 리포트는 열람 유지(`D-12`) |
| 클래스 변화 서사 | §4 |
| 내 설정 | 리포트 반영 기본값·연구 동의 기본값 보기/변경(`다음 회차부터 적용돼요`), 알림, `클래스에서 나가기`(확인 시트: `나가면 앞으로 예정된 회차 4개가 취소돼요. 지난 기록과 리포트는 그대로 볼 수 있어요`) |

- 열람 범위: 클래스 멤버면 클래스 상세·**회차 타임라인(일정·상태·제목)**을 볼 수 있다. 회차 **입장·리포트**는 그 회차의 출석 기록이 있을 때만. 중간 합류자의 지난 회차는 **일정만**, 리포트·기록은 본인 참석분만(`D-07` 기본값).
- 현행 규칙은 "그 회차의 참여자 행이 있으면 그 회차를 본다"라 결석한 회차를 회원이 볼 수 없다. 멤버십 `EXISTS` 를 OR 로 추가하는 판정 일원화가 필요하다(인덱스 `class_members(user_id, class_id)`).

## 4. 클래스 단위 변화 서사 (회원용, 점수 환원 금지)

원칙(`R6 §3·§8`): ① 종합점수·점수 환원·순위·타인/그룹 대비 수치 금지 ② 서사 + 변화량(방향·±) ③ 미측정 ≠ 0, 유실 ≠ 미측정 ④ 제외한 참여자는 모든 파생물에서 제외.

| 구분 | 내용 | 원칙 정합 |
|---|---|---|
| MVP | **회차별 변화 방향 띠**: 본인 6지표(몸 3·마음 3) 각각 `↑ / → / ↓`(그 회차 전반→후반). 출석한 회차만 표시, 결석·미착용은 빈칸(`측정 안 됨`) | 방향 + 변화량, 점수 없음 |
| MVP | **첫·마지막 비교 서사**: `1회차에서는 이완이 오른 흐름이 많았고 8회차에서는 안정적으로 유지됐어요` 식의 규칙 기반 템플릿(결정론적, LLM·전역 서사 캐시 비사용). 수치는 ±% 카드로만 | 서사 + 변화량 |
| MVP | **출석 요약**: `3/8 참석`, 결석 회차, 보강 완료/대기 | 점수 아님, 결석≠0 |
| MVP | **착용 회차 수**: `뇌파 측정 회차 5/8`(미착용은 정상 미측정 — 감점·강조 없음) | 미측정≠0 |
| 후속 | 개인 장기 기준선(1회차 첫 N분 기준 상대값) | 데이터 모델 신설 필요, 별도 SDD |
| 제외 | 강사별 통계·강사 간 비교·회원 순위·종합점수·타인 대비 | 원칙 위반/위험 |

- 현행으로 가능한 것: 한 회차 안의 전반→후반 변화량(6지표 방향·%/±), 타임라인, 서사. **없는 것: 회차 간 비교 기준**(개인 장기 기준선이 없다). 회차 간 비교를 정규화 점수 0~100 으로 만들면 사실상 종합점수화·성적표화가 되고 타당도 근거도 없으므로 **방향·변화량 나열**이 기본이다(`D-40` 수준값은 넣지 않음).
- 데이터: 회차 리포트 생성 시 `build_metrics_summary` 결과를 `content.eeg.change` 로 **가산 저장**(스키마 변경 없음, 하위호환). 클래스 추이는 해당 클래스의 승인된(`completed`) client 리포트에서 읽어 조립한다 → 제외 참여자는 애초에 행이 없어 자동 제외, 승인 후에만 노출. 기존 리포트는 백필 태스크(윈도우에서 결정론적 재계산, 서사 LLM 호출 없음).
- `eeg.score`(종합점수)는 데이터로는 저장돼 있으므로 **추이·집계 입력으로 쓰면 안 된다** — 구현 시 테스트로 고정.
- 서사 문구는 평가·진단 표현("개선", "악화" 단정) 금지, "진단/치료 목적 아님" 고지 유지.
- 회원 화면에 두지 않는 것: 클래스 방향 분포 인원수, 그룹 평균 곡선(상담사 전용, 착용자 ≥3명일 때만 — `group_aggregate` 의 `MIN_WEARERS`).

## 5. 비회원(4자리 코드) 참가자의 노출 범위

- 비회원은 앱 셸이 없다(입장 흐름만 있고 "내 …" 목록이 없다). 입장 자격은 현행 `sessionStorage` 탭 단위라 새로고침 외 재방문 시 이력이 남지 않는다.
- 제안(`R4 §7`, `D-16`): 클래스 코드 입장 성공 시 `class_members(kind='guest', joined_via='code')` + **클래스 단위 장기 자격**(마지막 사용 후 N일 슬라이딩, 기기 저장소). 자격 보유 기기의 `/class/{id}` **한 화면**에 한정: 다음 회차 일시 · 내 출석 요약 · 본인 리포트 링크. 개인정보는 클래스당 1회 입력.
- 기기 분실·브라우저 정리 시 끊김 → 지도사의 **"같은 사람 합치기"**(중복 비회원 멤버 병합, 이벤트 기록)로 복구한다. 공용 기기용 로그아웃은 현행 `entry/revoke` 재사용. 이메일 링크 복구는 SDD-209 D-1(이메일 OTP 제외 확정) 재논의가 필요해 후보로만 둔다.
- 회원가입 유도는 안내만 한다(가입 시 `class_members.user_id` 연결 — 소유 증명 방법 미결).
- 비회원에게는 **클래스 단위 추이를 제공하지 않는다**(계정 없음 → 회차 간 연결 불가). 리포트는 회차별 메일 링크만(`D-43`).
- 회차 사이에 코드를 입력하면 입장 불가가 아니라 가입만 되고 `다음 회차는 11월 17일 19:00에 시작해요. 그때 입장해 주세요` 대기 화면.
- 개인정보 보관: 스크럽 기준일 = "마지막으로 출석한 회차 종료일 또는 멤버십 종료일 중 늦은 날 + 90일", 멤버십 + 출석 사본을 같은 실행 단위에서 스크럽. 비회원 리마인더 메일은 입장 시 별도 동의가 있을 때만(`D-15`).

## 8. 미확인

1. 연구 동의를 가입 1회로 받아 미래 회차에 적용하는 것의 적법성(법무).
2. 회원에게 `pending_review` 리포트가 승인 전에 노출되는지 — 서버·프론트 목록에 상태 필터를 찾지 못했고 호출 검증은 하지 않았다(`R6-X1`). **Phase 0 에서 실제 호출로 검증**.
