# 프론트 디자인 조사 — 글씨 크기·모바일 가독성 (2026-10-10)

> 범위: `frontend/src` 전체(테스트 제외) 정적 분석. 실기기 시각 검수는 포함하지 않음.
> 외부 기준은 일반 가이드라인(Apple HIG·Material·WCAG) 기준이며 이번 조사에서 웹 재검색은 하지 않음.

- 행간이 지정돼 있지 않음(브라우저 기본 약 1.2~1.3). 디자인 토큰의 본문 행간은 1.57(22/14)인데 채팅 말풍선은 토큰을 쓰지 않고 인라인 style로 직접 지정.

## 3. 모바일 기준 대비

| 기준 | 권장 | 현재 |
|---|---|---|
| 본문(읽는 글) | iOS 17pt(HIG body), Android 14~16sp, 국내 메신저(카카오톡·LINE) 채팅 15~16px | 14px |
| 최소 글씨 | iOS 11pt, Material 12sp | 9~11px 376건 |
| 입력 필드 | **16px 이상**(iOS Safari는 미만이면 포커스 시 화면 자동 확대) | 입력창 중 16px 미만 18건 (`text-sm`/`text-xs`): 기관 검색·필터 select, 초대 모달, 일정 장소, 변경 사유 textarea 등. 채팅 입력창은 16px라 해당 없음 |
| 터치 영역 | 44×44pt(iOS) / 48×48dp(Android) | 하단 탭 h-14(56)로 양호. 그러나 h-6~h-8(24~32px) 요소 약 76곳 확인 필요 |
| 한글 행간 | 1.5~1.6 | 토큰은 1.5 이상, 채팅은 미지정 |
| 색 대비 | WCAG AA 4.5:1 | 시간 `#9CA0AE` on 흰색 2.61:1·on 보라 말풍선 `#F5EDFC` 2.29:1 **미달**(실측 계산), 보조 텍스트 `#6F6F6F` on 크림 4.58:1·on 흰색 5.02:1 통과(실측 계산) |

한글은 같은 px에서 영문보다 획이 조밀해 작게 느껴지므로 영문 기준(14px)보다 1~2px 크게 잡는 것이 일반적.

## 4. 진단 요약

1. 채팅 본문 14px는 모바일 메신저 기준(15~16px)보다 작다. 제보와 일치.
2. 시간·이름·안내(10~12px)는 글씨도 작고 색 대비도 낮아 이중으로 읽기 어렵다.
3. 크기 값이 서비스 전반에서 임의로 흩어져 있고 디자인 토큰이 적용되지 않는다 → 한 곳을 고쳐도 다른 화면이 어긋남.
4. 인라인 style로 지정된 채팅 컴포넌트는 반응형·토큰 적용이 불가능한 구조.
5. 사용자가 OS 글씨 크기를 키워도 반영되지 않는다.

## 5. 개선안

### A. 채팅 즉시 개선 (작은 변경, 저위험)
| 요소 | 현재 → 제안 |
|---|---|
| 말풍선 본문 | 14 → **16px**, 행간 1.5 |
| 시간 | 10 → **12px**, 색 `#9CA0AE` → `#6F6F6F`(흰 배경 5.02:1, 기존 보조색 재사용) |
| 발신자 이름 | 11 → **13px** |
| 안내 문구·라벨 | 12·11 → **13px** |
| 말풍선 폭 | 70/78% → **80%** (글씨가 커져도 줄 수 증가 억제) |
| 방식 | 인라인 style → Tailwind/토큰 클래스로 전환(일반 채팅·루시·클래스 채팅 3곳을 공용 컴포넌트로 일원화) |

### B. 전체 타입 스케일 정립
- 스케일: caption 12 / small 13 / body 16 / label 16(semibold) / heading 20 / title 24 / display 28~
  - 모바일 본문은 16, 데스크톱 보조 정보는 14 허용(`text-[15px] md:text-sm` 식 반응형)
- 최소 크기 **12px 하한** 확정, 9~11px 376건은 12px로 상향하거나 배지 숫자만 예외 허용.
- 임의 값(13.5, 14.5, 17, 19…)을 스케일에 정렬.
- 입력 필드 16px 미만 18곳을 16px로 (iOS 자동 확대 방지).
- 작은 터치 요소(h-6~h-8)는 모바일에서 히트영역 44px로 확장(설정 화면의 Toggle에서 이미 쓰는 `p-2.5 -m-2.5` 방식 재사용).

### C. 사용자 글씨 크기 설정 (선택)
- 설정에 "글씨 크기: 보통/크게/매우 크게"(루트 `font-size` 16/18/20px)를 두고 rem 기반 스케일 적용. 시니어·상담 내담자 연령대 고려 시 효과 큼. 단 px→rem 전환 범위가 커서 단계적 진행 필요.

## 7. 한계
- 정적 분석 수치이며 실제 렌더 크기는 `rem`·상속·브라우저 최소 글씨 설정의 영향을 받을 수 있음.
- 색 대비는 hex 값으로 WCAG 공식 계산(렌더 후 측정은 미수행).
- `pages/design`(목업 291건)은 실서비스 화면이 아니라서 수치에 포함돼 있음 — 제외하면 작은 글씨 비중이 약간 낮아짐.
