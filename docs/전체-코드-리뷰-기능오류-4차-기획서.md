## 상(상) 5건 — 본문 상세

### 1. REC-PRIV-001 — 기록지 개인정보 유출 📊
- **현상**: `GET /sessions/{id}/record`·`/transcript`가 세션 참여자(내담자·그룹 참여자)에게 상담사 내부 메모(counselor_notes)·세션 전체 전사문·AI 요약을 그대로 반환. 1:N 그룹 세션에서는 다른 참여자의 발화까지 노출.
- **근거**: `record_service.py:26-41`(참여자 통과, role 미구분) · `:137-191`(_serialize가 counselor_notes/transcript/ai_summary 필터 없이 포함) · `App.tsx:175`(라우트 RoleGuard 없음). 반면 `report_task.py:379-382`는 그룹 client 리포트에서 ai_record를 의도적으로 제외.
- **영향**: 내담자 개인정보(타인 발화·상담사 메모) 유출.
- **해결**: 참여자(비host)에게는 counselor_notes·전체 transcript·ai_summary 제외, 본인 슬롯만 반환. 공수 1일.

### 2. SEC-LIVEKIT-PUBLISH-BYPASS — LiveKit 발언권 우회 📊
- **현상**: 레거시 `POST /sessions/{id}/livekit-token`이 host뿐 아니라 일반 참여자(대기열 포함)에게 `can_publish=True` 토큰을 발급. SDD-094의 그룹 발언권 게이트(speaking)를 완전 우회.
- **근거**: `session.py:456-472`(`_get_session_for_participant`로 참여자 통과 → `generate_livekit_token` 기본 can_publish=True) · `session_service.py:1248-1273` · `:1572-1587`(_compute_can_publish는 member_livekit_token에서만 사용).
- **영향**: 발언권 없는 참여자가 세션에 발언 가능 → 수업 통제력 상실.
- **해결**: 이 엔드포인트를 host 전용으로 제한하거나 `_compute_can_publish`를 적용. 공수 0.5일.

### 3. RPT-EMAIL-SEND-002 — 리포트 메일 자동 발송 안 됨 🚪
- **현상**: 상담사가 승인해도 내담자 리포트 메일이 자동 발송되지 않음. 생성 완료 시점(pending_review)에 예약된 태스크는 status!=completed라 미발송하고, `approve_report`는 메일을 재예약하지 않아 승인 후 발송 경로가 끊김.
- **근거**: `report_email_service.py:159-170`(deliver_report_email이 status!=completed면 미발송) · `report_service.py:801-847`(approve_report가 completed 전이만, 메일 미예약) · `report_task.py:417-450`(pending_review에서 enqueue).
- **영향**: 내담자가 리포트를 이메일로 받지 못함.
- **해결**: approve_report에서 completed 전이 시 메일 재예약. 공수 0.5일.

### 4. EEG-NUM-001 — 인지부하(cognitiveLoad) 점수 항상 0 📊
- **현상**: 코호트(B0) 정규화에서 cognitiveLoad 점수가 항상 0. raw cognitiveLoad는 절대 선형 파워(μV²)인데 점수화 함수는 θ/α 비율 백분위를 적용.
- **근거**: `EEGSignalProcessor.ts:378`(cognitiveLoad = 절대 μV²) · `eegScore.ts:86-89`(scoreCognitiveLoadRealtime → COGNITIVE_LOAD_PERCENTILES θ/α 비율) · `eegScoreConstants.ts:47`.
- **영향**: 인지부하 지표가 항상 0으로 표시(데이터 오염).
- **해결**: cognitiveLoad 점수화를 절대 파워에 맞는 백분위로 교정 또는 raw를 θ/α 비율로 변경. 공수 0.5일.

### 5. STREAM-LIFE-001 — 재연결 시 StreamProcessor 누수 🔋
- **현상**: 자동 재연결 시 이전 StreamProcessor를 cleanup 없이 새 인스턴스로 교체해 ppgResetTimer(setInterval)와 리스너가 영구 누수.
- **근거**: `useBand.ts:1137-1158`(onConnectionLost→connect 예약) · `:1105-1106`(새 StreamProcessor 생성, 이전 cleanup 없음) · `StreamProcessor.ts:123-128`(setInterval).
- **영향**: 재연결마다 타이머·메모리 누적 → 성능 저하.
- **해결**: connect()에서 이전 streamRef cleanup 호출. 공수 0.5일.
