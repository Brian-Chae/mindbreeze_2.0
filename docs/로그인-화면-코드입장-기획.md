# 로그인 화면 코드 입장(로그인 없이 클래스 입장) 기획

- 작성일: 2026-10-22 · 상태: Phase 1 기획 + Phase 2 시안 (방향 확정, 시안 확인 대기)
- 시안: `designs/login-code-entry/index.html`
- 관련: SDD-209(코드 입장 `/join`), SDD-226(즉석 클래스·회차 공용 입장 주소)

## 1. 문제

- 웹 홈페이지(랜딩) 첫 화면에는 **[코드로 입장]** 버튼이 있어 로그인 없이 `/join`으로 갈 수 있다.
- 앱(iOS·Android)은 랜딩을 건너뛰고 바로 로그인 화면을 연다(`App.tsx` `EntryRoute` → `RoleRouter` → `/login`).
- 로그인 화면(`LoginPage.tsx`)에는 코드 입장 링크가 없다. 그래서 **앱에서는 계정 없는 참여자가 클래스에 들어갈 길이 없다.**
  - 상담사가 "앱 깔고 코드 4자리 넣으세요"라고 안내해도 참여자는 회원가입부터 해야 한다.
  - 즉석 클래스(SDD-226)는 "코드만 알려 주면 바로 입장"이 핵심인데, 앱 사용자에게는 막혀 있다.
- 웹에서도 로그인 화면으로 직접 들어온 사람(북마크·로그아웃 직후·메일 링크)은 같은 문제를 겪는다.

## 2. 목표

- 앱을 처음 연 사람이 **로그인 화면에서 1번 눌러** 코드 입력 화면으로 간다.
- 코드 입장 흐름(코드 확인 → 이름·이메일 등 입력 → 녹음 동의 → 입장)은 **기존 `/join`을 그대로** 쓴다. 새 서버 기능 없음.
- 로그인 화면의 주 목적(로그인)은 흐리지 않는다.

## 3. 범위

| 포함 | 제외 |
|---|---|
| 로그인 화면에 코드 입장 진입점 추가(앱·웹 공통) | 코드 입장 흐름 자체 변경(코드 확인·개인정보·동의) |
| `/join`에서 뒤로 가기 → 로그인 화면 복귀 | 서버 API 변경 |
| 입장 코드 전달 시 URL에 코드를 싣지 않는 기존 원칙 유지 | QR 입장(SDD-226에서 제거됨) |
| 앱 첫 실행 시 진입점 노출 확인 | 게스트 입장 후 회원가입 전환 유도(별도 기획) |

## 4. 화면 배치 (확정 방향, 2026-10-22 Brian)

- **회원 탭에서만** 화면 하단에 코드 입장 카드를 떠 있게(플로팅) 고정한다. 상담사·기관 탭, 플랫폼 관리자 로그인에는 없다.
  - 이유: 코드 입장은 회원(참여자) 전용 기능.
- 카드: 열쇠 아이콘 + "입장 코드가 있나요? / 로그인 없이 바로 들어가요" + [코드로 입장] → `/join`.
- 카드 뒤는 아래에서 위로 옅어지는 어두운 그라데이션으로 폼과 구분한다.
- 기기 하단 안전영역(iPhone 홈 바)만큼 띄운다(`env(safe-area-inset-bottom)`).
- **스크롤 여백**: 회원 탭 폼 아래에 카드 높이 + 안전영역 + 여유(약 24px)만큼 빈 공간을 둔다. 끝까지 내리면 비밀번호 찾기·회원가입·개인정보 처리방침이 카드에 가려지지 않는다.
- **키보드**: 이메일·비밀번호 입력 중(키보드 표시)에는 카드를 숨기고, 입력이 끝나면 다시 보인다.
- **회원 탭 순서 변경**: 이메일·비밀번호 + [이메일로 회원 로그인] + 비밀번호 찾기·회원가입을 위에, "간편 로그인" 구분선 아래에 Google·Apple을 둔다(상담사 탭과 같은 순서). Google·Apple 신규 가입 동의 항목은 간편 로그인 버튼 아래에 그대로 표시.
- 이전 검토안(A 하단 카드 / B 상단 버튼 / C 직접 입력)은 위 방향으로 대체.

## 5. 사용자 흐름

### 5.1 앱, 계정 없는 참여자

1. 앱 실행 → 로그인 화면
2. 회원 탭(기본 탭) 하단의 **[코드로 입장]** 누름 → `/join` 코드 입력(기존 화면)
3. 4자리 입력 → [코드 확인] → 클래스 이름·시간·진행자 확인 + 이름·이메일·성별·생년월일 입력 + 녹음·녹화 동의
4. [입장] → 대기실/진행 화면 (`/class/:sessionId/enter`)
5. 코드 화면에서 뒤로 가기 → 로그인 화면

### 5.2 이미 로그인한 회원

- 로그인 상태면 로그인 화면 자체가 안 뜬다(역할별 홈으로 이동). 회원 홈의 기존 "코드로 입장하기" 버튼을 쓴다. 변경 없음.

## 6. 문구

| 위치 | 문구 |
|---|---|
| 카드 제목 | 입장 코드가 있나요? |
| 카드 설명 | 로그인 없이 바로 들어가요 |
| 버튼 | 코드로 입장 (웹 랜딩과 같은 이름) |

## 7. 지켜야 할 기존 원칙

- 입장 코드는 URL·주소창·저장소에 남기지 않는다(SDD-209).
- 코드 오류는 한 가지 문구로만 안내(없는 코드 추측 방지). 시도 제한(429) 안내 유지.
- 녹음·녹화 필수 동의(SDD-220 F1) 유지.
- LINK BAND 없이도 입장 가능(착용은 대기실에서 선택).

## 8. 검증 기준 (구현 시)

- 앱(iOS·Android)에서 로그아웃 상태로 실행 → 회원 탭 첫 화면에서 스크롤 없이 카드가 보인다.
- 상담사·기관 탭으로 바꾸면 카드가 사라지고, 회원 탭으로 돌아오면 다시 보인다. 플랫폼 관리자 로그인에는 없다.
- 회원 탭을 끝까지 스크롤하면 개인정보 처리방침 링크까지 카드에 가려지지 않는다.
- 이메일·비밀번호 입력 중에는 카드가 입력칸을 가리지 않는다(숨김).
- 카드 → 코드 입력 → 게스트 입장까지 dev 서버에서 실제 클래스 코드로 끝까지 성공. 뒤로 가기 → 회원 로그인 화면.
- 주소창·방문 기록에 코드가 없다.
- 작은 화면(iPhone SE 375×667)·홈 바 있는 기기(iPhone 15)에서 카드가 잘리거나 홈 바와 겹치지 않는다.

## 9. 상태

- 방향 확정(회원 탭 전용 하단 플로팅 + 스크롤 여백). 시안 확인 후 구현(SDD-227).
