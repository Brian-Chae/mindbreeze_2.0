## Executive Summary

**회원·세션·클래스·리포트 전 기능이 작동하며, 최근 정비(SDD-125~135)로 대기/진행/종료 화면은 안정화된 상태다.**

다만 **인증·권한 경계에 구멍이 7개** 있다. 그중 하나는 **무인증으로 타인의 자격증빙(면허·신분증)을 승인 처리할 수 있는 치명 결함**이다. 이건 출시 전에 반드시 막아야 한다.

**가장 시급한 3건:**
1. ⚠️ **무인증 자격증빙 승인** — 누구나 상담사 면허를 "승인" 상태로 바꿀 수 있음 (치명)
2. **로그인 후 정지된 계정도 계속 활동** — 정지/탈퇴 회원이 토큰으로 계속 접근
3. **JWT 서명 키가 코드에 하드코딩** — 개발용 키가 그대로 배포됨

**결정 요청:**
- [ ] **Q1 — 보안 7건(1순위)을 즉시 수정·배포할까?** (공수 약 4.5일)
- [ ] **Q2 — celery beat를 cron으로 전환해 복구 안전망을 가동할까?** (공수 1일)

## 1순위 — 보안·권한 (출시 차단, 7건 · 약 4.5일)

### ⚠️ [SEC-01] 무인증 자격증빙 승인 📊 (치명)
상담사가 올린 면허·신분증을 **로그인 없이 누구나 "승인" 처리**할 수 있는 엔드포인트가 남아 있다. 승인 시 상담사 등급이 "검증됨(verified)"으로 올라가 검증을 우회한다.
- 근거: `backend/app/api/v1/credential.py:85-100` (인증 선택적), `credential_service.py:217-252`
- 해결: 해당 엔드포인트 삭제 또는 관리자 전용 게이트 + 감사 기록. **0.5일**

### [SEC-02] 정지·탈퇴 계정이 계속 활동 📊
로그인이 JWT 서명만 확인하고 계정 상태(정지/대기)를 매 요청 검사하지 않는다. 정지된 계정이 기존 토큰으로 계속 접근 가능.
- 근거: `backend/app/api/deps.py:14-45` (status 미검사)
- 해결: get_current_user에서 매 요청 status 검사. **0.5일**

### [SEC-03] JWT 서명 키 하드코딩 📊
서명 키 기본값이 코드에 `dev-secret-change-me`로 박혀 있고, 설정 누락 시 이 키로 모든 토큰이 서명된다.
- 근거: `backend/app/config.py:16,39,44`
- 해결: 키 미설정 시 기동 중단(fail-fast). **0.5일**

### [SEC-04] Google 로그인 토큰 검증 누락 📊
Google 로그인이 사용자 정보 응답만으로 세션을 발급하고, 토큰의 대상(audience)/앱ID를 검증하지 않는다. 선언된 client_id가 실제로 사용되지 않음.
- 근거: `backend/app/api/v1/auth.py:670-700`
- 해결: audience/client_id 검증 추가. **1일**

### [SEC-05] 비밀번호 재설정 후 세션 미무효화 📊
비밀번호를 바꿔도 기존 로그인 세션(토큰)이 유지된다. 관리자 재설정은 무효화하는데 본인 재설정 경로는 누락.
- 근거: `backend/app/services/password_reset_service.py:68-115`
- 해결: 본인 재설정에도 토큰 전부 무효화. **0.5일**

### [SEC-06] 리포트 수정 권한 게이트 없음 📊
상담사 리포트 본문을 **내담자·게스트도 덮어쓸 수 있다.** 수정 엔드포인트가 역할 검사 없이 "세션 참여자면 통과"로 되어 있다.
- 근거: `backend/app/api/v1/reports.py:101-108`, `report_service.py` 권한 함수 재사용
- 해결: 상담사·관리자만 수정 가능하도록 역할 게이트. **0.5일**

### [SEC-07] 프론트 화면 권한 가드 미적용 📊
역할 가드가 일부 화면에만 붙어 있고, 내담자가 상담사 화면(세션·내담자 관리·증빙)을, 상담사가 내담자 화면을 그대로 열 수 있다. (서버는 일부 보호되나 화면은 열림)
- 근거: `frontend/src/App.tsx:146-230` (RoleGuard 일부 라우트만)
- 해결: 역할별 라우트 가드 전면 적용. **1일**

## 2순위 — 데이터 무결성·기능 (6건 · 약 3일)

### [DATA-01] 계정 삭제 시 연관 데이터 누락 📊
관리자가 회원을 삭제하면 자식 테이블(소속·가입신청·기관 소유자) 정리가 누락돼 외래키 오류가 난다.
- 근거: `backend/app/services/admin_service.py:584-607`
- 해결: 자식 테이블 정리 목록 보완. **0.5일**

### [FE-JOIN] 게스트 이름 미입력 시 영구 차단 🚪
게스트가 이름 없이 참여를 시도하면, 이후 이름을 제대로 입력해도 참여 잠금이 풀리지 않아 영구히 입장 불가.
- 근거: `frontend/src/pages/class-join-page.tsx:348-440` (joinStartedRef 미해제)
- 해결: early-return 시 잠금 해제 + resetJoin 보강. **0.5일**

### [FE-REC] 기록지 실시간 갱신 중단 📊
기록지 화면의 실시간 소켓이 네트워크 재연결 시 방 재구독을 안 해서, 끊겼다 복구되면 기록이 더 이상 갱신되지 않는다.
- 근거: `frontend/src/hooks/useRecordSocket.ts:59,72-90`
- 해결: connect마다 재구독. **0.5일**

### [FE-AUDIO] 녹음 마지막 구간 유실 📊
세션 음성 녹음이 종료 직후 화면을 벗어나면 마지막 수 초가 저장되지 않고, 실패 청크 재전송도 없다. (영상은 이미 재전송 구현됨)
- 근거: `frontend/src/hooks/useAudioRecorder.ts:21,47-59,88-94`
- 해결: 영상과 동일하게 flush 대기 + 실패 청크 재전송. **0.5일**

### [VID-01] 영상 병합이 중간에서 멈출 수 있음 📊
영상 청크 병합 시 앞선 청크 하나만 로드 실패해도 그 뒤 전부가 파일에 안 쓰이는 경우가 있다.
- 근거: `backend/app/services/video_service.py:219-235`
- 해결: 누락 청크 건너뛰고 나머지 계속 기록. **0.5일**

### [RPT-01] 리포트 재생성 시 즉시 "실패" 처리될 수 있음 📊
오래 걸린 리포트를 재생성하면 진행 시작 시각이 갱신되지 않아, 감시 로직이 즉시 실패로 오판할 수 있다.
- 근거: `backend/app/tasks/report_task.py:378-386`
- 해결: 재생성 시 시작 시각 리셋. **0.5일**

## 3순위 — 성능·운영 (2건 · 약 2일)

### [PERF-01] EEG 실시간 모니터링 과부하 🔋
상담사가 실시간 지표를 볼 때 매 4초마다 세션 전체 참가자의 뇌파 데이터를 전부 불러와 서버에서 계산한다. 참가자가 많을수록 부하 누적.
- 근거: `backend/app/services/session_service.py:1752,2109-2150`
- 해결: DB 집계로 이관 + 범위 제한. **1일**

### [PIPE-01] 복구 안전망(celery beat) 미가동 📊
실패한 리포트 재발행·이메일 발송·리마인더가 Celery beat 주기 스케줄에 의존하는데, beat가 실제로 구동되지 않는다(알려진 이슈 SDD-100). 이걸 돌릴 cron/systemd 진입점이 없다.
- 근거: `backend/app/core/celery_app.py:30-40`
- 해결: cron 또는 systemd timer로 주기 스윕 실행. **1일**
