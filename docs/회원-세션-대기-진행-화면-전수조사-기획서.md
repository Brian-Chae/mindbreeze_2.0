# 회원 세션 대기화면 · 클래스 진행 화면 전수조사 기획서

> 대상: 회원(내담자·게스트)이 클래스에 들어가서 나갈 때까지의 모든 화면
> 범위: 입장 게이트 → 대기실(3단계 준비) → 시작 대기 → 명상/상담 진행 → 종료 화면
> 방법: 3개 병렬 조사 에이전트가 프론트·백엔드 코드를 전수조사, 파일:라인 근거로 문제 52건 도출

## Executive Summary — 30초 요약

**한 줄 결론:** 회원 화면에서 "클래스가 사라지거나, 회원이 갇히거나, 데이터가 틀리거나" 하는 치명 결함 8건이 발견됐다. 모두 실제 사용에서 바로 드러나며, **회원 이탈과 뇌파 리포트 신뢰도에 직결**된다.

**가장 시급한 3가지:**
1. **일시정지 한 번에 클래스가 사라지고 회원이 갇힘** — 상담사가 잠깐 멈추면 회원 목록·홈에서 클래스가 통째로 사라지고, 회원은 대기 화면에 무한 대기. *(회원 이탈, 수업 중 수시로 발생)*
2. **참여자 데이터 오염** — 같은 게스트가 새로고침할 때마다 유령 참가자로 중복 생성되고, 대기열 회원이 입장해도 관제에 안 보임. *(데이터 신뢰, 뇌파 리포트·좌석 관리 근거 붕괴)*
3. **"지난 5분 추이" 그래프가 정지된 그림** — 숫자(72%)와 그래프가 서로 모순. *(데이터 신뢰)*

**지금 결정할 3가지 (예/아니오):**
- [x] **Q1. 일시정지 기능 자체를 제거** — 2026-10-05 확정. 상담사의 "일시정지/재개" 시나리오가 불필요하므로 상태·버튼·알림 일괄 제거 (SDD-125)
- [x] **Q2. 중도 입장도 3단계 강제 유지** — 2026-10-05 확정. 링크밴드 연결 등 준비를 마친 뒤 입장.
- [x] **Q3. 출시 차단 범위 = 1순위 7개 항목 전부** — 2026-10-05 확정. 일시정지 제거(1) + 대기열·게스트(2,3) + 추이그래프·타이머(4,5) + 대기 복귀·미터(6,7) 전부 수정 후 출시.

> 상세 근거는 §2, 일정·공수는 §3, 전체 목록은 §5 부록 참조

## 2. 상(심각) 8건 상세

### 2-1. 일시정지 시 클래스가 목록·홈에서 사라짐 🚪 → **기능 제거로 해소 (SDD-125)**
- 회원 홈·목록의 "지금 참여 가능" 필터가 `ready/open/in_progress`만 보고 **`paused`를 뺌**. 일시정지 1회로 클래스가 목록·홈에서 통째로 사라진다.
- 근거: `ClientSessionListPage.tsx:155-157`, `ClientHomePage.tsx:124-127`

### 2-2. 일시정지 시 회원이 대기 화면에 갇힘 🚪 → **기능 제거로 해소 (SDD-125)**
- 회원 자동 입장이 `in_progress`일 때만 발동해서, 일시정지(`paused`) 상태에선 **회원이 "잠시 후 시작합니다" 대기 화면에 무한 대기**한다. (상세 화면에선 paused도 입장 가능하므로 화면끼리 모순)
- 근거: `class-join-page.tsx:461`(sessionLive 판정), `ClassWaitingRoom.tsx:345-357`(자동 입장 게이트)

### 2-3. 대기열 회원이 입장해도 관제 누락 📊
- 정원 초과로 대기열에 있던 회원이 코드로 입장하면 기존 참여자 행의 `is_waitlisted`가 해제되지 않아, **상담사 관제·좌석·인원 집계에서 제외**된다. 회원은 입장한 것처럼 진행되는데 관제엔 안 보임.
- 근거: `session_service.py:1313-1329`, `class-join-page.tsx:348-367`

### 2-4. 게스트 재입장 시 유령 참가자 누적 📊
- 게스트가 새로고침·재접속하면 매번 새 참여자 행이 생겨 유령 참가자가 쌓이고, 참여 인원·정원이 부풀고, 이전 식별 정보가 끊긴다(회원은 user_id로 멱등 처리되지만 게스트는 없음).
- 근거: `session_service.py:1290-1346`

### 2-5. "지난 5분 추이" 그래프 정지 📊
- 그래프 데이터를 제자리에서 수정하는데, 그래프 컴포넌트가 "안 바뀐 걸로" 판단해 처음 그린 그림을 그대로 유지. 같은 카드의 "지금 72%" 숫자는 매초 갱신돼 **숫자와 그래프가 서로 모순**.
- 근거: `GuestMeditationPanel.tsx:197, 373-386, 556` + `MemberTrendGraph.tsx:37-52`

### 2-6. 1초 측정 타이머 리셋 → 샘플 누락 📊
- 1초마다 값을 수집하는 타이머가 서버 신호가 올 때마다 해제·재생성되어, 실제로는 신호가 올 때마다 리셋. 샘플이 불규칙하게 누락.
- 근거: `GuestMeditationPanel.tsx:345-386`

### 2-7. [준비 다시 확인] 후 대기실로 돌아갈 길 없음 🚪
- 3단계를 마치고 시작 대기 화면에서 "준비 다시 확인"을 누르면 준비 화면으로 돌아오는데, **대기 화면으로 복귀하는 경로가 없고** 시작 전 [입장하기]도 무동작이다. (완전한 데드엔드는 아니나 — [나가기]로 세션을 이탈해야만 빠져나옴)
- 근거: `ClassWaitingRoom.tsx:345-357`, `class-join-page.tsx:178-188`

### 2-8. 대기 화면 초당 60회 다시 그려짐 🔋
- 마이크 음량 미터가 브라우저 프레임마다(60fps) 갱신돼 대기실 전체가 초당 60번 다시 그려진다. 마이크는 진입 즉시 자동으로 켜지므로 대기 내내 지속.
- 근거: `ClassWaitingRoom.tsx:175-184, 243-247`

## 4. 결정 사항

### Q1. 일시정지 기능 제거 🚪 — **확정 (2026-10-05)**
- 상담사의 "일시정지/재개" 기능 자체를 제거한다. (수업 중 잠깐 멈추는 시나리오가 필요 없다는 Brian 결정)
- 기존 `paused` 상태 데이터는 진행 중(`in_progress`)으로 통합 마이그레이션.
- 제거 범위·절차는 SDD-125으로 분리 — 세부는 `specs/125-remove-session-pause/spec.md` 참조.

### Q2. 진행 중 중도 입장 정책 🚪 — **확정 (2026-10-05): 3단계 강제 유지**
- 중도 입장 시에도 설문·밴드·기기 3단계 준비를 **모두** 거친 뒤 입장한다. (링크밴드 연결 등 준비를 마무리하고 들어가야 함)
- 이에 따라 부록 ①-8("진행 중에도 3단계 준비 강제")은 이슈가 아니라 **의도된 동작**으로 확정 → 이슈 목록에서 제외.

### Q3. 출시 범위 승인 — **확정 (2026-10-05): 1순위 7개 전부 출시 차단**
- 일시정지 제거(1) + 대기열·게스트 정합(2,3) + 추이그래프·타이머(4,5) + 대기 복귀·미터(6,7) **전부 수정 후 출시**.
- 순서: SDD-125 → 126 → 127 → 130 순으로 하나씩 순차 처리.

> **엔지니어 재량(승인 불필요)**: ③-2 상태 계약 정합의 "필드 추가 vs FE 매핑" 방향, 게스트 유령 참가자 정리 시점은 기술 구현 세부. 방향은 엔지니어가 정하되 **범위는 Q3로 승인**받는다.
