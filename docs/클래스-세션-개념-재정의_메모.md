# 클래스·세션 개념 재정의 메모 (2026-10-17, Brian)

> SDD-209 완료 후 기획 → 별도 SDD(210~)로 진행. 지금은 구현하지 않는다.

## 개념
- **클래스** = 프로그램(상위). 예: "MBSR 봄 클래스", 상담은 "채용욱 상담".
- **세션** = 클래스의 회차(하위). 예: MBSR 봄 클래스의 3번째 세션.
- 현재 코드는 `sessions` 1개 테이블이 단회차 단위이고 상위 개념이 없다 (`is_template`·`run_id` 는 회차 개념이 아님).

## 확정된 답변
1. 회원은 회차마다 변동 가능: **결석·보강·중간 합류·이탈** 지원 필요.
2. 주요 고객이 명상 센터 → **화면 용어는 "클래스"** 유지. 상담센터 고객이 늘면 그때 "상담 세션" 유형을 별도로 연다.
3. 명상 클래스는 **회차가 정해진 형태**(예: 8회) + 간혹 **정기 클래스**(회차가 계속 이어지는 형태) → 둘 다 지원.
4. 기존 단회차 데이터는 **클래스 1개 + 세션 1개**로 이전.
5. 진행 순서: SDD-209를 현재 계획대로 끝까지 → 그 후 개념·IA 기획 확인 → 구현.

## 후속 기획에서 정할 것
- 클래스/멤버십/세션 모델, 동의 시점(클래스 가입 vs 회차), 회차 일괄 예약, 보강·결석 처리, 클래스 단위 리포트·추이, 회원 홈/목록/상세/만들기 IA 재설계.
- SDD-209 의 용어 "세션→클래스" 치환은 현재 단회차 = 클래스로 쓰는 임시 상태 → 후속에서 클래스(프로그램)/세션(회차)로 재정리.
