## 상(상) 5건 — 본문 상세

### 1. MB2-AUTH-RESET-LINK — 비밀번호 재설정 링크 깨짐 🚪
- **현상**: 비밀번호 찾기 이메일의 링크가 `/auth/password/reset?token=…` 을 가리키지만, SPA에는 `/auth/*` 라우트가 없다. 실제 재설정 화면은 `/reset-password`. → 링크 클릭 시 404.
- **근거**: `backend/app/services/password_reset_service.py:66` ↔ `frontend/src/App.tsx:148`
- **원인**: 1차 SEC-07에서 상대경로→절대 URL로 바꾸며 API 경로를 프론트 라우트로 잘못 사용.
- **영향**: 비밀번호를 잊은 회원이 재설정 불가 → 로그인 불가 → 이탈.
- **해결**: 링크를 `{base}/reset-password?token={token}` 로 생성. 공수 0.5일.

### 2. MB2-ONB-GOOGLE-ESSENTIALS — Google 신규 가입 내담자 앱 진입 차단 🚪
- **현상**: Google 신규 가입 내담자가 필수정보(essentials) 입력 후 '시작하기'를 누르면 완료 호출이 400으로 실패 → `/app` 진입 불가.
- **근거**: `frontend/src/pages/onboarding/ClientEssentialsPage.tsx:56-65`(step 저장 없이 `completeClientOnboarding()` 호출) ↔ `backend/app/api/v1/onboarding.py:360-364`(`client_complete`가 step1~4 저장 강제)
- **원인**: 2차(SDD-153)에서 Google client를 essentials로 보내는 라우팅을 추가했지만, essentials 페이지는 step1~4 저장 없이 완료만 호출. step 저장은 이메일 가입 경로(`register_client`)에서만 수행.
- **영향**: Google로 가입한 신규 내담자 전원 가입 불가 → 이탈. (2차 작업 회귀)
- **해결**: essentials 제출 시 step1(필수정보)을 함께 저장하거나, Google 가입 내담자는 `client_complete`의 step 강제를 면제. 공수 1일.

### 3. RPT-IDOR-001 — 리포트 수평 권한 상승(IDOR) 📊
- **현상**: `GET /reports/{report_id}` 상세 조회가 "세션 참여자면 통과"만 검사. client 리포트의 **소유자(participant_id) 일치**를 검사하지 않아, 같은 그룹 세션의 다른 참여자 리포트를 열람 가능.
- **근거**: `backend/app/services/report_service.py:673-703`(get_report) · `:742-763`(_can_access_report — participant_id 매칭 없음) · `backend/app/api/v1/reports.py:94-100`
- **원인**: 내담자 접근 판정이 "세션 참여 여부"만 보고, "리포트가 내 것인지"를 안 봄.
- **영향**: 내담자 개인정보(뇌파·상담 내용 요약) 타인 노출 → 신뢰 훼손·개인정보보호 위반.
- **해결**: client 리포트 조회 시 `report.participant_id`의 `user_id == 조회자` 일치 검사 추가. 공수 0.5일.

### 4. LIVE-01 — 상담사 '준비 리마인드' 100% 실패 (기능 불능)
- **현상**: 대기실에서 상담사가 '미완 N명 리마인드'를 보내면 항상 실패. 허용 참가자 목록을 `snapshot['participants']`에서 읽는데, 호스트 join 스냅샷에는 이 키가 없어 항상 빈 집합 → 부분집합 검증 무조건 실패.
- **근거**: `backend/app/ws/session_live_namespace.py:705` ↔ `backend/app/services/session_service.py:1917-1932`(get_live_metrics는 'metrics' 키만 반환)
- **원인**: 리마인드 핸들러가 스냅샷의 잘못된 키(`participants`)를 참조.
- **영향**: 상담사의 준비 독려 기능이 전혀 동작하지 않음.
- **해결**: 허용 참가자 목록을 올바른 소스(세션 참여자 조회 또는 스냅샷의 실제 키)에서 읽도록 수정. 공수 0.5일.

### 5. EEG-BLE-001 — BLE 재연결 시 EEG 데이터 중복 처리 📊
- **현상**: BLE 재연결 시 `characteristicvaluechanged` 리스너가 제거되지 않고 누적되어, 동일 EEG/PPG/ACC 패킷이 중복 처리된다.
- **근거**: `frontend/src/lib/eeg/bluetooth/WebBluetoothProvider.ts:109-112`(익명 리스너 addEventListener) · `:115-125`(stopNotifications가 stopNotifications만 호출, removeEventListener 없음)
- **원인**: 익명 리스너를 등록하고 해제하지 않음.
- **영향**: 재연결 시 데이터 이중 처리 → 지표 오염.
- **해결**: 리스너를 변수에 보관해 stopNotifications에서 removeEventListener, 또는 named listener 사용. 공수 0.5일.
