# Mind Breeze 2.0 — 클래스 유형 · 실시간 소통(채팅) 기획안

> 작성: 2026-09-28 · 기획 종합 (Brian 브리프 반영, 최종)
> 범위: 클래스 유형 분류 → 유형별 기능 → 클래스 내 채팅 → 백엔드 영향 → MVP 로드맵
> 대상: **오프라인 명상센터·상담센터** 중심. 공개 방송형(오픈 강좌)은 별도 서비스로 후순위.

---

## 1. 배경 & 방향

- 현재 회원 화면은 **단방향**(상담사 영상·음성만 수신, `can_publish=False`).
- 클래스 = **장소(오프라인/온라인) × 인원(1:1/1:N)**. 양방향 영상은 온라인에서만, 1:N은 20명 초과 시 차단.
- 오프라인에서 상담사 영상을 보여주는 이유: **"클래스가 실제 진행 중이고, 녹화·AI 분석 중임"을 참여자에게 보여주기 위함** (대면 확인용이 아님). 단, **오프라인도 20명 초과 시 영상 미표시**.

---

## 2. 클래스 유형 + 영상 규칙

| 유형 | 영상 | 회원 송출 | 비고 |
|---|---|---|---|
| 오프라인 1:1 | 단방향 (상담사 영상 = 진행·녹화·AI 표시) | ✗ | 대면, 스피커 뮤트 |
| 오프라인 1:N (≤20) | 단방향 (동일) | ✗ | 대면, 스피커 뮤트 |
| 오프라인 1:N (>20) | ✗ 영상 없음 | ✗ | 대면, EEG·몰입만 |
| 온라인 1:1 | ✅ 양방향 영상통화 | ✅ | 상담 기본값 |
| 온라인 1:N (≤20) | ✅ 양방향 (발언권 관리) | ✅ | 명상·그룹상담 |
| 온라인 1:N (21~50) | 단방향 + 채팅 | ✗ | 스트리밍+채팅 |
| 온라인 1:N (>50) | — | — | **별도 서비스(공개 강좌) 후순위** |

### 영상 규칙 (자동 결정)

```
회원 송출(can_publish) = online AND (one_on_one OR (group AND max_participants ≤ 20))
상담사 영상 표시(show)  = NOT (offline AND group AND max_participants > 20)
```

- **온라인 1:N 상한 = 50명(등록 인원 기준).** 20명 초과 시 양방향 영상 자동 차단 → 채팅만.
- **오프라인 1:N도 20명 초과 시 상담사 영상 미표시** (대면으로 진행 확인이 불필요).
- **`interaction_mode`·`class_type` 필드 불필요** — `location_type` + `participant_mode` + `max_participants`로 완전 유도.

## 3. 유형별 기능 매트릭스

| 기능 | 오프라인 1:1 | 오프라인 1:N ≤20 | 오프라인 1:N >20 | 온라인 1:1 | 온라인 1:N ≤20 | 온라인 1:N 21~50 |
|---|---|---|---|---|---|---|
| 회원 카메라·마이크 송출 | ✗ | ✗ | ✗ | 상시 | 발언권 부여 | ✗(채팅만) |
| 상담사 영상 수신 | ✅(진행·녹화·AI 표시) | ✅(동일) | ✗ | ✅ | ✅(발표자 고정) | ✅(스트리밍) |
| 채팅 | 보조 | 보조 | 보조 | 보조 | 보조 | 주 채널 |
| EEG 지표 | 개인 | 전원+그룹 평균 | 전원+그룹 평균 | 개인 | 전원+그룹 평균 | 선택 |
| 녹화·리포트 | 요약 | 요약+참여자별 | 요약+참여자별 | 요약 | 요약+참여자별 | 미생성 |
| **스피커 기본값** | OFF(하울링 방지) | OFF | OFF | ON | ON | ON |

> 스피커 기본값은 `location_type`에만 의존(online=ON / offline=OFF). 회원 화면 우측 상단 토글로 수동 전환 가능(이미 구현).

## 4. 클래스 내 실시간 채팅 시스템

### 4-1. 개념
- 클래스 = 상태가 흐르는 가상의 방. 채팅은 그 방의 **우측 사이드 패널**.
- 상담사가 **「채팅 켜기」**를 누르면 참여자 화면에 유튜브 라이브 채팅처럼 열린다.
- **"소통 시간"은 별도 단계로 지정하지 않는다** — 명상 지도사가 재량으로 토글한다. 시스템은 강제 전환하지 않음.

### 4-2. 패널 UX
| 항목 | 정의 |
|---|---|
| 위치 | 우측 고정 패널, 몰입 화면 위 오버레이 |
| 접기/펼치기 | 헤더 토글, 접힘 시 안읽음 배지만 |
| 모바일 | 하단 반높이 시트로 전환 |

### 4-3. 몰입 화면과의 공존
| 상태 | 회원 화면 | 채팅 |
|---|---|---|
| `open`(대기실) | 코드·밴드 착용 대기 | 열림(준비 대화) |
| `in_progress`(명상) | 풀블리드 몰입(검정) | 접힘, 알림만 — 지도사가 켜면 펼침 |
| `completed` | 완료 화면 | **방 유지 · 이어가기** |

### 4-4. 지속성 · 방 매핑
| 클래스 방 | 기존 매핑 | 종료 후 |
|---|---|---|
| 세션 방 | `session` 방 | `completed`에도 **무기한 보존**, 읽기·쓰기 유지 |
| 다자 소통 | `group` 방 | 참여자 승계로 재개 |

- **종료 ≠ 방 폐쇄.** 내담자는 「내 채팅」 목록에서 재접속해 대화를 이어갈 수 있다.

### 4-5. 읽음 · 메시지 유형 · 토글
- 읽음: `read_by` / `recipient_count` → 안읽은 인원 표시 (기존 구현 재사용).
- 유형: 일반(text) / 시스템(입장·시작·종료·채팅 켜기) — 시스템은 중앙 회색 캡션.
- **「채팅 켜기」= 개설이 아닌 개방.** 클래스당 방 1개, 토글이 참여자 노출·입력 제어(꺼짐=읽기만). 상담사 전용.

## 5. 백엔드/데이터 모델 영향

### 5-1. 현재 모델로 표현 가능한가

| 요구 유형 | 현재 표현 | 판정 |
|---|---|---|
| 온라인 양방향(1:1, ≤20) | `online` + `one_on_one`/`group` | ⚠️ 회원 토큰 `can_publish=False` 하드코딩(`session_service.py:948`) → 분기만 추가하면 됨 |
| 오프라인(단방향, 진행 표시) | `offline` | ✅ 현행(구독 전용) 그대로 |
| 오프라인 >20(영상 없음) | `offline` + `group` + `max_participants>20` | ✅ 프론트 렌더링 분기만 |
| 온라인 21~50(채팅만) | `online` + `group` + `max_participants 21~50` | ✅ 규칙으로 유도 |

### 5-2. 필요 변경
| 항목 | 변경 |
|---|---|
| 토큰 정책 | `can_publish`를 §2 규칙으로 분기 + 응답에 `can_publish` 필드 추가 (온라인 양방향=`True`, 그 외=`False`) |
| `max_participants` 검증 | 온라인 그룹 상한 **50** (등록 기준). 오프라인 그룹은 현행(≤100) 유지 |
| `sfu_enabled` | online + group → True 강제 |
| 신규 `chat_enabled` | 상담사 토글(명상 중 off, 전후 on) — 재량 토글 (P2) |
| 채팅방 생성 | 세션 생성 시 자동 개설(`room_type="session"`) (P2) |
| 채팅방 보존 | **무기한** (상태 전이·종료와 무관하게 유지) (P2) |

> **신규 필드 최소화**: `interaction_mode`·`class_type` 불필요. P1은 토큰 분기 + 상한 검증 + 프론트 렌더링 분기만.

## 6. MVP 로드맵

| Phase | 범위 | 백엔드 | 프론트 |
|---|---|---|---|
| **P1** 온라인 양방향 | 1:1 + 1:N(≤20) 양방향, 21~50 채팅만, 오프라인 >20 영상 없음 | `can_publish` 분기, 온라인 그룹 50 상한, `sfu_enabled` 강제 | 회원 카메라/마이크, 상담사 영상 숨김 분기 |
| **P2** 클래스 채팅 | 재량 토글, 종료 후 방 무기한 유지 | `chat_enabled`, 방 자동 개설·보존 | 채팅 패널, 읽음/알림, 「내 채팅」 재접속 |
| **P3** (별도 서비스) | 공개 방송형·오픈 강좌 | 별도 기획 | 별도 기획 |

- **우선순위 근거**: 온라인 양방향은 `can_publish` 분기 1곳 + 상한 검증이 핵심 → P1 즉시 착수. 오프라인은 현행 유지. 공개 방송형은 별도 서비스로 분리(P3).

---

## 7. 확정 사항 요약

1. **정원·양방향 임계** — 등록 인원(`max_participants`) 기준. 온라인 1:N 상한 **50명**, **20명 초과 시 양방향 영상 차단(채팅만)**.
2. **오프라인 영상** — 상담사 영상은 "클래스 진행·녹화·AI 분석 중임을 참여자에게 보여주기" 목적. 단 **오프라인 1:N도 20명 초과 시 영상 미표시**.
3. **소통 시간** — 별도 단계로 지정하지 않음. 명상 지도사 재량 토글.
4. **공개 방송형(>50)** — 별도 서비스(공개 강좌)로 후순위. 지금은 오프라인 명상센터·상담센터만 대상.
5. **채팅방 보존** — 무기한.
