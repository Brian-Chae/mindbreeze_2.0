## 0. 사업 관점 요약 (1분 브리핑)

- **핵심 자산 관점**: 뇌파·생체 데이터 유실은 UX 문제가 아니라 **회사 자산 손실**이다. 리포트 시스템은 유실을 "숨기는" 것이 아니라 **구분·표시·복구·보존**해야 한다.
- **구분이 정책의 출발점**: `미측정(opt-in 미선택 = 정상)`과 `유실(측정 의도 있었으나 끊김/실패)`은 **다른 사건**이다. 현재 시스템은 둘을 모두 `not_measured`로 수렴시킬 수 있어 자산 손실이 "정상"으로 위장될 위험이 있다 — 이것이 가장 큰 빈틈.
- **이미 갖춰진 것**: 2축 상태머신, `data_credibility` 파생, `content.eeg` 미측정 숨김, `ai_record` 가용성, `sweep_stale_reports` 워치독, `pending_review` 승인 게이트, 발행 아웃박스(durable 재발행)가 모두 구현되어 있다. 본 기획은 **재설계가 아니라 그 위에 "유실(loss)" 축을 얹는 것**이다.
- **정책 3줄 요약**:
  - 표시: 유실은 숨기지 않고 **명시한다**(A1: 내담자에게도 이유와 함께). 미측정은 종전대로 숨긴다.
  - 관리: 부분 정상 **50% 이상이면 산출 가능**, <50%는 **"참고용 + 신뢰도 매우 낮음" 명시**(B2), 산출 시 **상담사 리뷰 후 발행**(기존 결정과 정합).
  - 복구: 밴드는 저장소가 없어 **끊기면 영구 유실**. "복구"는 이미 영속화된 데이터의 **백엔드/시스템 오류** 처리만 의미(C2).
  - 발행: 발행 의도는 종료 전이와 **동일 트랜잭션에 durable 기록**(아웃박스), beat가 재발행한다(기존 결정과 정합).

## 1. 현황 진단 (현재 구현 기준)

### 1.1 현재 리포트 시스템이 데이터 유실 시 동작하는 방식

- **2축 상태머신(독립)**
  - `Report.status`(승인 게이트): `pending_analysis → pending_review → completed / error`
  - `Report.generation_status`(생성 진행): `pending → processing → ready / partial`
  - 유실은 두 축 어느 쪽에서도 **직접 표현되지 않는다**. 생성 실패면 `error`, 타임아웃이면 `partial`로 수렴할 뿐, "데이터가 유실되었다"는 사건 자체는 상태값으로 남지 않는다.
- **데이터 신뢰도(`data_credibility`)**
  - EEG 품질 게이트에서 파생: `valid→high`, `degraded→medium`, `invalid/insufficient→low`, `not_measured→None`.
  - 부분 수집(끊김)은 품질 게이트에서 `degraded/invalid/insufficient`로 내려가 `medium/low`로 표현된다. 즉 **신뢰도 수치에는 유실이 반영되지만**, 그 원인이 "끊김(유실)"인지 "원래 품질 낮음"인지는 신뢰도 값만으로 구분 불가.
- **EEG 콘텐츠 블록(`content.eeg`)**
  - 윈도우가 전무하면 `status="not_measured"` → 프론트가 EEG 섹션을 **숨김**.
  - 문제: **밴드를 착용했으나 전 구간 끊김으로 윈도우 0개가 된 유실 케이스도 `not_measured`로 수렴** → 미착용(정상)과 동일하게 숨겨진다. 자산 손실이 "정상 미측정"으로 위장되는 경로.
  - 부분 수집 시 `reliability`, `longest_usable_run`(연속 usable 최장 길이), 7지표(null 보존), 타임라인이 남으므로, **표시 근거 데이터는 이미 존재**한다(측정 구간을 그릴 수 있음).
- **음성/AI 요약 가용성(`ai_record`)**
  - `available` / `not_available`(`mic_off` / `low_confidence` / `no_transcript`). STT 실패·저신뢰·전사 없음이면 AI 요약을 숨기되 **원본 전사문은 유지**.
  - STT 실패는 이미 사유 코드로 **구분 표기**된다 — EEG 유실보다 성숙한 모델. (EEG도 이 수준의 사유 코드가 필요.)
- **실패/워치독**
  - 생성 실패 → `status=error` + `generation_error`(50자) + 알림.
  - `sweep_stale_reports`(beat, 5분 주기): `processing` 30분 초과 → `partial` + `reason=timeout`. STT 단계도 30분 초과 시 `failed` 마감.
- **진행 스텝퍼**: `save → stt → summary → ready` 4스텝, `compute_report_progress`로 파생.
- **발행 흐름 + 아웃박스**
  - 세션 종료 → `generate_reports_for_session` → counselor + client 리포트 → `pending_review`(상담사 승인 대기). `auto_approve_report`면 즉시 `completed`.
  - 세션 `/end` 전이와 **동일 트랜잭션**에 `PipelineOutbox`를 durable 기록, `process_pipeline_outbox` beat(30초)가 재발행(최대 5회, 지수 backoff). **발행 유실 복구는 이미 해결됨.**

### 1.2 빈틈(Gap) — 정책이 메워야 할 지점

| # | 빈틈 | 현재 동작 | 위험 |
|---|---|---|---|
| G1 | **유실과 미측정 미구분** | 전 구간 끊김 → 윈도우 0 → `not_measured` → 숨김 | 자산 손실이 "정상 미측정"으로 위장. 상담사·내담자 모두 유실 사실을 모름 |
| G2 | **신뢰도 하향 사유 부재** | `medium/low`만 노출, 원인 미표기 | 끊김인지 원래 저품질인지 구분 불가 → 복구 판단 불가 |
| G3 | **유실 상태의 1급 표현 없음** | 2축 상태머신에 "유실/부분" 의미 없음 | 50% 게이트·24h 복구 기한을 걸 수 있는 **상태 앵커가 없음** |
| G4 | **부분 산출 50% 게이트 미구현** | 품질 게이트는 있으나 "정상 구간 비율" 기준 산출 가부 로직 없음 | SDD-101 결정②가 코드로 실현되지 않음 |
| G5 | **복구 창(24h) 미반영** | 끊김 후 미업로드분 재업로드 경로는 있으나, 리포트가 "복구 대기"를 표현·대기하지 않음 | 조기 발행 후 데이터 뒤늦게 도착 → 리포트와 자산 불일치 |
| G6 | **유실 가시성(관리자)** | 유실 집계·대시보드·알림 축 없음 | 자산 손실 규모를 사업적으로 추적 불가 |

> 요지: **발행 신뢰성(아웃박스)은 이미 해결**. 남은 과제는 **(1) 유실의 식별·표시, (2) 50%·24h 관리 규칙의 상태 앵커, (3) 유실 가시성**이다.

## 2. 표시(Display) 정책

### 2.1 대원칙

- **미측정(정상)은 숨기고, 유실(비정상)은 명시한다.** 이 두 개를 같은 화면 처리로 묶지 않는다.
- **점수 환원 금지**: 종합점수 단일 숫자 노출 금지. 서사 + 변화량(전후 비교) 중심, EEG는 opt-in 보조 지표로 표시.
- **없는 데이터를 지어내지 않는다**: 유실 구간은 보간·추정으로 채우지 않고 "측정 안 됨/끊김"으로 구분 표기한다.
- **원본은 항상 보존·노출**: 전사문·수집된 EEG 구간 등 **실제 획득 자산**은 신뢰도와 무관하게 접근 가능해야 한다.

### 2.2 시나리오별 표시 규칙

| 시나리오 | 판정 신호 | EEG 섹션 | 신뢰도 뱃지 | 서사/요약 | 비고 |
|---|---|---|---|---|---|
| **① 미측정 (정상·opt-in 미선택)** | 밴드 미착용 의도 = 측정 시도 없음 | **숨김** | 뱃지 없음(None) | 상담·AI 요약 **정상 제공** | "뇌파 미측정(선택 안 함)" 1줄 안내만. 결함 아님 |
| **② 부분측정 (끊김·정상 구간 존재)** | 윈도우 일부 수집 + 끊김 발생 | **표시 + 측정 구간/유실 구간 명시** | medium/low + **사유="연결 끊김"** | 측정된 구간 기준 서사, 유실 구간 회색 처리 | `longest_usable_run`·타임라인으로 유효 구간 시각화 |
| **③ 유실 (측정 의도 있었으나 전 구간 끊김/0윈도우)** | 측정 시도=yes + 윈도우 0 | **"측정 시도됨·데이터 유실" 안내 표시(숨김 아님)** | low 또는 "유실" | EEG 없이 상담·AI 요약 기반 서사 | ①과 **반드시 구분**. "미측정"으로 표기 금지 |
| **④ STT 실패/저신뢰/마이크오프** | `ai_record=not_available`(사유 코드) | (EEG는 해당 시나리오 규칙 따름) | 해당 없음 | **AI 요약 숨김, 원본 전사문 유지** | 사유별 문구: 마이크 꺼짐 / 인식 신뢰 낮음 / 전사 없음 |
| **⑤ 생성 실패** | `status=error` | — | — | "리포트 생성 실패" + 재시도 안내 | 상담사 알림 발송 |
| **⑥ 복구 대기 중** | 유실 감지 + 24h 복구 창 open | 잠정 표시 + "복구 대기(남은 시간)" | 잠정(provisional) | 잠정 서사 | 복구 완료/만료 시 자동 갱신 |

### 2.3 표시 UI 구성요소 (신규/보강)

- **신뢰도 뱃지 + 사유 칩**: 기존 `data_credibility`(high/medium/low) 뱃지에 **사유 칩**을 추가(예: `연결 끊김`, `측정 구간 짧음`, `저품질 신호`). 신뢰도 숫자가 아니라 **원인**을 읽게 한다.
- **측정 커버리지 바**: 세션 길이 대비 유효 측정 구간 비율을 막대/타임라인으로 표시(예: 4.3분 중 2.0분 측정 = 47%). 유실 구간은 회색/빗금.
- **유실 고지 배너(시나리오 ③·⑥)**: "뇌파 측정을 시도했으나 연결 끊김으로 데이터 일부/전부가 유실되었습니다." + (복구 대기 중이면 남은 시간).
- **내담자용(client) vs 상담사용(counselor) 노출 차등**:
  - client: 서사·변화량 중심. 유실은 **명시하되 차분한 문구 + 이유 최대한 설명**(A1, 예: "중간에 연결이 끊겨 뇌파 일부 구간은 측정되지 않았어요. 측정된 구간으로 안내드려요."). 기술 사유 코드·커버리지 수치는 비노출하나, **무엇이 왜 빠졌는지는 설명**.
  - counselor: 사유 칩·커버리지·복구 상태 등 **관리 정보 노출**(리뷰·발행 판단 근거).

## 3. 관리(Management) 정책

> 기존 확정 결정(SDD-101)과 정합: ①고아 유예 24h/취소 시 폐기+상담사 확인, ②부분 정상 ≥50% 산출 가능·복구 24h·산출 시 상담사 리뷰 후 발행, ⑤발행 아웃박스.

### 3.1 산출 가부 게이트 (부분 정상 50% 규칙)

- **측정 커버리지** = (유효 측정 시간) / (세션 유효 길이). "유효"는 EEG 품질 게이트의 usable 윈도우 기준.
- **≥ 50%**: 리포트 **산출 가능**. EEG 섹션을 부분측정(시나리오 ②)으로 표시. `data_credibility`는 품질 게이트대로.
- **< 50%**: 유효 구간 지표를 **"참고용"으로 노출하되**, **"데이터 유실로 신뢰도가 매우 낮은 상태"임을 확실히 표시**(B2). 리포트 본문은 상담·AI 요약 기반으로 산출하고, EEG 지표는 참고용 부속으로 표기(수집 자산 최대 활용). 자산(수집 구간)은 그대로 보존.
- **공통**: 유실이 개입한 모든 산출물은 `auto_approve_report` 여부와 무관하게 **상담사 리뷰 후 발행**(자동 승인 우회 금지).

### 3.2 복구 개념 정정 + 복구 창 (24시간)

> **핵심 정정(Brian)**: LINK BAND에는 **자체 저장소가 없다** — 밴드는 실시간 스트리밍만 하므로, BLE가 끊긴 순간부터 밴드가 송출한 데이터는 클라이언트가 수신하지 못하면 **즉시 영구 유실**이다. "밴드 재연결하면 복구된다"는 성립하지 않는다.

**복구(Recovery)의 올바른 정의**: 이미 영속화된 데이터(클라이언트 로컬 큐·서버 DB/S3)가 **시스템 상 백엔드 오류·파이프라인 실패·WS 단절**로 처리·발행되지 못한 것을 되살리는 것.

- **복구 가능(24h 창 대상)**: 클라이언트 IndexedDB에 저장됐지만 미전송된 raw/feature(WS 단절 시 재전송), 서버에 저장됐지만 처리·발행 안 된 데이터(백엔드·파이프라인 오류).
- **복구 불가(즉시 영구 유실)**: 밴드→클라이언트 BLE 구간이 끊겨 클라이언트가 수신조차 못한 데이터(밴드에 저장소 없음).
- 복구 창(24h) 내 시스템 오류 해소 → 데이터 반영 → 리포트 **재생성/갱신**(멱등). 커버리지·신뢰도·서사 자동 갱신.
- 24h 만료 → 그 시점 데이터로 **확정**. 단, 고가치 세션은 상담사가 **수동 복구 1회 요청** 가능(C2).
- 고아(세션 종료 전이 없이 끊긴 데이터) 유예도 24h(결정①). 취소 시 데이터 폐기 기본 + **상담사 폐기 확인**.

### 3.3 상태·승인 규칙

- 유실 리포트도 종전 2축을 그대로 사용하되, **유실 메타(사유·커버리지·복구 상태)를 1급 필드로 추가**(§4.1).
- 승인 게이트: 유실 개입 산출물은 `pending_review` 고정 → 상담사 리뷰 → `completed`. 자동 승인 예외.
- 발행: 종료 전이와 동일 트랜잭션 durable 기록(아웃박스), beat 재발행(결정⑤). **유실 여부와 무관하게 발행 신뢰성 보장.**

### 3.4 보관(Retention) 규칙

- **수집된 원자료는 유실 여부와 무관하게 보존**: 부분 수집 EEG/feature, 원본 전사문은 자산으로 보관(프라이버시 규칙 §저장 암호화·접근제어 준수).
- **유실 이벤트 로그 보존**: 어떤 세션이 언제·얼마나 유실되었는지 감사 로그로 기록(자산 손실 추적). 기존 감사 로그 정책(6개월) 준수.
- 취소/폐기: 폐기 기본 + 상담사 확인(결정①). 폐기 시에도 "폐기됨" 사실은 감사 로그에 남긴다.

## 4. 발행 시스템 개선 (설계 수준)

> 재설계 아님. 기존 구현 위에 **유실 축**을 얹는다. 구현 세부는 Phase 3(SDD)로 이관.

### 4.1 유실의 1급 표현 추가 (상태머신 보강)

- **2축은 유지**(status·generation_status). 유실을 상태값 폭증으로 처리하지 않는다.
- **유실 메타 필드 신설**(`content.eeg` 및 리포트 메타):
  - `measurement_intent`: `yes | no` — 밴드 착용/측정 시도 여부. **미측정(①)과 유실(③)을 구분하는 근거**(G1 해소).
  - `loss_reason`: `band_disconnect | ws_drop | raw_upload_gap | backend_error | none` — 신뢰도 하향 사유(G2 해소). `band_disconnect`=영구 유실(복구 불가), `ws_drop`/`backend_error`=복구 가능.
  - `coverage_ratio`: 유효 측정 비율(50% 게이트의 입력, G4 해소).
  - `recovery`: `{ state: provisional | recovered | expired, window_deadline, recoverable: bool }` — 24h 복구 창(G5 해소). `recoverable=false`(밴드 끊김)면 복구 대기 없이 즉시 유실 확정.
- **`not_measured` 분기 규칙**: `status="not_measured"`는 `measurement_intent="no"`일 때만 사용(숨김). `intent="yes"`인데 윈도우 0이면 `status="lost"`(신규, 표시)로 분기.

### 4.2 유실 감지 (Detection)

- **감지 시점**: 세션 종료 리포트 생성 파이프라인 진입 시, 측정 시도(의도) 대비 수집 결과를 대조해 유실 판정.
- **입력 신호**: 밴드 연결 이벤트(끊김 로그), 수집 윈도우 수·커버리지, WS 끊김 큐 유실 표시, raw 업로드 gap.
- **산출**: `measurement_intent / loss_reason / coverage_ratio`를 리포트 생성 시 계산해 §4.1 필드에 기록.

### 4.3 산출 게이트 + 복구 대기 (Generation Gate)

- `generate_reports_for_session`에 **50% 게이트** 삽입: coverage ≥50% → EEG 서사 산출, <50% → 유효 구간 지표를 **"참고용"으로 노출 + "신뢰도 매우 낮음" 명시**(B2), 본문은 상담·AI 기반 산출.
- **복구 가능한 유실**(`ws_drop`/`backend_error`, 데이터 이미 영속화)만 리포트를 **provisional**로 생성 + 24h 복구 창 open. 복구 워치독 beat가:
  - 복구 데이터 도착 → 재생성/갱신(멱등),
  - 24h 만료 → 확정 전이. 고가치 세션은 상담사 수동 복구 1회 요청 허용(C2).
- **복구 불가한 유실**(`band_disconnect`, 밴드→클라이언트 구간)은 복구 창 없이 **즉시 유실 확정** 표기.

### 4.4 발행·재발행 (Publish)

- **변경 없음(이미 충족)**: 종료 전이 동일 트랜잭션 durable 아웃박스 + beat 재발행(결정⑤). 유실 리포트도 동일 경로.
- 추가: 유실 개입 리포트는 아웃박스 발행 시 **자동 승인 우회 플래그 무시**(항상 `pending_review` 경유, §3.3).

### 4.5 유실 가시성 (Observability) — G6 해소

- **유실 이벤트 집계**: 세션별 유실 사유·커버리지·복구 결과를 집계 로그로 적재.
- **상담사 알림**: 유실 발생 시 리뷰 대기 알림에 **유실 사유·커버리지** 포함(기존 `report_generation_failed` 알림 축 재사용/확장).
- **관리 대시보드(지표 정의만)**: 유실률(세션 대비), 평균 커버리지, 복구 성공률 — 자산 손실 규모의 사업적 추적 지표. (대시보드 UI는 별도 범위.)

### 4.6 변경 요약표

| 영역 | 현재 | 개선 | 기존 결정 정합 |
|---|---|---|---|
| 상태 표현 | 2축, 유실 미표현 | 2축 유지 + 유실 메타 1급 필드 | — |
| 미측정/유실 구분 | 둘 다 `not_measured` | `intent`로 분기, `lost` 신설 | 제약(정상 옵션 구분) |
| 산출 게이트 | 품질 게이트만 | +50% 커버리지 게이트 | 결정② |
| 복구 | 재업로드 경로만 | +24h provisional 복구 창·워치독(복구 가능 유실만) | 결정②③·C2(밴드 끊김=영구 유실) |
| 승인 | auto_approve 가능 | 유실 시 리뷰 강제 | 결정② |
| 발행 신뢰성 | 아웃박스(완비) | 변경 없음 | 결정⑤ |
| 가시성 | 없음 | 유실 집계·알림·지표 | — |

## 5. Brian 확정 결정 (2026-10-04)

### 결정 A — 내담자(client) 리포트에 유실 사실 명시 + 이유 상세 (**A1**)
- client 리포트에도 유실 사실을 **명시**하고, **최대한 이유를 설명**한다.
- 기술 용어(사유 코드·커버리지 수치)는 비노출하되, "무엇이 왜 빠졌는지"는 차분한 문구로 설명(예: "중간에 연결이 끊겨 뇌파 일부 구간은 측정되지 않았어요. 측정된 구간으로 안내드려요.").

### 결정 B — 50% 미만 커버리지 시 지표 "참고용" 노출 + 신뢰도 매우 낮음 명시 (**B2**)
- 유효 구간 지표를 **"참고용"으로 노출**하되, **"데이터 유실로 신뢰도가 매우 낮은 상태"임을 확실히 표시**한다.

### 결정 C — 복구 개념 정정 + 수동 복구 1회 허용 (**C2**)
- **핵심 정정(Brian)**: LINK BAND에는 **자체 저장소가 없다**. 밴드는 실시간 스트리밍만 하므로, BLE가 끊긴 순간부터 밴드가 송출한 데이터는 클라이언트가 수신하지 못하면 **즉시 영구 유실**이다. "밴드 재연결하면 복구된다"는 성립하지 않는다.
- **복구의 올바른 정의**: "이미 영속화된 데이터(클라이언트 로컬 큐·서버)가 시스템 상 백엔드 오류·파이프라인 실패로 처리·발행되지 못한 것을 되살리는 것" — 이 의미라면 C2(수동 복구 1회 허용)가 맞다.
