## 1. 배경과 목적

### 1.1 문제 정의

현재 MIND BREEZE 2.0 채팅 시스템에서 상담사가 메시지를 보낸 후 **내담자가 읽었는지 확인할 수 있는 방법이 없다.** 이는 상담사의 업무 효율을 저하시키고, 긴급한 메시지에 대한 응답 여부를 파악하지 못하는 문제를 야기한다.

### 1.2 현재 상태 분석

**이미 구현된 인프라:**
- `ChatMessageRead` 테이블 — 사용자별 메시지 읽음 상태 추적 (message_id + user_id + read_at)
- `mark_read()` API — `PUT /api/v1/chat/rooms/{roomId}/read` — 채팅방 입장 시 전체 메시지 읽음 처리
- 사이드바 채팅 unread 뱃지 — 채팅방 리스트의 안읽은 메시지 개수 표시

**누락된 기능:**
- 개별 메시지 말풍선에 읽음/안읽음 표시 없음
- 상대방이 메시지를 읽은 시점에 대한 실시간 피드백 없음
- 메시지 응답(`_serialize_msg`)에 읽음 상태 정보 미포함

### 1.3 목표

카카오톡 스타일의 **메시지별 읽음 표시** 기능을 구현한다:

1. 내가 보낸 메시지에 상대방이 읽지 않았으면 `1` (안읽은 사람 수) 표시
2. 상대방이 채팅방에 입장하여 읽으면 `1` 표시가 사라짐 (실시간)
3. 1:1 채팅에서는 단순히 "읽음/안읽음" 이진 상태로 충분

## 2. 서비스 개요

### 2.1 UX 플로우

```
[상담사 메시지 전송]
  → 말풍선 우측 하단에 작은 "1" 표시 (내담자 미확인)
  
[내담자가 채팅방 입장]
  → `PUT /chat/rooms/{roomId}/read` 호출
  → 서버가 읽음 처리 + Socket.IO로 `messages_read` 이벤트 broadcast
  → 상담사 화면에서 "1" 표시가 사라짐 (실시간)
```

### 2.2 디자인 원칙

| 원칙 | 설명 |
|------|------|
| **미니멀** | 카카오톡처럼 말풍선 옆에 아주 작게 숫자만 표시. 12px, #9CA0AE |
| **실시간** | Socket.IO로 읽음 상태 변경 즉시 반영 |
| **비침투적** | 기존 메시지 UI 구조를 변경하지 않고, 말풍선 우측 하단에 숫자만 추가 |
| **1:1 전용** | 현재 MIND BREEZE는 1:1 채팅만 지원하므로 "읽지 않은 사람 수=1"로 고정. 그룹채팅 도입 시 확장 가능 |

### 2.3 적용 범위

| 화면 | 파일 | 변경 내용 |
|------|------|-----------|
| 상담사 채팅 | `ChatPage.tsx` → `ChatRoom.tsx` → `MessageBubble.tsx` | 말풍선에 읽음 표시 추가 |
| 내담자 채팅 | `ClientChatPage.tsx` → `ClientChatRoomPage.tsx` → `ChatRoom.tsx` | 동일 컴포넌트 사용하므로 자동 적용 |

## 4. 상세 화면 설계

### 4.1 MessageBubble 변경 상세

```tsx
// 내 메시지 말풍선 — 읽음 상태 추가
<div style={{ display: 'flex', justifyContent: 'flex-end', alignItems: 'flex-end', gap: '4px' }}>
  {/* unread_count > 0 일 때 "1" 표시 */}
  {isMine && (message.unread_count ?? 0) > 0 && (
    <span style={{ fontSize: '11px', color: '#F5B041', marginBottom: '6px' }}>
      {message.unread_count}
    </span>
  )}
  {/* 기존 시간 표시 */}
  {isMine && <span>{timeStr}</span>}
  {/* 말풍선 */}
  <div style={{ ... }}>{content}</div>
</div>
```

- 색상: `#F5B041` (앰버/골드 계열) — 브랜드 퍼플(`#5F0080`)과 대비되어 시인성 확보
- 글자 크기: `11px` — 시간(10px)보다 약간 크게, 하지만 여전히 작게
- 위치: 시간 왼쪽 (시간 앞에 표시)

## 5. 기술 아키텍처

### 5.1 데이터 흐름

```
POST /chat/rooms/{id}/messages (메시지 전송)
  ↓
chat_service.post_message()
  ↓
_serialize_msg() → unread_count: <수신자 수> 포함
  ↓
REST 응답 + broadcast_message() → new_message 이벤트
  ↓
ChatRoom → addMessage(msg) → MessageBubble 렌더링 (unread_count 표시)

PUT /chat/rooms/{roomId}/read (읽음 처리)
  ↓
chat_service.mark_read()
  ↓  
broadcast_messages_read(room_id, user_id) → messages_read 이벤트
  ↓
ChatRoom 리스너 → 모든 메시지 unread_count = 0으로 업데이트
  ↓
MessageBubble → unread_count 표시 사라짐
```

### 5.2 백엔드 변경

| 파일 | 변경 내용 |
|------|-----------|
| `backend/app/services/chat_service.py` | `_serialize_msg()`에 `unread_count` 필드 추가 / `mark_read()` 후 broadcast |
| `backend/app/ws/chat_namespace.py` | `broadcast_messages_read()` 함수 추가 |

### 5.3 프론트엔드 변경

| 파일 | 변경 내용 |
|------|-----------|
| `frontend/src/lib/api/chat.ts` | `ChatMessage` 타입에 `unread_count?: number` 추가 |
| `frontend/src/components/chat/MessageBubble.tsx` | 읽음 표시 UI 추가 |
| `frontend/src/components/chat/ChatRoom.tsx` | `messages_read` Socket.IO 리스너 추가 |

### 5.4 프론트엔드 API 타입 확장

```typescript
// frontend/src/lib/api/chat.ts
export interface ChatMessage {
  id: string;
  room_id: string;
  sender_id: string | null;
  sender_name?: string | null;
  type: 'text' | 'image' | 'file' | 'system';
  content: string | null;
  file_url: string | null;
  event_type?: string | null;
  created_at: string;
  unread_count?: number;  // ← 신규: 안읽은 사람 수 (1:1은 0 또는 1)
}
```

## 7. 리스크

| 리스크 | 영향 | 완화 |
|--------|------|------|
| `messages_read` 이벤트가 Socket.IO로 전달되지 않음 | 읽음 표시 실시간 업데이트 불가 | REST API 응답에도 `unread_count` 포함 → 폴백으로 최소한의 기능 보장 |
| `_serialize_msg`가 datetime 직렬화 문제 | 기존 pitfall 재발 가능 | `.isoformat()` 확인 |
| `ChatMessageRead` 테이블에 데이터가 없음 | `unread_count`가 항상 0으로 표시 | `post_message()`에서 발신자 읽음 상태는 자동 생성하도록 처리 |
