# 대기실 체크인 통합 + 준비 현황 대시보드 — UX 개선 기획안

> MIND BREEZE 2.0 · 클래스 시작 전 준비 흐름 재설계
> 작성: 2026-10-03

---

## 1. 현황 진단

현재 회원(게스트 포함)은 클래스 시작 전에 **두 개의 화면**을 순차 통과한다.

| 단계 | 화면 | 내용 |
|---|---|---|
| A | 입장 전 준비 (`ClassWaitingRoom`) | 참여 이름 · 사전 설문(SAM 2축) · 마이크 자동확인 · 카메라/스피커 선택 · LINK BAND opt-in → [입장하기] |
| B | 시작 대기 (`MemberWaitingScene`) | Welcome → 밴드 착용 가이드 → 시작 대기 |

**문제점**

1. **단절된 2단계** — 설문·기기 체크(A)를 끝내고 [입장하기]를 누르면, 또 다른 대기 화면(B)이 나타나 "어디까지 준비됐는지" 흐름이 끊긴다.
2. **상담사 가시성 부족** — 상담사는 대기실에서 체크인 목록을 `details`(접힘)로만 확인한다. 그룹 전체 완료율과 사용자별 준비 상태가 한눈에 들어오지 않는다.
3. **"완료" 개념 없음** — 설문·기기·밴드가 각각 스킵 가능해, 참가자가 "준비 완료"인지 "미완"인지 구분할 신호가 없다.

---

## 2. 개선 목표

- **대기 화면 하나로 통합** — 입장하면 하나의 화면에서 설문 + 기기 체크를 자연스럽게 수행한다.
- **완료 상태를 실시간 공유** — 참가자의 준비 진행이 상담사 화면에 즉시 반영된다.
- **상담사는 그룹 전체 + 사용자별 상황을 한눈에 확인** — 미완 참가자에게 리마인드할 수 있다.

---

## 3. 회원 UX — 통합 대기 화면 (3단계)

단계 A·B를 하나의 대기 화면으로 병합. **3단계 스텝**으로 자연스럽게 흐른다.

```
┌─────────────────────────────────────────────┐
│  [나가기]      클래스 제목      [대기중]      │
├─────────────────────────────────────────────┤
│  "잠시 후 시작합니다"  (참가자 N명 대기 중)   │
│                                             │
│  ○───○───○  (스텝 인디케이터)               │
│  ① 설문   ② 밴드   ③ 기기                  │
│                                             │
│  ┌─ ① 설문 ───────────────────────────┐    │
│  │  지금 기분(SAM 2축) + 전할 말       │    │
│  │  → [체크인 남기기] / [건너뛰기]      │    │
│  └──────────────────────────────────────┘    │
│  ┌─ ② 링크밴드 연결 ──────────────────┐    │
│  │  LINK BAND 2.0 페어링 안내           │    │
│  │  → [밴드 연결] (선택, opt-in)        │    │
│  └──────────────────────────────────────┘    │
│  ┌─ ③ 기기 테스트 및 설정 ─────────────┐   │
│  │  마이크(자동) ✓ · 카메라(선택) ·     │    │
│  │  스피커 테스트음(선택)               │    │
│  └──────────────────────────────────────┘    │
│                                             │
│  ● 준비 완료 상태 (자동 판정)                │
│  "상담사가 시작하면 자동으로 입장됩니다"      │
└─────────────────────────────────────────────┘
```

**3단계 정의**

| 단계 | 이름 | 내용 | 필수 여부 |
|---|---|---|---|
| ① | 설문 | 기분 SAM 2축 + 상담사 전달 말 | 완료 필요(스킵 가능) |
| ② | 링크밴드 연결 | LINK BAND 2.0 페어링·착용 안내 | 완료 필요(스킵 가능) |
| ③ | 기기 테스트 및 설정 | 마이크(자동)·카메라·스피커 확인 | 완료 필요(스킵 가능) |

**핵심 규칙**

- **3단계(설문·링크밴드·기기)를 모두 완료해야 입장한다** (Q2 확정, 2026-10-05). 각 단계는 **건너뛰기로도 완료 처리**된다.
- 각 단계 완료 여부가 **"준비 상태"** 로 누적된다:
  - `①설문` / `②밴드` / `③기기` 충족 항목 수 → 뱃지 3개.
- 상담사가 클래스를 시작하면 대기 화면이 **자동으로 라이브 뷰로 전환** (버튼 입력 불필요).

---

## 4. 상담사 UX — 준비 현황 대시보드

대기 화면(우측)에 **"준비 현황"** 패널을 추가한다.

```
┌────────────────────────────────────────────┐
│  준비 현황                    3/5 완료     │
│  ████████░░░░░░░░░░  60%                  │
│                                            │
│  김민지  ● 설문 ● 기기 ○ 밴드   (2/3)      │
│  이준호  ○ 설문 ● 기기 ● 밴드   (2/3)      │
│  박서연  ● 설문 ○ 기기 ○ 밴드   (1/3)  ←  │
│  ...                                       │
│                                            │
│  [미완 2명 리마인드]                        │
└────────────────────────────────────────────┘
```

- **그룹 전체**: 완료 인원 / 전체 인원 + 진행률 바.
- **사용자별**: 설문·기기·밴드 3개 뱃지로 상태 표시.
- **미완 하이라이트**: 준비가 덜 된 참가자를 구분해 리마인드 유도.
- 기존 참가자 카드(생체 지표)와 같은 리스트 내에 상태 뱃지를 함께 노출.

---

## 5. 상태 모델 (데이터 계약)

참가자별 준비 상태를 서버가 집계해 내려준다. (기존 `WaitingRoomCheckin` 확장)

```typescript
interface ParticipantReadiness {
  participant_id: string;
  survey_done: boolean;     // 사전 설문 제출 여부
  device_done: boolean;     // 마이크(자동)+카메라/스피커 확인 여부
  band_connected: boolean;  // LINK BAND 연결 여부
  ready: boolean;           // 필수(이름) 충족 → 대기 화면 체류 중
}
```

- 프론트는 기존 WS 대기실 이벤트에 위 상태를 실어 실시간 갱신한다.
- 3단계 완료가 **입장 게이트**다 (Q2 확정, 2026-10-05). 건너뛰기 = 완료 처리.

---

## 6. 구현 범위

| 영역 | 작업 |
|---|---|
| 회원 대기 화면 | `ClassWaitingRoom` + `MemberWaitingScene` 병합 → 단일 대기 화면, 준비 상태 누적 UI |
| 상담사 대시보드 | 대기 화면 우측 "준비 현황" 패널 + 참가자 카드 뱃지 |
| 계약 | `WaitingRoomCheckin` → `ParticipantReadiness` 확장 (백엔드 집계 + WS 이벤트) |
| 자동 전환 | 상담사 시작 시 대기 화면 → 라이브 자동 입장 |

---

## 7. 우선순위

1. **P0** — 회원 대기 화면 통합 (2단계 → 1단계, UX 단절 제거)
2. **P0** — 상담사 준비 현황 대시보드 (그룹 전체 + 사용자별)
3. **P1** — 준비 상태 실시간 계약 확장 (백엔드 집계 + WS)
4. **P2** — 리마인드·자동 입장 고도화
