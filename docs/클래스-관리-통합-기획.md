# 상담사 클래스 관리 통합 기획 — "오픈 페이지 ↔ 대기 화면" 단일화

> 작성일: 2026-10-03 · 작성: Hermes (기획 브리프: Brian)
> 목표: 상담사가 클래스 생성 → 입장하면 **하나의 "클래스 관리" 페이지**로 진입해 오픈/시작/종료를 연속 진행하도록, 현재 ① 세팅(오픈 페이지)과 ② 대기실(대기 화면)로 전면 교체되던 화면을 단일 관리 레이아웃으로 통합.
> 전제: 기존 기획 `docs/class-entry-start-end-player-기획.md`(SDD-088)의 상태 머신·단일 플레이어 방향은 유지. 이 문서는 그 중 **상담사 씬의 "오픈 페이지"와 "대기 화면" 분리**만 고친다.

## 0. 요약 (TL;DR)

- **현황**: 상담사가 [입장]하면 `ClassPlayerPage`가 상태에 따라 화면을 **전면 교체**한다. `ready/scheduled` → ① 세팅 씬(`SessionPreJoinPreview` 미디어 프리뷰 + [클래스 오픈]), `open` → ② 대기실 씬(`HostClassWorkspace` 코드+참가자 그리드 + [시작하기]). 두 씬의 레이아웃이 완전히 달라, [클래스 오픈]을 누르는 순간 "미디어 프리뷰 화면"이 "참가자 관리 화면"으로 뒤바뀌어 **별개 페이지처럼 느껴진다**.
- **문제**: 상담사 입장 시점에 참가자 그리드·코드·라이브 지표가 아예 안 보이고(세팅 씬), 오픈 후엔 반대로 미디어 선택이 사라진다(대기실 씬). 상태 전이와 화면 교체가 1:1로 묶여 있어 흐름이 끊긴다.
- **해결**: 상담사가 입장하면 **상태와 무관하게 동일한 "클래스 관리" 레이아웃**(좌: 호스트 미디어+코드 / 우: 참가자 그리드+지표)을 바로 렌더하고, 오픈/시작/종료는 **툴바의 단일 primary CTA 라벨만 상태에 따라 바뀌는 연속 동작**으로 수렴. 미디어 체크(카메라·마이크)는 별도 풀스크린 씬에서 좌측 호스트 미디어 영역으로 흡수.
- **비변경**: 상태 머신(`ready→open→in_progress→completed`)·회원 측 흐름(대기실/명상 immersive)·리포트 파이프라인·이탈 가드. 전부 그대로.

## 1. 현황 — 실제 구동 절차 (코드 근거)

1. **클래스 생성** `SessionCreatePage` → 생성 후 `SessionDetailPage`로 이동.
2. **상세 [입장]** 단일 버튼(`frontend/src/pages/sessions/SessionDetailPage.tsx:265-274`) → `navigate('/sessions/:id/player')`.
3. **`ClassPlayerPage`**(`frontend/src/pages/sessions/ClassPlayerPage.tsx`, 풀스크린·AppShell 밖)가 상태별 씬을 **전면 교체**:

| 상태 | 씬 분기 | 렌더링 내용 | 근거 |
|---|---|---|---|
| ready / scheduled | `isSetup` | `SessionPreJoinPreview` — 카메라/마이크 프리뷰 + **[클래스 오픈]** | `:911`, `:1713-1727` |
| open | `isLobby` | `HostClassWorkspace` — 좌(호스트 미디어·코드)/우(참가자 그리드) + **[시작하기]** | `:912`, `:1771` |
| in_progress / paused | `isRunning` | 라이브(모니터링·녹음·마커·경과 타이머) + **[종료]** | `:913`, `:1771` |
| completed | `isEnded` | 종료 씬 + [기록 보기] | `:914` |

- `openClass()`(`:975-990`)·`startClass()`(`:992-1025`)가 각각 `transitionSession('open'/'start')`를 호출하고, 성공 시 `setSession(updated)`로 상태만 바꾸면 **상단 씬 분기가 통째로 다른 JSX를 렌더**한다.
- 즉 "오픈 페이지"(① 세팅)와 "대기 화면"(② 대기실)은 **같은 페이지 안의 두 개의 전혀 다른 레이아웃**이며, [클래스 오픈] 한 번에 전체 화면이 갈아끼워진다.

### 1.1 두 씬의 레이아웃 대비

| | ① 세팅(오픈 페이지) | ② 대기실(대기 화면) |
|---|---|---|
| 참가자 그리드/지표 | ❌ 없음 | ✅ `HostClassWorkspace` 우측 |
| 클래스 코드 | ❌ 없음(헤더에 소형) | ✅ 좌측 대형 + 복사 |
| 호스트 셀프뷰/미디어 토글 | ✅ `SessionPreJoinPreview` 중심 | ✅ 좌측 소형 `SessionHostVideoView` |
| primary CTA | [클래스 오픈] | [시작하기] |

→ 상담사 입장 직후(ready)에는 "누가 올지·코드가 뭔지·지표가 뭔지"가 안 보이고, 오픈한 뒤에는 "카메라/마이크 설정"이 사라진다. 두 기능이 서로 배타적으로 노출되는 구조.

## 2. 문제 정의

1. **화면 교체 = 상태 전이**라서 흐름이 끊긴다. "미디어 확인"과 "참가자 관리"는 사실 같은 방 안의 연속 작업인데, 전면 교체로 인해 두 단계로 분리되어 보인다.
2. **오픈 전 상담사에게 관리 맥락이 없다.** 입장하자마자 보여야 할 것(참가자 명단·코드·빈 그리드)이 아니라 미디어 프리뷰만 먼저 뜬다.
3. **1:1 즉석·단독 리허설에서 마찰이 크다.** 참가자 없이도 단독 시작을 허용(SDD-101)한 지금, "오픈 페이지→대기 화면→라이브" 3단계 화면 교체는 빈 그리드임에도 여러 번의 전면 전환이 강요된다.

## 3. 목표 설계 — 단일 "클래스 관리" 페이지

### 3.1 원칙

- **상담사가 입장하면 무조건 관리 레이아웃부터 보여준다.** 상태가 바뀌어도 **레이아웃 골격은 유지**하고, 콘텐츠·CTA만 바뀐다.
- **오픈/시작/종료는 "화면 전환"이 아니라 "상태 전이"** — 툴바의 primary 버튼 라벨만 `[클래스 오픈] → [시작하기] → [종료]`로 순차 변경.
- **미디어 체크는 관리 페이지의 일부 영역으로 흡수** — 별도 풀스크린 씬 제거.

### 3.2 단일 관리 레이아웃 (전 상태 공통)

`HostClassWorkspace` 기반(기존 대기실 레이아웃)을 **ready부터 적용**:

```
┌─────────────────────────────────────────────────────────┐
│ 헤더: ←나가기 │ 제목·코드·경과 │ StatusBadge │ [primary CTA] │
├──────────────────────────┬──────────────────────────────┤
│ 좌 (2fr)                 │ 우 (3fr)                     │
│ · 호스트 셀프뷰          │ · 참가자 카드 그리드            │
│   (카메라 OFF 시 플레이스홀더)│   + 라이브 지표/밴드 신호       │
│ · 마이크/카메라 토글      │ · 필터(전체/밴드착용/끊김 등)     │
│ · 클래스 코드 + 복사      │                              │
│ · (오픈 시) 명상 가이드/BGM│                              │
└──────────────────────────┴──────────────────────────────┘
```

- 좌:우 비율 2:3(`md:grid-cols-[minmax(0,2fr)_minmax(0,3fr)]`) 유지.
- 기존 대기실 좌측의 `SessionHostVideoView`·미디어 토글·코드 영역을 그대로 쓰되, **ready에서도 렌더**한다.

### 3.3 상태별 화면 차이 (레이아웃은 동일, 내용만 변화)

| 상태 | 우측 참가자 그리드 | 클래스 코드 | 좌측 호스트 미디어 | primary CTA(툴바) |
|---|---|---|---|---|
| ready / scheduled | "아직 오픈 전 — 회원이 입장할 수 없습니다" + 빈 그리드 | "오픈 후 공개" 가림 | 셀프뷰 + 마이크/카메라 토글 (체크) | **[클래스 오픈]** |
| open | 참가자 실시간(밴드 착용·신호) + 대기 체크인 | 활성 + 복사 | 셀프뷰(라이브 준비) | **[시작하기]** |
| in_progress / paused | 실시간 지표 + 발언권/필터 | 활성(소형) | 셀프뷰 + 녹음·화상 컨트롤 | **[종료]** (2단계 확인) |
| completed | — | — | — | 종료 씬 + [기록 보기] |

- 오픈 전 참가자 그리드는 빈 상태를 명시적으로 안내(오픈 후 회원 입장 가능함을 예고)해, "이 화면에서 회원을 받는 곳"임을 직관화.
- [클래스 오픈]은 ready에서만 활성. 오픈 후엔 그 자리에 [시작하기]가 온다 — 버튼 위치가 고정되어 손 이동 없음.

### 3.4 미디어 체크 흡수 (`SessionPreJoinPreview` 축소)

- 현재 `SessionPreJoinPreview`(풀스크린 카메라/마이크 선택 + [클래스 오픈])를 **폐기**하고, 그 기능(권한 요청·카메라/마이크 토글·셀프뷰)을 좌측 "호스트 미디어" 영역 + 툴바 [클래스 오픈]으로 분리.
- 카메라 기본 OFF(오디오 중심) 유지. 마이크는 마운트 시 자동 확인, 문제 시 비차단 인라인 경고(기존 정책 그대로).
- [클래스 오픈] 확정 시 현재 `openClass(prefs)` 로직(`:975-990`) 그대로 재사용 — `prefs`는 좌측 토글에서 이미 수집된 상태.

## 4. UX 흐름 상세 (상담사 여정)

1. **클래스 생성 → 상세 [입장]** → 곧바로 "클래스 관리" 페이지(ready) 진입. 좌측에 셀프뷰·마이크/카메라, 우측에 "아직 오픈 전" 빈 그리드.
2. 좌측에서 마이크/카메라 확인 → 툴바 **[클래스 오픈]** → 레이아웃 그대로, 코드 활성화 + 참가자 그리드 실시간 전환.
3. 회원 입장·밴드 착용 확인 → **[시작하기]** → 같은 레이아웃에서 라이브 지표·녹음·마커 활성화 + [종료] 노출.
4. **[종료]** → 2단계 확인 → 종료 씬([기록 보기]).

→ 화면 전환은 **종료(완료) 씬 한 번만**. 그 전까지는 한 화면에서 오픈→시작→종료가 연속 진행.
