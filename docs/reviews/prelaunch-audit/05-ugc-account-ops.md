## 2. Brian 이 결정해야 할 비즈니스 항목

1. **공개 범위·연령 정책**: 최소 가입 연령(만 14세/19세) 및 미성년 이용 허용 여부. 스토어 연령 등급과 연결.
2. **상담사 없는 사용자 처리**: Google 가입 후 상담사 코드가 없는 사용자에게 줄 경험(코드 입력 대기 / 셀프 기능 / 가입 제한). 위기 감지 시 이런 사용자에게 연락처를 줄지.
3. **위기 안내 문구와 번호 게시**: 109·1577-0199·119 등 상시 노출 여부와 문구, AI 요약·뇌파 지표에 대한 면책 문구(법무 검토).
4. **계정 삭제·재가입 정책**: 탈퇴 시 익명화 vs 완전 삭제 범위, 법정 보존 예외(있다면 근거), 삭제 처리 SLA, 재가입 허용 방식.
5. **약관·방침 확정과 법무 검토**: 이용약관 작성, 방침 필수 기재사항(책임자·위탁·국외이전·구제기관), 시행일 조정(현재 10/22).
6. **사업자 표기와 지원 채널**: 푸터에 노출할 상호·대표·사업자번호(230-81-10210)·통신판매업 번호·주소, 사용자용 지원 이메일 1개(`admin-mindbreeze@` vs `support@`), 응대 시간.
7. **UGC 정책**: 채팅 신고·차단 도입 여부 또는 "상담 관계 내 채팅이라 UGC 아님"으로 심사 대응할지. 신고 접수 후 누가 처리할지(운영 인력).
8. **AI 비용 상한**: 월 예산, 초과 시 서비스 정책(제한/중단), 무료 이용자 1인당 AI 사용 한도.
9. **Apple 로그인 vs Google 로그인 제거** 결정(스토어 정책 충족 방식).
10. **브랜드**: 'MIND BREEZE' 상표 출원·조사 의뢰 여부, 1.0과의 앱 이름 관계, 스토어 이름 확보.
11. **운영 수준(D3)**: 단일 서버로 공개할지, 공개 규모에 맞춰 2대+Multi-AZ로 올릴지. 가입 폭주 시 가입 대기열/초대제 도입 여부.
12. **심사용 데모 환경**: 리뷰어 계정 쌍과 샘플 세션 데이터를 둘 기관·계정 정책.

## 3. 기술적으로 처리할 항목

1. 본인 계정 삭제 API+UI(재인증, `device_tokens`/푸시 구독/S3 객체/채팅 본문 처리 포함), 웹 삭제 요청 URL.
2. `NSCameraUsageDescription`·`NSMicrophoneUsageDescription` 추가, `PrivacyInfo.xcprivacy` 작성, 실기기 권한 시나리오 검증.
3. `/terms` 페이지·라우트 추가, 동의 화면·랜딩 푸터 링크, 존재하지 않는 경로를 404로 반환(현재 SPA 폴백 200).
4. 랜딩·설정에 사업자 정보·문의 링크 푸터.
5. 위기 지원 화면(정적 안내 + 상시 접근 링크), 첫 사용 고지·리포트 면책 문구, 상담사 미배정 사용자의 감지 경로 에스컬레이션.
6. 채팅 메시지 신고·사용자 차단·관리자 처리 큐, 사용자 검색 결과 이메일 마스킹과 검색 범위 제한 확인.
7. Gemini/STT/요약 호출에 사용자별 일일 한도·월 예산 가드, 한도 초과 시 폴백 응답, 프로바이더 콘솔 쿼터·알림 설정.
8. 가입·OTP·초대 요청에 IP 단위 제한과 봇 방어, OTP 메일 발송 일일 총량 상한.
9. 알림: SNS 이메일 구독 확인+시험 발화, Celery 큐 적체·메일 실패·리포트 실패율 경보, 오류 추적 도입, 이메일 워커 상태 감시. DMARC 단계적 강화.
10. 운영 API `/docs`·`/openapi.json` 비활성, `public/chat-test.html` 배포 제외.
11. 운영 `GOOGLE_CLIENT_ID`·FCM·APNs 설정 후 Google 로그인·푸시 실기기 검증. RDS 백업 보관일·PITR·삭제방지 값 직접 확인.
12. 감사: `counselor_info_service` 수정 이력 로그 적재 여부 확인·추가. 소속 해제 후 접근 차단 테스트.
13. 보관 스위프 dry-run 승인·활성화 일정 수립(방침 약속과 정합).
14. 심사용 시드: 상담사/내담자/기관/완료 세션/리포트 가공 데이터 시드 스크립트와 심사 메모 문서, 스크린샷용 합성 데이터.

## 4. 깨끗한 항목 (확인한 범위에서 문제 없음)

- 이메일 OTP 인증: 6자리, 15분 토큰, 5회 시도 제한, 재전송 쿨다운 구현(`otp_service.py`, `auth.py:286-299`).
- 로그인 시도 5회 잠금(423), 정지/대기 계정의 세션 발급 차단(`auth.py:147` 부근).
- 가입 동의: 약관·개인정보·민감정보 3종 동의를 서버가 명시적으로 검증(Google 신규 가입 포함, `auth.py` SEC-04), 동의 이력 `consents` 저장.
- 플랫폼 관리자는 Google 가입으로 승격 불가, 상담사·기관 신규 계정 자동 생성 차단.
- 삭제된 계정: 로그인·토큰·소속·알림·채팅참여 접근 권한 제거, 호스트 세션 숨김(`admin_service.delete_user`) — 단 데이터 잔존은 위 표 참고.
- 위기 감지 설계: 규칙 기반(프롬프트 주입 우회 불가), 알림 본문 비식별, 방해금지 시간 무시 즉시 알림.
- 라이브 확인: `https://mindbreeze.looxidlabs.com/` 200, `/privacy` 200, `https://api.mindbreeze.looxidlabs.com/health`·`/health/ready` 200 (단 `/privacy` 본문 렌더 자체는 curl로 확인 불가 — SPA).
- 운영 인프라: 전용 VPC, SG에 22·8000·7880·5432 비개방, 암호화 EBS, KMS+SSM SecureString, S3 퍼블릭 차단·버저닝·TLS 강제, CORS 운영 오리진 한정(`infra-result.md`).
- Android 매니페스트: 필요한 권한(BLE·카메라·마이크·알림)만 선언, 위치 권한은 `neverForLocation`/ 낮은 SDK 한정, 카메라·마이크 `required=false`.
- 푸시: 무효 토큰 응답(UNREGISTERED·INVALID_ARGUMENT) 처리 코드 존재(`push_service.py:28`).
- 서비스 설계상 LINK BAND 선택 사용(밴드 없이 입장·AI 기록·리포트 가능).
- 푸시 탭 이동 경로를 앱 내부 상대 경로로 제한(`capacitor-app-셸-운영가이드.md`).

## 5. 점검 한계

- 라이브 SPA 화면은 JS 렌더 결과를 확인하지 못했다(브라우저 미사용). `/privacy` 200은 앱 셸 응답이다.

- 전화번호(109 등)는 이번 점검에서 외부 출처로 재검증하지 않았다. 게시 전 최신 공식 정보 확인 필요.
