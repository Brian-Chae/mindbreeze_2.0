# 호스트 클래스 — 그룹 상태·참가자 표시 방식 3안

- 작성 목적: 수업을 진행하면서 그룹 흐름과 참가자 상태를 함께 읽고, 조용한 신호에 바로 반응할 수 있는 배치 비교.
- 범위: 설계 브레인스토밍 문서. HTML·제품 코드 구현, BGM 재설계, 최종안 확정은 포함하지 않음.
- 참고: `index.html`, `brainstorm-brief.md`, 기존 디자인·피드백 문서. 충돌 시 이번 Brian 확정 요구사항 우선.
- 우선 제안: **1안 — 그룹 요약 띠 + 참가자 작업판**. 그룹·참가자를 함께 읽으면서 기존 좌우 구성을 이어가기 쉬움.

## 현재 화면에서 바꿔야 할 점

- 그룹 상태·참가자·조용한 신호의 3개 탭 때문에 동시에 관찰할 수 없음.
- 참가자 카드는 이름·참여/발언 상태·장치 상태 위주이며, 맥박·호흡은 상세 모달 안에 있음.
- 카드가 남는 높이를 채우는 구조라 인원이 적어도 세로 공간을 크게 차지함. 정보량에 맞춘 높이 상한 필요.
- 현 목업에는 맥박·호흡·배터리·업로드 상태 예시가 있으나, 실제 데이터 제공 여부를 보장하는 근거는 아님. 설계는 제공 가능한 필드만 표시하는 전제.

## 세 안의 공통 원칙

### 화면·정보 기준

- 배경 `#12081C`, 선택 상태 보라 `#5F0080`, 본문 크림 계열, Pretendard 유지. 상태는 색과 텍스트를 함께 사용.
- 그룹 요약은 익명 이완·집중 집계, 유효 표본 수, 보정 상태, 페이스 안내만 표시. 개인 이완/집중 점수·순위·생체값 기준 자동 정렬 없음.
- 개인 맥박·호흡은 호스트에게 허용된 관찰값으로만 표시. 숫자에 좋음/나쁨 등급을 붙이거나 그룹 평균과 비교하지 않음.
- 그룹 집계는 현 목업 기준인 유효 표본 최소 3명·2분 보정 조건 유지. 2명 수업에서는 그룹 영역에 ‘표본 부족 — 집계 대기’를 표시하고 수치·페이스 판단을 숨김.
- 밴드 미사용·접촉 확인·수신 끊김은 숫자 대신 `—`와 이유 표시. 이전 값을 현재 값처럼 유지하거나 0으로 대체하지 않음.
- 그룹·참가자 전환 탭 제거. 그룹 요약은 고정하고 참가자 표현만 카드/테이블로 전환.
- 카드 높이를 남는 공간에 맞춰 늘리지 않음. 남는 공간은 여백으로 유지하고 큰 아바타·개인별 그래프는 기본 카드에서 제외.
- N은 현재 입장 참가자 전체 수이며 밴드 미사용자도 포함. 필터·페이지 이동으로 N을 줄여 카드 정보를 갑자기 늘리지 않음.
- 정보 항목 계산: 이름, 맥박, 호흡, 상태, 발언권, 배터리, 갱신 시각을 각각 1개로 계산. 맥박/호흡을 같은 줄에 써도 2개로 계산.
- 공통 필수 5항목: **이름 / 맥박 / 호흡 / 상태 / 발언권**. 상태는 ‘참여 중·밴드 연결’, ‘참여 중·밴드 미사용’, ‘수신 끊김’처럼 요약한 한 필드.
- 발언권은 ‘듣는 중 / 요청 / 발언 중’과 해당 동작을 표시. 기존 온라인 20명 이하·식별 가능한 참가자 조건 유지. 21명 이상은 관찰 레이아웃만 제안하며 발언권 기능 확장으로 해석하지 않음.

### 카드·테이블 조작

- 참가자 제목 옆 `[카드] [테이블]` 선택 버튼 상시 노출. 표기 방식 변경 후 선택 참가자·필터·목록 위치 유지.
- 인원별 기본 뷰는 수업 최초 진입에만 적용. 수업 중 인원이 임계치를 넘으면 전환 제안만 표시하고 자동 전환하지 않음.
- 밀도 축소가 필요하면 조작 중인 카드의 동작이 끝난 뒤 반영. 입퇴장 때 이름 순서를 반복 재배열하지 않음.
- 테이블 기본 열: 이름 / 맥박(bpm) / 호흡(회/분) / 상태 / 발언권. 데이터 단위는 열 제목에 명시.
- 데스크탑 행 높이 44px, 모바일 52px 기준. 요청·발언 버튼 터치 영역 최소 44×44px 확보.
- 모바일 테이블은 좌우 12px 여백을 제외한 366px 안에서 열 너비를 이름 64 / 맥박 48 / 호흡 48 / 상태 142 / 발언권 64px로 배분하는 초안. 셀 여백 포함, 가로 스크롤 없이 배치.
- 모바일 상태 셀은 최대 두 줄, 긴 이름은 말줄임 후 선택 시 전체 이름 확인. 숫자·이름 본문은 13px 이상, 열 제목은 12px 기준.
- 페이지 밖 발언 요청은 참가자 제목의 ‘발언 요청 n’으로 알림. 눌렀을 때 요청자 목록으로 이동하며 생체값 순위는 만들지 않음.

### 조용한 신호의 독립성

- 카드/테이블, 참가자 필터·페이지, 그룹 집계 유효 여부와 무관하게 별도 고정 영역에 노출.
- 익명 세 범주 ‘잘 따라가요 / 조금 어려워요 / 잠시 쉴게요’ 유지. 이름·아바타·카드 위치와 연결하지 않음. 현 상세 모달의 개인 신호 표시는 이 설계에서는 이어받지 않음.
- 현 계약의 ‘참가자별 최신 1건·최근 10초’를 현재 집계 기준으로 사용. 같은 사람이 반복해도 현재 인원을 중복 합산하지 않음.
- **제안하는 보완:** 10초가 지나 현재 수치가 0이 되어도 ‘미확인 새 신호 있음’ 표시는 호스트 확인 전까지 유지. 현재 집계와 미확인 수신 이력을 다른 라벨로 구분.
- 수신 즉시 범주별 새 신호 표시 갱신. 자동 사라지는 토스트만으로 처리하지 않음. 애니메이션은 짧은 강조로 제한하고 지속 점멸·자동 소리는 사용하지 않음.
- 시간순 이력은 익명 범주와 수신 시각만 제공. 그룹 최소 표본 조건으로 신호 자체를 숨기지 않되, 2명 등 소수 수업에서는 익명 표기만으로 추론까지 막을 수 없다는 한계가 있음.
- 참가자 상세는 신호 영역 아래의 내부 패널로 열어 신호를 가리지 않음. 모바일에서도 전체 화면 모달 대신 참가자 영역 안에서 상세/목록 전환.

### ‘1화면’의 현실적인 기준

- 기본 화면에서 그룹 요약·신호·일부 또는 전체 참가자·수업 제어가 함께 보이는 것을 목표로 함.
- **모바일에서 20명 모두의 상세 정보를 한꺼번에 보여주는 목표는 채택하지 않음.** 작은 글씨나 터치 영역 축소 대신 참가자 영역만 페이지 이동.
- 아래 크기는 레이아웃 가설이며 실제 렌더 검증 결과가 아님. 기본 글자 크기·지정 뷰포트 기준으로 산정.
- 모바일 높이에는 안전 영역·간격 여유 포함. 브라우저 UI로 가용 높이가 줄면 참가자 페이지당 인원을 먼저 줄임. 확대·큰 글자 설정에서는 스크롤을 허용해 정보 잘림 방지.
- 하단 일시정지·종료·채팅 배지는 고정 유지. BGM의 배치·크기·동작은 이번 안에서 정의하지 않음.

## 1안 — 그룹 요약 띠 + 참가자 작업판: 균형형, 우선 제안

### 레이아웃

- 데스크탑 1280×720: 좌우 여백 각 24px. 좌측 392px에 셀프뷰·진행 시간, 간격 16px, 우측 824px에 그룹+참가자 작업판.
- 화면 상단 헤더 48px → 전체 너비 조용한 신호 띠 56px → 본문 520px → 하단 제어 56px. 남은 40px은 바깥 여백·영역 간격.
- 우측 본문: 그룹 요약 80px → 뷰 전환·참가자 제목 44px → 목록 352px → 페이지 제어 36px, 간격 8px.
- 그룹 요약은 이완·집중 변화, 유효 표본·보정, 페이스 안내를 가로 배치. 세부 설명은 펼치되 기본 높이는 고정.
- 모바일 390×844: 헤더 48 + 신호 64 + 축소 셀프뷰·타이머 112 + 그룹 72 + 뷰 전환 44 + 참가자 360 + 페이지 36 + 하단 제어 56 + 여유 52px.
- 모바일 그룹 띠는 2줄: 집계 / 표본·보정·페이스. 그룹과 참가자를 모두 유지하며 셀프뷰를 먼저 축소.

### 참가자 표현·밀도 규칙

- N=1~2: 카드당 **7항목** — 필수 5 + 배터리 + 갱신 시각. 데스크탑 2열·높이 152px 상한, 모바일 1열·높이 168px 상한.
- N=3~6: 카드당 **6항목** — 필수 5 + 배터리. 데스크탑 3열·높이 136px 상한, 모바일 2열·높이 112px 상한.
- N=7~20: 카드당 **5항목** — 필수 5만. 데스크탑 4열·높이 108px, 모바일 2열·높이 112px. 지표는 나란히, 상태 한 줄, 발언권 한 줄.
- N≥21: 카드당 **5항목** 유지, 테이블을 기본 제안. 글자나 카드 높이를 더 줄이지 않고 페이지 수만 증가.
- 예시: 2명은 7항목×2장, 5명은 6항목×5장, 20명은 5항목×20장.
- 초기 뷰: 데스크탑 N≤6 카드 / N≥7 테이블, 모바일 N≤2 카드 / N≥3 테이블.
- 데스크탑 카드 페이지당 최대 12명(4열×3행), 테이블 7명(열 머리글 28px + 7행×44px). 20명은 각각 2페이지/3페이지.
- 모바일 카드 페이지당 최대 6명(2열×3행), 테이블 6명. 20명은 각각 4페이지. 2명일 때는 1열 두 장 모두 노출.
- 카드 선택 시 참가자 목록 일부를 상세 패널로 전환하여 배터리·신호 품질·업로드·갱신 시각 확인. 그룹과 신호는 그대로 노출.

### 조용한 신호

- 헤더 아래 전체 너비 고정 띠: 세 범주별 현재 인원 + 미확인 표시 + 최신 익명 신호 요약.
- 모바일은 첫 줄 세 범주, 둘째 줄 ‘새 신호 있음·최근 수신 시각’. 신호가 없어도 같은 높이 유지.
- 이력은 띠 아래 작은 패널로 펼치고 참가자 영역을 일부 사용. 신호 띠 자체는 항상 남김.

### 장점·트레이드오프

- 장점: 그룹 요약 바로 아래에 개인 지표가 있어 집계 변화와 연결 상태를 함께 파악하기 쉬움. 기존 좌우 시선 이동과 유사.
- 장점: 모바일에서도 상단부터 신호→그룹→참가자 순서가 명확. 2명·5명 카드의 과도한 세로 확대 방지.
- 단점: 20명 테이블은 데스크탑에서도 3페이지라 전체 동시 관찰에 불리함. 페이지 밖 참가자는 요청 배지에 의존.
- 단점: 상단 신호 띠가 넓은 만큼 본문 높이를 소비. 참가자 개별 정보보다 큰 셀프뷰가 중요한 수업에는 부담.

## 2안 — 좌측 그룹 요약 + 우측 전체 명단: 참가자 전체 조망형

### 레이아웃

- 데스크탑 1280×720: 좌우 여백 각 24px. 좌측 256px에 작은 셀프뷰·타이머(상단), 그룹 요약(중앙), 페이스 안내(하단). 간격 16px, 우측 960px 전체를 참가자 영역으로 사용.
- 높이: 헤더 48 + 본문 536 + 독립 신호 바 48 + 하단 제어 56 + 여백·간격 32px.
- 우측 본문: 참가자 제목·뷰 전환 44 + 명단 456 + 페이지 제어 36px.
- 그룹은 세로 요약: 이완 / 집중 / 유효 표본·보정 / 페이스. 참가자 수가 많아져도 좌측 폭·표시 항목 유지.
- 모바일 390×844: 헤더 48 + 셀프뷰·타이머 96 + 그룹 요약 80 + 뷰 전환 44 + 참가자 400 + 페이지 36 + 독립 신호 바 56 + 하단 제어 56 + 여유 28px.
- 모바일 좌측 요약은 상단 가로 요약으로 이동. 신호는 하단 제어 바로 위에 고정되어 엄지로 확인하기 쉬운 위치.

### 참가자 표현·밀도 규칙

- N=1~2: 카드당 **7항목** — 필수 5 + 배터리 + 갱신 시각. 데스크탑 2열·높이 144px 상한, 모바일 1열·높이 164px 상한.
- N=3~6: 카드당 **6항목** — 필수 5 + 배터리. 데스크탑 3열·높이 132px 상한, 모바일 2열·높이 120px.
- N=7~20: 카드당 **5항목** — 필수 5. 데스크탑 5열×4행, 카드 약 186×108px, 간격 8px. 모바일 2열·높이 120px.
- N≥21: 카드당 **5항목** 유지. 데스크탑 20명, 모바일 6명씩 페이지 이동.
- 예시: 2명 7항목, 5명 6항목, 20명 5항목. 데스크탑 20명 카드는 네 줄 구성: 이름 / 맥박·호흡 / 상태 / 발언권.
- 초기 뷰: 데스크탑 N≤20 카드 / N≥21 테이블, 모바일 N≤6 카드 / N≥7 테이블.
- 데스크탑 테이블은 열 머리글 28px + 9행×44px이 명단 456px 안에 들어감. 20명은 3페이지. 카드로는 20명 전체를 한 번에 조망 가능.
- 모바일 테이블은 열 머리글 28px + 7행×52px = 392px. 20명은 3페이지. 카드는 최대 6명씩 4페이지.
- 테이블은 같은 위치의 숫자를 세로로 비교하기 편하고 카드는 한 페이지에 더 많은 인원을 보여줌. 이 안에서는 ‘테이블이 항상 더 많은 인원을 표시한다’고 가정하지 않음.
- 명단 순서는 입장 시 정한 고정 순서 유지. 발언 요청·수신 끊김은 카드/행의 짧은 라벨로 표시하며 자동 위치 이동 없음.

### 조용한 신호

- 화면 하단 제어 위에 세 범주 고정 배지 바. 각 배지에 범주·현재 인원·새 신호 점을 함께 표시.
- 데스크탑은 오른쪽에 최신 익명 수신 시각 추가. 모바일은 세 배지를 366px 안에 균등 배치하고 ‘최근 10초’는 바 제목으로 표시.
- 신호 이력은 바 위로 펼침. 채팅 배지와 별도 구역으로 유지하고 새 신호 존재를 숨기지 않음.

### 장점·트레이드오프

- 장점: 데스크탑 20명 카드가 한 번에 보임. 요청·연결 상태를 전체 명단에서 훑는 수업에 적합.
- 장점: 테이블은 넓은 열 간격으로 단위·상태·발언권을 읽기 쉬움. 셀프뷰보다 참가자 모니터링에 면적 투자.
- 단점: 작은 카드 20장의 숫자를 지속해서 읽으면 피로가 큼. 모든 카드가 보이는 것과 모든 정보를 즉시 이해하는 것은 다름.
- 단점: 좌측 그룹과 우측 참가자 사이의 시선 이동이 큼. 하단 신호는 상단에 시선이 머무는 진행자가 놓치기 쉬워 미확인 표시가 특히 중요.
- 모바일 한계: 데스크탑의 20명 동시 조망 이점이 사라짐. 다만 테이블 7행으로 1안보다 페이지 이동을 줄일 수 있음.

## 3안 — 전체 목록 + 선택 참가자 상세: 개별 대응형

### 레이아웃

- 데스크탑 1280×720: 헤더 48 + 전체 너비 그룹 요약 72 + 본문 488 + 하단 제어 56 + 여백·간격 56px.
- 본문 너비 1232px: 좌측 296px(셀프뷰·타이머 위 / 독립 신호 패널 아래), 간격 16px, 중앙 640px(참가자 목록), 간격 16px, 우측 264px(선택 참가자 상세).
- 중앙 높이: 뷰 전환 44 + 목록 408 + 페이지 제어 36px. 우측은 선택한 한 명의 세부 상태를 고정 표시.
- 모바일 390×844: 헤더 48 + 독립 신호 64 + 그룹 72 + 셀프뷰·타이머 80 + 뷰 전환 44 + 참가자 목록 220 + 선택 상세 180 + 페이지 36 + 하단 제어 56 + 여유 44px.
- 모바일에서는 좌측 신호 패널을 상단 띠로 이동. 목록 아래 선택 상세를 두어 신호·그룹·목록 일부가 계속 보이게 함.

### 참가자 표현·밀도 규칙

- N=1~2: 카드당 **7항목** — 필수 5 + 배터리 + 갱신 시각. 데스크탑 2열·높이 156px 상한, 모바일 1열·높이 180px로 한 페이지 1명.
- N=3~6: 카드당 **6항목** — 필수 5 + 배터리. 데스크탑 2열·높이 128px, 모바일 2열·높이 128px로 한 페이지 2명.
- N=7~20: 카드당 **5항목** — 필수 5. 데스크탑 3열·높이 128px, 모바일 2열·높이 104px로 한 페이지 4명.
- N≥21: 카드당 **5항목** 유지. 더 축소하지 않고 페이지 이동.
- 예시: 2명 7항목, 5명 6항목, 20명 5항목. 고정 상세가 있으므로 카드가 좁아질 때 배터리·갱신 시각을 먼저 상세로 이동.
- 초기 뷰: 데스크탑 N≤6 카드 / N≥7 테이블, 모바일 N≤2 카드 / N≥3 테이블.
- 데스크탑 N=20 카드 페이지당 9명으로 3페이지. 테이블은 열 머리글 28px + 8행×44px로 3페이지.
- 모바일 N=20 카드는 4명씩 5페이지. 테이블은 열 머리글 28px + 3행×52px로 7페이지. 2명 카드도 2페이지가 필요하다는 비용을 명시.
- 상세 패널에는 이름, 맥박, 호흡, 밴드 상태, 배터리, 신호 품질, 업로드, 갱신 시각, 발언권의 **9항목** 표시. 모바일은 2열 요약 배열이며 신호 이력·개인 점수는 넣지 않음.
- 참가자를 누르면 상세 내용만 바뀜. 발언 요청이나 생체값 변화로 선택 대상을 자동 교체하지 않음. 선택자가 퇴장하면 ‘퇴장함’으로 표시하고 다음 선택을 기다림.
- 다른 페이지로 이동해도 상세에 선택자의 이름·‘선택 유지’를 표시하여 현재 목록의 사람으로 오인하지 않도록 함.

### 조용한 신호

- 데스크탑 좌측 독립 패널에 세 범주 집계 + 최신 익명 신호 3건 + 미확인 표시. 참가자 선택과 무관하게 유지.
- 모바일 상단 고정 띠에 세 범주 집계·미확인 표시를 남기고, 이력은 띠 아래로 펼침.
- 선택 참가자 상세에 조용한 신호를 복제하지 않음. 익명 그룹 신호를 특정 참가자의 상태로 연결하는 오해 방지.

### 장점·트레이드오프

- 장점: 특정 참가자의 접촉·수신 문제를 확인하면서 다른 참가자 요청과 그룹 흐름을 계속 볼 수 있음. 상세 모달을 반복해서 열 필요가 없음.
- 장점: 카드/테이블을 바꾸어도 자세히 관찰하던 대상과 정보가 유지됨.
- 단점: 기본 카드와 상세의 일부 정보가 중복되고 세 영역을 오가야 함. 단순 수업에는 구조가 과함.
- 단점: 선택자를 오래 보는 동안 다른 사람의 변화를 놓칠 수 있음. 요청 배지는 도움이 되지만 전체 관찰을 대신하지 못함.
- 모바일 한계: 상세 180px 때문에 목록이 크게 줄어 20명 테이블은 7페이지. ‘참가자를 한눈에’라는 요구에는 세 안 중 가장 불리함. 소수 대상 개별 대응이 잦을 때만 선택할 이유가 있음.

## 선택 판단

- **기본 후보는 1안:** 그룹 흐름·참가자 지표·신호의 균형, 기존 화면과의 연속성을 우선할 때 적합. 다만 20명 전체 동시 노출 요구가 강하면 우선순위 변경 필요.
- **20명 데스크탑 조망이 핵심이면 2안:** 카드 20명 동시 표시 가능. 정보량을 5항목으로 제한해도 실제 가독성은 후속 디자인 검증이 필요.
- **개별 접촉/수신 대응이 잦으면 3안:** 상세 접근 비용 최소화. 모바일과 전체 참가자 관찰 면적을 희생하는 선택임.
- 카드/테이블 두 뷰만 추가해서 해결되지는 않음. 그룹 고정 요약, 카드 높이 상한, 인원별 정보 제한, 독립 신호, 페이지 밖 요청 알림까지 함께 결정해야 효과가 있음.

## 후속 디자인 검토 기준 — 이번 작업에서는 실행하지 않음

- 2명: 그룹 집계 대기와 개인 관찰값을 구분할 수 있는지, 빈 공간을 카드 높이로 채우지 않는지 확인.
- 5명: 맥박·호흡·상태·발언권을 상세 진입 없이 읽을 수 있는지 확인.
- 20명: 각 안의 명시된 동시 노출 인원이 지정 해상도에서 들어가는지, 긴 이름·미사용·끊김 상태가 겹치지 않는지 확인.
- 신호: 다른 페이지·뷰·참가자 상세를 보고 있어도 수신을 알 수 있는지, 10초 뒤 현재 집계와 미확인 표시를 혼동하지 않는지 확인.
- 모바일: 44px 조작 영역·본문 가독성을 유지하는지, 큰 글자·줄어든 가용 높이에서 정보가 잘리지 않는지 확인.
