# 상담사(호스트) 클래스 진행 화면 — 개선 디자인 정본 기획

## 미션
상담사가 클래스를 진행하는 호스트 화면(`frontend/src/pages/sessions/ClassPlayerPage.tsx`, 1859행)을 점검하고,
**이미 1화면으로 리팩토링된 게스트 화면과 동일한 디자인 언어·밀도**로 개선한 디자인 정본 HTML을 만들어라.

## 반드시 읽을 파일
1. `frontend/src/pages/sessions/ClassPlayerPage.tsx` — 호스트 화면 전체(4개 씬, 데이터 계약·기능 전부)
2. `design/member-class-player/index.html` — **게스트 화면 디자인 정본(이미 확정)**. 이 디자인 언어·색상·타이포·밀도를 그대로 따른다
3. `frontend/src/components/class/` 하위 컴포넌트들 — CuesheetPanel, ClassAudioPanel, CounselorLiveTile 등

## 현재 구조 (점검 결과)
ClassPlayerPage = 4개 씬:
- ① 세팅(ready/scheduled): 미디어 프리뷰 + [클래스 오픈]
- ② 대기실(open): 클래스 코드 대형 표시 + 호스트 카메라 + 참가자 실시간 그리드 + [시작하기]/[클래스 닫기]
- ③ 라이브(in_progress/paused): 좌(셀프뷰+진행시간+큐시트+오디오) / 우(모니터 패널) / 하단(녹음·화상·마커 접기) / 채팅 오버레이
- ④ 종료(completed): [기록 보기]

## 문제점 (개선해야 할 것)
1. **세로 스크롤**: 라이브 씬이 3단 세로 스택(좌 컬럼 4종 + 우 모니터 5종 + 하단 접기)이라 1화면에 안 들어옴. 게스트는 1화면인데 호스트만 스크롤
2. **디자인 언어 불일치**: 게스트는 브랜드 다크(#12081C), 호스트는 흰색 카드(bg-white)·옅은 회색(#F2F3F8) 혼재
3. **헤더 버튼 과다**: 닫기/시작/일시정지/종료/채팅토글 5개 버튼 — 상태 전이 버튼은 통합·정리
4. **정보 과밀**: 우측 모니터 패널(상태바+요약+발언권+카드그리드+호스트밴드)이 세로 누적

## 개선 방향 (핵심 지시)
1. **라이브 씬을 1화면 2단 그리드**로: 좌(상담사 셀프뷰 + 진행시간 + 큐시트 + 가이드·BGM) / 우(참가자 모니터: 요약 게이지 + 카드/테이블 그리드)
2. **녹음·화상·마커 보조 기능은 하단 접이식 또는 우측 탭으로** — 진행 중 화면에서 가리지 않게(게스트 화면처럼 접기)
3. **채팅은 우측 오버레이**(기존 유지, 접힘 가능)
4. **헤더 간소화**: 상태 전이 버튼(닫기/시작/일시정지/종료)은 씬별 최소 노출, 채팅토글은 오버레이 내부로
5. **브랜드 토큰 통일**: 배경 #12081C(다크), 보라 #5F0080, 크림 #F7F4F0, 민트 #01f0c8, Pretendard. 게스트 정본과 동일 토큰
6. **데이터·AI 판단을 한 흐름으로**: 게스트 정본처럼 좌(영상/진행) 우(데이터 지표) 구분. 상담사는 우측에 참가자 모니터(요약→그리드), 좌측에 본인 진행(셀프뷰→큐시트→오디오)

## 산출물
`design/host-class-player/index.html` — self-contained 단일 HTML(인라인 CSS/SVG, 외부 폰트·라이브러리·이미지 의존성 없음, Google Fonts도 금지)
- 데스크탑 1280×720(1화면 스크롤 없음) + 모바일 390×844(세로 스택)
- **라이브 씬(진행 중) 중심**으로 상세 설계. 세팅/대기실/종료 씬은 간략히(같은 셸에서 상태만 다르게)
- 게스트 정본처럼 미니파이 없이 가독성 있는 HTML. 데스크탑 720px 높이 안에 모든 핵심 요소 수렴
