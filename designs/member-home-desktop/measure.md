## 범위와 판정 한계

- I1·I2·I4: 위 DOM 수치로 정렬·높이·넘침 검증. 홀수 카드에 격자용 빈 셀이나 높이 보정용 가상 카드가 없다. 1개인 줄의 남는 공간은 자연스러운 여백이다.
- I3: overflow-x:auto, CSS 스냅, 좌우 버튼·끝 그라데이션, Tab 가시성 검증. 실제 트랙패드·Shift 휠·터치 기기 제스처는 실기기 미검증이다.
- I5: style.css의 공통 토큰(--radius:20px, --space:24px, --shadow), 공통 section-head 사용.
- I6: 클래스 영역의 빈 상태·로딩·오류와 히어로 대체 문구를 검증했다. 나머지 패널은 독립적으로 정상 샘플을 유지한다. 요약은 대체 상태에서 — 표시.
- I7: 834·390px 정적 시안의 넘침·겹침만 보조 측정. 실제 앱의 기존 모바일 동작 회귀 검증은 시안 승인 후 구현 단계 대상이다.
- I8: 실제 소스 문구·콘텐츠 역할과 목적 경로를 참고했다. 링크는 data-service로 실제 이동을 막고 목적 경로를 안내한다. 초대된 클래스는 초대가 없는 샘플이며 비표시. 담당 상담사는 기존 조건부 패널을 유지했다. 데이터·API·라우팅 동작 검증은 포함하지 않는다.
- I9: 시안 방향 승인 대기. 구현 코드는 수정하지 않았다.
- I10: 내 상담 섹션 미노출 확인.

## 구성과 선택 기준

A는 히어로 전폭 아래 주 영역/요약 레일의 정렬을 유지한다. 1280px에서는 카드 두 장과 다음 카드 일부가 보이므로 스크롤 탐색 중심이다. B는 요약 한 줄과 전폭 클래스 줄을 사용해 같은 폭에서 더 많은 클래스를 보여주지만 하단 일정까지의 세로 거리가 늘어난다. 두 안 모두 단일 main 폭(최대 1280px, 패딩 포함)을 사용한다.

실제 컴포넌트 근거: member-structure-home-page.tsx(히어로·내 클래스), ClientHomePage.tsx(요약·이번 주 클래스·리포트·상담사·대화·알림), member-class-views.tsx(클래스 상태·진행·다음 회차·지도사). 가상 데이터의 기준 날짜는 2026-10-20이며 이름·클래스·기록은 예시다.

원시 측정 수치 및 판정: measure-results.json.

## 측정 중 보완

초기 브라우저 미설치 및 시스템 Chrome 실행 지연으로 Playwright 전용 headless shell을 설치했다. 로컬 파일 탐색 시간 초과는 동일 시안 소스를 메모리 응답으로 제공해 해소했다. 초기 B안 7개 카드의 Tab 가시성 2건 실패를 확인했고, 카드 focusin에서 inline:start로 스크롤하도록 시안을 보완한 뒤 전체 70건을 재측정했다. 최종 결과는 위 기록과 원시 JSON에 해당한다.
