## 2. 화면 간 이동 흐름

```
[로그인 /login?role=client] ──> /app (ClientAppPage)
        │ 상담사 목록 조회(GET /client/counselors)
        ├─ 0명 ─────────────────> S-M00 상담사 코드 6칸 입력 ─(POST /client/counselors)─> /app 새로 진입
        ├─ 조회 실패 ───────────> "연결 정보를 불러오지 못했습니다" + 다시 시도
        └─ ≥1명
             ├─ S-M01 홈 ──[히어로 입장 버튼]──────────────┐
             │     ├─ [초대된 클래스 > 클래스 확인] ───────┤
             │     └─ [이번 주 일정 항목] ─────────────────┤
             ├─ S-M02 세션 목록 ──[카드]───────────────────┤
             │     └─ [세션 신청하기] ─> S-M20 모달(채팅방으로 '세션 신청합니다' 시스템 메시지)
             └─ (알림 토스트·딥링크) ───────────────────────┤
                                                            v
                                   S-M03/04/05/06 세션 상세 /app/sessions/:id
                                   ├ scheduled·ready ─ 버튼 비활성 "(아직 열리지 않음)"  (WS+5초 폴링으로 자동 갱신)
                                   ├ open·in_progress ─ [세션 입장하기] ─> /join?code=XXXXXX
                                   │                    (access_code 없으면 비활성 + 안내문)
                                   ├ completed ─ [리포트 보기] ─> ClientReportDetailModal
                                   └ cancelled ─ "취소된 세션입니다"

[홈페이지·링크·코드 공유] ──> /join (비로그인 가능)
        S-M07 코드 입력 ─(GET /sessions/by-code/{code})─┬ 404 ─> S-M08 오류 문구
                                                          ├ 종료/취소 ─> S-M22 오류 문구
                                                          └ 존재 ─> details
        details ── 게스트: S-M09/S-M21 이름·성별·생년월일 폼 ─[클래스 참여하기]─┐
                └─ 회원  : S-M10 (자동 참여, 오픈 전이면 3초 폴링 대기) ─────────┤
                                       POST /sessions/by-code/{code}/join ─────┘
                                                          v
              waiting(대기실)  S-M11 ─> S-M12 ─> S-M13 (탭 이동 자유, 각 단계 '건너뛰기' 가능)
                   │               3단계 모두 완료 + 상담사 미시작 ─> S-M16 시작 대기 ─[준비 다시 확인하기]─> 대기실 복귀
                   │               3단계 완료 + 상담사 시작(in_progress) ─> 자동 입장
                   │               취소 수신 ─> 코드 입력 단계로 복귀 + 오류 문구
                   v
              meditation(진행 화면 — 조사 제외, 리디자인 완료)
                   │  completed 수신(4초 폴링/WS)
                   v
              S-M17 종료 ─[리포트 받기]─> S-M18 시트 / [오늘 상태 남기기]─> S-M19 시트
                        └[대시보드로 이동(회원) | 홈으로(게스트)] ─> /role-redirect | /
```

**입장 단계 수(회원, 홈에서 시작)**: 홈 → 상세 → `/join`(details, 자동 통과) → 대기실(3단계) → (시작 대기) → 진행. 코드를 직접 입력하는 경로는 `/join` 코드 → details → 대기실.

10. 푸시 알림·딥링크 경로(`resolveNotificationTarget`)와 알림 센터 화면.
11. `by-code` 응답에 `scheduled_at` 이 있는지(details 요약 박스에 시작 시각이 없는 이유).
12. 서버가 회원의 녹음·녹화·뇌파 동의를 가입 시 동의로 갈음하는지(요약 #7).
13. 종료 화면 "함께한 시간"이 서버 기록과 일치하는지.
14. 색 대비비·스크린리더 동작 실측.
15. 실기기(iOS Safari 등) 동작 — Web Bluetooth 미지원 브라우저 안내는 코드(`:79-81`)로만 확인, Safari 실측 없음. 모든 캡처는 데스크톱 Chrome 에뮬레이션(dsf 1).
