# 클래스 사전 흐름 리디자인 — 기획 (정본)

> **R4·R5 정책 반영(2026-10-17, SDD-209 R0 정합화 완료):** `../../specs/sdd-209-class-flow-redesign/policy-revision-r4.md`(개정 R5 = D-1~D-5·N-1~N-6 확정)가 최신 정본이다. 로그인 없는 **4자리 코드 입장 → 개인정보(이름·성별·생년월일·이메일) 입력 후 입장**, 기록 원본은 **기본 DB 에서 설정 기간(`{N}일`) 경과 시 삭제**(연구 동의 건만 연구 DB 에 비식별 누적), 리포트 반영은 **참가자 선택(기본 제외)**, 밴드 없이 참가, 서버 **대기 취소**, 비회원 **이메일 초대·리포트 자동 발송**, **정원 스텐퍼**로 바뀌었다. 아래 §0 R1-1 의 "코드·OTP 전면 제거"와 "회원 전용·초대 방식"은 **R4 로 대체**되어 이력으로만 남긴다(시안·케이스는 R4/R5 기준). 케이스 정본 목록은 `case-keys.json`.

> 범위: 클래스 생성 → 입장 → 사전 확인(설문·밴드·기기) → 시작 대기 → (진행 화면은 완료) → 종료 후. 회원·상담사 전 화면.
> 근거: `survey/회원-화면조사.md`(24종), `survey/상담사-화면조사.md`(29종), 기준 디자인 = 진행 화면 A안(`../class-player-redesign/`).
> 모든 시안은 이 문서를 정본으로 따른다. 충돌 시 이 문서가 우선.

## 2. 디자인 원칙

1. **진행 화면의 연장.** 다크 소프트 시트 + 자연 사진 백드롭 + lucide 2px 아웃라인 + pill 버튼 + Pretendard. 토큰은 `../class-player-redesign/tokens.css`를 import하고 `flow-base.css`의 공용 컴포넌트를 쓴다.
2. **한 화면에 하나의 목적.** 긴 폼·대시보드를 단계(마법사)와 시트로 쪼갠다. 페이지 스크롤 0. 스크롤이 필요한 것은 목록·타일 영역만 내부 스크롤.
3. **CTA는 한 곳에, 항상 보이게.** 화면 하단 중앙의 주 버튼(pill) 하나. 보조 동작은 텍스트/아웃라인 버튼. 모바일에서도 라벨을 숨기지 않는다.
4. **상태는 색+선+아이콘+라벨.** 경고(코랄)는 조치가 필요한 경우만. 밴드·카메라 미사용은 정상 상태(경고 금지).
5. **방식이 화면에 반영된다.** 오프라인은 마이크·카메라·BGM 단계를 자리째 제거(빈칸 금지, 안내로 채움). 밴드 모드(없음/선택/필수)에 따라 밴드 단계가 숨김/건너뛰기 허용/권장 안내(R4-3: 어떤 모드든 `LINK BAND 없이 계속하기` 제공, 참가를 막지 않음).
6. **균형.md(S1~S10, CS, MS) 전부 적용.** 단독 요소 중심축, 좌우 여백 동일, 태블릿 세로는 사이드 시트 금지, 8의 배수 간격. 점수·종합점수·순위 금지.

## 3. 화면 유형 2가지

| 유형 | 해당 | 특징 |
|---|---|---|
| **몰입형(Immersive)** | 입장 확인, 사전 확인 마법사, 시작 대기, 종료, 호스트 생성 마법사, 세팅, 로비, 시작/종료 확인, 닫힘·오류 | 앱 셸 없음. 자연 사진 풀블리드 백드롭 + 중앙 컬럼 카드/시트(max 640). 상단 바(좌 나가기/뒤로 · 중앙 제목 · 우 같은 크기 자리) |
| **셸형(Shell)** | 회원 홈·클래스 목록·클래스 상세, 상담사 클래스 목록·상세 | 기존 앱 셸(사이드바·하단 탭, 라이트 `#F7F4F0`) 유지 — 메인 화면과 통일감. 단 **클래스 카드·상태 칩·입장 버튼·시트는 진행 화면 언어**(radius 16/24, pill, lucide, 같은 상태 색)로 교체 |

> 셸형을 다크로 바꾸지 않는 이유: 요청된 "이전 메인 화면들과 통일감" 유지. 클래스 관련 컴포넌트만 A안 언어로 맞춘다.

## 6. 이동 흐름 (신)

```
회원  FM01/02/알림 ─> FM03 ─[입장하기]─> FM05 ─> FM06 마법사(a→b→c→d→e) ─> FM07 시작 대기 ─> (진행 화면) ─> FM09   (입장 = 4자리 코드 → 개인정보 입력, R4)
       └ 정원 초과 FM08 / 취소·오류 FM10 (어느 단계에서든)
상담사 FH01 ─[+ 클래스 만들기]─> FH02 마법사(a~e) ─> FH03 ─[클래스 열러 가기]─> FH05 세팅 ─[클래스 열기]─> FH06 로비 ─[시작하기]─> FH07 시작 확인 ─> (진행 화면) ─> FH09
       └ FH04 상세에서도 열기 가능 / FH08 닫기·나가기 / FH10 닫힘·오류
```
- 홈·목록·알림에서 "입장하기"는 상세를 거치지 않고 FM05로 바로 간다(클릭 1회 절감). 코드로 입장하는 경로는 `FM01 코드로 입장하기 / 메일 링크 → FM04 코드 확인 → FM04b 개인정보 입력 → FM05`. 로그인 회원은 FM04b 가 계정 값으로 채워진다.
- 상담사 생성 → 열기까지 클릭 수: 4회 → 2회(생성 완료의 주 CTA).
