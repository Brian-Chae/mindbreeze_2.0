## 2. 디자인 원칙

1. **진행 화면의 연장.** 다크 소프트 시트 + 자연 사진 백드롭 + lucide 2px 아웃라인 + pill 버튼 + Pretendard. 토큰은 `../class-player-redesign/tokens.css`를 import하고 `flow-base.css`의 공용 컴포넌트를 쓴다.
2. **한 화면에 하나의 목적.** 긴 폼·대시보드를 단계(마법사)와 시트로 쪼갠다. 페이지 스크롤 0. 스크롤이 필요한 것은 목록·타일 영역만 내부 스크롤.
3. **CTA는 한 곳에, 항상 보이게.** 화면 하단 중앙의 주 버튼(pill) 하나. 보조 동작은 텍스트/아웃라인 버튼. 모바일에서도 라벨을 숨기지 않는다.
4. **상태는 색+선+아이콘+라벨.** 경고(코랄)는 조치가 필요한 경우만. 밴드·카메라 미사용은 정상 상태(경고 금지).
5. **방식이 화면에 반영된다.** 오프라인은 마이크·카메라·BGM 단계를 자리째 제거(빈칸 금지, 안내로 채움). 밴드 모드(없음/선택/필수)에 따라 밴드 단계가 숨김/건너뛰기 허용/필수.
6. **균형.md(S1~S10, CS, MS) 전부 적용.** 단독 요소 중심축, 좌우 여백 동일, 태블릿 세로는 사이드 시트 금지, 8의 배수 간격. 점수·종합점수·순위 금지.

## 3. 화면 유형 2가지

| 유형 | 해당 | 특징 |
|---|---|---|
| **몰입형(Immersive)** | 입장 확인, 사전 확인 마법사, 시작 대기, 종료, 호스트 생성 마법사, 세팅, 로비, 시작/종료 확인, 닫힘·오류 | 앱 셸 없음. 자연 사진 풀블리드 백드롭 + 중앙 컬럼 카드/시트(max 640). 상단 바(좌 나가기/뒤로 · 중앙 제목 · 우 같은 크기 자리) |
| **셸형(Shell)** | 회원 홈·클래스 목록·클래스 상세, 상담사 클래스 목록·상세 | 기존 앱 셸(사이드바·하단 탭, 라이트 `#F7F4F0`) 유지 — 메인 화면과 통일감. 단 **클래스 카드·상태 칩·입장 버튼·시트는 진행 화면 언어**(radius 16/24, pill, lucide, 같은 상태 색)로 교체 |

> 셸형을 다크로 바꾸지 않는 이유: 요청된 "이전 메인 화면들과 통일감" 유지. 클래스 관련 컴포넌트만 A안 언어로 맞춘다.

## 6. 이동 흐름 (신)

```
회원  FM01/02/알림 ─> FM03 ─[입장하기]─> FM05 ─> FM06 마법사(a→b→c→d→e) ─> FM07 시작 대기 ─> (진행 화면) ─> FM09   (입장 코드 없음)
       └ 정원 초과 FM08 / 취소·오류 FM10 (어느 단계에서든)
상담사 FH01 ─[+ 클래스 만들기]─> FH02 마법사(a~e) ─> FH03 ─[클래스 열러 가기]─> FH05 세팅 ─[클래스 열기]─> FH06 로비 ─[시작하기]─> FH07 시작 확인 ─> (진행 화면) ─> FH09
       └ FH04 상세에서도 열기 가능 / FH08 닫기·나가기 / FH10 닫힘·오류
```
- 홈·목록·알림에서 "입장하기"는 상세를 거치지 않고 FM05로 바로 간다(클릭 1회 절감). 클래스 링크(상담사가 공유하는 경우)는 코드가 아니라 **클래스 상세 딥링크**이며 로그인이 필요하다.
- 상담사 생성 → 열기까지 클릭 수: 4회 → 2회(생성 완료의 주 CTA).
