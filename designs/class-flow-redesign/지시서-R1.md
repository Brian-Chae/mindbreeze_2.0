# 수정 요청 R1 — 사용자 피드백 4건 (4개 워커 공통, 담당 파일만 수정)

`기획.md` 의 **§0 개정 이력 R1-1~R1-4** 와 갱신된 화면표(§5)를 먼저 다시 읽어라(이미 반영됨). 규칙·측정·산출 경로는 `지시서-공통.md` 그대로. **담당 html 과 자기 shots/fit/tools 만 수정.** 폐지된 화면·케이스의 스크린샷·인덱스 행은 삭제하고, 남은 것 전체를 4개 뷰포트로 다시 캡처·측정한다(수정 전 위반 수 → 수정 후 0).

## R1-1 입장 코드·인증 코드 전면 제거 *(R4 에서 대체됨 — 4자리 코드 입장·개인정보 입력으로 재도입. 아래 금지어 목록은 이력이며 현행 기준은 `지시서-R4.md`)*
- 사용자는 이메일 인증을 마친 가입 회원이고 클래스는 초대 방식이다. 코드 입력·게스트·OTP 없음. **화면 텍스트·인덱스 표 모두에서** `클래스 코드`, `참여 코드`, `참여코드`, `코드 복사`, `코드 입력`, `6자리`, `게스트`, `인증 코드`, `OTP`, `QR` 0건(grep 검증). 클래스 링크는 코드가 아니라 로그인이 필요한 클래스 상세 딥링크.
- 회원은 홈·목록·상세·알림에서 "입장하기" 한 번으로 입장 확인(FM05)으로 간다.

## R1-2 LINK BAND — 이마에만 착용 + 전극 접촉 UI
- "귀 뒤"·"귀" 표현 0건(grep). 착용 안내는 "이마 중앙에 밴드를 맞춰요" 계열.
- **전극 접촉 UI = 기존 `SensorTracker` 를 그대로 재현**: 288×64 알약형 외곽선 안에 좌(L)·기준·우(R) 전극 3개 LED, 접촉 양호=민트 `#01F0C8`, 접촉 실패=빨강 `#D33F3F`(시안 안에서는 코랄 경고 팔레트와 충돌하지 않게 빨강은 이 LED에만 사용), 기준 LED는 L·R 둘 다 양호할 때만 민트, 아래 범례(접촉 양호/접촉 실패), 상태는 색뿐 아니라 LED 안 아이콘(체크/엑스) + 라벨 병행. 원본 코드: `frontend/src/components/class/SensorTracker.tsx`, 복구 안내 3단계 문구: `LeadOffModal.tsx`(이마 중앙에 밀착 → 머리카락·땀 정리 → 다시 착용) — 읽고 문구를 해요체로 가져와라.
- **전극이 닿지 않을 때만 띄워서 보여준다**: 접촉 양호일 때는 트래커를 숨기고 작은 "접촉 양호" 칩만. 불량 시 카드/시트로 나타나며 L·기준·R 중 어느 전극이 안 닿는지 보인다.
- 적용: member-b FM06c(연결됨·접촉 불량·필수 모드), host-b FH06 대기 회원 행(밴드 접촉 불량이면 LED 3개 소형 표시) · FH06a "내 밴드" 시트(호스트 본인 접촉 불량 시 트래커), member-a FM03 방식 칩 문구에 귀 언급 있으면 삭제. 접촉 불량 케이스에서 L만 실패 / R만 실패 / 둘 다 실패 3종을 보여라.

## R1-3 영상+음성 합친 "내 영상·소리" 컴포넌트
- 카메라 영상이 나타나는 경우(회원 FM06d, 상담사 FH05, 로비의 내 영상) **마이크와 카메라를 한 컴포넌트로 합친다.** 현재 시안은 마이크 카드·카메라 카드가 따로 있고 영상 프리뷰가 얇은 띠처럼 작다(첨부 캡처 참고).
- 구성: 카드 폭 전체의 **큰 영상 프리뷰**(모바일 390 기준 폭 ≥ 342px, 높이 ≥ 220px, 태블릿·데스크톱은 4:3~16:9 로 컬럼 폭 전체) — 하단 오버레이에 마이크 레벨 막대, 우측 하단/상단에 마이크·카메라 토글 아이콘 버튼(44px), 좌상단 상태 칩(필수/정상/권한 필요). 카메라 꺼짐이면 영상 영역 없이 마이크 레벨 + 토글만 있는 낮은 상태(카드가 작아짐). 권한 거부·장치 없음은 같은 카드 안의 상태로 처리(문구 구분 유지).
- 스피커는 카드 아래 한 줄 행(테스트음 듣기). 이 합침으로 모바일 한 화면(스크롤 0)에서 영상이 가장 큰 요소가 되어야 한다.

## R1-4 소요 시간 5분 단위 (host-a FH02c)
- 소요 시간은 **5분 단위 스텝퍼(− / 값 / +, 최소 5분)** + 자주 쓰는 값 칩(30·45·50·60·90분). 값 직접 표시는 `50분`, 60분 이상은 `1시간 30분`. 시작 시각 선택(예약)도 **5분 단위**(분 선택 00·05·…·55). 확인 단계(e)에 같은 표기로 노출.

## 담당별 작업
- **member-a**: FM04 삭제(파일·인덱스·스크린샷). FM05 게스트 케이스 삭제, 회원 확인 카드만. FM01~FM03의 코드 노출 삭제(참여코드 칩·복사). FM03 방식 칩/준비물에 귀 언급 있으면 삭제. FM10 의 "열리지 않음/종료·취소" 상태를 FM04 대신 흡수(전체 화면 템플릿 케이스 추가).
- **member-b**: FM06a 에서 이름 입력·게스트 삭제. FM06c R1-2 반영(귀 삭제, 전극 접촉 트래커). FM06d R1-3 반영(합친 컴포넌트). FM09 게스트 OTP 삭제 — 리포트 받기 시트는 "계정 이메일(마스킹)로 신청 1탭 / 신청 완료" 2상태. FM07·FM08 에 코드·게스트 언급 있으면 삭제.
- **host-a**: FH02c R1-4. FH03 코드·QR 삭제 → 초대 현황(초대한 회원 N명 알림 발송, 일부 실패 시 재시도 행). FH04·FH01 의 코드 박스·코드 칩 삭제(초대·입장 상태 표시로 대체).
- **host-b**: FH05 R1-3(합친 큰 컴포넌트). FH06 코드·링크 공유 → 초대 현황(초대 N명·대기실 M명) + 아직 입장하지 않은 회원에게 "다시 알림", 참가자 접촉 불량 소형 LED(R1-2). FH06a 시트 "코드 공유" → "회원 초대", "내 밴드" 시트 R1-2. FH10 닫힘 안내의 코드 언급 삭제.
