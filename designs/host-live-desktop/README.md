## 작업 기준

## 열어 보기

`index.html`을 Chrome에서 연다. 기본 페이지는 현재/A/B 데스크톱·모바일 비교와 각 상태의 진입 링크다. 별도 서버·빌드가 필요하지 않다.

- `?variant=A` / `?variant=B`: 브라우저 폭에 따라 반응하는 제안.
- `&state=hand-one|hand-many|quiet-one|quiet-many|status`: 상태 고정 샘플.
- `?variant=current`: SDD-235 `screens/none-{390,1440}.png` 원본 화면. 저장된 하니스 캡처를 표시하므로 현재 운영 화면·실시간 렌더라고 해석하지 않는다.
- 제안의 수업 상태 버튼 → 체크인 응답 펼치기, 신호 줄/토스트 → 해당 시트, 닫기/Escape/포커스 복귀를 확인할 수 있다.
- 토스트는 디자인 검토를 위해 자동 소멸하지 않는다. 아래 시간 정책은 **후속 제품 구현 제안**이며 이 HTML의 실행 정책이 아니다. 서버·발언권 조치·채팅·미디어는 연결하지 않았다.
- 화면은 전원 밴드 미착용, 가상 회원 6명, 접속 5명, 체크인 완료 4명 사례다. 현재 저장 캡처는 기존 고정 샘플(체크인 6/6)로 수치가 다르다.

**A 추천:** Brian이 확인한 모바일 구조를 그대로 확장하면서 폭 불일치와 신호 위치 문제를 해결한다. 도크는 체크인만 제거해 5→4개로 줄인다. 체크인은 실시간 감시 대상이 아니므로 상태를 열고 필요할 때 응답을 펼치는 2단계가 적합하다. 기본 응답 수는 상태 시트 진입 1회로 확인한다. B는 상단 카드를 지표 진입점으로 사용한다. 전원 미착용일 때도 안내 시트를 열 수 있으며, 실제 지표 선택은 밴드 연결 후 가능하다. 이는 기존 미착용 카드의 비활성 정책을 바꾸므로 A보다 구현·학습 변화가 크다.

## 토스트 정책 제안 — 모바일·데스크톱 공통

### 현재 지연 근거

`host-signal-toast.ts:68-70`: 단일 표시 슬롯, 손들기/조용한 신호 pending **2000ms**, 입장 대기 **3000ms**, 조용한 신호 재표시 간격 **10000ms**. `HostLiveContainer.tsx:283-284`는 이벤트 변경 때 즉시 `update()`를 호출하고 이후 **200ms** 주기로 처리한다. 따라서 폴링은 약 0~200ms의 추가 임계값 처리 지연이며 모든 신호에 고정 200ms 대기를 넣는 것은 아니다.

### 제안 수치

| 항목 | 제안 |
|---|---|
| 첫 유효 이벤트 | 의도적 대기 **0ms**. 상태 수신과 같은 업데이트 경로에서 칩·토스트 생성. 수신→페인트 목표 **100ms 이내** (후속 측정 목표, 네트워크 지연 보장 아님) |
| 같은 주제 연속 이벤트 | **0ms 묶음 대기**, 현재 카드의 이름·선택·현재 집계를 갱신. 새 카드 스택 생성 안 함 |
| 표시 시간 | 손들기·어려움·휴식·입장 대기 **6초**, following만 있는 신호 **4초** |
| 갱신 시 연장 | 남은 시간을 최소 **3초**로 하되 최초 표시 후 **10초** 상한. 수식: `min(firstShown+10s, max(currentExpiry, now+3s))` |
| 조용한 신호 쿨다운 | 기존 **10초 제한 제거**. 만료 후 새 유효 이벤트는 즉시 새 카드. 초당 도배를 막기 위한 인위적 대기 대신 동일 카드 갱신 |
| 서로 다른 주제 동시 수신 | 대기 큐로 보내지 않고 한 알림 패널 안에 주제별 행 즉시 추가. 손들기·신호 최대 **2행**, 입장 대기는 별도 간결 행 포함 최대 **3행**. 각 행 44px 이상, 전체 최대 **224px**, 참가자 영역만 축소·스크롤. 이는 추가 상태 설계이며 현재 캡처는 단일 주제 4상태를 보여 줌 |
| 시트 열린 동안 | 같은 주제는 시트 본문 즉시 갱신. 다른 주제는 시트 머리글 아래 알림 슬롯에 위 규칙 적용, 하단 조치 버튼 가림 금지 |
| 접근성 | 무음·무진동, `aria-live=polite`, 포커스 이동 없음. 시각 갱신 즉시, 반복 읽기만 최대 **1초당 1회**로 통합 |
| 정지·닫기 | hover/focus 동안 타이머 정지, 해제 후 최소 **3초** 읽기 시간 보장(10초 상한 예외). 닫기는 해당 알림만 숨기며 신호 상태는 유지. 같은 이벤트 재노출 금지, 새 이벤트는 즉시 표시 |

다중 주제는 각 행이 자체 최초 시각/만료를 가진다. 연속 신호로 상한에 도달하면 해당 행은 닫고, 그 이후 새 이벤트에서만 새 주기를 시작한다. 224px가 확보되지 않는 낮은 화면에서는 알림 패널 내부를 스크롤 가능하게 하고 신호 줄·도크를 우선 보존한다. 후속 Verify에 동시 3종·390 세로·짧은 가로 화면을 포함한다.

### 내용과 데이터 의미

- 손들기 1명: **지은님이 손을 들었어요 / 현재 대기 1명 · 발언권 0명**.
- 여러 명: **지은 외 2명이 손을 들었어요 / 현재 대기 5명**. 첫 문장의 인원은 이번 표시 구간 신규 요청자(ID 중복 제외), 둘째는 현재 전체 대기자다. 시안은 둘 다 3명인 단순 사례. 대표 이름은 이번 구간 첫 유효 요청자로 고정해 카드 흔들림을 줄인다.
- 손 취소·퇴장·발언권 부여 시 현재 대기자를 재산정하고 해소된 회원은 알림 대상에서 제거. 0명이며 새 대상도 없으면 즉시 닫는다. 탭은 목록을 열 뿐 발언권을 자동 부여하지 않는다.
- 신호 1건: **지은 · 조금 어려워요 / 전체: 어려워요 1**.
- 여러 건: **서연 · 잠시 쉴게요 / 전체: 어려워요 2 · 잠시 쉴게요 1**, 아래에 **지은·민수: 어려워요 · 최근 10초**. 최신 발신자/선택을 첫 줄에, 현재 전체 종류별 상태를 다음 줄에 표시. 사람 목록 전체는 신호 시트에서 확인.
- 전체 집계는 **최근 10초 / 참여자별 최신 선택 1건**이며 전송 누적 횟수가 아니다. following도 양수이면 `잘 따라가요 N`을 포함하고 좁은 화면에서는 줄바꿈. TTL은 기존 만료 판정을 유지하고 최대 200ms 주기로 만료 갱신(새 수신 표시를 폴링에 의존시키지 않음).
- 같은 사람이 선택을 바꾸면 총합이 같아도 이벤트 내용 갱신. 중복·역순 서버 이벤트, 기존 at 없는 payload 500ms 중복 억제 유지. 초기 스냅샷·재접속·백그라운드 복귀는 새 알림으로 만들지 않음. 세션 종료/전환 시 큐·이름 메모리 초기화. TTL 종료 시 신호 행/상세에서 이름 제거.
- 이름 누락은 **참가자**, ID 노출 금지. 동명이인은 내부 ID로 집계하고 임의 실명·순번을 만들어 구분하지 않는다. 서버가 주는 `익명`도 이름 미확인으로 취급한다.

## Brian 결정 항목 (비즈니스만)

1. **레이아웃 A/B 선택 — A 추천.** 익숙한 모바일·지표 메뉴 유지와 최소 변화(A), 참가자 공간·상태 접근 우선(B) 중 선택.
2. **신호 안내 문구 확인.** 요청하신 상담사 이름 표시를 기본 반영하고 회원에게 “선택한 상태와 이름이 상담사에게만 보여요”라고 명시한다. 이름 표시 자체를 다시 승인받기 위한 항목이 아니라 회원에게 보여 줄 설명 문구 결정이다.

대기시간·CSS·파일 구조·검증 방식은 구현자가 처리한다. 제품 구현 시작은 별도 후속 요청 범위다.
