## 제안 (Brian 위임, 채택 전제)

### #4 배포 토폴로지 (초기 1000명 미만)
- **단일 EC2 인스턴스 + systemd**: uvicorn 단일 프로세스 + Celery 워커 단일 프로세스 동일 호스트.
- 오디오 `/tmp`가 API·워커 간 공유되므로 **오디오 S3 전환 연기**.
- Redis: ElastiCache(관리형) — 브로커+결과 백엔드.
- WS: 단일 API 프로세스면 in-memory 소켓으로 충분. 리포트 진행 emit(Celery 워커→API)은 프로세스 경계가 있으므로 **Redis pub/sub 1채널 추가**(초기엔 폴링 대체 가능).
- 확장 트리거(1000+ 또는 API 다중 프로세스 전환): WS Redis manager + 오디오 S3 전환 도입.

### #5 발행 유실 복구
- **파이프라인 발행 아웃박스 채택.** 종료 상태 전이와 **같은 트랜잭션**에서 발행 의도를 durable 기록 → 발행 성공 시 마킹, 미발행 건은 celery beat가 주기 재발행. 아웃박스 행이 **멱등키 겸용** → 중복 리포트 방지.
- 101-4 워치독은 MVP 생략이므로 발행 유실 복구를 이 아웃박스가 담당. `NotificationOutbox`(알림용)와 별도 sibling 테이블.
