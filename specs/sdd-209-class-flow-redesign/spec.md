# SDD-209 — 클래스 사전·사후 흐름 리디자인 (생성·입장·사전 확인·대기·로비·종료 · 회원/상담사 · 모바일/태블릿/데스크톱)

> **2026-10-17 R4·R5 통합:** 정책 정본은 [policy-revision-r4.md](policy-revision-r4.md)(R5 개정 포함)이며, 이 spec의 확정 결정·범위는 R4·R5에 맞게 갱신했다(기본 DB 기간 삭제 + 연구 동의 건 연구 DB 영구 누적·리포트 제외 선택·유예 없음·밴드 없이 참가·로그인 없는 4자리 입장 후 개인정보 입력·비회원 리포트 메일 자동 발송·서버 대기 취소·플랫폼 관리자만 삭제). plan·verify 가 R4·R5 통합본이다.

## 목적
SDD-208로 클래스 **진행 화면**이 새 디자인(다크 소프트 시트 + 자연 배경)으로 바뀌었으나, 그 앞뒤 흐름(클래스 생성·입장·사전 확인·대기·세팅·로비·종료)은 구형 UI다. 톤이 4번 바뀌고, 모바일 대기실은 1,000px 넘게 스크롤되고, 핵심 CTA가 헤더에 숨고, 6자리 코드·게스트 OTP 중심의 옛 입장 모델이 남아 있다. **로그인 없는 4자리 코드 입장(비회원 개인정보 입력)과 초대 회원 편의 경로**를 함께 지원하도록 흐름을 단순화하고 진행 화면과 같은 디자인 언어로 통일한다.

## 확정 결정 (2026-10-17, Brian — 시안 리뷰 R1~R3)
1. **로그인 없이 클래스 공통 4자리 숫자 코드로 입장한다(R4·R5).** 상담사가 비회원 이메일로 초대하면 메일에 4자리 코드가 들어 있고, 비회원은 입장 화면에서 코드 입력 → **개인정보(이름·성별·생년월일·이메일) 입력 후 입장**한다. 서버가 참여자별 입장 자격을 발급한다. 가입·로그인·초대 행·이메일 OTP는 요구하지 않는다. **종료 후 리포트는 입력한 이메일로 자동 발송**한다(기존 Celery `email_app` 경로). 코드 노출 위험은 수용하고 시도 제한·종료 즉시 무효화만 둔다(입장 승인·재발급은 후속).
2. **LINK BAND는 이마에만 착용**("귀 뒤" 문구 삭제). 기존 `SensorTracker`(L·기준·R 전극 LED, **색만 — v/x 아이콘 없음**)를 접촉 불량일 때만 띄워 어느 전극이 안 닿는지 보여준다.
3. 카메라 영상이 있으면 **영상+음성을 하나의 "내 영상·소리" 컴포넌트**로 합친다. 마이크 레벨은 **아이콘 미터**(마이크 토글 둘레 5단계 링 + 아이콘 밝기, 칩 `정상`/`조용해요`). 카메라 없이 마이크만이면 가로 막대 유지.
4. **소요 시간 5분 단위**(최소 5분 스텝퍼 + 칩), 예약 시작 시각도 5분 단위.
5. **상담사는 준비 안 된 회원이 있어도, 대기실이 비어 있어도(초대 0명 포함) 시작할 수 있다.** 시작 확인 시트에 준비 중 회원(이름·미완 단계)을 보여준다. 시작 후에도 초대 회원이 입장해 준비를 이어서 한다. 회원이 준비 단계에 있을 때 시작되면 `지금 입장하기` / `준비 이어서 하기` 시트.
6. 화면 유형: **몰입형**(입장 확인·사전 확인 마법사·시작 대기·종료·생성 마법사·세팅·로비·시작/종료 확인·닫힘·오류)은 앱 셸 없이 자연 배경 + 중앙 컬럼. **셸형**(회원 홈·목록·상세, 상담사 목록·상세)은 기존 앱 셸(라이트) 유지 + 클래스 카드·칩·버튼·시트를 진행 화면 언어로 교체.
7. **용어 통일**: 클래스(세션·수업 금지) / 회원 `입장하기` / 상담사 `클래스 열기`→`시작하기` / `나가기`(화면만 이탈) vs `클래스 닫기`(회원 전원 퇴장·확인 필요) / 해요체 / 영문 대문자 아이브로우 금지 / `LINK BAND 사용 안 함·선택·필수`(필수 설정이어도 참가자 안내는 `LINK BAND 사용을 권장해요. 없어도 참가할 수 있어요`), `1:1·그룹`.
8. 입장 전 **고지·리포트 반영 선택·연구 목적 데이터 활용 동의 단계(FM06a)**를 신설한다. 고지(녹음·AI 기록·뇌파·영상, 기록은 설정 기간 후 삭제), 리포트 반영 선택(기본 제외), 연구 동의(선택, 기본 미동의, 동의 시 비식별 데이터 무기한 보관 고지)를 서로 분리하며 어느 선택도 입장·수집을 막지 않는다(R4·R5). 상담사 **시작 전 확인 시트(FH07)**에서 녹음 시작을 확인하고 리포트 제외 인원(익명 수)을 본다.

## 범위
- **참가자(회원·비회원)**: FM01~FM03(홈·목록·상세, 입장 CTA 정합), FM04(4자리 코드 입장 + 개인정보 입력 — R4·R5 신규), FM05(입장 확인), FM06a~e(준비 마법사), FM07(시작 대기), FM08(대기열), FM09(종료·시트 2종), FM10(취소·오류·끊김·열리지 않음).
- **상담사**: FH01(목록, 열린 클래스 고정), FH02a~e(만들기 마법사, 즉시·예약 통합), FH03(생성 완료=초대 현황), FH04(상세), FH05(세팅), FH06(로비, 초대 현황·준비 현황), FH07(시작 확인 시트), FH08(나가기/닫기 확인), FH09(종료 확인·종료 씬·리포트 진행), FH10(닫힘·오류).
- 모든 화면 4개 뷰포트(390×844, 834×1194, 1194×834, 1280×720): 페이지 스크롤 0(셸형 목록 영역 내부 스크롤 제외), 12px 미만 글자 0, 터치 ≥44px, 균형 규칙, 이모지·문자 글리프 아이콘 0.

## 코드 조사로 결정할 항목 (plan에서 확정 — 기본값은 plan이 제안)
시안이 가정한 것들(기획.md §9): A1 고지 확인·리포트 반영 선택 저장(별도 필드, R4) / A2 예약 생성 시 방식(online/offline) 서버 저장(현행 notes 문자열 버그) / A3 시작 예정 시각 응답 / A4 대기열 안내 / A5 시작 판정(대기실 기준) / A6 초대 참여자 이름 표시(UUID 버그) / A7 6자리 입장·게스트 OTP를 4자리 공개 입장·입장 자격으로 같은 배포에서 교체(R4) / A10 연구 동의 저장·이력·철회(R5) / A11 기본 DB 기간 삭제 스위프(설정값·연구 ack 게이트·dry-run, R5) / A12 연구 DB 내보내기 배치(비식별 번들·암호화 ID·pull 전송, R5) / A13 비회원 이메일 초대·리포트 자동 발송(R5) / A14 정원 스텐퍼(온라인 그룹 최대 50, R5) / A8 전극별(L·기준·R) 접촉 상태 전송 / A9 준비 미완 회원의 시작 후 입장 / S6 알림 재전송·초대 추가 API. 각 항목에 대해 **현재 코드 상태(있음/일부/없음)·백엔드 변경 필요 여부·프론트 대체안**을 조사하고, 백엔드 변경은 마이그레이션 안전성(기존 세션의 access_code·게스트 참가자 데이터 보존)을 plan에 명시한다.

## 비범위
- 진행 중 화면(SDD-208 완료), 지표 산출 로직, LiveKit 연결 방식, MVP3 셀프 트레이닝, 푸시 알림 콘텐츠, 상담사 코드(상담사–회원 연결 코드, `S-M00`)는 입장 코드가 아니므로 유지.
- 기존 데이터(과거 세션의 access_code, 게스트 참가자, 원본 EEG·음성·영상)는 승인 없이 삭제하지 않는다. 기본 DB 기간 삭제 스위프는 비활성으로 배포하고 dry-run 보고·Brian 승인 후 활성화한다(R5). 구 6자리 입장은 유예 없이 교체한다(R4). 연구 DB(Spark) 실접속·데이터 전송은 이 SDD 의 문서 단계에서 하지 않는다.
