# SDD-209 정책 개정 R4 · R5 — 2026-10-17

> R4 정책 중 **보관 기간·표시 이름만 입장·비회원 리포트·원본 삭제 권한**은 같은 날 Brian 의 D-1~D-5 확정으로 **R5 에서 개정**됐다. 아래 R4 항목 1·5, 위임 결정, R4-1, RV1 은 R5 반영본으로 본문을 고쳤고, R5 의 근거·설계 전문은 문서 끝 `개정 R5` 섹션에 있다.

## 적용 범위와 우선순위
Brian의 이번 대화에서 확정한 정책이다. 이 문서는 spec·plan·verify 및 이전 시안/조사의 충돌하는 내용을 대체한다. 조사 문서는 당시 코드의 증거로 보존하며 최신 요구사항으로 해석하지 않는다. 제품 코드·DB·배포에는 아직 적용하지 않았다. 기존 구현 전 verify 승인이 있었다고 간주하지 않는다. 아래 작업 계약을 기존 plan/verify에 통합하고 변경된 시안 케이스를 확인한 뒤 구현한다.

## 확정 정책
1. **원본 보관 (R5 개정)**: EEG·음성·영상 원본은 **기본 DB(운영 PostgreSQL·S3)에서 설정 기간이 지나면 삭제**한다(기간 값은 설정값). 기간 경과·리포트 제외 선택·클래스 종료 **그 자체로 즉시** 삭제하지 않고 정기 스위프가 기간 경과분만 삭제한다. **연구 목적 데이터 활용에 동의한 참여자의 비식별 데이터는 삭제 전에 연구 DB(영구 보관소)로 내보내 확인(ack)된 뒤에만** 기본 DB 사본을 삭제한다. 기간 전 삭제 권한은 **플랫폼 관리자만**이며 대상·실행자·시각·사유를 기록한다. 이 정책은 수집된 원본에 대한 것이며 장비 미사용·녹화 OFF 에서 없는 데이터를 만들라는 뜻이 아니다. (이전 R4: 무기한 보존 — 폐기)
2. **리포트 제외**: 기존 FM06a의 거부는 원본 수집/보존 중지가 아니라 해당 참여자의 리포트 반영 제외를 의미한다. 수집·보존 고지와 리포트 반영 선택을 분리한다. 거부해도 입장·녹음·영상·착용 시 EEG 업로드를 막지 않는다. 상담사용/회원용 리포트, 화면·PDF·메일·AI 입력·그룹 집계·캐시에서 동일하게 제외한다. 식별 불가능한 그룹 공통 녹음은 비동의 참여자 기여분을 분리할 수 있을 때까지 해당 원본에서 파생한 공통 요약을 리포트에 넣지 않는다. 원본은 그대로 보존한다.
3. **전환 유예 없음**: 신규 서비스이므로 8주 유예·구 앱 사용률 조사·유예 후 별도 배포를 폐기한다. 6자리 구 입장 방식은 새 4자리 방식과 같은 배포에서 교체한다. 기존 테스트 데이터는 승인 없이 삭제하지 않는다.
4. **밴드 없이 참가 가능**: 클래스 설정이 필수여도 연결·착용·브라우저 지원 여부로 입장/준비 완료를 차단하지 않는다. 시작 전/후 모두 `LINK BAND 없이 계속하기`를 제공한다. 필수 설정의 회원 안내는 `LINK BAND 사용을 권장해요. 없어도 참가할 수 있어요`로 고쳐 강제 조건처럼 표현하지 않는다. EEG 미수집은 0점이 아닌 미측정이다.
5. **로그인 없는 4자리 입장 (R5 개정)**: 클래스별 공통 숫자 코드 정확히 4자리로 비회원도 입장한다. 선행 0을 보존하는 문자열이다. 코드 소지만으로 입장하며 계정·초대 명단 대조를 요구하지 않는다. 따라서 `초대 회원만 입장`이라는 이전 서버 계약은 폐기한다. 별도 회원가입·이메일 OTP 없이, **코드 확인 뒤 개인정보(이름·성별·생년월일·이메일)를 입력하고 입장**한다(이전 R4 의 `표시 이름만`은 R5 에서 개정). 상담사가 비회원 이메일로 초대하면 메일에 4자리 코드가 들어 있다. 종료 후 리포트는 입력한 이메일로 자동 발송한다. 로그인 회원도 같은 코드로 입장할 수 있고 개인정보는 계정 값으로 채운다. 코드 검증 성공 후 서버가 해당 클래스/참여자 범위의 만료 가능한 입장 자격을 발급하고 이후 상태·미디어·WS·리포트 선택은 이 자격으로 소유권 검증한다. 코드 자체는 이후 요청의 상시 인증 토큰으로 쓰지 않는다.
6. **대기 취소**: `대기 그만하기` 대신 `대기 취소`. 서버 대기열에서도 실제 제외하며 자동 승격 대상에서 빠진다. 화면 닫기와 구분한다. 표시 이름·리포트 선택·초대/접근 이력을 지우기 위한 participant 행 삭제는 하지 않는다. 다시 대기하면 새 순번으로 끝에 등록한다.
7. **알림 정합**: 초대 등록 성공과 채널 발송/전달 성공을 구분한다. 확인되지 않은 전달·수신은 성공이라고 표시하지 않는다. 기본 문구는 `초대했어요`; 재발송은 실제 요청 결과를 표시하고 푸시 수신을 약속하지 않는다.

## 위임받은 기술 결정
- 이름/호스트 DTO와 타인 개인정보 차단(BE-4), 회원 상태(BE-7), 전극·준비 상태 중계(BE-9), 알림 재발송(BE-10), 선택 증빙·입장 시각(BE-11), 익명 집계(BE-13), 대기열 정합(BE-14), 삭제 상태 가드(BE-16)를 포함한다. 레거시 예약 백필(BE-17)은 제외한다. 신규 서비스이므로 구 API 폴백은 넣지 않는다.
- 4자리 코드: 활성/입장 가능한 클래스 사이 중복 없이 발급하고 종료/취소 클래스 코드는 무효화한다. 코드 공간 소진은 명시적 오류로 처리한다. 코드/IP 단위와 전체 유입에 반복 시도 제한을 적용한다. 없는 코드·틀린 코드·종료 코드의 공개 응답에는 회원 목록·클래스 상세를 노출하지 않는다. 코드 검증 전 회원/이메일/동의 상태를 공개하지 않는다. 코드 원문을 로그에 기록하지 않는다.
- 비회원 복귀는 입장 자격으로 본인 참여자에만 복귀한다. 브라우저를 새로 열어 같은 이름을 적었다는 이유로 기존 참여자를 인계하지 않는다. 리포트 제외 선택은 기본 제외에서 시작하며 명시 선택 시에만 포함한다. 로그인 여부에 관계없이 적용한다.
- 리포트 선택은 `report_included` 등 별도 필드로 저장한다. 기존 `consent_audio/eeg`를 의미만 바꿔 재사용하지 않는다. 영상도 같은 리포트 선택에 포함한다. 고지 확인/버전/시각과 리포트 선택/변경 이력을 분리하고 관련 컬럼·마이그레이션 수는 실제 모델 검토 후 확정한다. 기존의 `nullable 3컬럼만` 제한은 폐기한다.
- 보관·삭제 (R5 개정): 기본 DB 삭제는 **기존 스위프(`sweep_stale_media`·`sweep_stale_eeg_raw`)를 설정값 기반으로 재사용**하고 기준일을 세션 종료일로 통일한다. 고아 파일 정리·클래스/사용자 삭제·처리 후 청크 제거·스토리지 lifecycle 은 이 스위프와 모순되지 않는지 점검한다. 원본과 재생성 가능한 임시파일을 구분한다. 일반 클래스 삭제/탈퇴는 즉시 하드 삭제가 아니라 숨김(보존 전환)으로 처리해 원본 참조가 CASCADE 로 사라지지 않게 하고, 실제 삭제는 스위프(기간 경과) 또는 플랫폼 관리자 지시로만 한다. **연구 동의 건은 연구 DB ack 전에는 스위프가 삭제하지 않는다(보류).** 보관 기간 상수만 바꾸는 방식은 금지하며 최초 활성화는 dry-run 보고 후 승인으로 한다(기존 테스트 데이터 승인 없이 삭제 금지).
- 리포트 제외 선택 변경 시 이미 생성된 리포트/집계/캐시를 무효화하고 재생성한다. 이미 외부 발송·다운로드된 사본은 회수할 수 없다는 한계를 안내한다. 데이터 내보내기 권한을 리포트 선택 플래그와 혼용하지 않는다.
- 그 외 이전 D6/D8/D10/D13/D15/D16은 이번 요청에서 일괄 승인된 것으로 간주하지 않고 기존 제안 상태로 둔다. D9는 4자리 코드 표시/공유로 전환하므로 코드 박스 전면 제거안을 폐기한다. 기존 D12의 AD1~14 전체 묶음 승인도 폐기하고 아래 검증 기준으로 재작성한다.

## 추가·수정 구현 작업
- R4-0: spec/plan/verify/기획/시안의 회원 전용·코드 제거·수동 기록·기간 고지·필수 밴드 게이트·로컬 대기 이탈 문구를 정합화한다. 기존 205 케이스는 기준선이며 개정 후 케이스 수를 다시 산출한다.
- R4-1 (R5 개정): 보관 설정과 모든 삭제 경로 조사, 기본 DB 기간 삭제 스위프(연구 동의 건 ack 게이트·dry-run), 일반 삭제의 보존 전환, 플랫폼 관리자 전용 삭제와 감사 계약. 연구 동의·연구 DB 내보내기는 R5-A~D 참조.
- R4-2: 리포트 선택 모델/API·변경 이력, 수집 권한 분리, 업로드 게이트 수정, 모든 리포트 생성/조회/발송/캐시 경로 필터.
- R4-3: 4자리 코드 생성/교체/검증·시도 제한, 공개 입장 화면(코드 확인 → 개인정보 입력, R5), 비회원 자격 발급/만료/복귀, REST·WS·LiveKit·EEG 소유권 통합. 호스트 권한과 분리.
- R4-4: 대기 취소 API(본인만·멱등), 참가자 상태 필드, 잠금 아래 취소/승격 경합 처리, 순번 재정렬·이벤트/집계·재대기. 취소 이후 자동승격/토큰 발급 거부.
- R4-5: 밴드 필수 게이트 제거, 초대/상세/진행 도구의 4자리 코드 표시·공유, 로그인 없는 입장·리포트 제외 UI·실시간 호스트 표시.
- R4-6: 기존 B5의 게스트 차단을 폐기하고 6자리 경로 교체로 대체. 구 API 폴백·8주 대기·호환 분기 제거. 단 공개 경로의 권한 검증은 완화하지 않는다.
- R4-7: 기존 공용/회원/상담사/셸형 트랙과 통합, 테스트·시안 측정·dev 검증·summary. 보관 정책은 백엔드/설정/스토리지까지 검증하기 전 완료로 보고하지 않는다.

## 구현 전 검증 계약 (기존 verify의 충돌 행을 대체)
- RV1 (R5 개정): 기간 경과분만 기본 DB 에서 삭제되고 미경과분 바이트·DB 참조는 유지된다. 연구 동의 건은 ack 전 보류, ack 후 삭제, 거부·철회 건은 연구 DB 미적재. 기간 전 삭제는 플랫폼 관리자만(감사 기록), 일반 삭제·탈퇴는 숨김 전환. 최초 활성화 dry-run·실제 스토리지 lifecycle 읽기 확인. 연구 동의 화면·비식별 검사·내보내기는 verify RV8.
- RV2: 리포트 제외 참여자가 코드 입장·미디어 송수신·밴드 업로드 가능하고 원본이 보존된다. 해당 참여자의 텍스트·지표·영상·집계 기여분이 상담사/회원 리포트·PDF·메일·AI 생성 입력에 나타나지 않는다. 혼합 녹음 분리 불가 시 공통 파생 요약도 비노출. 선택 변경 전 생성물과 캐시도 재검증한다.
- RV3: 0000 등 선행 0 코드 정상, 3/5자리·문자·틀린 코드 거부. 로그인/초대 행 없이 코드 확인 후 개인정보(이름·성별·생년월일·이메일) 입력으로 입장 가능(R5). 동시 코드 발급 충돌·공간 소진·반복 시도 제한·종료 코드 무효화 검증. 참가자 자격으로 타인/다른 클래스 REST·WS·토큰·EEG 접근 불가, 로그아웃/만료·재접속도 검증한다.
- RV4: 밴드 required/optional/none × 연결/미연결/미지원 × 시작 전/후 모든 조합에서 참가 가능. 미측정 데이터를 점수 0으로 만들지 않는다.
- RV5: 대기 취소 후 새로고침·다른 호스트 화면·정원 증가·승격 작업에서도 취소자가 제외된다. 취소와 승격 동시 실행은 잠금 순서에 따라 일관된 응답, 취소 완료 후 재승격 없음. 재대기 순번은 마지막. 타인 취소 거부·중복 취소 멱등·활성 참가자 취소 요청은 대기 취소로 처리하지 않는다.
- RV6: 초대 등록 성공+발송 실패·발송 요청 성공+전달 미확인·재시도·채널 미지원에서 성공 문구를 과장하지 않는다.
- RV7: 새 4자리 경로 배포 즉시 사용, 유예/구 코드 폴백 없음. 기존 테스트 데이터 비삭제. 변경된 시안 케이스 전수×4뷰포트와 SDD-208 회귀, 백엔드/프론트 테스트·타입·빌드·실기기를 확인한다.

## 남은 확인
- 코드 규칙과 기존 DB unique 제약, 비회원 자격·WS 경로의 재사용 가능 범위, 리포트의 참여자별 기여분 분리 가능성, 원본 삭제/외부 lifecycle 실제 경로는 구현 전 코드 조사로 확정한다.
- D6 종료 화면(같은 화면 리포트)·D13③ 캘린더 제거는 R5 에서 확정됐고(독립 커밋), D8① 정원 10 고정은 철회되어 정원 스텐퍼로 대체됐다(R5-E). 이번 위임은 백엔드 권장 항목·문서 오류에 대한 위임이다.
- 이번 산출물은 정책 반영 및 구현 계약이다. 코드 구현·커밋·푸시·배포·데이터 삭제는 수행하지 않는다.

## R5-A 비회원 입장·메일 (D-1·D-4)

**흐름**: 상담사 클래스 생성/상세에서 비회원 이메일 목록 입력 → 서버가 초대 메일 발송을 큐에 등록(메일 본문: 클래스 제목·시작 시각·4자리 코드·`/join` 안내, **코드는 URL 에 싣지 않음**) → 비회원이 `/join` 에서 코드 입력(FM04) → 코드 확인 성공 시 클래스 요약(제목·시각·진행자) → **개인정보 입력(FM04b: 이름·성별·생년월일·이메일, 기존 게스트 입력 항목과 동일)** → 입장 자격 발급 → 사전 확인 마법사(고지·리포트 선택·연구 동의 FM06a) → … → 종료 → 리포트 자동 발송.

- API: `POST /sessions/enter/verify`(코드만, 시도 제한 적용, 클래스 요약만 반환 — 회원 목록·상세 비노출), `POST /sessions/enter`(코드+프로필, 자격 발급). 코드는 프론트 메모리에만 두고 URL·저장소에 두지 않는다. 로그인 회원은 계정 정보로 채워 확인만 한다.
- 이메일 OTP 는 하지 않는다. 대신 **형식 검증 + 확인용 재입력 1회**로 오타를 줄이고, 발송 실패(반송·거부)는 상담사 화면에 표시한다. 본인 확인 없이 입력 주소로 보내므로 **오발송 가능성은 수용된 잔여 위험**이다(리포트에 개인 정보가 있음을 고지).
- 발송 경로: 기존 `report_email_service` → Celery `email_app`(큐 `email`, systemd `mindbreeze-email-worker`) 재사용. 워커 미기동 시 발송이 쌓이므로 배포 확인 항목에 포함한다. 초대 메일도 같은 경로. `email_verified` 를 OTP 대신 `입장 시 입력값` 으로 두는 변경은 `report_email_service.py` 에 한정한다.
- 리포트 제외 선택자는 발송할 내용이 없으므로 자동 발송 대상에서 제외한다(R4 정책 2 유지). 리포트 승인 정책(상담사 승인 후 발송)은 현행을 유지하며 승인 완료 시점에 자동 발송한다.
- 초대 메일 등록 성공과 실제 전달은 구분한다(큐 등록 ≠ 전달 확인). 문구는 `메일 발송을 요청했어요`/`발송하지 못했어요`.
- D-4: 코드 공유 시 누구나 입장할 수 있는 위험을 수용한다. 구현은 시도 제한(코드·IP·전체)과 종료·취소 시 즉시 무효화만. 입장 승인·코드 재발급은 후속 SDD 로 남기고, 상담사 화면에 `코드는 참가자에게만 전달하세요` 안내를 둔다.

## R5-B 원본 삭제 권한 (D-2)

플랫폼 관리자(`admin` 역할)만 기간 전 원본 삭제와 연구 DB 삭제 요청을 실행한다. 상담사·기관 관리자는 거부(403). 지시마다 대상·실행자·시각·사유를 감사 기록한다. 참가자 요청은 운영 문의로 접수해 플랫폼 관리자가 처리한다.

### C3 연구 동의 화면과 이력
- 위치: FM06a(입장 전 동의 단계)의 **고지·리포트 반영 선택과 분리된 별도 블록·별도 체크**. 기본 미체크, **거부·미응답이어도 클래스 참여·녹음·EEG 업로드는 막지 않는다**.
- 필수 고지: ① 기록은 N일 후 삭제된다 ② 연구 동의 시 비식별 데이터가 **삭제 기한 없이 계속(무기한) 보관**된다 ③ 보관 항목(아래 C4) ④ 철회는 운영팀 요청 ⑤ 비식별이라도 **사후 재식별 위험이 0 이 아님**.
- 저장: 현재 상태 `research_consents`(참여자별 1행) + 불변 이력 `research_consent_events`(동의·변경·철회, 문구 버전·시각·주체). 리포트 반영 선택과 고지 확인 증빙과 **서로 다른 저장소**. 종료 전까지 변경 가능, 종료 후 변경은 플랫폼 관리자 철회 경로만.
- 동의 상태는 참가자 본인과 플랫폼 관리자만 조회한다(상담사에게는 익명 수만).

### C5 암호화 ID 방식
- `research_subject_id = HMAC-SHA256(K[v], NFC(trim(이름)) + "|" + 생년월일)` — **지속키 기반 결정적 단방향**이라 같은 사람이 다른 세션·클래스에서 같은 ID 로 누적 매핑된다. 이름 원문은 복원할 수 없다(복원이 필요하면 별도 가역 암호화 결정 필요).
- 키 `K[v]`: 운영 서버 `.env`(권한 600, 값 출력·로깅 금지)에 `RESEARCH_ID_KEY_V1`, 버전 번호 `key_version` 을 번들·동의 행에 기록. **Spark 에는 키를 보내지 않는다.** 키 오프라인 백업 1부 필수 — 분실하면 이후 동일인 매핑이 끊긴다. 키 교체는 전체 재계산이 필요하므로 버전 관리만 하고 정기 교체는 하지 않는다.
- 회원·비회원 모두 같은 공식(이름+생년월일). 동명이인·생년월일 동일 충돌은 낮은 확률로 수용(연구용 ID 이므로 계정 연결 목적 아님).

### C6 내보내기 경로 — 네트워크 조사와 제안
Spark 는 `kccs@192.168.45.149`(**사설 LAN 주소**)라 AWS 운영 EC2(18.183.86.88)에서 직접 라우팅되지 않아 운영→Spark 직접 접속이 불가하다(실제 접속 시험은 하지 않음). SSH 는 일반 ssh 만 허용(tailscale ssh 금지)이다.
| 방식 | 구조 | 평가 |
|---|---|---|
| **A. Pull(권장)** | 운영이 비식별 번들을 S3 스테이징 prefix(`research-export/`, SSE 암호화, 현 단일 버킷의 별도 prefix)에 올림 → Spark 가 LAN 안에서 **아웃바운드 HTTPS** 로 주기 당김(systemd timer, 읽기 전용 IAM 사용자·prefix 제한) → sha256 검증·적재 → `ack` 를 운영 API(서비스 토큰)로 회신 | 인바운드 포트·SSH·VPN 불필요, 장애 시 번들이 S3 에 남아 재시도 가능. Spark 에 읽기 전용 키 보관 필요 |
| B. Push via Cloudflare Tunnel | Spark 에 수신 API 를 터널+Access 서비스 토큰으로 노출, 운영이 push | 인바운드 없음이나 공개 호스트명·수신 서버 운영 부담 |
| C. 운영 EC2 를 VPN(tailnet)에 가입 | 운영→Spark 사설 통신 | 운영 서버 변경·접근면 확대, 별도 승인 필요 — 비권장 |
| D. 일반 ssh/rsync push | EC2→Spark ssh | LAN 주소 라 불가(포트포워딩·VPN 없이는 도달 안 함) — 비권장 |
- **권장 A.** 번들 = Parquet(데이터 종류별) + `manifest.json`(batch_id·세션 가명·`key_version`·행 수·파일별 sha256·바이트) — 비식별 필드만 포함하는 **스키마 허용 목록** 검증을 통과해야 업로드. 인증: 운영→S3 는 전용 IAM(해당 prefix 쓰기), Spark→S3 는 읽기 전용 IAM, ack 는 서비스 토큰 + batch_id 일치 + sha256 확인. 전송 중 TLS, S3 SSE.
- 누적: 연구 DB 는 append-only. 같은 세션·참여자 재내보내기는 새 batch(`revision`) 로 추가하고 기존 행을 덮어쓰지 않는다(중복은 내용 해시로 제거).

### C7 전송 시점
- **세션 종료 후 배치**: 세션 `completed` + EEG 지표 처리 완료 + 연구 동의 참여자 존재 시 내보내기 작업(Celery `exports` 큐 계열)이 번들 생성·업로드.
- **삭제 전 배치**: 삭제 스위프가 연구 동의 건의 미적재·미ack 분량을 발견하면 먼저 내보내기 큐에 넣고 그 건을 보류(ack 후 다음 스위프에서 삭제). 보류가 임계(제안 14일)를 넘으면 운영 알림.
- 종료 전 중도 이탈자도 그때까지 수집분은 종료 후 배치 대상.

### C8 동의 철회
- 요청 창구: 운영 문의 → **플랫폼 관리자만** 실행. 요청자는 이름·생년월일을 제시하고, 운영이 `research_subject_id` 를 재계산해 `research_consents` 의 가명 해시와 대조한다(기본 DB 개인정보가 이미 삭제됐어도 가명 해시가 남아 있어 식별 가능).
- 처리: ① 동의 이력 이벤트로 `withdrawn` 기록 ② 미전송 건 내보내기 제외·기본 DB 사본은 정책대로 삭제 ③ 연구 DB 삭제 요청 레코드(`research_withdrawal_requests`) 생성 → Spark 측 삭제 실행·확인 시각 기록. 연구 DB 의 실제 삭제 절차는 Spark 운영 스크립트(가명 ID 기준)로 별도 수행하며 이 SDD 범위 밖.
- 한계 고지: 이미 논문·모델 등에 쓰인 결과는 회수할 수 없다. 철회 이후 새로 수집되는 데이터는 적재하지 않는다.

### C9 사후 재식별 위험 고지
성별·생년월일의 조합과 상대 시각·세션 유형은 외부 정보와 결합하면 본인을 추정할 수 있다. 이름 가명 처리는 키가 유출되면 무력화된다. 화면 고지에 `비식별 처리해도 다른 정보와 결합하면 본인을 알아볼 가능성이 완전히 없지는 않아요`를 포함하고, 개인정보처리방침 갱신(출시 전 완료)에 포함한다. 완화안: 생년월일을 연령대로 일반화(plan 결정 N-4, 기본은 Brian 확정대로 생년월일 유지).
