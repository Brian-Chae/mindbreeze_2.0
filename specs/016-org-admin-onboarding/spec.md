# [SDD-016] 기관 담당자 온보딩 — 초기 인입 절차 정립 (초대 토큰 방식, 승인본)

## 1. 배경

기관이 서비스에 최초 진입하는 절차를 정립한다. 멀티에이전트 리뷰 반영 결과,
**임시 비밀번호 이메일 전송 대신 초대 토큰 방식**을 채택했다 (보안 우수 + 기존 비밀번호 재설정 메커니즘 재사용).

## 2. 초기 인입 절차

```
① system_admin(어드민 웹)이 기관 등록
     - 기관 정보: 이름 · 주소 · 전화번호
     - 주 담당자 정보: 이름 · 이메일 · 전화번호
② org_admin 계정 생성 + 초대 토큰 발급 (7일 만료, 일회용)
③ 담당자 이메일로 "비밀번호 설정 링크" 전송
④ 담당자 링크 클릭 → 최초 비밀번호 설정 → 계정 활성화
⑤ 이후 이메일+비밀번호 로그인 → 기관 대시보드(/dashboard/org)
```

## 3. 데이터 모델

| 대상 | 변경 |
|------|------|
| `Organization` | `primary_admin_id: UUID|null` 추가 (주 담당자 User 참조. 담당자 정보는 User가 진실원) |
| `User` | org_admin 계정은 기존 role="org_admin" + org_id 로 표현 (신규 필드 불필요) |
| 초대 토큰 | 기존 `password_reset_service`의 토큰 메커니즘을 재사용 (별도 테이블 최소화) |

## 4. API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/api/v1/admin/orgs` | 확장: 기관 + 주 담당자(이름/이메일/전화) → org_admin User 생성 + 초대 토큰 발급 + 이메일 발송. 이메일 중복 시 409 |
| POST | `/api/v1/admin/orgs/{org_id}/resend-invite` | 초대 토큰 재발급 + 재전송 (레이트 리밋) |
| POST | `/api/v1/auth/set-password` | 초대 토큰으로 최초 비밀번호 설정 (계정 활성화) |
| (기존) | `/api/v1/auth/login` | org_admin 로그인 (변경 없음) |

## 5. 상담사 기관 소속 필수

- **모든 상담사(counselor)는 org_id 필수** — 기관 코드 가입만 허용
- **레거시 `/api/v1/auth/register`(하위 호환 회원가입)의 counselor 경로를 차단** — 이 경로로 기관 없이 가입 불가하도록 수정
- 기존 미소속 상담사(freelance 등)는 보관 상태 유지 (신규 가입만 차단)

## 6. 프론트

| 화면 | 변경 |
|------|------|
| 메인 랜딩페이지 | "무료체험" 버튼 → "기관로그인" 버튼 교체 (기관 담당자 로그인 진입) |
| 어드민 기관 등록 | 담당자 정보 입력 + 초대 발송 + 발송 성공 패널(기관코드 + 담당자 계정 나란히 표시) |
| 비밀번호 설정 | 초대 토큰 링크로 진입하는 최초 비밀번호 설정 화면 |
| 담당자 대시보드 | 상단에 "상담사 초대용 기관 코드" 카드 |

## 7. 보안 (리뷰 반영)

- 초대 토큰: 일회용, 7일 만료, 원문 DB 저장 금지(해시만)
- 이메일 디버그 로깅에서 토큰/비밀번호 **마스킹 필수**
- 이메일 중복 등록은 409 거부 (자동 병합·승격 금지)

## 8. 검증 기준

1. 어드민 등록 → org_admin 계정 + 초대 토큰 + 이메일 발송
2. 초대 링크로 비밀번호 설정 → 계정 활성화 → 기관 대시보드 진입
3. 초대 토큰 재사용/만료 시 거부
4. 레거시 register로 상담사 기관 없이 가입 불가
5. 랜딩 "기관로그인" 버튼 동작
6. 백엔드 테스트 회귀 없음 (141 passed 유지)
