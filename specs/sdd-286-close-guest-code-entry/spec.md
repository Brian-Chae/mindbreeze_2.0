# SDD-286 — 비회원 코드 입장 버튼 숨김 (로그인 화면, 운영 빌드)

- 상태: Stage ① Spec **개정 3판** (대표 지시 11/4: 서버 스위치안 폐기 → 로그인 화면 버튼 숨김, 범위 축소)
- 브랜치: `sdd/286-close-guest-code-entry`
- 관련: SDD-282(11/4 유실 원인), SDD-284(iOS), SDD-285(안드로이드·서버), 후속 제안 SDD-287(비회원 동일인 연장)

## 0. 먼저 읽을 것 — 앱 안에 버튼 외 비회원 입구가 있는가 (코드 전수 확인 결과)

**결론: 없음.** 대표 가정("버튼만 없애면 앱 안에서 비회원으로 들어가는 경로가 없다")은 코드상 **성립한다.** 단, 아래 한 가지 조건이 붙는다.

- 조건: 이 결론은 **네이티브 앱(Android·iOS)** 기준이다. 네이티브 앱은 랜딩 페이지가 없고(`App.tsx:136~139` `EntryRoute`: `isNativeApp()`이면 `RoleRouter`→`/login`) 딥링크도 없다. **웹 브라우저**에는 랜딩·기관 페이지에 `/join` 링크가 따로 있으나(`Nav.tsx:33`, `LandingV6Chrome.tsx:17`, `OrgPublicPage.tsx:257`) 대표 지시로 이번 범위에서 제외한다.
- 근거 표는 `analysis.md` §10-1 (화면 흐름 12곳, 파일:줄).

## 1. 배경

11/4 행사에서 안드로이드 권한 문제로 다수가 태블릿으로 회원가입 없이 코드로 입장(비회원)했다. 참가자 40명 = 회원 24 + 비회원 16명이고, 비회원 참여 행 39개는 16명이 여러 번 입장한 결과다(재입장마다 새 행 → 정원 50을 51행이 채움, SDD-282 F3·F4). 행사 참가자는 모두 최신 버전을 받아 사용한다.

## 2. 대표 지시 (11/4)

- 비회원 코드 입장을 서버 기능으로 막지 않는다.
- **로그인 화면의 "로그인 없이 코드로 입장" 버튼(`LoginPage.tsx:286~298`)만 운영(prod)에서 숨긴다.** 랜딩·기관 페이지·`/join` 리다이렉트 등 다른 경로는 이번 범위에서 제외한다.
- 기능 코드는 삭제하지 않는다. dev에서는 계속 개발·안정화한다.
- 비회원 중복 입장(동일인 연장)은 별도 후속 SDD-287(dev 개발).

## 3. 해결할 문제 / 범위

- 포함: 운영 빌드 로그인 화면(회원 탭)에서 비회원 코드 입장 카드를 렌더링하지 않는다. 카드 높이용 하단 여백(`LoginPage.tsx:253`)도 함께 제거한다.
- 포함: 환경별 화면 플래그 1개(기본 숨김, dev 표시).
- 제외: 서버 변경, DB 변경, 랜딩/기관 페이지/`/join` 라우트 처리, 메일 문구, 구버전 앱 대응.
- 유지: 로그인 회원의 코드 입장(`/join`, 회원 홈의 `CodeEntryButton`)은 그대로.

## 4. 설계 요약 (상세 `plan.md`)

- 플래그: `isGuestEntryEnabled()` = `VITE_GUEST_ENTRY_ENABLED === 'true'` (`lib/feature-flags.ts`의 `isCounselingEnabled`와 같은 관례, 기본 false=숨김).
- 운영 빌드: `vite.config.ts` 운영 분기(`define`)에서 `false`로 **고정**(환경변수로 실수 활성화 불가, `VITE_LIVE_PROTOCOL_V2`와 같은 방식). dev 빌드: `deploy-dev.yml`·`cap:*:dev` 스크립트에서 `true` 주입.
- 서버·DB 변경 없음.

## 5. 한계

| # | 한계 | 대응 |
|---|------|------|
| L1 | 서버 API는 열려 있다: 주소·API를 아는 사람은 `POST /sessions/enter`로 비회원 입장 가능 | 운영 읽기 조회로 비회원 입장 건수 확인 가능(`analysis.md` §10-4, 건수만) |
| L2 | 서버 스위치가 없어 서버 쪽에서 즉시 차단은 못 한다 | 확장 여지: 서버 스위치 `GUEST_ENTRY_CLOSED`(폐기안, `analysis.md` §0~9·`plan.md` 폐기 절)를 나중에 추가 가능. DB 변경 없음 |
| L3 | 웹 브라우저에는 `/join` 링크가 랜딩·기관 페이지에 남는다(이번 범위 제외) | 필요 시 같은 플래그로 확장(`analysis.md` §10-2에 위치 기록) |

## 6. 성공 기준 (verify.md 구체화)

- 운영 빌드 로그인 화면에 `login-code-entry` 카드가 없다. dev 빌드(플래그 on)에는 있다.
- 로그인 회원의 코드 입장은 정상이다.
- `tsc -b` 통과, vitest 기준선(실패 23건) 동일, 운영 번들에 플래그가 `false`로 박혀 있다.

## 7. 제약

- 운영 쓰기·배포·푸시·메일·앱 빌드는 대표 승인 후. 운영 DB는 읽기 전용(건수만).

## 8. 대표 결정 필요

1. 비회원 입장 재개 시점(플래그 on 시점).
2. 웹 브라우저 랜딩·기관 페이지의 `/join` 링크를 같은 플래그로 함께 숨길지(L3).

## 폐기됨 (대표 지시 11/4) — 서버 스위치안

- 서버 전역 스위치 `GUEST_ENTRY_CLOSED`(+`hard` 모드)로 `POST /sessions/enter`·`/classes/{id}/guest-*`를 403으로 거부, `verify`에 `guest_entry_closed`, `CodeEntryPage`에 `signup-required` 안내 화면.
- 폐기 사유: 서버·DB 변경과 배포 위험을 줄이고, dev에서 기능을 계속 개발하기 위함. 상세 설계는 `analysis.md` §0~9에 보존(L2 확장 시 재사용).

## 폐기됨 — 개정 2판 범위 (대표 추가 지시 11/4 저녁)

- 랜딩/기관 페이지/`/join` 비로그인 리다이렉트/`/class-members` 처리와 "이미 설치된 앱에 버튼 잔존" 서술은 범위에서 뺐다.
