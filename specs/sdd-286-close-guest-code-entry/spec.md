# SDD-286 — 11/11 행사 대비 비회원 코드 입장 차단 (회원가입 필수)

- 상태: Stage ① Spec — 대표 지시로 착수 (11/4)
- 브랜치: `sdd/286-close-guest-code-entry`
- 작성일: 2026-11-04
- 기한: **11/10(화) 밤까지 운영 배포**. 행사 당일(11/11) 배포 금지.
- 관련: SDD-282(11/4 유실 원인), SDD-284(iOS), SDD-285(안드로이드·서버)

## 1. 배경

11/4 행사에서 안드로이드 권한 문제로 다수가 태블릿으로 **회원가입 없이 코드로 입장(비회원)** 했고, 비회원 39행 중 24행은 구조적으로 업로드가 막혔다(대기열 12, 뇌파 동의 거짓 12).
재입장마다 새 참여 행이 만들어져 정원 50을 51행이 채웠고, 이후 입장자가 대기열로 밀렸다(SDD-282 F3·F4).
대표 결정: 안드로이드·iOS 설치 문제가 해결됐으므로 **11/11 행사는 전원 회원가입 후에만 입장**한다. 비회원 코드 입장은 **닫는다**.

## 2. 해결할 문제

1. 클래스 회차에 **비회원(코드·이름만으로) 입장하는 경로를 차단**한다. 회원 로그인 없이는 입장·측정·업로드가 시작되지 않는다.
2. 차단 사실을 사용자가 이해할 수 있게 안내한다(회원가입·로그인 유도). 막다른 화면이 되지 않게 한다.
3. 기존 비회원 데이터·과거 회차 조회(리포트 등 읽기 경로)는 깨지지 않는다.

## 3. 범위

### 포함
- 입장 경로 전수 조사: 코드 입장(`access_code`), 비회원 입장 자격(entry credential), 초대 링크, 앱·웹(Android/iOS/PC) 각 입구
- 차단 방식 결정: 서버에서 회차 단위 또는 전역 스위치(예: 설정값)로 비회원 입장 거부 → 클라이언트는 회원가입/로그인 안내 표시
- 차단 시 사용자 문구와 화면(코드 입력 후 "회원가입이 필요해요" 등, 금지 표현 준수)
- 기존 진행 중·과거 비회원 회차의 데이터 읽기·리포트가 깨지지 않는지 회귀 확인
- dev 검증과 운영 배포 계획(되돌리기 쉬운 스위치형 선호)

### 제외
- 회원가입 UX 개선 자체(별도), 비회원 데이터 복구
- 운영 DB 쓰기·삭제
- 11/11 이후 정책(비회원 재개 여부는 대표가 별도 결정)

## 4. 성공 기준 (verify.md에서 구체화)

- 비회원이 코드만으로 입장 시도하면 **서버가 거부**하고(403/401 계열, 사유 코드 포함) 클라이언트가 가입 안내를 보여 준다. 우회 경로(직접 API 호출, 초대 링크, 오래된 앱 버전) 모두 막힌다.
- 회원 로그인 후 같은 코드로 입장하면 정상 입장한다(기존 SDD 회귀 포함).
- 과거 비회원 회차의 상세·리포트·업로드 현황 화면이 기존과 같이 열린다.
- 스위치를 끄면 이전 동작으로 되돌릴 수 있다(롤백 경로).

## 5. 제약

- 운영 DB 읽기 전용 확인, 쓰기·배포·푸시·메일은 대표 지시 후.
- 배포는 11/10 밤까지, 행사 당일 금지. 운영 배포 전 RDS 스냅샷.
- 구버전 앱(vc46 사이트 APK, TestFlight 39)이 차단 응답을 만나도 앱이 멈추지 않는지 확인(웹 번들 변경 위주, 앱 재빌드 지양).
- 금지 표현(점수·종합점수·좋음·나쁨·완료·보증·100% 단정)은 신규 화면에 쓰지 않는다.
- 개인정보는 건수만.

## 6. 대표 결정 필요

2. 비회원 입장 재개 시점과 조건
