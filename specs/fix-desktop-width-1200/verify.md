# [FIX] 데스크톱 넓은 화면 본문 폭 1200px 통일 — Verify (구현 전)

결정(Brian): 알림·설정·프로필(672px, 가운데)은 유지. 홈·리포트 등 넓은 화면 본문은 1200px·가운데·동일 시작선.
근거: ~/.hermes/share/width-audit/report.md (1920 기준 회원 목록·리포트 1600/x=280, 회원 상세 1280, 플레이그라운드 1152).

## 원인 분석
- 페이지마다 독립 max-width(1600/1280/6xl=1152/없음). 공용 PageFrame standard(max-w-mb-content=1200)를 일부만 사용.
- 홈 '내 클래스' 트랙: 데스크톱 카드 280px 고정 → 4개(1168px)가 1200을 못 채움.
- 스크롤 컨테이너(overflow-auto)에 scrollbar-gutter 없음 → 스크롤바 유무로 가운데 열 7.5px 이동.

## 범위
- 변경: 상담사/기관관리자/회원의 목록·대시보드형 본문(회원 목록·상세, 리포트 목록(+운영 설정), 플레이그라운드, 기관 대시보드, 관리자 목록들, 회원 리포트/클래스 목록).
- 제외(건드리지 않음): 채팅(전체 작업영역), 클래스 몰입 플레이어, 알림·설정·프로필(672), 리포트 본문 읽기(D3), 랜딩.

## 검증 시나리오
1. [계약] 대상 페이지 소스에 1600px/1280px/max-w-6xl 같은 독자 최대폭이 없고 mb-content(1200)를 쓴다. (vitest, RED→GREEN)
2. [계약] 알림·설정·프로필은 max-w-2xl 유지.
3. [계약] 홈 클래스 트랙 데스크톱 CSS에 카드 280px 고정이 없고 4등분 그리드를 쓴다.
4. [계약] 스크롤 컨테이너(.mobile-menu-swipe-page, .cs-structure-scroll)에 scrollbar-gutter: stable.
5. [실측] 로컬 빌드 + 합성 데이터, 1440/1920에서 본문 x·폭 측정 → 1920: x=480(±스크롤바), 폭 1200 / 1440: 가용폭.
6. [회귀] vitest 전체(기준선 17건/8파일 실패 외 신규 실패 0), tsc, eslint, build.
7. [시각] 전/후 캡처 비교 확인.
