## 목적

SDD-214가 만든 상위 구조(클래스·상담 관계)와 읽기 API 5종을 **화면에 드러낸다.** 사용자에게 "클래스(프로그램)"와 "회차(세션)"가 분리되어 보이게 하고, 기존 상담 기능이 사라지지 않도록 `상담` 메뉴를 임시 입구로 둔다. **편성(만들기·수정)은 아직 기존 마법사를 쓴다**(Phase 3).

## 범위 (포함)

### A. 상담사·지도사 웹
1. **사이드바 개편** (8항목): 홈 · **명상 클래스**(`/classes`) · **상담**(`/counseling`) · 채팅 · 리포트 · 플레이그라운드 · 알림 · 설정. 기관 관리자: 기관 대시보드 / 명상 클래스 / 상담 / 채팅 / **구성원** / 리포트 / 알림 / 설정.
2. **모바일 하단 탭**: 홈 · 클래스 · 상담 · 채팅 · 더보기. 리포트는 더보기로 이동, 승인 대기 배지는 더보기 아이콘에 합산. 배지 계산을 라벨 문자열이 아닌 **탭 키** 기준으로.
3. **클래스 목록** `/classes`: 한 행 = 클래스 + 다음 회차 + 진행률(`3/8`) + 진행 강사. 상단 "열린 세션" 카드 유지, 검색·필터, 모바일 카드.
4. **클래스 상세** `/classes/:classId`: 탭 `개요 · 회차 · 멤버/출석 · 리포트 · 설정`. Phase 2에서는 **개요·회차(타임라인)만 실데이터**, 나머지 탭은 읽기 전용 자리표시(Phase 3~5 예고, 동작 없음).
5. **회차(세션) 상세 축소** `/classes/:classId/sessions/:sessionId`: 코드·참여자·장소·기록·취소로 축소.
6. **상담 임시 입구** `/counseling`, `/counseling/:relationshipId`: 상담 관계 목록·상세를 **현행 화면을 재배치**해 읽기로 표시(탭 `진행 중 / 마무리한 / 내담자`). 만들기는 기존 마법사에서 상담 유형 고정 → `POST /sessions` shim이 관계 자동 생성.
7. **레거시 리다이렉트**: `/sessions`, `/sessions/new`, `/sessions/:id` → 새 경로(세션 id → 클래스로 해석). `/clients*` → `/counseling`. **영구 유지.**
8. **홈 `오늘 일정` 영역 칩** (`클래스 | 상담`) + 필터 `전체·클래스·상담`, 요약 타일 영역별 분리 집계.

### B. 회원 웹/앱
9. **회원 홈**: 히어로 = 다음 일정 `MBSR 봄 · 3회차`(클래스명·N회차·진행 강사·일시·입장 CTA).
10. **내 클래스 목록/상세 (읽기)**: `/app/classes`, `/app/classes/:classId`. 회차 타임라인(예정·취소 등). 출석·보강·변화 서사는 Phase 4~5.
11. 회원 하단 탭/사이드바: 홈 · 내 클래스 · 내 상담 · 리포트 · 더보기. `내 상담`은 최소 읽기 목록.
12. `/app/sessions`, `/app/sessions/:id` 유지(알림·메일·AI 비서 URL 호환).

### C. 공통
13. **영역별 용어 사전 적용**: `lib/terms.ts` 명상 값 재작성(약 78건 문구, S 137건 재작성 범위), 용어 가드(`BANNED_COPY`·`class-flow-shell-terms.test.ts`) 영역별 갱신.
14. **알림 `target_type`에 `class`·`counseling` 추가**(화이트리스트 확장, `session` 유지) + 딥링크 라우팅. 알림 카드에 영역 칩.
15. 세션 응답의 `class_id`·`class_title`·`seq`·`area` 활용(SDD-214 가산 필드).
