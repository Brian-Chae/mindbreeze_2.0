## 1. 목적과 작업 경계

명상 프로그램인 **클래스**와 하위 **회차**, **상담**을 구분해 탐색하게 한다. Phase 1 읽기 API로 상위 목록·상세를 만들고 호스트 회차 상세는 CH30 중심으로 축소한다. 실제 입장·진행·기록은 공유 엔진으로 연결한다. LINK BAND 없이도 모든 읽기·이동이 가능해야 한다.

이번 작업은 이 폴더의 Spec·Plan·Verify 작성만 한다. 코드 변경·실행, DB·AWS·dev/prod 접근, 파일·데이터 삭제, 메일, 머지를 금지한다. 지정 워크트리에서 문서 커밋·해당 브랜치 push·develop 대상 PR·CI 결과 확인까지만 수행한다. Stage ④ 이후는 별도 승인 대상이다. `summary.md`를 구현 완료처럼 미리 작성하지 않는다.

작업 중 이미 추가된 Spec 초안 커밋은 보존한다. 초안의 후속 탭·백엔드 알림 변경·dev 검증은 이번 사용자 지시에 맞춰 아래 범위로 정정한다.

> **2026-10-19 Brian 개정(`30ffef21`, 사용자 재확인)**: 기존 세션은 테스트 데이터이며 기존 목록·상세 화면 보존/무손실 이관은 요구하지 않는다. 새 경로 체계로 일괄 전환한다. 이는 화면 전환 기준이며 **파일·데이터 삭제 권한이 아니다**. 구 URL은 이동 어댑터로 처리하고 입장·플레이어·기록·리포트 엔진은 유지한다. 회원 상세의 부모 해석 실패 폴백만 명시적 예외다.

| 현행 세션 접근 범위를 부모 읽기에 투영 | 멤버십·센터 소속·강사 목록을 근거로 권한 확대 금지 |

| 상담사별 임시 관계(`is_placeholder`)에 여러 상담 회차 연결 | 내담자별 관계·개인 누적 이력으로 표시하지 않음 |
| `class_members`·비회원 상담·신규 출석 데이터 미제공 | 개인 참여 상태·출석·보강·합류 이력은 ‘데이터 없음’ |
| 읽기 응답에 EEG·음성·전사·리포트 본문 없음 | 본문 요청·추론 금지, 확인된 상태만 표시 |

SDD-214 plan §7.1 응답 필드는 **초안**이다. 최종 envelope, 페이지네이션·필터 지원, 집계·다음 일정·표시명·입장 가능 여부의 정확한 키/nullable 범위는 **미확인**이다. 구현 첫 작업에서 정적 계약을 확인해 adapter에 고정한다. 필수 식별자 계약을 확인하지 못하면 해당 연결을 보류한다. 기술 확인을 사용자 제품 결정으로 전가하지 않는다.

## 4. 범위와 IA

### 4.1 포함

- 소프트 사이드바·헤더·모바일 내비를 새 읽기 화면에 적용한다. 명상·상담 메뉴는 데이터 유무와 무관하게 항상 노출한다.
- 호스트 CH01 목록, CH02 개요, CH03 회차 표/타임라인. 회원 MC01 홈, MC02 목록, MC03 상세/타임라인. 상담 임시 입구는 호스트 CN01·CN02, 회원 CN07·CN08이다. CH30 축소 상세와 상담 회차 상세의 새 경로 연결, 기존 위저드의 새 경로 재배치도 포함한다.
- 제공되는 제목·상태·일정·회차·진행자 메타만 표시한다. 취소·권한 필터로 생긴 번호 빈칸을 복원하거나 `seq`를 재번호화하지 않는다.
- 기존 `/clients`는 상담의 ‘내담자’ 링크로 계속 접근한다. 센터 관리자 메뉴는 D-62에 따라 ‘구성원’으로 표시하되 기존 대상·권한을 유지한다.

| 사용자 | 새 메뉴/경로 | 유지할 진입점 |
|---|---|---|
| 상담사·센터 관리자 | 명상 클래스 `/classes`, 상담 `/counseling` | 대시보드·채팅·리포트·알림·설정, 기존 플레이그라운드/구성원 등 역할별 메뉴, `/clients`, `/classes/new` |
| 회원 | 홈 `/app`, 내 클래스 `/app/classes`, 내 상담 `/app/counseling` | 채팅·리포트·알림·프로필, 구 URL 이동 어댑터와 제한적 상세 폴백 |
| 플랫폼 관리자 | 기존 관리 내비 유지 | 새 업무 권한을 추가하지 않음 |

모바일은 홈·명상 영역·상담·채팅·더보기로 구성하고 리포트·알림·설정은 더보기에서 접근한다. 명상 라벨은 호스트 ‘명상 클래스’, 회원 ‘내 클래스’, 상담은 호스트 ‘상담’, 회원 ‘내 상담’이다. 리포트 배지는 더보기로 옮기되 기존 미읽음/승인 대기 의미를 보존한다. 기존 `class` 식별 키·새 `counseling` 키와 별도 표시용 용어 키를 사용하며 배지·active·권한을 라벨로 판단하지 않는다.

새 부모 화면은 명시적 라우트로 등록한다. `/app/*`의 기존 상담사 연결 강제 분기가 새 홈·두 영역 조회를 막지 않도록 분리한다. 상담사 연결이 없어도 빈 안내를 볼 수 있다. 기존 연결 절차와 권한은 변경하지 않는다.

### 4.2 제외

| 후속 범위 | 이번에 제공하지 않는 것 |
|---|---|
| Phase 3 편성·강사 | 클래스 생성/복제/설정, 반복·롤링 생성, 일괄 일정, 강사 지정·변경·수락·충돌 검사, 클래스 종료·취소 쓰기 |
| Phase 4 멤버십 | 클래스 단위 가입·초대·대기열·탈퇴·제외·출석·보강, 개인 수료, 비회원 장기 자격 |
| Phase 5 리포트 | 클래스 리포트 탭·추이·변화 이야기·집계·새 승인/열람 화면 |
| Phase 6 이후 상담 | 내담자별 관계 생성·종결·재개·보관, 새 위저드·비회원 입장·개인정보·메일·기록 연결 |

새 부모 상세 탭은 **개요/회차**만 제공한다. 멤버·출석/리포트/설정 탭과 미구현 쓰기 CTA는 숨긴다. 기존 단일 회차 생성 위저드를 `/classes/new`·`/counseling/new`에 재배치하되 다회차 편성·반복 상담 생성으로 오인시키지 않는다. CH30 취소는 기존 회차 취소 기능을 재사용하며 클래스/관계 종료 API를 신설하지 않는다. 입장·진행·기록·리포트는 공유 엔진에서 실행한다. 호스트 대시보드 집계 신설은 제외하되 링크는 새 경로로 갱신한다.

## 5. 시안 ↔ 화면 ↔ API 매핑

아래 11개 ID(CH30 포함)는 HTML 등록부(`reg`, `REG`, `INDEX`)에서 확인했다. 제품 라우트는 이번 설계이며 `{id}`는 각 부모 ID다.

| 시안 파일 / ID | 화면·신규 라우트 | 읽기 API | 연결·보정 |
|---|---|---|---|
| host-classes.html / CH01 | 명상 클래스 `/classes` | `GET /classes` | 카드 → CH02. 미제공 집계는 데이터 없음 |
| host-classes.html / CH02 | 개요 `/classes/:classId` | `GET /classes/{id}`, `GET /classes/{id}/sessions` 공유 | 회차 → `/classes/:classId/sessions/:sessionId`(CH30). 완료 상태 분리 |
| host-classes.html / CH03 | 회차 `/classes/:classId/sessions` | 같은 상세·회차 API | 표/타임라인 → CH30, 편성·보강·변경 시트 제외 |
| host-classes.html / CH30 | 축소 회차 상세 `/classes/:classId/sessions/:sessionId` | 부모 상세/회차 목록 + 기존 `GET /sessions/{id}` | 코드·참여자·장소·기록·취소. 일정/강사 편집·복제·삭제 메뉴 제외 |
| member-classes.html / MC01 | 회원 홈 `/app` | `GET /classes`, `GET /counseling` | 제공된 다음 일정만 비교. 임박 일정 추정 금지 |
| member-classes.html / MC02 | 내 클래스 `/app/classes` | `GET /classes` | 카드 → MC03. 개인 멤버십 탭 제외 |
| member-classes.html / MC03 | 내 클래스 상세 `/app/classes/:classId` | `GET /classes/{id}`, `GET /classes/{id}/sessions` | 회차 선택 → 같은 부모 경로의 `?session=<id>`. 출석·보강 데이터 없음 |
| counseling.html / CN01 | 상담 목록 `/counseling` | `GET /counseling` | 카드 → CN02. 내담자 링크 → 기존 `/clients` |
| counseling.html / CN02 | 상담 일정 `/counseling/:relationshipId` | `GET /counseling/{id}` | 가시 회차 → `/counseling/:relationshipId/sessions/:sessionId`. 기록·리포트는 상태만 |
| counseling.html / CN07 | 내 상담 `/app/counseling` | `GET /counseling` | 카드 → CN08. 표시명 계약 미확인 시 ‘상담 일정’ |
| counseling.html / CN08 | 내 상담 일정 `/app/counseling/:relationshipId` | `GET /counseling/{id}` | 가시 회차 → 같은 부모 경로의 `?session=<id>`. 개인 누적 횟수·종결 사유 미표시 |

상담 호스트 회차 상세는 `/counseling/:relationshipId/sessions/:sessionId`에서 공통 축소 상세를 상담 용어로 렌더링한다. 전용 시안 ID는 **미확인**이며 CH30을 상담 시안 ID라고 주장하지 않는다. 부모 관계의 가시 회차와 기존 `GET /sessions/{id}`를 대조한다. 회원 `?session=<id>`는 가시 회차 선택/강조와 기존 입장 기능 연결용이다.

**라우트 전환(기획 §7.4 + Brian 개정 적용)**: 앱이 만드는 내비·링크·알림 클릭 목적지는 새 경로로 통일한다. 구 URL은 과거 링크를 수용하는 어댑터이며 기존 목록·상세 보존의 근거가 아니다.

| 구분 | 처리 |
|---|---|
| `/sessions` | `/classes`로 이동(얇은 `Navigate`, 북마크·메일·알림 링크용) |
| `/sessions/new` | 새 클래스 만들기 `/classes/new`(기존 위저드 컴포넌트를 새 경로에 연결, 상담 유형은 `/counseling/new`로 분기). Phase 3에서 위저드 개편 |
| `/sessions/:id` | `class_id`와 검증된 부모 문맥으로 클래스 회차 경로에 이동. 상담은 확인된 관계 ID와 가시 회차 일치가 있을 때만 상담 회차 경로에 이동. 해석 실패 시 `/classes` |
| `/app/sessions` | `/app/classes`로 이동 |
| `/app/sessions/:id` | 부모가 검증되면 `/app/classes/:classId?session=<id>` 또는 `/app/counseling/:relationshipId?session=<id>`. 부모만 해석 실패하고 세션 읽기 권한이 있으면 기존 회원 상세 컴포넌트를 어댑터 안에서 직접 렌더링. 같은 URL로 재이동하지 않음 |
| `/sessions/:id/{live,player,record}` | 공유 엔진 경로로 **유지**(기획 §7.4: 영역 무관). 진입 링크는 새 회차 상세에서 연결 |
| `/join`, `/class/:sessionId/enter` | 유지(입장 코드·외부 링크 호환). id는 세션 id |

기존 세션·위저드 화면 자체의 보존은 요구하지 않는다. 회차 상세는 코드·참여자·장소·기록·취소 중심으로 축소한다(CH30). 기존 코드·참여자 읽기·회차 취소 계약을 재사용하되 출석·멤버십·클래스 공통 코드로 의미를 바꾸지 않는다. 미제공 값은 데이터 없음이다.

상담 관계 ID는 보장된 세션 가산 필드가 아니다. 부모 화면에서 이동할 때의 검증된 문맥 또는 확인된 API 필드만 사용한다. `area=counseling`만으로 ID를 만들거나 전체 관계 상세를 N+1 조회하지 않는다. ID만 있는 구 링크/일반 세션 알림은 기존 `getSession`으로 1건 확인 후 위 규칙을 적용한다. 회원 폴백도 401/404·권한 오류를 우회하지 않는다. 부모/회차 불일치와 접근불가는 같은 안내로 처리한다.

위저드 완료·취소·뒤로, 대시보드·AI 안내·알림·플레이어의 목록 복귀도 같은 경로 함수로 통일한다. 일반 세션 알림은 클릭 시 부모를 해석하고, 회원 입장 이벤트는 기존 `/class/:sessionId/enter`로 바로 이동한다. 새 경로 전환은 REST `/sessions/*`·소켓 룸·식별자·공유 엔진 계약을 바꾸는 일이 아니다.

| 기존/후속 시안 참조 | 확인 상태·이번 처리 |
|---|---|
| CH04·CH05·CH06, CH10~CH15·CH20 | host HTML 등록 확인. 후속 편성·멤버·리포트·설정 시안 구현 제외 |
| MC04~MC07 | member HTML 등록 확인. 후속 리포트·비회원·멤버십·알림 시안 구현 제외 |
| CN03a·CN03b·CN03r·CN03c·CN03d, CN04~CN06·CN09~CN16 | counseling HTML 등록 확인. 생성·변경·승인·비회원 흐름 제외 |
| FM05·FH05·FH06 | 외부 연결 문구만 확인. 기존 SDD-209 화면과 정확한 case 대응은 **미확인**. 운영 이동은 `App.tsx` 확인 경로만 사용 |
| 위 표에 없는 ID/연속 번호의 빈칸 | **미확인**. 추정하여 화면을 만들지 않음 |

## 6. 데이터 표현·권한

1. 성공한 빈 목록: ‘아직 클래스가 없어요’/‘아직 상담이 없어요’. 항목이 있으나 값이 없거나 미제공: **‘데이터 없음’**. 실제 0만 0으로 표시한다.
2. 로딩·오류·빈 목록·권한 없음·필드 누락을 구별한다. 오류는 ‘목록을 불러오지 못했어요’와 ‘다시 시도’, 404는 ‘내용을 찾을 수 없어요’와 목록 복귀. 서버 오류 원문은 노출하지 않는다.
3. 진행률은 확인된 서버 집계 계약만 사용한다. 분모·취소·보강 포함 규칙 미확인 시 데이터 없음. 개인 참석률과 클래스 진행률을 혼용하지 않는다. 완료 회차만 보고 클래스 완료·개인 수료를 판정하지 않는다.
4. `seq`·일정·진행자 누락도 ‘데이터 없음’. 0회차·가짜 인명·날짜를 채우지 않는다. 상담 임시 관계의 순번은 개인 누적 횟수가 아니므로 일정 중심으로 표시하고 개인 ‘N번째 상담’으로 의미를 바꾸지 않는다.
5. 서버가 반환한 가시 행만 표시한다. 빈 번호를 타인의 회차로 복원하거나 회원에게 코드·내부 필드·비공개 기록을 노출/저장하지 않는다.
6. 목록별 상세를 전수 호출하는 N+1 요청 금지. 집계가 없으면 데이터 없음. 서버 검색 확인 전 검색은 **현재 불러온 목록**에 한정하고 ‘현재 목록에서 찾기’라고 안내한다. 일부 페이지 개수를 전체 합계처럼 쓰지 않는다.
7. 다음 일정 비교는 두 API의 유효한 시간만 사용한다. 한쪽 실패는 해당 영역 오류이며 전체 다음 일정이라고 단정하지 않는다. 시안의 15분 규칙을 새로 구현하지 않고 기존 입장 판정·공유 엔진 흐름을 사용한다.
8. `area` 누락·미지 값은 임의 분류하지 않고 §5의 역할별 해석 실패 처리를 따른다. `class_id` 부재로 상담 관계 ID를 추측하지 않는다.
9. 알림에 실제 `class`·`counseling` 대상 ID가 제공될 때만 부모 URL을 해석한다. 발행 계약 변경은 제외한다. 일반 `session` 알림의 클릭 목적지는 새 경로로 해석하며 report·채팅·직접 입장 이벤트의 의미/목적지는 유지한다. 영역 미확인 초대 배지는 공통 알림에 유지하며 양쪽에 중복 집계하지 않는다.

## 7. 용어·공개 문구

- `lib/terms.ts` 기존 키·기본 영역·반환값은 보존하고 새 메뉴/호칭용 키를 가산한다. 기존 `class`의 전역 의미를 상담으로 바꾸지 않는다. 새 UI는 명상 ‘지도사·클래스·회차’, 상담 ‘상담사·내담자·상담 N회차’, 센터 메뉴 ‘구성원’을 쓴다.
- D-62·D-64는 확정 사항으로 다시 결정 요청하지 않는다.
- 공통 금지어와 영역별 금지어를 각각 적용한다. 명상 새 본문: `세션·수업·오픈` 금지. 상담 새 본문: `클래스·수업·오픈`과 정식 ‘상담 세션’ 이외의 단독 ‘세션’ 금지. 정규식은 기존 banned 파일을 기준으로 한다.
- 시안 지시서의 명상 ‘세션’ 허용과 기존 가드가 충돌하므로 ‘회차’로 치환하고 시각 차이에 기록한다. 기존 가드를 약화하지 않는다.
- 공통 내비, 명상 본문, 상담 본문, 혼합 홈 카드의 검사 영역을 분리한다. 상담 화면 내비 ‘명상 클래스’는 공통 내비 계약으로 검증하며 전역 금지어 예외를 만들지 않는다.
- 공개 문구에는 API·DTO·Phase·placeholder·shim·JSON·마이그레이션 등 개발 용어를 쓰지 않는다. 시안 인덱스·가정 설명·테스트 선택기도 제품에 노출하지 않는다.

## 8. 회귀·시각 수용 기준

- 입장·플레이어·기록·리포트의 권한·동작은 회귀 없이 유지한다(경로 `/sessions/:id/{live,player,record}`, `/join`, `/class/:sessionId/enter` 포함). 목록·상세·위저드는 새 경로로 대체하며 구 화면의 시각적 동일성·데이터 무손실 이관은 수용 기준이 아니다. 현재 파일·데이터 삭제 금지는 유지한다. 공유 화면의 목록/상세 이동 링크는 새 경로로 갱신하며 공통 스타일 전역 변경은 피한다.
- SDD-209 `ShellFrame`은 디자인 하네스용이므로 실제 AppShell/ClientShell에 중첩하지 않는다. `shell-data.ts`·`host-shell-data.ts`의 세션→카드 변환을 부모 데이터 변환으로 재해석하지 않는다.
- LINK BAND 연결·측정·녹음 유무로 읽기/이동을 막지 않는다. no-band를 오류·0점으로 표현하지 않는다.
- **390×844, 834×1194, 1194×834, 1280×720** 전부 검증한다. 최소 글자 12px, 유효 터치 영역 44px 이상, 페이지 가로/세로 넘침 0, 셸 내부 목록 스크롤만 허용한다.
- 케이스별 적용/보정/제외와 픽셀 비교 절차·허용 차이·증거 개수는 Verify에 고정한다. 이번 문서 작업에서는 브라우저 실행·캡처를 하지 않는다.
