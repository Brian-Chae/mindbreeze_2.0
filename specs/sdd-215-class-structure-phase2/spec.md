# SDD-215 — 클래스·세션 재설계 2단계 (클래스 읽기·화면 구조 전환)

- 상태: Stage ① Spec — 검토 요청 / Stage ③ 승인 전 구현 금지
- 브랜치: `sdd/215-class-structure-phase2`
- 작성일: 2026-10-19
- 산출물: [plan.md](plan.md), [verify.md](verify.md)

## 1. 목적과 작업 경계

명상 프로그램인 **클래스**와 하위 **회차**, **상담**을 구분해 탐색하게 한다. Phase 1 읽기 API로 상위 목록·상세를 만들고 실제 진행은 기존 세션 단위 화면으로 연결한다. LINK BAND 없이도 모든 읽기·이동이 가능해야 한다.

이번 작업은 이 폴더의 Spec·Plan·Verify 작성만 한다. 코드 변경·실행, DB·AWS·dev/prod 접근, 파일·데이터 삭제, 메일, 머지를 금지한다. 지정 워크트리에서 문서 커밋·해당 브랜치 push·develop 대상 PR·CI 결과 확인까지만 수행한다. Stage ④ 이후는 별도 승인 대상이다. `summary.md`를 구현 완료처럼 미리 작성하지 않는다.

작업 중 이미 추가된 Spec 초안 커밋은 보존한다. 초안의 상세 축소·강제 리다이렉트·후속 탭·백엔드 알림 변경·dev 검증은 이번 사용자 지시에 맞춰 아래 범위로 정정한다.

## 3. Phase 1 인수 조건

| 확인된 계약/제약 | Phase 2 처리 |
|---|---|
| 읽기 API 5종: `/classes`, `/classes/{id}`, `/classes/{id}/sessions`, `/counseling`, `/counseling/{id}` | 새 상위 화면의 출처 |
| 세션 응답 선택 필드 `class_id`, `class_title`, `seq`, `area` | 가산 활용. 누락되어도 기존 상세 이동 보존 |
| 신규 API 미존재·접근불가 동일 404 | 동일 안내·복귀. 존재 여부·타인 정보 추론 금지 |
| 현행 세션 접근 범위를 부모 읽기에 투영 | 멤버십·센터 소속·강사 목록을 근거로 권한 확대 금지 |
| 생성 기본 `planned_session_count=1`, `schedule_mode='fixed'` | 실제 결과를 다회차·정기형 프로그램으로 꾸미지 않음 |
| 세션 종료와 클래스 `status` 미연동 | 클래스 상태·회차 상태 분리. 자동 완료·개인 수료 판정 금지 |
| `new-run` 부모/세션 미생성, PUT 유형 변경에도 부모 유지 | `type`·제목으로 재분류하지 않고 제공 `area`·부모 ID 사용 |
| 상담사별 임시 관계(`is_placeholder`)에 여러 상담 회차 연결 | 내담자별 관계·개인 누적 이력으로 표시하지 않음 |
| `class_members`·비회원 상담·신규 출석 데이터 미제공 | 개인 참여 상태·출석·보강·합류 이력은 ‘데이터 없음’ |
| 읽기 응답에 EEG·음성·전사·리포트 본문 없음 | 본문 요청·추론 금지, 확인된 상태만 표시 |

SDD-214 plan §7.1 응답 필드는 **초안**이다. 최종 envelope, 페이지네이션·필터 지원, 집계·다음 일정·표시명·입장 가능 여부의 정확한 키/nullable 범위는 **미확인**이다. 구현 첫 작업에서 정적 계약을 확인해 adapter에 고정한다. 필수 식별자 계약을 확인하지 못하면 해당 연결을 보류한다. 기술 확인을 사용자 제품 결정으로 전가하지 않는다.

## 4. 범위와 IA

### 4.1 포함

- 소프트 사이드바·헤더·모바일 내비를 새 읽기 화면에 적용한다. 명상·상담 메뉴는 데이터 유무와 무관하게 항상 노출한다.
- 호스트 CH01 목록, CH02 개요, CH03 회차 표/타임라인. 회원 MC01 홈, MC02 목록, MC03 상세/타임라인. 상담 임시 입구는 호스트 CN01·CN02, 회원 CN07·CN08이다.
- 제공되는 제목·상태·일정·회차·진행자 메타만 표시한다. 취소·권한 필터로 생긴 번호 빈칸을 복원하거나 `seq`를 재번호화하지 않는다.
- 기존 `/clients`는 상담의 ‘내담자’ 링크로 계속 접근한다. 센터 관리자 메뉴는 D-62에 따라 ‘구성원’으로 표시하되 기존 대상·권한을 유지한다.

| 사용자 | 새 메뉴/경로 | 유지할 진입점 |
|---|---|---|
| 상담사·센터 관리자 | 명상 클래스 `/classes`, 상담 `/counseling` | 대시보드·채팅·리포트·알림·설정, 기존 플레이그라운드/구성원 등 역할별 메뉴, `/clients`, `/sessions/new` |
| 회원 | 홈 `/app`, 내 클래스 `/app/classes`, 내 상담 `/app/counseling` | 채팅·리포트·알림·프로필·기존 세션 URL |
| 플랫폼 관리자 | 기존 관리 내비 유지 | 새 업무 권한을 추가하지 않음 |

모바일은 홈·명상 영역·상담·채팅·더보기로 구성하고 리포트·알림·설정은 더보기에서 접근한다. 명상 라벨은 호스트 ‘명상 클래스’, 회원 ‘내 클래스’, 상담은 호스트 ‘상담’, 회원 ‘내 상담’이다. 리포트 배지는 더보기로 옮기되 기존 미읽음/승인 대기 의미를 보존한다. 기존 `class` 식별 키·새 `counseling` 키와 별도 표시용 용어 키를 사용하며 배지·active·권한을 라벨로 판단하지 않는다.

새 부모 화면은 명시적 라우트로 등록한다. `/app/*`의 기존 상담사 연결 강제 분기가 새 홈·두 영역 조회를 막지 않도록 분리한다. 상담사 연결이 없어도 빈 안내를 볼 수 있다. 기존 연결 절차와 권한은 변경하지 않는다.

### 4.2 제외

| 후속 범위 | 이번에 제공하지 않는 것 |
|---|---|
| Phase 3 편성·강사 | 클래스 생성/복제/설정, 반복·롤링 생성, 일괄 일정, 강사 지정·변경·수락·충돌 검사, 클래스 종료·취소 쓰기 |
| Phase 4 멤버십 | 클래스 단위 가입·초대·대기열·탈퇴·제외·출석·보강, 개인 수료, 비회원 장기 자격 |
| Phase 5 리포트 | 클래스 리포트 탭·추이·변화 이야기·집계·새 승인/열람 화면 |
| Phase 6 이후 상담 | 내담자별 관계 생성·종결·재개·보관, 새 위저드·비회원 입장·개인정보·메일·기록 연결 |

새 상세 탭은 **개요/회차**만 제공한다. 멤버·출석/리포트/설정 탭과 미구현 쓰기 CTA는 숨긴다. 기존 생성 위저드로의 이동은 가능하지만 새 ‘클래스 만들기’·‘반복 상담 만들기’ 기능으로 오인시키지 않는다. 기존 회차 입장·진행·기록·리포트 동작은 기존 화면에서 실행한다. 호스트 대시보드의 영역별 집계 신설도 이번 10개 화면 범위 밖이다.

## 5. 시안 ↔ 화면 ↔ API 매핑

아래 10개 ID는 HTML 등록부(`reg`, `REG`, `INDEX`)에서 확인했다. 제품 라우트는 이번 설계이며 `{id}`는 각 부모 ID다.

| 시안 파일 / ID | 화면·신규 라우트 | 읽기 API | 연결·보정 |
|---|---|---|---|
| host-classes.html / CH01 | 명상 클래스 `/classes` | `GET /classes` | 카드 → CH02. 미제공 집계는 데이터 없음 |

| member-classes.html / MC01 | 회원 홈 `/app` | `GET /classes`, `GET /counseling` | 제공된 다음 일정만 비교. 임박 일정 추정 금지 |

## 6. 데이터 표현·권한

1. 성공한 빈 목록: ‘아직 클래스가 없어요’/‘아직 상담이 없어요’. 항목이 있으나 값이 없거나 미제공: **‘데이터 없음’**. 실제 0만 0으로 표시한다.
2. 로딩·오류·빈 목록·권한 없음·필드 누락을 구별한다. 오류는 ‘목록을 불러오지 못했어요’와 ‘다시 시도’, 404는 ‘내용을 찾을 수 없어요’와 목록 복귀. 서버 오류 원문은 노출하지 않는다.
3. 진행률은 확인된 서버 집계 계약만 사용한다. 분모·취소·보강 포함 규칙 미확인 시 데이터 없음. 개인 참석률과 클래스 진행률을 혼용하지 않는다. 완료 회차만 보고 클래스 완료·개인 수료를 판정하지 않는다.
4. `seq`·일정·진행자 누락도 ‘데이터 없음’. 0회차·가짜 인명·날짜를 채우지 않는다. 상담 임시 관계의 순번은 개인 누적 횟수가 아니므로 일정 중심으로 표시하고 개인 ‘N번째 상담’으로 의미를 바꾸지 않는다.
5. 서버가 반환한 가시 행만 표시한다. 빈 번호를 타인의 회차로 복원하거나 회원에게 코드·내부 필드·비공개 기록을 노출/저장하지 않는다.
6. 목록별 상세를 전수 호출하는 N+1 요청 금지. 집계가 없으면 데이터 없음. 서버 검색 확인 전 검색은 **현재 불러온 목록**에 한정하고 ‘현재 목록에서 찾기’라고 안내한다. 일부 페이지 개수를 전체 합계처럼 쓰지 않는다.
7. 다음 일정 비교는 두 API의 유효한 시간만 사용한다. 한쪽 실패는 해당 영역 오류이며 전체 다음 일정이라고 단정하지 않는다. 시안의 15분 규칙을 새로 구현하지 않고 입장은 기존 상세/입장 흐름에 맡긴다.
8. `area` 누락·미지 값은 임의 분류하지 않고 기존 세션 링크를 중립적으로 유지한다. `class_id` 부재로 상담 관계 ID를 추측하지 않는다.
9. 알림에 실제 `class`·`counseling` 대상 ID가 제공될 때만 부모 URL을 해석한다. 발행 계약 변경은 제외한다. 기존 `session`·`report`·채팅과 입장 딥링크를 보존한다. 영역 미확인 초대 배지는 공통 알림에 유지하며 양쪽에 중복 집계하지 않는다.

## 7. 용어·공개 문구

- `lib/terms.ts` 기존 키·기본 영역·반환값은 보존하고 새 메뉴/호칭용 키를 가산한다. 기존 `class`의 전역 의미를 상담으로 바꾸지 않는다. 새 UI는 명상 ‘지도사·클래스·회차’, 상담 ‘상담사·내담자·상담 N회차’, 센터 메뉴 ‘구성원’을 쓴다.
- D-62·D-64는 확정 사항으로 다시 결정 요청하지 않는다.
- 공통 금지어와 영역별 금지어를 각각 적용한다. 명상 새 본문: `세션·수업·오픈` 금지. 상담 새 본문: `클래스·수업·오픈`과 정식 ‘상담 세션’ 이외의 단독 ‘세션’ 금지. 정규식은 기존 banned 파일을 기준으로 한다.
- 시안 지시서의 명상 ‘세션’ 허용과 기존 가드가 충돌하므로 ‘회차’로 치환하고 시각 차이에 기록한다. 기존 가드를 약화하지 않는다.
- 공통 내비, 명상 본문, 상담 본문, 혼합 홈 카드의 검사 영역을 분리한다. 상담 화면 내비 ‘명상 클래스’는 공통 내비 계약으로 검증하며 전역 금지어 예외를 만들지 않는다.
- 공개 문구에는 API·DTO·Phase·placeholder·shim·JSON·마이그레이션 등 개발 용어를 쓰지 않는다. 시안 인덱스·가정 설명·테스트 선택기도 제품에 노출하지 않는다.

## 8. 회귀·시각 수용 기준

- 기존 세션 페이지·위저드·입장·플레이어·기록·리포트의 코드/동작과 URL을 유지한다. 새 셸 시각 변형은 선택 적용하고 기존 화면의 공통 스타일을 전역 변경하지 않는다.
- SDD-209 `ShellFrame`은 디자인 하네스용이므로 실제 AppShell/ClientShell에 중첩하지 않는다. `shell-data.ts`·`host-shell-data.ts`의 세션→카드 변환을 부모 데이터 변환으로 재해석하지 않는다.
- LINK BAND 연결·측정·녹음 유무로 읽기/이동을 막지 않는다. no-band를 오류·0점으로 표현하지 않는다.
- **390×844, 834×1194, 1194×834, 1280×720** 전부 검증한다. 최소 글자 12px, 유효 터치 영역 44px 이상, 페이지 가로/세로 넘침 0, 셸 내부 목록 스크롤만 허용한다.
- 케이스별 적용/보정/제외와 픽셀 비교 절차·허용 차이·증거 개수는 Verify에 고정한다. 이번 문서 작업에서는 브라우저 실행·캡처를 하지 않는다.
