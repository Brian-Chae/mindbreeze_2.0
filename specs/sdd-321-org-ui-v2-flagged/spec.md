# SDD-321 — 기관 관리자 화면 D안 적용 (기능 플래그, dev 한정)

- 상태: Stage ① Spec 완료 → ② Plan → ③ Verify
- 브랜치: `sdd/321-org-ui-v2-flagged`
- 작성일: 2026-11-07
- 승인: 대표 승인(11/7 "기관 화면은 왜 보류되었지? 진행시켜") — 단계 ③~⑥ 연속 진행
- 선행: SDD-318(내담자 D안). 동시 진행: SDD-320(코치 화면, 다른 워커 — 코치 파일 수정 금지)

## 1. 무엇을, 왜
기관 관리자(`org_admin`) 화면을 시안 D(C 레이아웃 + A 색상)로 교체한다. SDD-318 의 `UI_V2`(`VITE_UI_V2`) 플래그·`.ui-v2` 스코프 토큰·자체 호스팅 Pretendard·락업 로고를 그대로 재사용한다.
플래그 off(운영 빌드)에서는 **한 픽셀·한 바이트도 바뀌면 안 된다**(최우선 불변 조건). 기관 관리자는 데스크톱이 주 사용 환경이므로 사이드바 + 본문 구조는 유지하고 색·타이포·카드·간격·버튼·표를 D안으로 바꾼다. 모바일(390)도 깨지지 않게 한다.

## 4. 제약
- 금지 표현(화면 문구·신규 소스): 점수·종합점수·좋음·나쁨·완료율·보증·100% 단정. 기존 통계 라벨 "완료"(마친 클래스 수)는 D안에서 "종료한 클래스"로 표기한다. 상태 배지는 공용 라벨 출처(`sessionStatusLabel`)를 그대로 쓴다 — 대표 결정 사항에 기록.
- 이메일은 불변 아이디, 기관관리자는 상담사 개인정보 전부 수정 가능 — 기존 `CounselorInfoEditor`·`patchOrgCounselorProfile` 재사용으로 동작 그대로 보존(재구현 금지).
- 접근성: 본문 대비 4.5:1, 터치 44px, `prefers-reduced-motion` 존중, 390~393px 제목 잘림 금지, dialog 는 `useDialogA11y`(ESC·포커스 복원) 유지.
- 코딩: kebab-case 파일, PascalCase 컴포넌트, `any` 금지, 불변성. 기존 테스트·기존 화면 파일 무수정.
- 금지: 푸시·PR·배포·앱 빌드·메일·삭제·DB/서버 접근·시크릿 출력. 커밋은 로컬 브랜치만.
