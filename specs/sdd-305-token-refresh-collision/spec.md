# SDD-305 — 측정 중 토큰 갱신 충돌로 15분마다 데이터 중단

- 상태: Stage ① 분석·기획안 작성, 구현 미승인·미실행
- 브랜치: `sdd/305-token-refresh-collision`
- 작성일: 2026-11-05
- 산출물: 이 문서, [plan.md](plan.md), [evidence.md](evidence.md)
- 기존 SDD-305 전용 워크트리와 발급된 뼈대를 사용했다. 번호를 재발급하거나 원격 예약·푸시하지 않았다.

## 문제와 목표

안드로이드 20대 회차 b46d31에서 분석창 저장이 중단되었다. dev 수명은 15분이며, WebView와 네이티브가 복제한 refresh token을 독립 회전한다. 유예 내 재회전은 잠시 성공해도 서로 다른 토큰을 남겨 다음 만료에서 계정 전체 폐기로 이어질 수 있다. test1~3은 첫 경계에서 2회 회전 후 약 15분 뒤 최종 폐기되는 패턴이 확인됐다. 사건의 개별 재사용 요청자는 미확정이다.

목표는 11/06 20대 재시험의 중단 위험을 줄이고, 11/11 행사 전에는 반복 갱신에도 측정·업로드·소켓·화면이 지속되는 구조를 검증하는 것이다. 단순 수명 연장을 근본 해결로 인정하지 않는다.

## 범위

- 이번 작업: 코드·dev DB/로그 읽기, 원인 분류, A/B/C 옵션 비교, 구현 순서와 시험 합격 기준, 대표 결정 항목.
- 실행하지 않음: 제품 코드/서버 설정 변경, dev DB 쓰기, 운영 접근, 앱 빌드, commit·push·PR·배포·메일·삭제.
- 향후 우선 구현 대상: Android와 공통 서버/웹. iOS는 동일 위험을 명시하고 SDD-301 협업 범위로 분리한다. 현재 워크트리에 SDD-301 문서가 없어 세부 일정은 확정하지 않는다.
- 회원의 JWT 갱신과 비회원 entry credential·동의·대기열 거절은 별도로 다룬다.

## 요구사항

1. 앱 인증 갱신 소유자는 계정별 한 곳이어야 한다. WebView·측정 Runtime·ScopeSweeper·오디오가 서로 다른 refresh 복사본을 독립 회전하지 않는다.
2. 갱신 중 요청은 같은 결과를 기다리며, 늦은 응답이 새 자격증명을 덮어쓰지 않는다. 로그아웃·계정 전환은 이전 요청 결과를 무효화한다.
3. background 측정이 WebView 생존에 의존하지 않도록 native 소유 방식을 우선 검토한다. refresh token을 JS 이벤트로 다시 퍼뜨리는 방식은 기본안으로 삼지 않는다.
4. 서버 중복 갱신 응답은 동일 결과로 수렴하도록 설계하되, 유예 기간·재사용 탐지·계정 정지/로그아웃을 무력화하지 않는다.
5. 401·소켓 인증 만료 시 측정 원본·outbox를 삭제하지 않는다. 복구 이후 stream/sequence 중복 없이 적재하고 UI가 최신값으로 돌아오는지 검증한다.
6. 토큰 수명 변경은 새 발급에만 적용됨을 운영 절차에 반영한다. 이미 전부 폐기된 계정은 갱신 시도로 복구되지 않으므로 승인된 시험에서 재로그인이 필요하다.
7. 관측에는 갱신 주체·원인 코드·비밀이 아닌 요청 식별자·갱신 세대만 사용한다. JWT·refresh·푸시 토큰·IP·이메일 원문은 증거에 기록하지 않는다.
