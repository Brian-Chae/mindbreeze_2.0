# SDD-284 — iOS 측정 데이터 저장·실시간 안정화 (TestFlight 공개 베타)

- 상태: Stage ① Spec — 대표 go/no-go 대기 (대표 지시로 착수 의사 확인됨, 11/4)
- 브랜치: `sdd/284-ios-data-stability`
- 작성일: 2026-11-04
- 기한: **11/11(수) 행사 전** TestFlight 공개 베타 빌드로 배포 가능해야 함 (App Store 심사 통과는 전제하지 않음)
- 관련: SDD-282(11/4 유실 원인·복구), SDD-283(부하), SDD-285(안드로이드 검증·서버)

## 1. 배경

11/4 행사에서 iPhone은 TestFlight·앱 설치까지 정상이었지만 **측정 데이터 전송이 사실상 전멸**했다.
- 푸시 등록이 iOS인 회원 7명은 분석 데이터(`eeg_feature_windows`) 0건. 1명(`94234b`)만 원시 1,517 청크.
- iOS 웹 경로 `eeg-raw/presign` 403 약 2,378건(대기열·뇌파 동의 조건 포함, 사유 미분리).
- 이전 회차에서도 iOS 별도 결함 이력: SDD-277(journal 기록 중단), SDD-276, 라이브 이벤트 등.
- 대표 판단: 11/11 행사는 iOS를 **TestFlight 공개 베타**로 진행. 지금 App Store 심사가 통과해도 이 결함 때문에 쓰지 못함.

## 2. 해결할 문제

1. iOS에서 데이터(분석 지표·원시·PPG/ACC)가 **왜 서버에 도착하지 않았는지 원인 확정** (SDD-282의 가설 H4 포함).
2. 수정하여 **데이터 저장과 실시간 스트림이 완벽히 동작**하도록 한다. 합격 기준은 verify.md에서 수치로 정의.
3. 11/11까지 TestFlight 빌드로 배포 가능한 상태(빌드는 APP 창구가 수행).

## 3. 범위

### 포함
- iOS 앱 코드(Swift/Capacitor 플러그인, `ios/`)와 웹 번들의 iOS 경로: BLE 연결 → 측정 → `features/batch` → 원시 업로드 → 실시간 소켓 → 종료·final 보고 전 구간
- 서버 쪽 iOS 대응(필요 시 SDD-285와 조율)
- iOS 실기기 재현 절차(디바이스 로그 수집 방법 포함), dev 서버·dev 앱 기준 검증
- 11/4 iOS 사용자 7명(푸시 등록 기준)의 서버·기기 증거 대조

### 제외
- 운영 DB 쓰기·삭제 (복구는 SDD-282에서 별도)
- App Store 심사 대응·재제출 (별도 카드)
- Android 앱 변경 (SDD-285 소관)
- 앱 빌드·TestFlight 업로드는 APP 창구가 수행 (이 SDD는 코드·검증까지)

## 4. 성공 기준 (verify.md에서 구체화)

- iOS 실기기 + LINK BAND로 dev 서버 30분 이상 측정 시 분석 데이터·원시 청크가 기대량의 99% 이상 서버 도착
- 앱을 백그라운드로 보내거나 화면 잠금해도 측정·업로드 유지
- 실시간 지표 6종이 매초 표시되고 소켓 끊김 후 자동 복구
- 종료 후 리포트 생성에 필요한 데이터가 서버에 완결 (`final=true`, 기대량 대비 불일치 0 또는 설명 가능)

## 5. 제약

- 운영 DB 읽기 전용(SSM `i-0487c67fb0db7dcba`), 쓰기·배포·푸시·메일은 대표 지시 후.
- iOS 빌드·업로드는 APP 창구 전용. 이 워커는 빌드하지 않는다.
- 금지 표현(점수·종합점수·좋음·나쁨·완료·보증·100% 단정)은 신규 화면에 쓰지 않는다.
- 개인정보는 건수만.

## 6. 대표 결정 필요

1. 이 SDD 진행(go) — 대표 지시 의도로 보여 워커를 먼저 가동함, 문제가 있으면 중단
2. 11/11까지 일정상 필요하면 iOS 리소스 투입 범위(워커 병렬 수)
