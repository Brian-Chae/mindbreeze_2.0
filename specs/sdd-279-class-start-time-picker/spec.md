# SDD-279 — 클래스 만들기 시작 시각 빠른 선택

- 상태: Stage ① + 디자인 시안. 대표 선택 대기, 제품 구현 미착수.
- 브랜치: `sdd/279-class-start-time-picker` / 작성일: 2026-11-03.
- 승인 범위: spec·독립 HTML 시안·캡처·공유 사본·로컬 커밋. Phase 3 및 Stage ④ 미승인.

## 문제와 코드 근거

코치는 멀리 떨어진 시작 시각으로 바꿀 때 반복 탭이 많다고 제보했다. 전달 화면은 시작 시각을 5분씩 변경한다. 오후 7시에서 오전 9시로 이동하면 600분 ÷ 5분 = 120회(같은 날짜, 감소 방향, 가속 없음)다.

현재 워크트리 코드는 이미 날짜·시·분을 분리한다. `frontend/src/components/class/flow/host/wizard-steps.tsx:245` 이후 시는 60분씩, `:263` 이후 분은 5분씩 바꾼다. 이 코드 기준 동일 이동은 시 감소 10회다. 전달 화면과 소스의 차이는 배포 상태를 조회하지 않아 원인 미확인이다.

`frontend/src/lib/class/class-wizard.ts:39`의 값은 `draft.timeMin`(자정부터 분)이며 `:82`~`:83`에서 오전 7시~오후 10시를 허용한다. `:302`~`:307`은 시각 경계 제한과 분의 시간 내 순환을 처리한다. 브리프의 `draft.startTime` 표현은 현 코드 식별자와 다르므로 신규 필드를 만들지 않는다.

## 목표

- 주요 시각을 1~3회 탭으로 선택. 대표 시나리오 19:00 → 09:00으로 비교한다.
- 모든 허용 시각(07:00~22:00, 5분 단위)은 직접 입력 또는 목록 선택으로 접근 가능해야 한다.
- A의 비인접 시각 전체가 3탭 이내라는 뜻은 아니다. B의 1탭은 칩으로 제공된 시각에 한한다. C의 횟수는 OS 선택기 별도 검증이 필요하다.
- 색·투명도·반경·폰트 스택은 기존 제품 토큰 사용. 숲 배경은 기존 `background4.webp`를 HTML에 내장한다.

## 비목표와 보존

날짜·소요 시간·서버 API·draft 형식·예약 알림 변경 없음. 앱 빌드, 소스 수정, 서버 조작, 푸시, PR, 배포, 메일, 삭제 없음. 최근 사용 기록의 저장·조회 기능 추가 없음.

현재 StepSchedule에는 횟수·요일이 없으므로 시안에 새 필드를 만들지 않는다. 제공 화면의 해당 영역이 실제 배포본에 존재한다면 후속 구현 시 보존 대상이다. 예약 알림은 시각 컨트롤 뒤에 유지한다. 시안에서 다른 필드는 문맥용 정적 표시다.

## 후보

- A: 오전/오후 토글 + 시·분 분리 스테퍼 + 직접 입력. 예시 3탭.
- B: 4개 제안 시각 칩 + 직접 고르기 안의 A. 예시 1탭. 칩 시각은 사용 빈도를 측정한 결과가 아닌 디자인 제안이다.
- C: 오전/오후가 포함된 시 네이티브 select + 분 select. 데스크톱 예시 목록 열기·항목 선택 2탭. WebView의 스크롤·확인 동작은 미확인.

## 접근성과 입력 정책

- 조작 영역 최소 44×44px, Tab 이동, 명시적 label/aria-label, focus-visible 테두리.
- A/B: 시·분 직접 입력과 ↑↓. 시는 1시간, 분은 5분. 분 증감은 시간 안에서 55↔00 순환.
- C: 네이티브 select의 키보드 방향키·문자 탐색 사용. 자유 문자열 입력은 A/B에만 있다.
- 5분이 아닌 입력·경계 밖 값은 안내 후 이전 유효값 유지. 오전/오후 전환도 경계 밖이면 유지한다.
- C에서 22시 선택 시 분은 00으로 맞추고 다른 분은 비활성화한다. 이는 시안 정책이며 구현 승인 시 확정한다.
- 결과는 aria-live polite, 입력 오류는 role alert. 스크린리더 실제 발화·실기기 키보드 검증은 후속 단계.

## 수용 기준

1. 세 HTML은 외부 스크립트·이미지 요청 없이 단독으로 열린다. index는 로컬 상대경로로 세 안을 비교한다.
2. 1280px/390px에서 가로 넘침 없고 시작 시각의 모든 보이는 조작 영역은 44px 이상이다.
3. A 3탭/B 1탭으로 19:00 → 09:00. C 목록 선택으로 09:00 반영. C의 실기기 탭 수는 미확인으로 표시.
4. A/B의 직접 입력·방향키·5분 미만 입력 거부, C의 22:00 경계를 검증한다.
5. 예약 알림이 시각 선택기와 겹치지 않고 스크롤로 접근된다. 제품 소스·계약 변경은 없다.
6. 대표가 시안을 선택한 뒤 별도 Plan·구현 전 Verify·승인 절차를 거쳐 구현한다. 이번 작업을 전체 SDD 완료로 표기하지 않는다.
