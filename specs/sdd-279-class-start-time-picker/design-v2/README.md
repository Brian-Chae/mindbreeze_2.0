**추천: C-1.** 동일 폭 3열과 88px 컨트롤 높이를 유지하면서 목표 이동이 2회로 가장 짧다. 추가 팝오버 상태와 포커스 관리 없이 모바일과 같은 선택 모델을 유지한다. 네이티브 메뉴 내부 스크롤·선택 방식은 OS별로 다르므로 2회를 실기기 탭 수로 단정하지 않는다.

C-2·C-3에서 오후 7시→오전을 누르면 허용 범위 내 오전 7시가 된다. 이어서 9시를 선택한다. 07:00 미만·22:00 초과 값은 경계로 보정하며, 22시에서는 00분만 허용한다. C-3은 시 또는 분 선택 시 닫히고 필드로 포커스가 돌아온다. 시·분을 모두 바꿀 경우 다시 열어야 하는 비용이 있다.

## 화면 재현 근거와 범위

- **화면 구성은 11/3 브리프를 우선했다.** 현재 `frontend/src/components/class/flow/host/wizard-steps.tsx:219`는 '언제 열까요?', '지금 바로/시간 예약' 2개 세그먼트와 분리된 시·분, 별도 소요 시간 행이다. 브리프의 3세그먼트·횟수·요일·둘 다 알림과 일치하지 않는다. 따라서 현재 앱과 픽셀 단위 동일함은 주장하지 않는다.
- `frontend/src/components/class/player/shared/player-tokens.css:5` 브랜드 #5F0080, #B373EF, #D2AEFC, 텍스트 #F7F4F0/#CFC6D6, sheet rgba(24,12,36,.58), 테두리 rgba(255,255,255,.14), 반경 24/16px, 최소 타깃 44px, 폰트 스택 사용.
- `frontend/src/components/class/flow/host/host-flow-create.css:9` 카드 padding 16/24px, 그룹 gap 8px, 그리드 gap 16px, 스테퍼 버튼 44px를 확인했다. 카드 padding 16/24px·열 gap 16px는 소스를 따랐다. 브리프가 지정한 1010px 카드·88px 컨트롤은 소스의 최소 56px보다 크게 재현했다.
- `frontend/src/lib/class/class-wizard.ts:82`~83 시간 범위 420~1320분. `:303`~307 시간·분 조작 경계 보정, `:361` timeMin을 시·분으로 변환. 시안은 동일 정수 분 형식으로 `document.body.dataset.timeMin`에만 반영한다. 서버 계약은 변경하지 않았으며 서버 호출은 하지 않았다.
- `frontend/public/images/background4.webp` 원본 인라인 복사. 폰트 파일은 내장하지 않았으므로 설치 환경에 따라 대체된다.
- 제품 프레임에는 비교 설명·기술 메모·추가 요약 박스를 넣지 않았다. 시작 시각만 동작하며 다른 버튼은 제품 동작을 연결하지 않은 문맥 표현이다.

## 검증

별도 검증자 작성 스크립트를 감독자가 최종 재실행: **3안 × 5개 viewport, 15/15 통과**. 데스크톱 라벨 y차 0px, 모든 컨트롤 88px(높이차 0), 라벨 간격 8px, 가로 넘침 0px, 보이는 타깃 44px 이상. C-1·C-2 시/분 select 폭비 약 1:1, C-3 팝오버 열 폭비 0.99989~1.0. 09:00 이동·07:00/22:00 경계·5분 옵션·C-3 키보드·포커스 복귀·비교 탭 검사 통과. PNG를 직접 열어 정렬을 확인했다. 원시 측정과 동작 결과는 [validation.json](validation.json), PNG는 [shots](shots/)에 저장한다. 모바일은 세 열이 세로로 쌓이므로 라벨 y 동일 조건은 적용하지 않고 라벨-컨트롤 간격 8px를 검사한다. 보조 라벨은 제거하여 좌측 정렬 검사 대상이 없다. 분의 5분 간격은 접근성 이름과 실제 옵션으로 표현했다.
