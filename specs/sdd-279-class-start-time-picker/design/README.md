## 3안 비교

탭은 초기 19:00에서 같은 날 09:00까지를 기준으로 한다. 페이지 열기·스크롤·텍스트 입력 키 수는 제외한다.

| 항목 | A 시·분 스테퍼 | B 빠른 시각 칩 | C 네이티브 목록 |
|---|---|---|---|
| 예시 탭 수 | 3: 오전 전환 + 시 증가 2회 | 1: 오전 9:00 칩 | 데스크톱 2: 시 열기 + 9시 선택; OS별 확인·스크롤은 별도 |
| 임의 시각 | 직접 입력 또는 반복 증감 | 칩 외 값은 펼침 + A; 전체 3탭 보장 아님 | 시·분 각각 선택; 두 필드 변경은 대체로 4회 이상 |
| 구현 난이도 추정 | 낮음~중간: AM/PM 경계 정책 필요 | 중간: 칩·선택 상태·확장 패널 | 낮음~중간: 네이티브 UI·경계 처리 |
| 파일·컴포넌트 추정 | wizard-steps.tsx의 시작 시각 그룹 + host-flow-create.css, 필요시 host-flow-atoms.tsx | 같은 2~3개 파일; FhSeg·FhStepper 재사용 | wizard-steps.tsx + host-flow-create.css, 필요시 공용 select |
| 접근성 | label·직접 입력·↑↓; AM/PM 의미 설명 필요 | 눌림 상태 + details; 확장 후 포커스 순서 주의 | 네이티브 키보드/보조기술 활용; OS별 표시 차이 |
| 모바일 | 44px 이상, 시·분 2열 | 44px 이상, 2×2칩; 펼치면 세로 공간 증가 | 56px 높이; 선택기 모습은 WebView에 따라 다름 |
| 기존 일관성 | 기존 시·분 스테퍼와 가장 가까움 | 소요 시간 바로 선택의 보라 선택색·칩 패턴 확장 | 카드·색·반경 유지, 팝업은 OS 스타일 |
| 위험 | 오전/오후 전환 후 허용 범위 초과 | 칩 시각의 실제 사용 빈도 미확인 | 스크롤·확인 횟수와 화면낭독 동작 미확인 |

현 코드의 시 감소는 60분 단위이므로 600÷60=10회다. 전달 화면의 5분 단위 감소는 600÷5=120회다. 순환이나 길게 누르기 가속은 계산에 넣지 않았다. 배포본의 실제 UI는 확인하지 않았다.

## 추천 1안: B

대표 시나리오가 1탭이고 기존 소요 시간의 `FhSeg variant="fh-c5"` 패턴을 재사용할 수 있다. 칩 밖의 5분 단위 시각도 A를 펼쳐 입력할 수 있다. 실제 사용 통계는 없으므로 09:00·10:00·14:00·19:00은 제안값이다. 화면 높이 최소화가 더 중요하면 A를 선택할 수 있다.

## 최근 사용의 데이터 근거

`frontend/src/lib/class/class-wizard.ts:39`의 draft에는 단일 `timeMin`만 있고, 같은 파일의 초기 상태(`:116`)는 15:00이다. 검토한 마법사 상태·일정 화면에는 최근 사용 시각 전용 상태·목록이 없다. 전체 서비스에 데이터가 없다는 뜻은 아니다. 기존 클래스 일정에서 추출할 수 있는지, 조회 권한·범위·정렬·개인정보 정책은 확인하지 않았다. 따라서 시안에 실제처럼 보이는 최근 사용 칩을 넣지 않았다. 도입한다면 별도 승인 후 근거 있는 최대 3개 시각과 빈 상태 정책을 정한다.

## 대표 결정 질문

1. 기본 진입은 B의 빠른 칩으로 할까요, A의 상시 스테퍼 또는 C의 목록으로 할까요?
2. B 선택 시 기본 시각 09:00·10:00·14:00·19:00을 유지할까요? 다른 운영 시각이 있나요?
3. 최근 사용은 이번 변경에서 제외할까요, 별도 후속 기능으로 검토할까요?

## 토큰·현재 화면 근거

- `frontend/src/components/class/player/shared/player-tokens.css:5` 이후: #5F0080, #B373EF, #D2AEFC, #F7F4F0, #CFC6D6, sheet rgba(24,12,36,.58), 경계 rgba(255,255,255,.14), 반경 24/16px, 44px 타깃, Pretendard 계열 스택 복사.
- `frontend/src/components/class/flow/host/host-flow-create.css:38`~`:56`: 반응형 일정 그룹, 5열 소요 시간 칩, 44px 스테퍼 버튼.
- `frontend/src/components/class/flow/host/wizard-steps.tsx:195`~`:214`: 소요 시간 바로 선택; `:245`~`:273`: 시·분 분리; `:291` 이후 예약 알림.
- 기존 `frontend/public/images/background4.webp`의 숲 배경을 인라인 base64로 복사. 정확한 전달 스크린샷 파일은 제공되지 않아 픽셀 일치 비교는 하지 않았다.
- Pretendard 폰트 파일은 내장하지 않았다. 같은 폰트 스택을 적용하며 설치 여부에 따라 시스템 한글 폰트로 표시된다.
- 날짜·소요 시간·예약 알림은 변경 범위 밖이므로 시안에서 정적 문맥으로 표시한다. 현재 소스에 없는 횟수·요일은 새로 만들지 않았다. 제품 내 기존 기능 보존은 후속 구현 시 검증한다.

## 검증과 한계

Chrome headless + 기존 설치 Playwright로 1280×900·390×844 총 6개 조합을 검증했다. 제품 앱 빌드는 실행하지 않았다.

- 6/6 예시 이동 결과 09:00 반영, 가로 넘침 없음, 보이는 button/input/select 모두 44×44px 이상, 페이지 JS 오류 없음.
- A/B 직접 입력·↑↓·5분이 아닌 입력 거부, C 22:00 경계 확인. index 탭 전환·세 안 나란히 표시 확인.
- 저장된 모바일 A·데스크톱 C 캡처를 직접 열어 숲 배경·카드·예약 알림 배치를 확인했다.
- C의 자동화 `selectOption`은 값 반영 검증이며 네이티브 팝업의 실제 2탭 증명이 아니다. 화면의 '시각 조작' 계수도 값 변경 횟수이며 OS 선택기 내부 터치 횟수와 다르다.
- 실기기 앱 WebView, iOS/Android 선택기, 실제 화면낭독기, 배포본 동작, 제품 API·서버·최근 사용 데이터는 미확인이다. 다른 검증자에 의한 독립 리뷰는 미실시.
- Stage ③ Verify 문서를 사후 작성하지 않았다. `verify-design.cjs`는 독립 HTML 시안 검증용이며 제품 구현 게이트 문서가 아니다.
