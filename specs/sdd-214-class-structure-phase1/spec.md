## 용어 풀이 (이 문서 한정)

| 용어 | 뜻 |
|---|---|
| 클래스 | 명상 프로그램(상위). 회차(세션)를 묶는 단위. 예: `MBSR 봄` |
| 상담 관계 | 상담의 상위 단위. 내담자 1명 + 상담사 1명 (`counseling_relationships`) |
| 보관용 관계 | 내담자가 아직 정해지지 않은 상담 세션을 담는 상담사별 임시 관계(`is_placeholder`). Phase 1 에서 새 상담 세션은 모두 여기에 들어간다 |
| 부모 | 세션의 상위. 명상은 클래스, 상담은 상담 관계. 비템플릿 세션은 부모가 정확히 하나 |
| 가산(추가형) | 기존 것을 바꾸거나 지우지 않고 새 테이블·새 컬럼만 더하는 변경 |
| 복합 외래키(복합 FK) | 두 컬럼 묶음으로 거는 외래키. 예: `(class_id, host_id)` 가 해당 클래스의 강사 행이어야 함 |
| 데이터 초기화(Z) | 정식 릴리스 전 전제에서 기존 데이터를 모두 지우고 새 구조로 시작하는 일회성 절차. 마이그레이션이 아니라 별도 수동 절차 |
| dual-write | 새 부모를 만들되 `sessions` 의 기존 컬럼도 그대로 채우는 방식. 엔진이 세션만 읽기 때문 |

## 목적

기획 `§9 Phase 1` 의 목표에서 **"기존 데이터 이전"을 뺀다.** 새 구조의 데이터 뼈대와 제약을 만들고, 기존 데이터는 지운 채 새 구조로 시작한다. 사용자에게는 아무 변화가 없다.

- Phase 2(명상 클래스 읽기·IA 전환)와 Phase 6(상담 영역)이 올라설 바닥을 만든다.
- 이후 모든 Phase 가 기대하는 불변식(부모 정확히 하나, 진행자는 해당 클래스 강사, 회차 번호 유일)을 **데이터베이스가 처음부터** 지키게 한다.
- 세션 id·참여자 id·`/sessions/*` 61개 계약·엔진은 바꾸지 않는다.
