# [SDD-104] — Verification (Pre-Implementation)

## Test Scenarios

### TS1: 입장 시 관리 레이아웃 즉시 렌더 (ready)
1. 상담사로 로그인 → 클래스 생성 → [입장] (ready/scheduled 상태).
2. 예상: `HostClassWorkspace` 관리 레이아웃(좌측 패널 + 참가자 그리드)이 즉시 표시되고, 별도 "미디어 프리뷰 전용 화면"은 없다.
- **Expected:** 좌측에 카메라/마이크 체크 + [클래스 오픈], 우측에 "아직 오픈 전" 빈 그리드.

### TS2: 오픈 → 동일 레이아웃에서 참가자 그리드 활성화
1. TS1 상태에서 [클래스 오픈] 클릭.
2. 예상: 화면 전면 교체 없이, 좌측이 셀프뷰+코드로, 우측 참가자 그리드가 실시간으로 전환.
- **Expected:** 레이아웃 골격(좌/우 분할) 유지, 코드 "오픈 후 공개" → 실제 코드 활성화.

### TS3: 시작 → 종료 연속 진행
1. 오픈 상태에서 [시작하기] → in_progress → [종료] (2단계 확인).
2. 예상: 같은 관리 레이아웃에서 라이브 지표/녹음 활성화 후 종료 씬으로 전환.
- **Expected:** 종료(완료) 씬만 유일한 화면 전환.

### TS4: 참여자 0명 단독 진행 (SDD-101 회귀)
1. 참여자 없이 오픈 → 시작 → 종료.
2. 예상: 단독 시작 허용, 상담사 리포트 생성.
- **Expected:** 기존 동작 회귀 없음.

### TS5: 오픈 전 빈 그리드·코드 가림
1. ready 상태에서 우측 그리드 문구 + 좌측 코드 영역 확인.
- **Expected:** "아직 오픈 전" 안내 + "오픈 후 공개" 가림.

## Edge Cases
- [ ] 카메라/마이크 권한 거부 상태에서도 [클래스 오픈] 가능(기존 SessionPreJoinPreview 폴백).
- [ ] 미디어 미지원 브라우저(Safari)에서도 관리 레이아웃 정상 표시.
- [ ] 오픈 직후 새로고침 → open 상태로 관리 레이아웃 유지(세팅 씬 미복귀).
- [ ] 모바일(390×844)에서 좌/우 패널 세로 스택 정상.

## Security Review
- [ ] 미디어 프리뷰 스트림은 오픈 전 getElementById 로컬 전용(서버 전송 없음) — 기존 SessionPreJoinPreview 동작 유지.
- [ ] 상태 전이 API 호출은 기존 `transitionSession` 그대로(권한 검증 변경 없음).
