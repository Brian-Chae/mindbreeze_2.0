# UX 리뷰 — MB 2.0 라이브 세션 개선 (Cursor)

> 역할: UX 리뷰어  
> 근거: 1.0 `SessionScreen` / `GuestMeditationScreen` / `useSocket` vs 2.0 `SessionLivePage` / `GuestMeditationPanel` / `useBand` / `useSessionLiveSocket`  
> 범위: 코드 수정 없음. 웹 이식 설계 + 우선순위만.

---

## 지도사 모니터링 UX 개선

### 1.0이 잘한 점 (유지·이식 가치)

| 패턴 | 코드 근거 | UX 의도 |
|------|-----------|---------|
| DashboardBox 4종 | `SessionScreen` + `DashboardBox.tsx` — 참여자 / 접촉불량(SENSOR_FAILURE) / 기기연결 실패(CONNECTION_FAILURE) / 배터리&lt;25 | 한눈에 “지금 개입할 사람” 수 |
| 60초 무응답 행 강조 | `getRowColor`: CONNECTION_FAILURE \| SENSOR_FAILURE \| `now - updatedAt > 60000` → 적색 배경 | 폴링 공백·업로드 중단을 행 단위로 발견 |
| 업로드 경과 표시 | `TimeSince` on `updatedAt` | “몇 초/분 전 마지막 갱신”으로 지연 체감 |
| 행 롱프레스 → 자리/이름 수정 | `onLongPress` → `patchSessionLogUser` | 현장 좌석 배치·오타 즉시 보정 |
| 시작 가드 | `disabled={!connected \|\| sessionLogs?.length === 0}` | 소켓·참가자 없이 시작 방지 |

### 2.0 현황 진단

이미 이식된 것:
- `SessionMonitorSummary` 4박스 + **클릭 필터**(1.0에는 없던 개선).
- `SessionMonitorTable` — 이름/접촉/연결/배터리/평균·현재 휴식도/업로드.
- WS `eeg_feature` 우선 + REST 4초 폴백 (`SessionLivePage`).

아직 부족한 것:
1. **60초 무응답 행 강조 없음** — `last_eeg_at`은 메트릭/이벤트에 있으나 테이블 행 스타일에 미사용. lead_off만 `bg-[#FDECEC]`.
2. **“마지막 갱신” 상대시간 컬럼 없음** — 업로드 상태 라벨(`streaming`/`delayed`…)만 있어, 1.0 `TimeSince`만큼의 시간 감각이 약함.
3. **자리번호·인라인 편집 없음** — 웹에 롱프레스는 부적합. 행 액션이 전무.
4. **접촉 vs 연결 컬럼 의미 혼선 가능** — 1.0은 deviceStatus를 접촉/기기연결 두 렌더로 분리. 2.0은 `device_status`(ok/lead_off/…)와 `band_connected` 병행. SQI&lt;40→`lead_off` 파생만 있어, 1.0의 SENSOR vs CONNECTION 4종과 1:1이 아님.
5. **배터리 임계값 불일치** — 1.0 `&lt;25`, 2.0 summary `&lt;20`. 운영 기준 통일 필요.
6. **시작 전 모니터가 빈약** — 2.0은 시작 전에도 테이블 미리보기 있음(좋음). 다만 Dashboard 4박스는 `isRunning`일 때만 노출 → 대기실에서 접촉/배터리 조기 점검 불가.

### 웹 반영 설계

#### A. Dashboard 4종 — “상태 요약 + 필터”로 고정

- 현재 `SessionMonitorSummary` 구조를 유지하되, **경고 박스에 건수&gt;0일 때 시각적 경고 톤**(1.0 `warningCheck` 배경)을 추가. 선택은 유지.
- 시작 전(`ready`/`scheduled`)에도 4박스 노출: 참여자만 의미 있고 나머진 0이어도, 호스트가 “대기 → 점검 → 시작” 멘탈모델에 맞음.
- 라벨 카피: 1.0 “밴드 베터리 부족” → 2.0 “배터리부족” 유지하되 임계값 문구를 툴팁으로 (`배터리 20% 미만`).

#### B. 60초 무응답 행 강조 (P0 핵심)

- 행 위험 조건(OR):
  - `device_status === 'lead_off'`
  - `!band_connected || device_status === 'disconnected'`
  - `last_eeg_at` 존재 && `Date.now() - last_eeg_at > 60_000` (세션 `in_progress`일 때만)
- 시각: 행 배경 경고색 + 좌측 3px accent bar(테이블에서도 스캔 가능).
- 업로드 컬럼에 `last_eeg_at` 상대시간 보조 텍스트 (`12초 전` / `2분 전`) — 1.0 `TimeSince` 웹 대응.
- WS 연결 시에도 `last_eeg_at`을 feature 수신마다 갱신(이미 `applyEegFeatureToMetrics` 수행) → **폴링 없이도** 무응답 감지 가능. 이게 1.0 대비 2.0의 구조적 우위.

#### C. 행 편집 — 롱프레스 대체 인터랙션

모바일 롱프레스는 웹에서 발견 불가·터치패드 오작동. 대체안:

| 인터랙션 | 용도 | 권장 |
|----------|------|------|
| 행 우측 `⋯` 또는 이름 hover `편집` | 표시명(게스트)/자리번호 | **1안 (권장)** |
| 더블클릭 인라인 | 빠른 수정 | 접근성·실수 위험으로 보조만 |
| 키보드: 행 포커스 + `E` | 파워유저 | P2 |

편집 모달 필드: **자리번호(선택)**, **표시 이름**. API는 참가자 PATCH(기존 게스트명/메타). 현장 클래스는 자리번호가 지도사 호출의 1차 키이므로 테이블 첫 컬럼에 `seat` 복원 권고.

#### D. 1.0 단점 — 그대로 가져오지 말 것

1. **폴링 지연**: `OPERATOR_INTERVAL_TIME = 2500`ms 전량 refetch. 접촉불량→지도사 인지까지 최대 ~2.5s+네트워크. 브리프의 “1초”보다 실제는 2.5초. 2.0은 WS 푸시를 주채널로 두고, 폴링은 **폴백·정합 스냅샷**만.
2. **DashboardBox 비인터랙티브**: 1.0은 숫자만. 2.0 필터는 유지·강화.
3. **수동 “화면 새로고침”**: WS+자동 폴백이면 1차 CTA에서 제거하거나 Advanced에만.
4. **모바일 전용 제스처**: 롱프레스·태블릿 가로 테이블 밀도. 웹은 데스크톱 밀도(열 더 많음) + 반응형 카드 스택을 분리.

#### E. 정보 설계 권고 (테이블 열)

우선순위 열 순서(좌→우):
`자리` → `이름` → `접촉` → `연결` → `배터리` → `현재 휴식도` → `평균` → `마지막 신호` → `업로드` → `⋯`

- 현재 휴식도는 lead_off/무응답 시 `-` 강제(1.0: CLEAR일 때만 efficiencies 표시). 지도사가 오염 숫자를 신뢰하지 않게.

## 접촉불량/LeadOff UX 이식

### 1.0 동작 요약 (게스트)

코드: `GuestMeditationScreen` + `LeadOffModal` + `useSessionLogUploader` + band `leadOff{left,ref,right}`.

1. **전극 단위 접촉 상태** — 1.0 Redux `leadOff`: `true`=접촉 양호(센서 UI 초록), `false`=불량(빨강). 네이밍이 표준 “lead-off”와 **반대**라 이식 시 반드시 재명명.
2. **전체 양호** `every(true)`일 때 큰 숫자 표시; 불량 시 `-`.
3. **불량 시 `LeadOffModal`**: “LINK BAND 위치를 조정해주세요” + `SensorTrackerContainer`(좌/우/ref 전극 시각) + “무시하기”.
4. **양호 복귀 직후 15초 `AI 분석중`** (`isAnalyzingRef` + `BlinkingText`) — 안정화 버퍼. 그 동안 숫자를 숨김.
5. **지도사 측**: `SENSOR_FAILURE` vs `CONNECTION_FAILURE`로 Dashboard/행 색 분리. 업로더는 `some(false)`→SENSOR, `!isConnected`→CONNECTION.

### 2.0 현황

- `useBand.deviceStatus`: 연결 끊김→`disconnected`, SQI&lt;40→`lead_off`, 그 외 `ok`/`unknown`. **채널 단위 LeadOff 미노출**.
- EEG 타입에는 `LeadOffStatus { ch1, ch2 }` (`true`=분리)가 이미 정의됨 — SDK 경로와 UI 미연결.
- `GuestMeditationPanel`: 접촉을 사이드 리스트 한 줄(`정상`/`불량`)로만 표시. 모달·AI 분석중·전극 다이어그램 없음.
- 호스트: summary/테이블의 `lead_off` 집계만. 참가자에게 “지금 고쳐라”는 푸시 UX 없음.

### 이식 원칙

1. **용어 통일**: UI 카피 = “접촉불량”. 내부 상태는 2.0 SDK 의미(`true`=분리)를 따르고, 1.0 boolean 반전을 그대로 복사하지 말 것.
2. **신호 소스 계층**  
   - L1: 채널 LeadOff(가능하면)  
   - L2: SQI/signal_quality 임계  
   - L3: BLE disconnect  
   DeviceStatus 매핑: L3→`disconnected`, L1\|L2→`lead_off`, else `ok`.
3. **숫자 신뢰성 가드**: lead_off 또는 analyzing 중에는 큰 숫자/`current_efficiency`를 `-` 또는 플레이스홀더로. WS로 호스트에 올리는 feature에도 `device_status: lead_off` 유지(이미 emit 경로 있음).

### 게스트(참여자) UX 설계

```
[접촉 불량 감지]
  → 전체 화면 LeadOffSheet/Modal (웹)
      · 제목: LINK BAND 위치를 조정해 주세요
      · 본문: 전극 밀착 안내 (1.0 카피 정제, 웹 단락)
      · 시각: 2채널 헤드밴드 심플 다이어그램 (ch1/ch2 점등)
      · CTA: “확인했어요” (dismiss) — dismiss해도 불량 지속 시 상단 배너는 유지
  → 메인 지표 영역: 깜빡임 “신호 안정화 중” (카피 후보)
      · 1.0 “AI 분석중”은 실제 LLM이 아니므로 웹에서는 과장 카피 지양
      · 권장: “신호 안정화 중…” / 보조: “전극이 밀착되면 수치가 다시 표시됩니다”
      · 타이밍: 접촉 회복 후 10~15초 (1.0 15초 유지 가능)

[접촉 회복 + 안정화 종료]
  → 큰 숫자 + 차트 재개
```

Dismiss 정책: 1.0 “무시하기”는 모달만 닫고 상태는 유지. 2.0도 동일 + **지속 불량 시 compact 배너**(모달 재오픈 링크).

### 호스트 UX 설계

- Dashboard `접촉불량` 클릭 → 해당 행만 필터(이미 있음).
- 행에 **토스트/인라인 힌트** 불필요. 대신 행 hover 시 “참여자 화면에 접촉 안내가 표시 중” 정도의 상태 칩(게스트가 dismiss했는지까지는 P2).
- 호스트 본인 밴드(`SessionLivePage` useBand): 동일 LeadOffSheet를 **비차단 배너**로 — 지도사는 모니터링이 1순위라 풀모달 지양.

### 1.0 단점 / 이식 시 주의

- **“AI 분석중” 오해**: 사용자에게 AI 파이프라인으로 보임. 웹 카피는 정직하게.
- **leadOff 네이밍 반전**: 그대로 포팅 시 버그 확정. 2.0 `LeadOffStatus` 주석 기준으로 재구현.
- **모달 라우트 가드** (`currentRoute.name === 'GuestMeditation'`): 웹은 패널 mount 여부로 충분.
- **전극 3점(left/ref/right) vs 2.0 2채널**: 다이어그램은 ch1/ch2만. ref UI 강요 금지.
- **SQI만으로 lead_off**: 일시 노이즈에 깜빡일 수 있음 → **N초 연속 임계**(예: 3초) 후 모달, 회복도 debounce.

## 참여자 명상 화면 웹 대응

### 1.0 구성 (몰입형)

- 풀스크린 블랙 + `FadingImageBackground` 순환.
- 좌: **진행시간** (`Timer` Text130B급) / 우: **두뇌휴식도** 초대형 숫자 또는 “AI 분석중”.
- 하단: `BrainChart` (D3 바, 값&gt;40 강조).
- FAB: **화면 끄기/켜기** — 절전 모드에서는 타이머만 남김(밝기 API는 주석 처리, UI 오버레이로 대체).
- 종료 확인 모달: “리포트를 받아볼 수 없어요.”

### 2.0 현황 (`GuestMeditationPanel`)

- 그라데이션 카드 안 레이아웃: 타이틀 + `mm:ss / 목표` + 두뇌휴식도(~text-6xl/7xl) + SVG sparkline + 밴드 상태 aside.
- **없는 것**: 절전 모드, LeadOff 몰입 오버레이, 배경 이미지 페이드, 초대형 타이머 대칭 레이아웃, 종료 시 리포트 경고 카피.
- 차트는 연결 시에만 막대 sparkline — 역할은 유사하나 시각 밀도·몰입감은 1.0보다 약함.

### 웹 대응 설계

#### 1) 레이아웃 — “몰입 우선, 데스크톱 2열”

**모바일/세로(참여자 폰 브라우저 주 타깃)**  
```
[종료]     이름/자리
     진행시간 (중)
  두뇌휴식도 (영웅 숫자)
     BrainChart
[밴드 연결]     [화면 절전]
```

**데스크톱**  
- 좌 60%: 숫자+차트 / 우 40%: 타이머·밴드·안내 — 현재 그리드 유지하되 숫자 스케일을 1.0에 가깝게(최소 clamp `min(18vw, 7rem)`).
- AppShell 크롬(글로벌 내비)은 게스트 명상 중 **숨기거나 최소화** — 몰입 방해.

#### 2) 영웅 숫자 + 차트

- 숫자: 휴식도 정수, lead_off/안정화 중에는 플레이스홀더 문구.
- 차트: 최근 60포인트(이미 `CHART_MAX_POINTS`) 바/스파크. 1.0처럼 “높을수록 밝기” 정도의 단순 부호화면 충분. 장식용 그라데이션 남발 금지(운영 화면).
- 밴드 미연결: 숫자 `-` + 연결 CTA 강조. WS remote efficiency만 있는 경우(타 기기?)는 보조 문구 유지.

#### 3) 타이머

- 1.0: 경과만. 2.0: 경과/목표 — **목표 병기는 웹에서 유지**(수업 길이 인지에 유리).
- 호스트 종료 시 화면 전환은 소켓 이벤트에 맡기고, 로컬 타이머는 `startedAt` 기준(이미 구현).

#### 4) 화면 절전 (웹 제약 명시)

네이티브 밝기 API 없음. 웹 대안 스택:

| 수단 | 역할 | 비고 |
|------|------|------|
| UI dim 오버레이(검정 90% + 중앙 타이머) | 1.0 `isScreenOff`와 동일 체감 | **P0** |
| `navigator.wakeLock` (Screen Wake Lock) | 절전 해제 시 스크린 꺼짐 방지 | 지원 브라우저만, 실패 silent |
| Page Visibility 안내 | 백그라운드 시 측정 중단 가능 고지 | P1 |

절전 ON: 차트·숫자 숨김, 타이머+“화면 켜기”만. 밴드/업로드는 **백그라운드 유지**.

#### 5) 1.0 단점 — 웹에서 버릴/줄일 것

- **배경 이미지 10장 페이드**: 대역·주의 분산. 웹은 단색/약한 그라데이션 + 충분한 여백으로 대체(브랜드 톤은 기존 purple 계열 유지하되, 마케팅 랜딩과 분리된 “세션 도구” 톤).
- **모바일 전용 제스처·헤더 버튼 밀도**: 웹은 명시적 버튼.
- **1초 PATCH 폴링 업로더**: 2.0 WS emit이 상위. 절전 중에도 WS 유지.
- **초대형 폰트만으로 정보 부족**: 접촉/배터리 완전 숨김은 위험 → 절전 아닐 때 status chip 한 줄은 유지.

#### 6) 호스트 vs 게스트 비대칭

- 게스트: 몰입형 명상 패널(본 섹션).
- 호스트 `SessionLivePage`: 모니터링이 본업 — 본인 밴드는 compact. 게스트와 동일 풀스크린 명상을 호스트에 강제하지 말 것.

### 명시적 Non-Goals (이번 UX 범위)

- 1.0 Mongo SessionLog 스키마·1초 HTTP PATCH 재도입.
- 네이티브 밝기 API·앱 전용 롱프레스.
- “AI 분석중” 카피의 문자 그대로 복제.
- 호스트 화면을 게스트 명상 UI와 동일 풀스크린으로 통일.

### 한 줄 결론

2.0은 이미 **WS + 필터 가능한 Dashboard**로 전송 계층은 1.0을 앞서 있으나, **무응답 행 강조·LeadOff 안정화 UX·명상 절전**이 비어 운영 현장감이 약하다. P0로 이 세 축을 웹 네이티브 인터랙션으로 채우고, 1.0의 폴링·롱프레스·과장 카피는 이식하지 않는 것이 맞다.
