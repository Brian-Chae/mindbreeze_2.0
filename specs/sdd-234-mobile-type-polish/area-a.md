# SDD-234 A — 홈 모바일 글자·간격 결과

## 범위와 판단

- 작업 브랜치 `sdd/234-a-home`. 공통 기반과 develop 반영 상태에서 A 소유 파일만 변경했다. 기능·상태·API·문구·데스크톱 스타일·레일 16/15/13px 규격은 유지했다.
- `screens/before`는 공통 기반 이전 기록이다. PR #60과 공통 기반이 포함된 현재 시작점을 `screens/before-a`로 추가 보존했다. 데스크톱 불변 판정은 이 시작점과 `after-a`를 비교한다.
- 767px 이하 의미 토큰을 적용했다. 상태 라벨/동작은 14/20, 캡션은 13/20, 카드 본문은 15/24, 클래스 제목은 18/27, 히어로는 24/32, 주요 숫자는 28/34다.
- 통계 152px/18px 패딩, 클래스 304px/24px 패딩, 반경20, 섹션 간격24를 유지했다. 기본 크기에서 통계 하단 여유47px, 클래스 하단 여유25px이고 내부 scrollHeight=clientHeight다.
- 히어로 메타 박스는 두 줄을 수용하도록 양쪽 모두 모바일 최소68px로 맞췄다. 같은 fixture에서 양쪽 히어로 높이276px로 일치한다. 긴 문구는 자동 높이로 확장한다.

## 검증 결과

- 신규 Chrome 회귀 6개: 실제 라우트 390/768/1440 렌더. 모바일 하한·CTA48·터치44·가로 넘침, 768/1440 `texts/touches/spacing` 전체 값 비교(클래스 문자열 제외).
- RED: 수정 전 회원 작은 글자·상담사 40px 버튼으로 2개 실패. 추가 CTA48 검사에서 회원 코드 입장44px 실패를 확인하고 선택자 우선순위를 보정했다.
- 관련 vitest 9파일/55개 통과. 타입 검사, 변경 TSX/신규 테스트 eslint, production build 모두 exit 0. 빌드 CSS의 mobile 토큰·중요도 지정 높이 규칙 생성도 확인했다. 최종 실행 로그는 `checks/area-a-*` 참고. 전체 vitest는 실행하지 않았다.
- 768/1440 회원·상담사 총12개 계산 스타일 배열 비교가 동일하다. 모바일 클래스 문자열 이외의 텍스트·글자·행간·좌표·크기·패딩·간격을 그대로 비교했다.
- 합성 API 라우트 렌더·JS 오류·미등록 API 0. Chrome executablePath는 요청 경로를 사용했다. 외부 요청/웹소켓 차단, 빈 envDir로 실행했다. 빌드는 원본 Vite 설정을 import한 임시 설정에서 빈 envDir만 주입해 `npm run build -- --config ...`로 실행했다.
- `area-a-check.cjs --parity`: SDD-233 원본 코드를 실행하되 산출물 경로만 A 디렉토리로 바꾼다. **기존 레일의 minHeight 0 != 200 조건 8건으로 실패**한다. 다른 규격 차이는 없다.
- `--parity --rail-contract`: 원본 parity 비교를 유지하면서 레일은 PR #60의 최소 높이0 계약으로 따로 검사한다. 양쪽 홈 390/1440 카드 개수·규격·히어로·간격·넘침 실패0. 원본 스크립트/기존 산출물은 수정하지 않았다.
- 독립 검증자가 제품 diff·실측 JSON·390 캡처를 확인했다. 중요 구현 결함 없음. 아래 확대 검증 한계를 별도로 지적했다.

## 잔여 후보·공통 요청

- 회원·상담사 `.home-rail-card span.rounded-full.text-\\[12px\\]`: 기존 읽지 않은 대화 수 배지12px(각1개).
- 상담사 `.home-rail-card div.h-10.w-10`: 기존 아바타 이니셜12px(1개).
- 위 3개는 이번 요청의 PR #60 레일 유지 지시를 우선해 변경하지 않았다. 통합 담당이 원시 후보0을 요구한다면 해당 selector의 모바일 캡션 토큰13/20 적용 여부를 결정해야 한다. 기존 이름16·본문15·시간13·최소 높이0은 그대로다.
- 공통 제품 파일 수정 요청은 없다. 공통 검증 파일 `specs/sdd-233-home-stats-floating-nav/parity.cjs`에는 `.home-rail-card`를 일반 패널 최소200 검사에서 분리하고 최소0을 확인하는 업데이트가 필요하다.
- 768px 상담사 폭44 미만 후보1은 수정 전과 동일한 데스크톱 영역이며 변경하지 않았다.

## 검증 한계

- OS fallback 글꼴의 Chrome headless 합성 데이터 검증이다. 실기기/iOS 키보드/BLE/LiveKit/실서비스 API 증거가 아니다.
- 390/767에서 긴 한글·URL을 히어로에 주입하고 글자 크기를200%로 바꾼 추가 검사: 문서 가로 넘침0 및 히어로 CTA48 유지. **확대 후 고정 카드 전체의 내부 잘림·겹침·모든 조작 접근성은 검사하지 않았으므로 200% 전체 통과를 주장하지 않는다.** 통합 후 별도 확대/실기기 QA가 필요하다.
- 빌드의 기존 dynamic import/plugin timing 및 Tailwind screen object 경고는 남는다. 검사나 빌드 실패는 아니다.
- SDD 전체 완료/배포 판정은 감독의 A~D 통합 검증 후 진행한다. PR·머지·develop 푸시·배포 없음.
