## 근거와 범위

- 15~16px 본문과 13px 보조 하한은 Brian 요청 및 현재 `sm=15px`와 홈 규격을 고려한 제품 결정이다. WCAG가 최소 폰트 16px를 의무화한다고 주장하지 않는다.
- 독립 터치 44×44는 [W3C 2.5.5 Target Size](https://www.w3.org/WAI/WCAG21/Understanding/target-size) AAA 기준을 제품 기준으로 채택한다(AA 최소 규칙과 구별).
- 행간은 [W3C C21](https://www.w3.org/WAI/WCAG21/Techniques/css/C21.html)의 읽기 지원 원칙을 참고한다. 1.4.12 사용자 텍스트 간격 변경 허용과 기본 스타일 수치 의무는 구별한다.
- MB의 퍼플·라이트 앱 셸/다크 클래스 진행 테마, 기존 폰트 계열은 유지. DESIGN.md의 일반 다크 방향을 근거로 현재 앱 색상을 바꾸지 않는다.

## 측정 계약

`measure.cjs`는 합성 API로 실제 라우트를 렌더한다. 앱 화면은 AppShell/ClientShell/StructureShell 포함, 입장·로비·진행은 기존 독립 flow/player 하니스임을 JSON shell로 구분한다. 외부 네트워크·웹소켓은 차단하며 빈 envDir로 .env를 로드하지 않는다.

390×844 기본, 768/1440 회귀. 텍스트 직접 노드 기준(부모 중복 제외) computed font-size/line-height/weight, 터치 bbox, 카드/섹션 padding/gap/margin과 선택자를 저장한다. 작은 글자 비율은 **12px 이하 요소 수 / 텍스트 요소 수**다. 화면 아래 스크롤 콘텐츠도 포함하며 숨김/aria-hidden은 제외한다. 간격 위반은 4px 단위 미일치 후보로, 예외 검토 없이 자동 불합격 처리하지 않는다.

폰트 외부 다운로드 차단으로 OS fallback으로 실측한다. 실제 기기/iOS 키보드/BLE/LiveKit/실서비스 API 증거가 아니다. 후속 통합 검증에서 실기기 확인이 필요하다.
