# SDD-307 — 상담사 클래스 오픈부터 시작까지 간소화

- 작성일: 2026-11-05 / 브랜치: `sdd/307-host-open-to-start-flow`
- 상태: 분석·기획·시안 검토안. 구현 승인 전. Stage ③ 검증 문서가 아니며 제품 구현을 수행하지 않는다.
- 입력: `~/.hermes/share/briefs/plan-307-host-open-to-start.md`

## 문제와 범위
상담사가 40명 행사장에서 회원에게 입장 코드를 알려 주면서 준비 상황을 살피고 수업을 시작해야 한다. 현재 대기실 본문에는 코드가 없고 초대 시트를 열어야 한다. 열기·시작·시작 확인이 연속되어 목적이 비슷한 버튼을 반복해서 누른다.

범위는 기존 클래스의 목록·상세 진입 → 장비 점검 → 열기 → 대기실 → 첫 시작이다. 진행 중 재입장과 녹음 재개는 경계 조건으로 분석한다. 클래스 생성 화면, 새 회차 생성, 회원 동의 정책 변경, 제품 코드·서버 변경은 이번 작업 밖이다.

## 확인한 현행
- 목록 버튼은 `바로 입장`, 상세는 `진행 화면으로`이다. 모두 이미 열려 있으면 대기실, 진행 중이면 라이브로 분기한다.
- 첫 시작은 회차 상세 기준 4탭, 온라인 마이크 비활성은 5탭. 아직 열지 않은 회차를 클래스 목록에서 찾는 경로는 각각 6/7탭. 녹음을 끄는 선택은 별도 1탭이며 브라우저 권한 요청은 기기 환경에 따라 추가된다.
- 첫 시작 직후 별도 녹음 동의 모달은 없다. 시작 시트의 녹음 선택은 기본 선택 상태다. 진행 중 녹음 시작은 별도 동의 모달을 연다.
- 대기실 코드는 초대 시트에만 있다. 라이브 상단에는 코드 및 크게 보기, 확대창 안에 복사가 이미 있다.
- 회원 준비, 녹음 동의, 연구 활용 선택은 다른 데이터다. 현재 대기실 모델만으로 `동의 K명`이나 `밴드 연결 M명`을 계산하면 안 된다.
- 근거와 조건별 수치는 plan.md에 기록한다. 실제 제품 화면·서버·기기 실행은 이번 분석에서 검증하지 않았다.

## 대안과 선택 제안
|항목|A: 화면 유지·확인 인라인 통합|B: 준비·대기실 통합 작업 공간|
|---|---|---|
|열기 전|기존 장비 점검 유지, 마이크 경고를 인라인으로|같은 화면에서 장비 점검·회원 초대 정보 제공|
|열기|명시적 1탭, 서버 open 유지|명시적 1탭, 준비 영역이 대기실로 전환|
|시작|고지와 녹음 선택을 대기실에 상시 표시, 시작 1탭|같은 화면에서 시작 1탭|
|탭 수|회차 상세 4/5 → 3, 목록 6/7 → 5|회차 상세 4/5 → 3, 목록 6/7 → 5; 화면 전환 감소|
|장점|현재 상태 전이·API 유지, 변경 영역이 작음|준비와 대기 맥락을 이어서 볼 수 있음|
|위험|기본 녹음 선택의 인지가 약해질 수 있음|장비 스트림 수명·반응형 재배치·재입장 처리 범위 확대|
|시점|11/11 전 후보|행사 후 검토|

A를 행사 전 제안으로 삼는다. 목록 진입만으로 자동 open 하지는 않는다. 열기는 회원 입장·알림에 영향을 주므로 사용자의 명시적 행동을 보존한다. B도 자동 시작하지 않는다.

## A 수용 기준
1. 대기실 상단에 유효한 4자리 코드, 복사, 크게 보기, 초대 링크 공유를 노출한다. 코드 조회 실패는 `코드 확인 중`으로 표시하고 공유를 막는다.
2. 녹음 선택·보관 고지·접근 대상 안내를 시작 버튼 바로 위에 둔다. 온라인 마이크 꺼짐은 `음성 없이 클래스 열기`와 결과 안내로 한 번만 선택한다. 오프라인은 현장 녹음과 화상 장비를 구분한다.
3. 준비 중 회원·입장 0명은 한 줄 안내이며 시작을 막지 않는다. 일정 충돌의 서버 확인은 보존한다.
4. 클릭 직후 짧은 취소 구간은 서버 호출 전에만 허용한다. 시작 요청 이후는 진행 상태를 조회하며 대기실 복귀를 약속하지 않는다.
5. 서버의 회원별 필수 동의·입장 권한은 변경하지 않는다. 법적 필수 범위는 이 코드 분석으로 판정하지 않는다.
6. 390·768·1280px에서 코드와 주 행동이 읽히고 가로 넘침이 없어야 한다. 40명 명부는 별도 스크롤. 확대 화면에는 회원 이름을 표시하지 않는다.
7. SDD-299 라이브 독의 분석·채팅·미디어(오프라인 녹음)·설정을 유지한다. 대기실 도구 개편은 행사 후이며 행사 전에는 기존 도구 명칭·기능을 유지한다.

## 대표 결정 질문
1. 행사 전에는 A안의 확인 인라인 통합까지 진행할지, 코드 상시 노출·문구 정리만 먼저 진행할지?
2. 시작 버튼을 누르면 2초 동안 취소할 수 있게 할지, 지연 없이 시작할지? (시안은 2초 취소 구간)
3. 행사장 확대 화면은 코드만 표시할지, 검증된 참여 링크가 있을 때 QR도 함께 제공할지? (행사 전 기본은 코드)
