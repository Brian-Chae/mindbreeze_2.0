# [SDD-189] — Verification (Pre-Implementation)

## Test Scenarios
### TS1: 아침 브리핑 생성
설정 08:00, 현재 08:00(KST), 상담사에게 오늘 세션 3건(내담자 3명) → 스윕. **Expected:** `briefing_morning` 메시지 1건, 내담자 실명·회차·온라인/오프라인 포함, 장소·전화·길찾기 없음, 승인 대기 리포트 수 포함.
### TS2: 멱등
스윕 3회 추가 실행. **Expected:** 메시지·로그 각 1건.
### TS3: 시각 윈도우
설정 08:00에서 현재 07:59 → 미생성 / 08:20 → 보정 생성 / 08:40 → 미생성(30분 초과).
### TS4: 일정 없음
skip=true, 일정 없음 → 미생성. skip=false → "오늘 일정이 없어요" 메시지 1건.
### TS5: 저녁 정리
오늘 완료 세션 2건(AI 요약 있음 1, 기록 없음 1), 불참 1건, 내담자 피드백(`disappointed` + 원문 텍스트) 1건. **Expected:** `briefing_evening`에 다룬 주제 요약, "기록 없음", 불참, 리포트 상태, 피드백 **원문 그대로**, 내일 일정. 진단·점수 표현 없음.
### TS6: 상담사 간 격리
상담사 A의 브리핑·대화·relay 목록에 상담사 B 내담자/세션/이벤트가 **없음**(고유 문자열로 검증).
### TS7: relay 목록·처리
본인 target 이벤트만, `status=open`은 handled_at null만, `handled` 호출 후 목록에서 제외, 타인 이벤트 handled → 404.
### TS8: 설정 API
기본값 반환, 수정 반영, "25:00"/"8:0" 등 잘못된 시각 422, 내담자 토큰 403.
### TS9: 상담사 대화
"오늘 일정 알려줘"→ 오늘 일정, "<내담자 이름> 지난 요약"→ 담당 내담자일 때만 요약(타 상담사 내담자 이름은 "찾을 수 없어요"), 변경·발송 요청("메시지 보내줘")은 초안만 안내하고 실행하지 않음.
### TS10: 푸시 Outbox 비식별
채널 push pending 1행, payload에 이름·내용 없음.
### TS11: LLM 폴백·가드
키 없음/예외/진단·점수 응답 모킹 → 정상 폴백·필터.
### TS12: 프론트
상담사 AI 화면 진입·메시지 렌더·CTA 이동, 설정 시트 저장, relay 목록 미처리 우선·처리 버튼, 미읽음 배지. 내담자/타 role 접근 차단(RoleGuard).
### TS13: 계약 교차 대조
`schemas/agent.py` ↔ `lib/api/agent-counselor.ts` 필드·enum 일치.
### TS14: 회귀
`alembic heads` 단일 `e036a0000037`, 전체 pytest/vitest(기존 실패 외) 신규 실패 0, build 통과.

## Edge Cases
- [ ] 같은 내담자가 하루 2세션 → 각각 항목
- [ ] 세션 취소/비활성 내담자 → 취소 표시 또는 제외 규칙 일관
- [ ] 상담사 설정 행이 없으면 기본값으로 동작(행 자동 생성)
- [ ] 다중 기관 소속 상담사는 host 기준 세션 모두 포함
- [ ] 저녁 정리는 마이크 오프/기록 없음 세션에서 오류 없음
- [ ] 피드백 texts 없음(3지선다만) 처리

## Security Review
- [ ] 모든 상담사 API 인증 + role=counselor, 소유자(host/target_user) 검증
- [ ] LLM 프롬프트는 `counselor_context` 반환 데이터만
- [ ] 푸시/이메일 payload 비식별
- [ ] 로그에 내담자 이름·상담 내용 출력 금지
- [ ] 상담사 채널이 내담자 대화 원문을 요약 이벤트 외로 노출하지 않음
