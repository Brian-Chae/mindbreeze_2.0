# SDD-235 — 상담사 모바일 손들기·조용한 신호 바로 보기

- 상태: Stage ① Spec + 디자인 시안 — Brian 검토 대기 (제품 구현 전)
- 브랜치: `sdd/235-host-mobile-signals`
- 작성일: 2026-10-22
- 분석 기준: `origin/develop` / `be0e50e1`, fetch·rebase 후 기존 뼈대 복원.
- 이번 범위: 소스 분석, 기획, 독립 HTML 시안, Chrome headless 검증. 제품 코드·서버·DB·환경변수 접근 없음.

## 문제와 목표

390px 상담사 화면은 녹음·체크인 뒤의 손들기와 조용한 신호가 `+N`에 묻힌다. 새 요청을 인지할 알림도 없다. 참가자 얼굴을 보며 수업을 진행하는 상담사가 신호를 즉시 알아차리고 한 번 탭해 해당 상태와 조치 버튼에 도달하게 한다. 실제 조치는 대상 확인 후 추가 한 번 탭한다. 발언권을 토스트 전체 탭으로 즉시 주지는 않는다.

성공 기준: 모바일에서 손들기·조용한 신호 진입점은 0건에도 같은 위치에 노출; 상태 확인 1탭, 발언권 부여·손 내리기까지 총 2탭. 조용한 신호에 이름·아바타·개별 타일 연결 없음. 소리·진동 없음. 본문 15px 이상, 보조 13px 이상, 터치 44px 이상, 블러 없음. 데스크톱의 기존 레이아웃과 다섯 도크 항목은 유지한다.

## 현재 표시와 접근 단계

아래는 소스 기준이며 dev 실기기 관찰을 새로 수행한 결과가 아니다. 탭 수는 기본 화면에서 상세/조치에 도달하는 최소 경로이며 스크롤은 별도 표기한다. 데스크톱에서도 칩 개수가 많으면 접힐 수 있다.

| 신호 | 현재 데스크톱 | 현재 모바일 390px | 확인 / 조치 탭 수 |
|---|---|---|---|
| 손들기 대기 | 손든 회원 칩, 밴드 상태별 타일 표시, HandsSheet | 칩이 +N 뒤로 접힘; 전원 밴드 미착용이면 타일 손들기 표시도 없음 | 칩 노출 1/2, 접힘 2/3; 상세 조치에는 HandsSheet 필요 |
| 발언권 있음 | 첫 발언자 이름 칩·회수 버튼, 타일, HandsSheet 전체 목록 | 이름·회수도 접힘; 전원 미착용 타일에는 발언 상태도 없음 | 0(칩)/1(회수), 접힘 시 2/3 |
| 조용한 신호 | 양수일 때 합계 칩 → CheckinSheet 하단 익명 집계 | +N → 신호 열기, 또는 도크 체크인 → 아래 스크롤 | 칩 1, 접힘 2; 도크 1 + 스크롤 |
| 체크인 | 전원 밴드 없음일 때 응답 n/m 칩, 도크 체크인 | 같은 구조 | 요약 1, 개인 상세 2 |
| 입장 대기 | 대기 칩 → QueueSheet | +N에 접힐 수 있음 | 노출 1, 접힘 2 (조치는 시트에서 추가 탭) |

| 접촉 불량·낮은 배터리 | 필요 조치 칩 → ActionsSheet | +N에 접힐 수 있음 | 노출 1, 접힘 2 |
| 새 채팅 | 도크 안읽음 배지 → ChatSheet | 동일 | 0(건수)/1(본문) |
| 녹음·카메라·마이크·네트워크 | 녹음 칩·미디어 도크, 오류 배너 | 동일 | 녹음 상태 0, 미디어 조치 1 + 버튼; 오류는 기존 배너 |

### +N의 실제 의미와 원인

`host-player-case.ts`의 칩 생성 순서: rec → checkin(전원 밴드 없음) → speak → hands → actions → queue → signals → myband → first → filter → band. 마지막 range는 선택 항목이다. `fitChipCount`는 선택 항목을 먼저 빼고 뒤에서부터 폭에 맞춰 접는다. 손들기 우선순위 보호는 없다. `+N`은 새 이벤트/사람 수가 아니라 **숨겨진 칩 그룹 수**다. 발언자 그룹에는 회수 버튼까지 포함된다. 정확한 N은 이름·상태·렌더된 폭에 따라 변한다. 특히 `HostParticipantGrid`의 allOff 분기는 손들기/발언권 상태 대신 체크인·접속 상태만 표시한다. Brian의 전원 밴드 미착용 화면에서는 타일도 보완 수단이 되지 않는다. 제안은 미착용 타일에도 손들기/발언권 보조 상태를 유지한다.

`HostChipLine`의 +N은 AlertsSheet를 연다. `chipTarget('signals')`는 체크인으로 연결하며, CheckinSheet의 신호 영역은 체크인/입장 전 응답 뒤에 있고 합계가 0이면 사라진다. `chipTarget('band')`는 null이라 알림 전체에서도 제외된다.

### 데이터 의미와 제한

- 조용한 신호: following(잘 따라가요), difficult(조금 어려워요), resting(잠시 쉴게요). `class:signal` 수신을 참여자별 최신 1건으로 덮어쓰고 최근 10초만 집계. 누적 전송 횟수도 미확인 건수도 아니다. 같은 사람이 종류를 바꾸면 총합은 같을 수 있어 합계 증가만으로 알림을 판단하면 안 된다.
- 현재 호스트 신호 UI는 합계만 전달받는다. 구형 코드 주석의 개인 카드 6초 배지는 현 HostLiveView 동작 근거로 사용하지 않는다.
- 손들기: `speaking_changed`의 raise_hand/speaking으로 갱신. 현재 SpeakingRightsPanel은 손든 사람 → 발언권 있는 사람 → 나머지, 같은 그룹은 이름순. 엄밀한 요청 시간순 대기열이 아니다.
- speaking은 실제 음성 활동 감지가 아니라 **발언권 있음**이다. 제안 문구도 이를 사용한다. 여러 명에게 부여 가능하며 제안에서 임의로 단일 발언자로 제한하지 않는다.
- 발언권 관리 패널은 온라인 그룹·정원 20명 이하에만 제공된다. 다른 수업에는 손들기 칩 대신 적용 안 됨 안내를 제공하고 빈 조치 시트를 열지 않는다.

## 대안 비교와 추천

| 안 | 구성 | 장점 | 비용·단점 | 추천 |
|---|---|---|---|---|
| A. 상시 신호 줄 | 기존 5개 도크 바로 위에 손들기 / 조용한 신호 2개 고정 칩, 발언권 수는 손들기 칩 보조 문구 | 기존 도크 학습 유지, 스크롤해도 신호 보임, 상세 각각 1탭 | 하단 약 76px 추가 사용; 키보드/시트 대응 필요 | **추천** |
| B. 신호 우선 도크 | 손들기 / 신호 / 채팅 / 미디어 / 더보기; 지표·체크인·도구는 더보기로 이동 | 하단 한 줄로 화면 공간 확보, 엄지 접근 | 기존 지표·체크인 접근이 1→2탭, 데스크톱과 위치 차이 | 공간을 최우선으로 할 때 |

A 상세: `손들기 0` + `발언권 0` / `조용한 신호 0` + `최근 10초`. 0도 읽을 수 있는 보조색과 테두리를 사용하고 disabled 처리하지 않는다. 양수는 퍼플 강조와 숫자 배지. 손들기와 signals/speak는 모바일 기존 접힘 줄에서 제외하여 중복하지 않는다. 나머지는 `+N` 대신 `수업 상태` 명시 버튼으로 모으고 녹음 상태는 유지한다. 체크인은 기존 도크에서 바로 접근한다. 상태 시트에는 밴드 요약도 넣는다.

데스크톱(기존 1000px landscape 기준)은 현행 상단 칩·도크·우측 시트 배치를 유지한다. 기존 칩의 문구·건수·시트·토스트 정책만 공유한다. 상단 손들기·신호의 0건 진입점도 제공하되 모바일 고정 줄을 중복 배치하지 않는다. 태블릿 세로는 모바일 동작을 적용한다.

## 시트와 조치

- 손들기: 손든 회원 목록 / 발언권 있는 회원 목록 분리. 각 행에 발언권 주기, 손 내리기 또는 발언권 회수. 한 번 탭해 열고 대상 행에서 한 번 더 탭한다. 요청 시각 계약이 없으므로 MVP는 기존 이름순, 번호·대기시간을 만들어내지 않는다.
- 처리 중 중복 탭 차단. 서버 성공 후 건수/행 갱신. 실패는 행에 재시도와 오류 유지, 손들기를 먼저 지우지 않는다. 대상 퇴장/손 취소 후 남은 토스트를 눌러도 현재 목록만 열고 조치하지 않는다.
- 조용한 신호: 독립 시트 상단에 세 종류 집계와 `최근 10초 · 이름 없이 집계`, 0이면 `최근 10초에 받은 신호가 없어요`. 신호 종류별 사람 목록·개인별 시간·타일 하이라이트 없음. 체크인 요약은 별도 연결 버튼 제공.
- 신호 TTL이 지나면 배지는 0이 되고 시트도 빈 상태로 갱신. 토스트가 사라졌다고 손들기 요청을 지우거나 조용한 신호를 읽음 처리하지 않는다.
- 시트는 390px 하단, 1440px 우측. 닫기 44px 이상, Escape/포커스 복귀/포커스 제한. 시트 안에서 발생한 같은 주제 이벤트는 내용 갱신만 한다.

## 이벤트별 토스트 규칙 (추천 기본값)

우선순위 P0=기존 진행 장애, P1=상담사 대응, P2=참고. 수신 직후 상태 배지는 바로 갱신하고 토스트만 묶는다. 아래 시간·묶음은 제안값이다.

| 이벤트 | 표시 / 우선순위 | 묶음·빈도 | 표시 시간 | 탭 동작 |
|---|---|---|---|---|
| 새 손들기 false→true | 켬 / P1, `손든 회원 1명` | 2초 내 신규 요청은 `새 손들기 3명 · 대기 5명`; 동일 상태 재수신 제외 | 6초 | 손들기 시트, 대상 확인 후 발언권 버튼 |
| 손 내림·발언권 부여/회수 | 별도 토스트 끔 | 현재 행/칩 상태만 갱신; 실패는 행 오류 | — | — |
| 조금 어려워요·잠시 쉴게요 | 켬 / P1, 종류와 집계만 | 2초 묶음, 조용한 신호 전체 최대 10초에 1회; 세 종류를 한 카드로 묶고 어려움/쉼 우선 | 6초, 최신 신호 TTL 이내 | 조용한 신호 시트 |
| 잘 따라가요만 수신 | 켬 / P2 | 2초 묶음, 같은 조용한 신호 10초 제한 공유; 위 신호가 오면 한 카드에 병합 | 4초, TTL 이내 | 조용한 신호 시트 |
| 체크인 응답 | 개별 끔 / P2 | 응답 수만 갱신, 전원 응답 완료 시 1회 | 4초 | 체크인 시트 |
| 입장 대기 신규 | 켬 / P1 | 3초 묶음, 같은 대기자 재수신 제외 | 6초 | 입장 대기 시트 |
| 일반 입장·퇴장/접속 변화 | 기본 끔 | 접속 수·타일만 갱신; 네트워크 상태만으로 퇴장 확정 문구 금지 | — | — |
| 밴드 최초 연결·미착용 | 끔 | 선택 기능이므로 미착용을 경고하지 않음 | — | — |
| 연결됐던 밴드 끊김·접촉 불량·낮은 배터리 진입 | 켬 / P2 | 5초 안정화 후 3초 묶음, 동일 참여자·원인 60초 쿨다운; 복구 시 폐기 | 5초 | 필요 조치/밴드 상태 시트 |
| 새 채팅 | 기본 토스트 끔 / P2 | 기존 안읽음 배지 유지; 수업 중 본문 노출 없음 | — | 도크 채팅 1탭 |
| 녹음 실패·네트워크 단절 등 | 기존 오류 배너 / P0 | 새 토스트와 중복하지 않음; P1/P2 토스트 표시 보류 | 기존 규칙 | 기존 복구 조치 |

공통 정책:
- 화면에 토스트 한 장만, 상단 카드 아래 고정. 하단 신호 줄/도크, 시트 조치 버튼과 겹치지 않는다. 소리·진동·푸시 모두 없음. 스크린리더 polite 안내, 포커스 강제 이동 없음.
- 대기 슬롯은 손들기/조용한 신호/입장 대기/체크인/밴드의 최대 5종류로 합침. P1 먼저, 같은 우선순위 FIFO. P2는 10초 이상 지연 시 버리고 상태만 유지한다. P1도 표시 직전 최신 상태 재확인, 이미 해소된 요청과 만료 신호는 폐기한다.
- 포인터 hover/키보드 focus 중 자동 닫힘 정지. 닫기 버튼은 알림만 닫음. 상태 칩에서 언제든 다시 확인 가능. 연속 수신으로 표시 시간을 무한 연장하지 않으며 최초 표시 기준 최대 8초(사용자 focus 제외).
- 시트가 열려 있으면 같은 주제는 토스트 없이 내용 갱신, 다른 주제는 조치 영역 밖의 시트 상단 알림 슬롯 하나로 표시. 입력 중에는 P2를 보류/폐기한다.
- 초기 스냅샷/재연결/백그라운드 복귀는 기존 상태를 새 요청으로 알리지 않는다. 현재 건수는 복원하되 신호의 로컬 10초 상태는 만료 처리; 중복 WS/폴링 결과는 동일 알림을 만들지 않는다. 세션 변경/종료 때 알림 큐 초기화.
- 조용한 신호는 새 수신 자체를 감지하되 참여자별 최신 신호로 집계한다. 서버 at + participant + type을 내부 중복키로만 사용하고 UI/로그에 식별자를 노출하지 않는다. at 없는 구 payload는 짧은 중복 억제 창 적용. 이 내용은 구현 시 순수 정책 함수로 검증한다.

## 익명성 경계

UI는 이름 없이 집계하지만 현 `class:signal` payload에는 participant_id/display_name이 있다. **서버 수준 익명화가 아니다.** 프런트는 중복 제거에 필요한 식별자만 메모리에서 사용하고 새 토스트·분석 로그·접근성 라벨에는 전달하지 않는다. 1명 수업 또는 소수 인원에서 추측 가능성까지 막는 익명성은 보장할 수 없으므로 시안은 `이름 없이 집계`로 표기한다. 서버 익명화·최소 집계 인원·영구 기록은 이번 MVP에서 제외한다.

## 백엔드 변경 필요 여부

- 칩/도크·토스트·익명 표시 집계·발언권 주기/회수는 기존 데이터/API로 프런트 중심 구현 가능.
- **상담사가 다른 회원의 손만 내리는 기능은 백엔드 변경 필요.** 현 lower-hand는 참여자 본인/입장 자격 인가이며 host 권한이 없다. speaking=false는 raise_hand를 지우지 않으므로 대체할 수 없다. 호스트 소유 세션·활성 참가자 범위로 인가한 명시적 손 내리기 계약 확장이 필요하다. 마이그레이션은 현재 분석상 불필요. 본인 취소 권한은 유지하고 타 세션·비호스트 거부 테스트 포함.
- 요청 시각순 대기열·재접속 후 신호 이력·서버 수준 익명성은 별도 계약 변경이므로 제외. 기본 정렬은 현행 이름순.
- 이번에는 백엔드 소스만 읽었으며 서버 실행/API 호출/DB/.env 접근을 하지 않았다.

## Brian 결정 항목 (비즈니스)

1. **화면 우선순위: A안 추천.** 하단 공간 약 76px를 쓰더라도 기존 메뉴와 신호를 동시에 바로 접근. B안은 화면 공간 우선.
