# [SDD-191] — Verification (Pre-Implementation)

## Test Scenarios
### TS1: 대상 선정
상담사가 켬/안 켬/내담자 paused/동의 전/링크 ended/계정 정지 6가지 → 스윕. **Expected:** 켬∧활성∧동의∧¬paused만 `checkin` 메시지 생성.
### TS2: 제한 규칙
하루 2번 스윕 → 1건. 주 4건 초과 시 생성 안 함. 무응답 2회 후 간격 증가(1→2→4일). 21:59 KST 허용, 22:00~07:59 금지, 08:00 허용(보정 포함). 열린 체크인 있으면 신규 없음. 멱등.
### TS3: 트리거
무응답 3일 / 직전 대화 watch로 종료 / 상담 완료 다음 날 각각 메시지 문구 분기. 아무 트리거도 없으면 생성 안 함.
### TS4: 체크인 대화
6턴 진행 → 마무리 메시지(`checkin_closing`, 상담사 연결 문구), `closed_at`·`summary`·`mood_direction` 저장. 마무리 후 새 메시지는 새 체크인/일반 응답으로 처리.
### TS5: 가드
LLM 응답을 "약을 드세요. 우울증 같아요. 항상 곁에 있을게요. 불안 점수 80점"으로 모킹 → 저장 메시지에서 모두 제거/대체.
### TS6: 프로파일
대화 "요즘 잠을 못 자고 직장 상사 때문에 힘들어요" → `sleep`·`stress` 항목 `ai_estimate`, evidence message_id 보존. 상담사 PATCH 확정/수정/기각. 내담자 토큰으로 프로파일 API 403, 내담자 API 응답/메시지에 프로파일 필드 없음.
### TS7: 위험 감지 — 상담사 알림
내담자 "죽고 싶다는 생각이 계속 들어요" → risk_signal(level 적절) 1건, 상담사 채널 `risk_alert` 메시지(CTA open_client/open_risk_signals), 인앱 알림 이벤트 `risk_signal`, 푸시 Outbox 1건(payload 비식별).
### TS8: 위험 감지 — 내담자 응답 (비노출 + 연결)
응답에 금지 단어(감지, 위험, 모니터링, 알림이 갔, 알렸) 없음, 공감 + 상담사 대화 권유 문구, CTA `talk_to_counselor` 1개(label "상담사님과 대화하기"), payload.room_id가 해당 상담사와의 direct 채팅방(없으면 생성). 해당 CTA 클릭 기록이 가능.
### TS9: 오탐 완화
"죽도록 맛있다", "배고파 죽겠어요", "자살 예방 캠페인 포스터를 봤어요", "드라마에서 자해 장면이 나와서 놀랐어요(제3자)" → 신호 미생성 또는 watch 미만. 진짜 표현은 탐지. (테스트 사례 표로 고정)
### TS10: 중복 억제/상승
같은 레벨 30분 내 재발 → 신호 1건. watch 후 high → 새 신호. 30분 경과 후 재발 → 새 신호.
### TS11: 어디서든 탐지
체크인 중 / 리포트 대화 중 / 일반 자유 메시지 중 모두 동일하게 탐지·응답.
### TS12: 격리
상담사 A는 B의 내담자 프로파일·체크인·위험 신호·enablement 조회/수정 불가(404). 내담자 간 격리.
### TS13: API 권한/검증
enable PUT 담당 아닌 내담자 404, 내담자 토큰으로 상담사 API 403, prefs PUT 형식 검증, profile PATCH text 300자 초과 422.
### TS14: 브리핑 연동
아침/저녁 브리핑에 안부 요약(변화 방향)과 미처리 위험 신호 섹션 포함, 처리 후 제외. 위험 excerpt는 상담사 채널에만.
### TS15: 푸시 비식별
안부/위험 push 행 payload에 이름·감정·위험 문장 없음.
### TS16: LLM 폴백
키 없음/예외 → 템플릿 대화·요약·프로파일(키워드 폴백) 생성.
### TS17: 프론트 — 내담자
checkin 메시지 렌더, 상담사가 켠 경우에만 일시중지 토글 노출·동작, `talk_to_counselor` 클릭 시 `/chat/:roomId` 이동, 위험을 암시하는 문구 UI 없음.
### TS18: 프론트 — 상담사
내담자 상세에서 켜기/끄기 즉시 반영, 프로파일 카테고리·AI 추정 배지·확정/수정/기각, 체크인 요약 타임라인(원문 없음), 위험 알림 카드와 목록(미처리 우선, 처리 완료 버튼).
### TS19: 계약 교차 대조 / 회귀
스키마↔프론트 타입 일치, `alembic heads` 단일 `e036a0000039`, 백엔드 전체 pytest·프론트 build/tsc/vitest 신규 실패 0.

## Edge Cases
- [ ] 체크인 도중 상담사가 끄기 → 열린 체크인은 마무리하고 신규 중단
- [ ] 내담자가 체크인 중 일시중지 → 아웃리치 중단, 대화는 가능
- [ ] 상담사가 여러 명(링크 다수): 각 상담사 기준으로 신호/프로파일 분리, 위험 알림은 모든 활성 담당 상담사에게
- [ ] 위험 메시지가 매우 긴 경우 excerpt는 해당 문장 최대 200자
- [ ] 한글 띄어쓰기 변형("죽고싶다", "죽 고 싶")
- [ ] 위험 응답 직후 사용자가 계속 대화 → 안전 템플릿 반복 남발 방지(연속 시 변형 1회 후 일반 공감)
- [ ] 푸시 방해금지 시간과 위험 알림: 위험 알림은 방해금지 무시(즉시), 안부는 준수

## Security Review
- [ ] 위험 excerpt·프로파일은 상담사 소유자 검증 후에만 노출, 로그 출력 금지
- [ ] 내담자 응답/메시지/Outbox에 감지 사실·레벨·excerpt 누출 없음
- [ ] 프롬프트는 `agent_policy` 반환 데이터만, 사용자 입력 인젝션으로 위험 탐지 우회/설정 변경 불가(탐지는 LLM 지시 이전 단계, 규칙 기반 선행)
- [ ] 푸시/인앱 알림 본문 비식별
- [ ] 영구 보관 정책 미구현·감지 비고지 → summary에 법무·임상 검토 필수 항목으로 명시
