- 브랜치: `sdd/241-research-export-metadata`

## 1. 목적과 확정된 경계

SDD-238의 Brian 결정은 **A안: 연구에 동의한 EEG의 비식별 연구 사본만 기한 없이 보관**이다. 서비스 원본은 연구 적재 ack 후에도 90일 삭제 규칙을 따른다. 이 결정을 바꾸지 않고, 연구자가 측정 조건과 인구학적 특성을 해석할 수 있도록 연구 번들 메타데이터를 보강한다.

Brian 추가 요구: “식별 정보에 성별, 생년월일, 측정 일시, 측정 프로그램에 대한 세부정보, 상담사 혹은 지도사 정보가 포함되어야 함”. 여기서 ‘식별 정보’를 실명 허용으로 해석하지 않는다. 아래 다섯 항목의 정밀도·포함 범위는 권장안과 대안을 비교하여 승인받는다.

- 대상: `research_export_service.py`가 만드는 `sessions.parquet`, `subjects.parquet`, `eeg_raw.parquet`, `features.parquet`, `manifest.json`의 후속 변경 요구.
- 비대상: 코드·마이그레이션·실데이터 변경, 기존 사본 재수출, 원본 보존 연장, PR 생성·머지, 배포, 서버·DB·`.env` 접근, 메일·알림 발송.
- ‘비식별’은 완전한 익명 보장을 뜻하지 않는다. 연결 가능한 HMAC ID와 준식별자가 있으므로 **가명정보에 준하는 접근·재식별 위험 관리**를 전제로 한다.
- 아래 ‘있음’은 체크아웃의 ORM·서비스 정의상 존재한다는 뜻이다. 실제 DB 배포·값의 충족률·장비 시계 정확도·연구 저장소 적재는 확인하지 않았다.

근거: [SDD-238 결정표](../sdd-238-eeg-raw-retention-90d/spec.md).

### 3.2 시간 의미와 결측 처리

제안 필드명은 의미 계약이며 최종 물리 스키마는 후속 Plan에서 정한다.

- `sessions.session_started_at_utc/session_ended_at_utc`: 수업 실제 시작·종료. 취소/미시작/누락은 null. 예약 시각이나 `created_at`으로 대체하지 않는다.
- `subjects.measurement_started_at_utc/measurement_ended_at_utc`: 해당 참여자 EEG 측정의 첫·마지막 유효 시각. 신뢰할 수 있는 장비-UTC 대응이 검증된 구간에서만 산출한다. 구간이 끊기면 전체 외곽 범위가 연속 측정을 뜻하지 않음을 명시한다.
- `measurement_time_source`, `measurement_time_status`: 검증된 장비 시계/미확인/결측을 허용 enum으로 구별. 수업 시각을 EEG 시작·종료로 복사하지 않는다.
- 저장은 timezone-aware UTC, 출력 의미는 ISO 8601 `Z` 또는 동일 의미의 Parquet UTC timestamp. KST를 별도 원본 컬럼으로 중복 저장하지 않는다. 정밀도(초)와 timezone을 manifest에 명시한다.
- 기존 `t_rel_ms` 등은 유지. 장비 시계 리셋·복수 스트림·pause/resume·미래 시각·종료<시작에 대한 검증 없이 절대값을 생성하지 않는다. 오류를 0이나 현재 시각으로 덮지 않는다.
- 현재 원천만으로 정확한 개인 측정 시각을 항상 보장할 수 없으므로 **null을 남기는 것까지가 1차 수용 범위**. 모든 신규 측정의 절대시각 보장은 이후 시계 동기화/수집 개선 범위로 분리한다.

### 3.3 진행자 범위와 속성

- 우선 대상은 해당 회차 `sessions.host_id`의 진행자. 명상 지도사/상담사라는 도메인 역할과 `users.role`(계정 권한), `class_instructors.role`(lead/assistant/guest)을 구별한다. 명상 진행자의 계정 role이 counselor일 수 있다.
- 클래스 강사팀 전체를 실제 참여자로 간주하지 않는다. `scope_session_id`, 추가·제거 시각, 진행자 변경 이력을 사용하여 해당 회차 관계를 판정하고, 실제 참여 근거가 없는 보조/참관자는 제외한다. 과거 진행자를 복원할 수 없으면 unknown으로 남긴다.
- 연구 범위별 `instructor_pseudo`를 사용한다. 사용자 UUID·이름의 단순 해시·상담사 공개 코드·기관명은 내보내지 않는다. 참가자 가명과 도메인을 분리한다.
- 확장 후보: `gender`, `experience_band`(예: 0–2/3–5/6–10/11년 이상), `qualification_category`. null은 미상/미제공이며 ‘자격 없음’으로 해석하지 않는다. `years_of_experience`를 쓸 수 있지만 경력 기관·정확한 경력 날짜는 제외한다.
- `qualifications.name/issuer`는 자유기입이며 `credentials.status`는 제출 증빙의 심사 상태이다. `verified_tier`와 함께 읽더라도 특정 전문 자격 보유를 자동 확정할 수 없다. 원문·증명서 파일/경로·AI 판정 JSON은 반출하지 않는다.
- 현재 프로필은 수정 가능하다. 신규 측정은 동의 범위와 당시 역할·선택 속성을 스냅샷하고, 과거 자료에 현재 경력·자격을 당시 값처럼 소급하지 않는다.

## 4. 개인정보·동의 판정

### 4.1 법적 근거와 제품 정책의 구분

2026-10-24 국가법령정보센터의 시행 2026-09-11 조문 확인 기준:

- 상담사/지도사는 참여자 연구 동의의 대상자가 아니다. **실명·연락처의 연구 이용에 다른 적법 근거가 확인되지 않은 현 단계에서는 진행자 본인의 별도 동의가 필요하다는 설계 판정**이다. 외부 연구자 제공이면 제공받는 자·목적·항목·기간도 특정해야 한다. 참여자가 진행자 대신 동의할 수 없다.
- 개인정보 영향 평가는 정성적 설계 판단이며, 법적 적합성 인증이나 실제 데이터 위험도 측정 결과가 아니다. 연월일+절대시각+진행자+희귀 프로그램의 결합은 각각을 가명 처리해도 재식별 위험을 높인다. 동의만으로 이 위험이 없어지지 않는다.

### 4.3 고칠 문구 초안 — 권장안 기준, 실제 게시하지 않음

**개인정보 처리방침 제5조 항목 문구 대체안**

> 연구 목적 활용에 동의한 경우, 뇌파(EEG)·맥박(PPG)·움직임(ACC) 데이터와 산출 지표, 이름과 생년월일로 계산한 가명 식별값, 성별, 생년·월을 연구에 활용합니다. 수업 시작·종료 일시와 확인 가능한 개인 뇌파 측정 시작·종료 일시, 프로그램 유형·진행 방식·길이·회차·운영 구성 및 표준화된 연구용 프로그램 정보를 함께 활용합니다. 일시는 UTC 기준으로 보관하며 한국시간으로 환산할 수 있습니다. 확인되지 않는 측정 시각이나 프로그램 정보는 임의로 채우지 않습니다. 진행자가 별도로 동의한 경우에는 해당 회차 진행자의 연구용 가명 식별값과 역할을 포함합니다. 참여자와 진행자의 실명·이메일·전화번호, 자유기입 클래스명·상담 메모·음성·영상 원본 및 녹음 내용은 연구 사본에 포함하지 않습니다.

**제5조의2 보관/철회 문구 보강안**

> 위 항목을 포함한 연구용 가명 사본은 기본 서비스 저장소와 분리하여 삭제 기한 없이 보관하고, 권한 있는 연구 담당자만 접근합니다. 서비스 원본은 기존 90일 보관 및 연구 적재 확인 기준에 따라 삭제합니다. 연구 활용 동의는 선택이며 거부해도 기본 서비스와 클래스 참여에 불이익이 없습니다. 설정 또는 문의처를 통해 동의를 철회하고 기존 연구용 개인 데이터의 삭제 또는 가명 처리를 요청할 수 있습니다. 이미 발표된 논문·학습된 모델 등의 결과는 되돌릴 수 없습니다. 외부 제3자 제공은 제공 전에 대상·목적·항목·기간을 별도로 알리고 동의를 받습니다.

**제5조의3 위험 및 제10조 ID 설명 보강안**

## 5. 후속 구현이 지켜야 할 요구사항(이번에는 구현하지 않음)

1. 새 동의·비철회·유효 연구 ID·실제 EEG 존재 조건을 모두 만족하는 건에만 확장 메타데이터를 내보낸다. 연구 미동의·밴드 미사용이어도 서비스 이용은 유지한다.
2. 과거 `r5-1`/가입 `1.0` 동의와 이미 exported/acked인 사본은 자동 확장·재수출하지 않는다. 구버전 동의의 pending 건은 기존 1.0 범위로 처리 가능하게 하고, 새 항목은 비워 둔다. 신규 동의는 동의 이후 측정부터 적용하며 과거 회차 소급은 이번 범위에서 제외한다. `sessions.parquet`는 세션당 공유 행이므로 같은 회차에 신·구 동의가 섞이면 **동의 범위별 번들을 분리하거나 그와 동등하게 연결을 차단**해야 한다. 구동의 subjects가 새 절대시각·프로그램·진행자 메타데이터와 조인되지 않도록 가명 연결 범위까지 분리하며, 단순히 subjects의 새 컬럼만 null로 만드는 것은 불충분하다.
3. 기존 4개 Parquet+manifest 구조를 우선 유지하되, 반복되는 프로그램/진행자 구조의 물리 형태는 Plan에서 결정한다. 새 schema 버전·허용 필드 해시·정밀도·동의 범위 버전·원천/결측 의미를 수신자와 맞춘다. 구버전 소비자가 새 파일을 오해하여 ack하지 않도록 계약을 구분한다.
4. 현재 `_scan_strings`는 문자열 컬럼만 검사하고, 금지 literal은 참여자 이름/이메일·세션 제목/메모 중심이다. 진행자/클래스 원문, nested 값, 날짜·수치 조합의 식별 위험까지 막아 주지 않는다. 허용 목록·타입·enum 검증을 확장하고 승인된 표준값만 반출한다. 새 필드를 위해 기존 스캔을 끄지 않는다.
5. 현재 `content_hash`는 동의 인구학 정보·features·raw payload 해시 중심이며 session 메타데이터를 포함하지 않는다. 승인된 새 메타데이터·스키마·동의 범위까지 revision/동일 내용 판정에 포함한다. 변경 감지와 재수출 권한은 별개다.
6. 연구 동의/원천 스냅샷은 개인정보 스크럽 전에 확보해야 하며, 이미 사라진 정보는 null로 남긴다. 새 메타데이터 부족을 이유로 서비스 원본을 무기한 보류하거나 SDD-238 보존 정책을 변경하지 않는다.
7. 진행자 철회는 참가자 철회와 구분한다. 신규 반출 중단과 기존 사본의 진행자 속성 제거/연결 해제 추적이 필요하다. 참여자의 연구 사본 전체 삭제를 자동 의미하지 않으며, 연구 저장소 처리 확인을 기록한다.
8. 후속 Stage ③에서 시간대·구간 리셋·결측·개인정보 문자열·권한·구/신 동의·철회 경합·revision·소비자 호환·원본 삭제 후 독립 해석을 실제 검증할 시나리오로 작성한다. 이 목록은 **구현 전 verify.md를 대신하거나 검증 통과를 주장하지 않는다**.
