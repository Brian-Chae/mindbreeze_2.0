- 상태: Stage ① Spec 확정 (2026-10-22 Brian 결정 5건 확정) → Stage ②~⑥ 연속 진행. 이번 구현은 1단계(목록+활동)만, 접속(C)은 후속
- 브랜치: `sdd/230-member-overview` · 조사일: 2026-10-22

## 1. 문제와 목표

현재 회원 목록은 이름·이메일·고민 태그만 카드로 제공한다. 여러 회원의 기본정보와 최근 활동을 비교하기 어렵고, 상세는 개인정보·상담사 메모·조건부 AI 안부 패널 중심이다. 수업 출석, 상담, 체크인, 측정, 리포트가 흩어져 다음 상담 준비에 여러 화면 이동이 필요하다.

목표는 ① 표를 기본으로 회원을 찾고 비교 ② 카드와 표 간 맥락 유지 ③ 권한이 있는 활동과 리포트를 회원 단위로 모아 보기 ④ 접속 여부와 실제 참여를 혼동하지 않기다. 건강 종합점수·회원 순위·회차 간 개선 점수는 만들지 않는다.

## 2. 범위와 비범위

### 승인 제안 범위

- 표 기본 + 카드 전환, 이름/이메일 검색, 온라인·클래스·최근 활동 기간 필터, 클래스별/접속 상태별 그룹핑.
- 표 열: 이름, 성별, 만 나이, 마스킹 연락처, 온라인, 최근 접속, 최근 활동, 소속 클래스. 생년월일 전체는 기본 표에서 제외.
- 상세: 동일 AppShell 내 전체 페이지. 요약 헤더, 기간·활동유형 필터, 활동 타임라인, 리포트 목록, 회차 내부 변화 기록, 기존 비공개 메모 진입 유지.
- 접속 기능은 별도 2단계 제안. 미지원 상태를 오프라인으로 대체하지 않는다.
- API의 서버 측 필터·전체 건수·페이지네이션과 개인정보 마스킹·권한 검증 포함. 현재 페이지의 프론트 필터로 전체 회원 검색을 흉내내지 않는다.

### 비범위

- 이번 단계의 Plan·Verify·제품 코드·마이그레이션·배포·외부 서비스 연동.
- 회원 관리 권한 확대, 타 상담사 상담 내용, 타 기관 기록 통합, 게스트 자동 병합, 개인정보 수정 기능 신설.
- 새 AI 요약 생성, 진단/치료 판단, EEG 원시 파형 전체 조회, 종합점수·등급·순위·타인 비교, 메일·알림 발송.
- 상담사와 연결되지 않은 클래스 참여자를 자동으로 기존 회원 목록에 추가하지 않는다. 회원 모집단 변경은 후속 비즈니스 결정이다.

## 5. 화면 구성

### 목록

1. 현재 기관/개인상담소 맥락 + 회원 수 + 표/카드 토글. 최초 표, 보기 선택은 기기 로컬 보관(개인정보 저장 금지).
2. 이름/이메일 검색; 온라인 전체/온라인/오프라인/확인 불가, 클래스, 최근 활동 전체/7일/30일/90일; 그룹 없음/클래스/접속 상태.
3. 표 열은 위 범위와 동일. 이름 링크/카드로 상세 이동, 키보드 접근 가능. 연락처는 기본 `010-****-1234`. 성별/나이는 권한·동의 없으면 `비공개`, 입력 없으면 `미입력`.
4. 최근 활동은 열람 가능한 실제 출석/상담 수행/수업 체크인/유효 측정 중 최종 시각. 리포트 생성·수정/예정 일정은 회원 활동에서 제외. AI 안부는 기능 공개·접근 가능할 때만 포함. 원천과 시각을 함께 표시.
5. 클래스 그룹핑은 복수 가입자를 그룹마다 재표시하되 총 회원 수는 unique ID. '미소속' 그룹 포함. 개인상담소·기관 간 그룹은 섞지 않는다.
6. 1440: 240px 사이드바+전열 표. 1194: 동일 사이드바, 표 내부만 수평 스크롤. 390: 사이드바 대신 상단 메뉴, 표 내부 수평 스크롤+고정 이름 열; 카드 보기는 단일 열. 가로 스크롤 안내 제공. 페이지 자체 가로 넘침 금지.
7. 필터 초기화·빈 결과·오류 재시도·불러오기 상태. 부분 데이터 조회 실패를 활동 없음으로 바꾸지 않는다. 뒤로 가기 시 검색·필터·그룹·페이지·스크롤 복원.

### 상세 (전체 페이지 추천)

- 상단: 목록 복귀, 가상 회원명, 선택 기관, 성별/만 나이, 마스킹 연락처, 접속 상태/확인 시각. '개인정보 열람'은 담당·동의·목적 확인과 감사 기록을 거친 별도 행위.
- 본문: 최근 30일 실제 활동 타임라인(유형+발생일+클래스/상담 제목+원본). 출석·체크인·측정을 독립 이벤트로 남기고 동일 수업으로 연결. 입장 시각/출석을 임의 보정하지 않는다.
- 리포트: 활동 발생일/생성일 구분, 회원용/상담사용 유형, 승인/검토 중/생성 중/실패/제외. 열람 권한 없는 리포트는 제목·건수도 미노출. 생성/발송 작업 버튼 신설 없음.
- 변화 기록: 승인된 동일 회차의 전반→후반 서사·변화량만. 예: '휴식 상태로 이동 · 전반 대비 +8%p' (정규화 원천 단위가 확인된 경우만). 다른 날짜는 독립 기록으로 나열하며 회차 사이 증가 선·평균 점수·개선률은 만들지 않는다. 표본/단위 불명확하면 수치 없이 '비교 자료 부족'. 직접 작성 소감과 생성 서사를 구분하고 원본 리포트 연결.
- 밴드 미사용도 활동과 리포트 사용 가능. 미측정은 0점이나 나쁜 상태가 아니다.
- 기존 상담사 메모는 연결별 비공개 유지, 타 기관/타 상담사 메모 공유 금지. 이번 시안은 읽기 예시만.
- 1440/1194: 타임라인+오른쪽 리포트/변화 2열. 390: 헤더→타임라인→리포트→변화→메모 단일 열, 페이지 세로 스크롤.

## 11. 1-2단계 — 기관관리자 범위 (Brian 결정 2026-10-22)

### '기관 전체 회원' 정의 (최소·안전)

  1. 기관 클래스(`Class`, 상태 draft·archived 제외)의 active `ClassMember` (role=client).

## 12. 1-3단계 — 기관 소속 상담사 연결 회원 포함과 회원/비회원 구분 (Brian 결정 2026-10-22)

결정: ① `ClientCounselorLink`(상담사↔회원)만 있고 기관 클래스·기관 귀속 상담관계가 없는 회원도, 담당 상담사가 **기관 소속(`UserOrgMembership` active)** 이면 기관관리자에게 기관 회원으로 보인다. 상담사의 개인상담소 회원이 섞여도 허용(비용·관리 책임이 기관). ② 회원/비회원을 구분해 표시한다. ③ 상담 세션 기록·상담사용 리포트 제외, 비공개 메모 비노출은 §11 그대로 유지.

### 포함 기준 (§11 정의 확장)
- 기관 회원 집합 = §11 의 ①기관 클래스 active 멤버 ②기관 귀속 active 상담관계 회원 ∪ **③ 관리 기관에 active 소속된 상담사와의 active `ClientCounselorLink` 회원**(역할 client 만).
- ③ 의 상담사 조건: `UserOrgMembership(org_id ∈ 관리 기관, status=active)` 이고 `User.status=active`. 소속 없음·`left`·`invited`·계정 비활성 상담사의 연결 회원은 제외. 링크 `status=active` 만. 관리 기관은 §11 과 동일(개인상담소·비활성 기관 제외, 다중 기관 전부).
- 마이그레이션 없음(기존 테이블 조회만).

### 회원/비회원 판정 (목록 배지·필터, 상세 헤더)
- **회원(`member`)**: 기관에 대한 소속 근거가 확실한 경우 — ① 또는 ② 에 해당(§11 정의, 귀속 확정 데이터).
- **비회원(`non_member`)**: ③ 만으로 포함된 경우(기관 소속 상담사와의 연결만 있고 기관 클래스·기관 귀속 상담관계 없음). 관리자 본인이 직접 연결한 회원이 ①② 에 없으면 역시 비회원.
- 화면 라벨(비전문가용): 배지 `회원` / `비회원`, 보조 설명 `회원 = 기관 클래스 또는 기관 상담에 등록됨`, `비회원 = 기관 상담사와 연결만 되어 있음(기관 등록 전)`. 필터: `전체 / 회원 / 비회원`(URL `member_type`). 점수·종합점수 없음.
- 상담사(role=counselor) 호출에는 `member_type=null`, 필터 무효(범위 불변).

### 게스트 조사
- 코드 입장 게스트는 `ClassMember(kind='guest', user_id=None)` 이며 `User` 행이 없다. 회원 목록 모집단은 `User` 기반이고 `org_member_ids` 는 `kind='member'`·`user_id` 필수로 거르므로 **게스트는 회원 목록에 들어오지 않는다**(다른 기관 목록 포함). 병합(`canonical_member_id`)도 guest→guest 뿐이다.
- 따라서 '계정 없는 게스트 = 비회원' 해석은 이 목록에서는 대상이 0명이라 의미가 없고, 목록에 실제로 섞이는 '계정은 있으나 기관 등록 근거가 없는 상담사 연결 회원'을 비회원으로 보는 기본 해석이 맞다. 게스트를 목록에 노출하는 것은 별도 결정 사항(비범위).
