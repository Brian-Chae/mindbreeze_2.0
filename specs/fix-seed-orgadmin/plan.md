# 기관관리자 테스트 계정 시드 수정 계획

10/24 Brian 승인 범위: 지정 fix 브랜치에서 코드·테스트·커밋·PR까지. DB 적용은 OPS 담당.

원인: 기존 시드는 상담사·내담자만 생성하고 기관 소속은 생성하지 않는다.

1. 격리 SQLite 테스트를 먼저 작성하고 실패를 확인한다.
2. 세 번째 계정과 활성 일반 기관 membership을 추가한다. 일반 기관은 생성 시각·ID 순으로 선택한다.
3. 일반 기관이 없으면 새 테스트기관을 만들며 개인상담소·기존 소속·주 소속·담당자는 보존한다.
4. production/prod 환경을 거부하고 원격 PG는 mindbreeze-dev RDS 호스트만 허용한다. 로컬 PG·SQLite는 허용한다.
5. 집중 테스트와 기존 시드 회귀, 독립 리뷰 후 한글 커밋·지정 브랜치 푸시·develop 대상 PR을 만든다.

소속 서비스는 개인상담소 주 소속을 자동 교체하므로 이 추가 전용 시드에서는 직접 membership을 추가한다.
.env 로딩을 막은 별도 테스트 런처로 실행하고 서버·실제 DB·메일 접근은 하지 않는다.
