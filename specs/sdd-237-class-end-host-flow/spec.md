## 1. 결론과 문제 정의

**10/23 결정됨: 클래스 종료 후 ‘회차 요약’을 기본 화면으로 제공한다. 참여자별 리포트와 비공개 진행 기록을 분리하고, 생성 중에도 기록 작성·목록 복귀가 가능하게 한다. LINK BAND 착용 세션에는 근거가 있는 뇌파 분석 요약을 포함하고, 진행 기록은 선택 작성으로 한 번만 안내한다.**

상담사가 종료 직후 해결할 일은 ① 종료됐는지 확인 ② 누구의 결과가 준비됐는지 확인 ③ 필요한 기록을 남김 ④ 승인·전달 등 남은 일 파악 ⑤ 다음 일정이나 홈으로 복귀다. 이는 사용자 행동 조사 결과가 아니라, 기존 기획 F7/F8와 현재 기능으로부터 도출한 업무 가설이다.

현재 ‘기록 보기’가 유일한 주요 다음 행동인 탓에, 생성된 리포트를 볼 곳과 상담사가 직접 쓰는 기록지가 혼동된다. 기록 저장을 리포트 발행의 필수 선행 단계처럼 보이게 해서도 안 된다.

### 2.4 1:1 상담과 명상 클래스

현행 라우터는 클래스 회차(`/classes/:classId/sessions/:id`)와 상담 관계 내 세션(`/counseling/:relationshipId/sessions/:id`)를 분리하고 SessionDetailPage/플레이어 엔진을 공유한다(`App.tsx:234–243`). 종료 플레이어의 활성 상담사 분기에는 영역별 업무 IA가 없다.

제안은 **동일 요약 컴포넌트, 다른 우선순위**다. 명상은 ‘회차 요약 → 참여자 결과’를 우선, 상담은 ‘상담 요약 → 비공개 상담 기록 → 내담자 리포트’를 우선한다. 명상 인원 1명을 상담으로 간주하지 않는다. 영역 판정은 class_id/관계 ID 등 서버 도메인 정보 사용. 레거시 부모 없는 세션은 기존 session 상세·목록으로 복귀한다. 상담 게이트가 꺼진 출시에서는 해당 메뉴를 새로 열지 않는다.

## 3. 정보의 소유권과 용어

| UI 명칭 | 역할·공유 대상 | 데이터·연결 |
|---|---|---|
| **회차 요약** | 상담사의 운영 진입점. 종료 시각·참여·처리 상태·다음 할 일 | 세션 메타 + 회차 참여/리포트 요약. 새 공개 리포트를 생성하는 개념 아님 |
| **클래스 리포트(상담사용)** | 해당 회차 전체를 돌아보는 상담사 전용 결과 | 기존 type=counselor. 개인 결과를 섞은 공개 문서가 아니며 회원에게 발송하는 CTA 없음 |
| **참여자 리포트** | 각 참여자의 결과. 본인 것만 공유 | type=client, report_id/participant_id로 상세 이동. 이름으로 조인하지 않음 |
| **진행 기록 / 상담 기록** | 세션당 내부 메모. 명상에서는 진행 기록, 상담에서는 상담 기록 | SessionRecord.counselor_notes. `record_service.py:120–145`에서 비host에 counselor_notes 필드 제외. 편집이력은 아래 별도 확인 항목 참조. 개인별 비공개 메모 모델 신설은 범위 밖 |
| **참여자에게 전할 코멘트** | 리포트에 포함되는 공개 글 | ReportDetailView의 counselor_comment 편집. 비공개 메모 저장과 별도 동작 |
| **클래스 전체 추이** | 여러 회차의 추이 | 기존 클래스 상세로 이동. 종료 직후 단일 회차 요약에 혼합하지 않음 |

`report_task.py:365–415`는 counselor 리포트에만 내부 메모를 포함하고 client에는 넣지 않는다. 따라서 ‘비공개’는 **기록 원문을 참여자 리포트에 직접 싣지 않는다는 경계**이며 작성자만 영구 독점 열람한다는 추가 권한 약속이 아니다. AI 공개 코멘트에 파생될 수 있는 내용은 §6.2의 별도 위험 검토 대상이다. 생성 시점 스냅샷을 담은 counselor 리포트가 나중에 메모를 저장할 때 자동 동기화된다고 가정하지 않는다. 최신 기록은 기록 API를 원본으로 열람하며, 내부 메모 저장은 리포트 재생성·승인·발송을 호출하지 않는다.

**독립 검토에서 확인한 개인정보 경계(정적 코드 근거):** `record_service.py:148`의 edit_history 반환은 include_internal 조건 밖에 있고, `:175–181` 팀 열람 분기만 이력을 비운다. `:225`는 메모의 before/after를 이력에 저장한다. 따라서 모든 비host 경로에서 이력까지 차단됐다고 단정할 수 없다. 실제 접근 가능성은 RECORD_VIEW 권한·응답 스키마까지 포함한 구현 전 검증 항목으로 남긴다(운영 노출 검증 아님). 비공개 표시를 제품에 적용하기 전에 이력까지 포함한 권한별 차단을 확인해야 한다. 이번 기획 작업에서 제품 코드는 수정하지 않았다.

## 4. 권장 여정과 화면 전환 (제안)

```text
플레이어 ‘클래스 종료’ → 기존 종료 확인 → 서버 종료 성공
  → /sessions/:id/summary (신규 제안, replace)
      ├─ 개요: 종료 확인 + 남은 일 + 클래스 리포트 진입
      ├─ 참여자 결과: 대상별 상태 → /reports/:reportId → 같은 결과 목록으로 복귀
      ├─ 진행 기록: /summary?tab=notes → 작성 → 명시적 저장 → 저장 시각
      └─ 클래스 상세 / 다음 회차 / 클래스 목록 / 홈
기존 /sessions/:id/record → 기록 편집 유지 + ‘회차 요약으로’ 링크
완료된 /player 재접속 → 서버 상태 확인 후 동일 /summary (권한 유지)
```

- **종료 실패/응답 불명은 성공 화면으로 이동하지 않는다.** 재조회로 completed 확인 후 이동. 아직 진행 중이면 종료 재시도. 네트워크 복구만으로 같은 종료 요청을 무조건 반복하지 않는다.
- 이탈 가드에서 명시적으로 고른 홈/목록은 기존 leaveTo 의도 존중. 다음에 세션을 열면 요약으로 복원.
- 요약은 잠깐 뜨는 모달이 아니라 다시 찾을 수 있는 화면. class/relationship/session ID를 서버로 확인해 상단 breadcrumb와 복귀 목적지 결정. 임의 returnTo 외부 URL은 허용하지 않음.
- 리포트 상세의 돌아가기 목적지는 `/summary?tab=participants`로 고정 가능한 내부 경로. 선택한 필터와 행은 URL/메모리로 복원하되 개인정보를 URL에 넣지 않음.
- 명상: 우선 CTA **참여자 결과 확인**. 생성 중이면 **진행 기록 남기기**, 별도 목록 복귀 허용. 완료 리포트가 한 건도 없으면 결과 목록의 상태 확인은 가능하되 열기 버튼은 없음.
- 상담: 우선 CTA **상담 기록 작성** 또는 저장된 경우 **내담자 리포트 확인**. 글쓰기를 마쳐야 나갈 수 있는 강제 단계는 아님.
- 다음 회차는 기존 예정 회차 상세로 이동. 없으면 ‘다음 일정 없음’ + 권한 있을 때 편성 화면 링크. 클릭 한 번으로 새 세션 복제/생성을 실행하지 않음.
- 메시지는 권한 있는 기존 채팅방으로 이동만 한다. 게스트 등 채널 없는 경우 ‘연결된 대화 없음’. 자동 메시지 발송 기능 추가 없음.

## 5. 화면 정보 구조·디자인

### A. 회차 요약

1. 상위 클래스 / 회차 / 완료 일시와 명확한 ‘클래스가 종료되었습니다’.
2. 시간·참여 인원·리포트 대상 수. 참여 등록 수와 실제 출석 수 구분. 값 미확인 시 ‘확인 중’, 0으로 대체하지 않음.
3. 남은 일: 생성 중 / 검토 대기 / 승인됨 수와 자동 승인 적용 정책. 현행 설정과 미승인 추천안 시안을 구분하며, 추천안의 대기 시각·회차 보류·유형별 설정은 [정책 기획](auto-approve-policy.md)에 따른다.
4. 클래스 리포트(상담사용) 진입, 참여자별 결과, 비공개 기록의 분리된 제목.
5. 뇌파 분석 요약(§5.E)과 미작성 진행 기록 한 번 안내(§5.F).
6. 다음 회차와 클래스 상세·목록·홈 복귀. 처리 종료를 기다리게 하지 않음.

### B. 참여자별 결과

데스크톱: 검색 + 상태 필터 + 표(참여자 / 측정 / 생성 / 승인 / 전달 / 열기). 모바일: 같은 행을 세로 카드로 배치하고 라벨 보존. ‘리포트 미반영’ 참여자는 별도 그룹으로 표시하고 승인/발송 대상에서 제외. 게스트·회원 구분은 필요할 때만 보조 라벨.

리포트 상세에서 공개 코멘트 저장 → 미리보기 → ‘승인’ 확인. 기존 자동 메일 예약이 있을 수 있음을 확인문에 표시. 요약 화면에서 전체 계정 대상 `approve-all`을 호출하지 않는다. 초기 범위는 **단건 상세 승인 재사용**. 회차 한정 일괄 승인·재발송은 기존 class report-jobs 계약을 검토한 후 후속 확장.

### C. 기록 작성

‘진행 기록 원문을 직접 공유하지 않습니다. 공개 코멘트는 별도로 확인하세요’ 설명 + 자유 입력 + 저장 상태 + 수정 이력. 입력 중/저장 중/저장됨 HH:mm/저장 실패를 구분. 저장 응답 성공 시에만 저장됨 표기. 탭 전환·상세 이동·목록 복귀는 dirty 확인창(계속 작성 / 저장 후 이동 / 저장하지 않고 이동). 저장 실패 시 입력 유지, 이동 중단. 새로고침/탭 종료는 브라우저 기본 이탈 경고. 이번 범위에서 민감한 기록의 localStorage 영속 저장은 제안하지 않음; 강제 종료 시 미저장분은 복구 보장하지 않고 이를 안내.

재접속은 마지막 서버 저장본과 수정 이력을 로드. 늦은 폴링 응답이 작성 중 입력을 덮어쓰지 않음. 동시 편집 충돌은 revision 또는 updated_at 조건부 저장이 필요하며, 현재 API에는 없으므로 BE 범위에 명시한다. 충돌이면 내 입력 유지 + 최신 저장본 확인, 무조건 덮어쓰지 않음.

### E. 뇌파 분석 요약 — 실제 데이터와 표시 범위

**회차 요약은 종료 직후 존재하는 데이터와 리포트 생성 후 결과를 구분한다.** 착용 여부와 분석 완료를 동일시하지 않는다. 아래는 로컬 소스 정적 확인이며 서버에서 현재 수집·생성 성공을 검증한 것이 아니다.

| 실제 원천·계약 | 시점·범위 | 근거 / 요약에서의 사용 |
|---|---|---|
| `focusIndex`, `relaxationIndex`, `stressIndex`, SQI·신호 품질 등 스트림 계산 | 수업 중 착용 기기/개인. 브라우저 최신값만으로 종료 후 서버 결과나 그룹 결과를 보장하지 않음 | `frontend/src/lib/eeg/EEGSignalProcessor.ts:211–285,344–368`, `AnalysisMetricsService.ts:137–188`, `StreamProcessor.ts:612–639`. 실시간 값은 잠정이며 마지막값을 회차 평균으로 쓰지 않음 |
| 참가자의 `band_connected`; 수집된 feature window·rollup | 이미 업로드된 범위는 리포트 생성 전에도 존재 가능. 종료 순간 최종 업로드 완료는 별도 확인 | `backend/app/models/session.py:168`, `schemas/eeg.py:47–80`, `services/eeg_rollup_service.py:85–119,165–199`. sample_count/valid_count/coverage/metrics 및 participant_id가 있음. 착용 시도 인원과 실제 데이터 있는 인원은 다른 분모 |
| `session_status`, reliability, raw 평균·중앙값, windows_total/usable | 리포트 생성 작업이 윈도우를 읽어 계산. 개인 또는 명시적 session_wide | `backend/app/services/eeg_metrics.py:285–338,368–389`. valid/degraded/insufficient/invalid를 구분. 기존 score/meditation_total_score도 코드에 있으나 **이번 명상 요약에서는 표시하지 않음** |

**채택 표시안:** 제목 ‘뇌파 분석 요약’, ‘전체 참여 N명 · 착용 기록 M명 · 분석 가능한 K명’처럼 출처가 확인된 분모만 표시한다. 클래스 전체 변화 방향을 임의 평균으로 만들지 않는다. 단일 착용자이거나, 요약 카드에서 대상 참여자를 명시한 개인별 결과 미리보기 또는 개인 결과 상세에서 해당 개인의 검증된 전후 서사(예: ‘측정 구간 후반에 이완이 깊어지는 흐름이 관찰됐어요’)를 사용한다. 여러 명이면 ‘분석 가능한 참여자의 개인별 변화는 리포트에서 확인할 수 있어요’ + 개인 결과 링크가 기본이다. 시안의 참여자 A 서사는 권한이 확인된 개인 미리보기 예시이며 대표값이나 우수 사례 선정이 아니다. 실제 목록은 고정된 참여 순서로 제공하고 임의 순위를 만들지 않는다. ‘비교 가능 K명 중 J명에게 이완 증가 방향’은 **개인별 구조화 방향을 안전하게 제공한 후의 집계 제안**이며 현행 응답에 이미 있다고 쓰지 않는다. 개인 간 비교·순위·치료 효과 단정은 금지한다.

측정 시간은 세션 길이와 다르다. 현행 `coverage_ratio`는 valid 윈도우 수/세션 초이며 합산 윈도우·스트림 빈도의 영향을 받는다(`report_task.py:165–180,304–308`). 이를 그룹 측정 분으로 환산하지 않는다. 원천 타임스탬프·유효 구간·겹침 제거 계약을 검증하기 전에는 ‘측정 시간 확인 중/정보 없음’ 또는 품질 상태만 제공한다. `reliability`와 coverage도 같은 값이 아니다. ‘눈에 띄는 12–15분 변화’ 자동 탐지 필드는 확인되지 않았으므로 초기 요약에서 제외한다. 실제 시간축이 확인된 개인 timeline 상세는 연결할 수 있지만 가짜 구간을 생성하지 않는다.

| 상태 | 요약 카드·동작 |
|---|---|
| 착용·분석 완료 | 품질 상태·분석 가능 인원·개인별 서사 확인 링크. 단일 개인은 검증된 서사/변화량만, 점수 없이 표시 |
| 일부 착용 | 착용자/전체 인원을 명시. ‘측정 참여자의 결과이며 전체 참여자의 상태를 대표하지 않아요’. 미착용자를 0이나 안정 상태로 포함하지 않음 |
| 미착용 | 카드 숨김 또는 ‘뇌파 미측정’ 한 줄. 기록·리포트 검토는 계속 가능 |
| 신호 불량 | degraded는 ‘일부 구간 해석에 주의’, invalid/insufficient는 ‘측정 자료가 부족해 변화를 확인하기 어려워요’. 결측을 안정·악화·0점으로 바꾸지 않음 |
| 연결 끊김/자료 유실 | 연결 시도 후 윈도우 0이면 lost/band_disconnect 안내. 일부 유실은 서버 사유가 확인된 범위만 안내. 종료 후 연결 해제 자체로 측정 실패 판정 금지 |
| 분석 중 | ‘뇌파 분석 중 · 준비되면 이곳에서 확인할 수 있어요’. 종료 직후는 수집 완료까지 확인 중일 수 있음. 예상 완료시간·변화 결론 없음, 기록·목록 이동 허용 |
| 조회 실패·분석 실패 | 오류와 미착용을 구분해 ‘분석 결과 확인 필요’ + 다시 확인. `_build_eeg_content` 예외가 not_measured로 반환되는 현행 경로(:298–300)는 요약 DTO 보강 시 원인 분리 필요 |

**1:1 상담 적용:** 밴드 선택 원칙과 같은 데이터·품질 가드를 적용한다. ‘상담 요약’에서 해당 내담자의 측정만 보여주며 증상·진단·상담 효과로 해석하지 않는다. 상담사 본인 EEG 또는 다른 내담자의 데이터를 합치지 않는다. 리포트 제외·파기·권한 정책을 적용하고 비공개 기록과 공개 코멘트를 분리한다. 상담 기능 게이트를 새로 켜지 않는다.

### F. 선택 진행 기록 — 회차당 한 번만 안내

미작성 회차 요약 첫 방문에 비차단 카드: **‘진행 기록을 남겨두면 다음 회차를 준비할 때 오늘의 진행 내용과 관찰을 다시 볼 수 있어요. 참여자에게 전할 코멘트를 작성할 때도 참고할 수 있어요.’** [지금 남기기]는 기존 기록 편집을 열고, [비워두기]는 카드를 닫는다. 저장하지 않아도 결과 열람·목록 복귀·승인 가능. 자동 변화 추적·AI 자동 반영·리포트 자동 재생성을 혜택으로 약속하지 않는다. 원문 직접 공유와 공개 코멘트 검토 경계는 §6.2에 따른다.

**저장 제안: 서버의 `(session_id, counselor_user_id)` 고유 키별 `seen_at`, `dismissed_at`와 선택 action.** 회차 상태이면서 보는 상담사별로 구분해 다른 상담사의 선택을 대신 적용하지 않는다. 첫 안내 렌더 전 서버에서 원자적으로 unseen을 claim하여 seen_at을 기록하고, 성공한 요청 하나만 카드를 표시한다. 이미 seen이면 다시 열거나 기기를 바꾸어도 안내하지 않는다. [비워두기]는 dismissed_at을 멱등 저장하고, seen_at만 있어도 재노출하지 않는다. 실패 시 닫힌 UI를 유지하면서 상태 저장 오류를 알리고 재시도하며, 서버 claim 실패·상태 불명에서는 안내를 재노출하지 않고 조용한 작성 버튼만 둔다. 브라우저 저장만으로는 기기 전환·스토리지 삭제에 대응할 수 없어 추천하지 않는다. 시안의 브라우저 저장은 합성 데모 동작에 한정한다.

[비워두기] 뒤에는 작은 ‘진행 기록 남기기’ 버튼만 유지하며 ‘미완료’ 경고·배지·재촉 팝업은 없다. 처음부터 기록이 있으면 안내하지 않는다. 기록을 나중에 지워도 seen 상태를 초기화하지 않는다. 첫 안내에서 [지금 남기기] 후 저장 없이 나가도 이미 한 번 본 안내를 반복하지 않는다.

**전체 끄기 옵션 제공 권장:** 계정의 `show_session_note_prompt`(제안, 기본 켜짐)를 설정 화면과 안내 카드의 ‘앞으로 안내하지 않기’에서 변경한다. 기존 기록·회차별 seen 기록·자동 승인에 영향 없음. 다시 켜면 아직 안내하지 않은 회차에만 적용. 안내 상태에는 메모 내용·개인정보를 저장하지 않는다.

## 6. 상태별 UX와 상태 계약

### 6.1 반드시 분리할 네 축

1. 세션: completed 여부 (종료 성공).
2. 생성: `pending | processing | ready | partial` + steps failed/reason 및 개별 report.status=error.
3. 승인: `pending_analysis | pending_review | completed | error` (completed는 승인됨).
4. 전달: 인앱 열람 가능 / 이메일 대기·발송·실패·미신청·확인 불가. **report.sent_at만으로 메일 발송 성공 표시 금지**.

근거: `lib/api/report-status.ts:152–207`; `useReportProgress.ts`는 `/record`의 `report:progress` + REST `/sessions/:id/report-status`를 5초 간격 조회, ready/partial 시 폴링 중단. 따라서 회차 진행 이벤트만으로 모든 참여자 리포트·메일을 완료 처리하지 않는다. 참여자 요약 조회를 별도로 갱신하며, 탭 재진입·재연결·focus 복귀 시 전체 상태 재조회. 연속 갱신 실패는 마지막 갱신 시각과 연결 상태로 노출한다.

### 6.2 현행 승인·자동 발송 정책과 제안의 경계

`backend/app/services/report_service.py:987–996`의 auto_approve_enabled는 현재 명상·상담 모두 계정 단일 설정을 사용한다. `:1112–1163` 승인에서는 completed와 sent_at/approved_at 설정 후, 최초 승인에 회원 알림 및 client 이메일 예약을 수행한다. `_enqueue_client_email_on_approval`은 participant·수신 이메일·기발송 여부를 확인한다. 메일 실제 완료는 `report_email_service.py:223–224`의 participant.report_email_status/sent_at이다.

자동 승인 경로는 `report_service.py:502–504`에서 공개 코멘트 초안 보완을 호출하며, 승인 후에는 `agent_report_chat.on_report_approved` 훅도 있다. 후자는 AI 활성·회원 client·비그룹 등의 조건부 동작이다(`agent_report_chat.py:45–80`). STT off와 AI 전체 off는 다른 설정이고, 이번 작업은 운영 설정값을 읽지 않았다. 새 자동 메시지를 추가하지 않되 기존 조건부 부수효과는 유지한다.

**이번 작업은 정책 변경 기획까지 포함하며 제품 정책은 구현·변경하지 않는다.** [자동 승인 정책 대안·추천안](auto-approve-policy.md)에 유형 분리, 클래스별 설정, 조건부 유예 방식과 이관을 비교한다. 추천은 상담/명상 분리 + 명시적 선택으로 도입하는 10분 유예·조건부 자동 승인이다. 기존 사용자의 설정을 몰래 끄거나, 기존 리포트를 소급 승인·재발송하지 않는다. 요약에는 적용 정책·예정 시각·보류 결과를 분리하고 유형 전체 변경은 설정 화면에서 영향 범위를 확인한다. 이 추천안은 Brian의 세부 결정 전이다.

개인정보 주의: `report_comment_service.py:139–163`의 비그룹 AI 공개 코멘트 초안에는 `counselor_notes`가 입력된다. `:186`의 원문 인용 금지 프롬프트만으로 의미 유출이 차단된다고 보장하지 않는다. 원문 직접 복사 없음과 AI 파생 코멘트의 공개 가능성을 구분하고, 정책 도입 전 입력 경계·공개 미리보기·승인 조건을 검증한다.

## 10. 결정됨 (Brian, 2026-10-23)
