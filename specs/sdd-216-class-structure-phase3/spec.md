## 1. 목적·전제·근거

- 지도사가 8회 명상 클래스를 한 번에 편성하고 회차별 진행자를 배정·변경한다.
- 백엔드 구현·검증·배포 → 프론트 구현·검증·배포의 2회 출시로 진행한다. Brian이 문서 기본값과 구현 전 검증 계약을 승인했다. 이번 문서 워커의 코드 구현 금지와 배포 금지는 유지한다.
- Brian 전제: 정식 릴리스 전, dev 계정은 테스터·단독 개발용, 기존 세션은 테스트 데이터. 기존 데이터 보존·백필·구 앱 호환 기간을 출시 조건으로 두지 않는다. 이번 작업에서 데이터 삭제를 실행하지 않는다.
- 신규 생성 이후의 회차·리포트·동의·감사 이력은 아래 제품 규칙대로 처리한다. 테스트 데이터 전제와 제품의 이력 규칙을 혼동하지 않는다.

## 3. 범위·이월

### 3.1 포함

- 시작 방법(S0) + 4단계 편성 + 완료/초안 이어쓰기.
- 고정형·정기형, 4종 배정, 일괄 편집 표·모바일 카드·시트, 서버 미리 보기.
- 클래스 강사 추가·제거·주강사 지정, 자기 회차 양도 요청, 시점별 진행자 변경·대강·수락.
- 지난 기수 복제, 한 회차/이후 회차 이동, 한 주 밀기, 정규·보강 회차 추가, 취소·마무리·보관.
- 명상+상담 통합 충돌, 정기형 4주 롤링, 최소 회원 멤버십, 클래스 코드, 알림·리마인더.
- 계정 정지·삭제·강제 소속 해제에 대한 명상 needs_reassign, 재배정 경고와 센터 대행.
- 비진행 강사 참관·사후 제한 열람, D-05 고지 개정, D-28 센터 관리자 열람 축소.

### 5.2 생성·배정·편집

- 시간대 `Asia/Seoul`, ISO 요일 월=1~일=7, 주 시작 월요일. 벽시계로 계산 후 UTC aware 저장. 시작일 포함, skip_dates 제외, interval_weeks 기본 1.
- fixed: 후보 N개 생성. rolling: 오늘부터 28일 미만, 선택 종료일 당일까지 생성. 과거 후보를 뒤늦게 만들지 않는다.
- `all_one`: 전체 한 명. `rotate`: 정규 회차 순서 `(정규 순번-1) % 강사 수`. `by_weekday`: 모든 선택 요일에 한 명 매핑. `per_session`: 각 후보에 한 명. rolling은 확인한 후보 순서별 배정 목록을 한 주기로 반복하며 다음 4주 미리 보기로 확인한다. 보강은 직접 지정하여 다음 정규 순환을 바꾸지 않는다.
- 배정 규칙은 생성 시 펼친다. 개별 수정은 해당 회차의 수동 override이며 다른 생성 회차·원래 반복 규칙을 소급 변경하지 않는다. 규칙 변경은 아직 생성하지 않은 회차에 적용한다.
- preview와 저장은 동일 생성·검증 함수를 사용한다. preview는 DB·코드·알림·ETA를 만들지 않는다. 저장 시 최신 권한·충돌·버전을 재검사한다.
- 클래스·강사·N개 회차·최소 회원/expected·코드·알림 및 예약 의도는 **한 DB 트랜잭션**. 외부 브로커·메일을 DB 트랜잭션에 포함했다고 주장하지 않는다. outbox를 커밋한 뒤 워커가 전달한다.
- 실패하면 생성 0건, 부분 성공 응답 없음. 제출 키 동일 재시도는 동일 class_id·session_ids 반환. 같은 키/다른 본문은 409.
- 편집 열: 선택·seq·날짜·시작/소요·방식/장소·진행자·충돌. 모바일/태블릿 세로는 같은 데이터와 검증을 쓰는 카드+시트. 드래그 필수 조작 없음.
- 일괄 시각/강사 변경, 선택 취소, 한 주 밀기, `이 회차만`/`이 회차부터 모두`는 서버 일괄 요청 1회. 전→후 확인 후 원자 저장. 선택 행에 완료·취소·진행 중 등 변경 불가가 있으면 전체 409·변경 0건.
- 한 주 밀기: 기준 회차 이후의 미진행 회차에 +7일. seq 유지, 원래 비운 날짜를 skip_dates에 기록. fixed 횟수 유지. rolling은 생성 커서를 되돌리지 않는다.
- 정규 추가는 마지막 seq+1 및 planned_session_count+1. 보강 추가는 마지막 seq+1, kind=makeup, 원 정규 회차 completed/cancelled 필요, 분모 증가 없음. 이번에는 대상 active 회원을 지도사가 직접 선택하며 결석자를 추정하지 않는다. 결석과의 출석 매칭은 P4.
- 정규 진행률: 분자=completed 정규, 분모=취소·숨김 제외 정규. 보강은 양쪽 제외. rolling은 총 분모 대신 완료 회차 수를 표시한다. 기존 API 집계도 이 의미로 함께 개정한다.
- 복제: 원본 recurrence_rule·assignment_rule·설정만 새 시작일에 투영. 보강·취소·수동 이동·코드·룸·run_id·동의는 복사하지 않는다. 원본 규칙이 없으면 미확인으로 표시하고 직접 일정 입력. 비활성 강사는 미정 초안, 공개 불가. 회원 초대 토글 기본 off.

### 5.3 클래스 수명·롤링

- draft에는 실제 회차·코드·회원·알림 없음. 개설자는 자동 lead. draft 관리 조회는 회차 존재 조건 없이 허용한다.
- 공개: draft→active 또는 직접 active 생성. 공개 후 draft 복귀 불가.
- fixed: 정규 회차가 모두 completed/cancelled이며 open/in_progress가 없으면 completed. 보강 때문에 새 정규 수료를 만들지 않는다. 종료 클래스의 기존 보강은 직접 초대 경로로 접근한다.
- rolling: 매일 02:00 KST OS cron + 명시적 보충 POST. GET은 쓰기를 하지 않는다. FE 상세 진입 후 관리 권한이 있으면 보충 POST를 별도 호출한다.
- class 행 잠금·생성 커서·seq 유일성으로 cron/동시 보충을 직렬화한다. 규칙에 남은 제거/비활성 강사 행은 보존하고 host_id를 그대로 참조하며 needs_reassign 생성. 유효 강사로 자동 치환하지 않는다.
- 수동 마무리/종료일: open/in_progress가 있으면 마무리 409, 경고를 남기고 생성은 중단. 나머지 미래 ready/scheduled를 취소하고 코드 사용 중단·멤버 완료·클래스 단위 알림 1통.
- 클래스 취소: open/in_progress가 있으면 409, 예정 회차 원자 취소, 코드 무효화. completed/cancelled→archived, 보관 해제는 보관 직전 상태로 복원. cancelled를 active로 되살리지 않고 새 기수 복제.
- completed 고정형에 정규 추가는 active 재개·새 코드 발급. 완료 멤버는 자동 재활성화하지 않고 새 초대 동작으로만 이어서 참여한다.

## 6. 강사·진행자·충돌

### 6.1 강사 구성과 경합

- 같은 기관 스냅샷의 active counselor membership을 확인한다. 개인 상담소의 타 강사·타 센터 지정은 불가. 센터 관리자는 자동 진행자로 등록하지 않는다. 생성 시 진행 가능한 lead를 지정해야 한다.
- 정상 제거: 미래 담당 회차 재배정/취소 선행, open/in_progress 담당자 제거 409, 마지막 active/lead 제거·강등 409. 제거는 status=removed, 같은 user 재추가는 기존 행 active 복구.
- 강사 배정·제거·주강사 변경·정지 처리는 같은 클래스 잠금 순서를 사용한다. 복합 FK는 존재만 보장하므로 active 검사를 생략하지 않는다.
- 강제 정지/삭제는 마지막 강사 보호로 차단하지 않는다. 계정 접근을 즉시 차단하고 운영 불가 상태·needs_reassign을 남겨 센터 관리자가 새 lead를 등록하게 한다. 과거 역할 행은 FK 이력으로 유지한다.
- guest는 지정 회차만 허용. `(class_id,user_id)` UNIQUE와 단일 scope_session_id 때문에 같은 guest의 다른 회차 동시 지정은 409. 여러 회차를 맡기려면 주강사가 일반 assistant로 명시 전환한다. scope=NULL guest는 권한 없음.
- guest의 ‘리포트 전부 승인’은 생성 완료된 실제 대상 리포트가 있고 모두 승인됐을 때만 성립한다. 생성 중/리포트 0건을 승인 완료로 간주하지 않고 14일 상한을 적용한다.
- guest 만료 및 회차 숨김/원본 삭제 경로에서 removed 처리. 이전 회차 접근은 감사 이력으로 본인이 확정 진행했던 범위만 판단한다. 임시 scope를 다른 회차로 옮겨 과거 권한을 넓히지 않는다.

### 6.2 진행자 변경

| 조건 | 처리 |
|---|---|
| ready 또는 시작까지 60분 초과의 scheduled | 즉시 변경, 새 host 기준 충돌 재검사 |
| 시작까지 0~60분 scheduled | pending_ack 요청, 기존 host_id 유지. 요청받은 강사만 수락/거절 |
| pending_ack 중 추가 변경 | 기존 요청 해소 전 409 |
| 수락 | class/session 잠금 안에서 후보 자격·상태·버전·충돌 재검사 후 host 교체 |
| 거절/만료 | 기존 host가 유효하면 assigned 복귀, 아니면 needs_reassign. 회원 알림 없음 |
| 마감 | 시작 15분 전. 요청 시 이미 마감 시각이면 새 수락 요청 409, 시각을 미뤄 다시 요청 |
| needs_reassign 재배정 | 같은 시간 규칙 적용. 수락 대기 중에도 기존 host 부적격이면 열기 불가 |
| open/in_progress/cancelled | 진행자 변경 409. 기존 진행자 재접속 또는 종료 후 보강 |
| completed | 승인된 리포트 0건일 때만 사유 필수 귀속 정정. 승인과 정정 경합도 동일 회차 잠금 |
| 승인 이후 | host_id·Report.user_id 불변, 표시 메모만 추가 |

- 모든 실제 교체: SessionHostHistory append-only + ChatRoom.host_id 동기화 + 새 host 기준 AI 접근/리마인더 + 이전/신규 강사 알림을 같은 커밋 기준으로 반영한다.
- host_state=pending_ack인 유효 기존 진행자는 열기 가능. 열기 시 미해결 요청을 만료 처리하여 인계 불가 규칙을 지킨다. 회원 화면에는 후보·기존 이름을 모두 숨기고 ‘진행 강사 확인 중’으로 표시한다.
- 계정 정지/삭제/강제 소속 해제: 명상 미래 ready/scheduled(지났지만 미진행도 포함)를 needs_reassign, pending 요청 폐기, hidden_at 불변. open/in_progress/completed/cancelled의 host·이력 유지. 명상 부모도 숨기지 않는다.
- 정지 해제만으로 assigned 복귀하지 않는다. 자격 재확인 후 재배정한다. 72h/24h 경고는 각 구간 1회, 이미 24h 안이면 현재 구간 1회만 발행한다. 24h 미해결은 센터 화면 최상단 ‘진행자 필요’ 목록에 표시한다.

### 6.3 통합 충돌

- 같은 host, 반개구간 `[start,end)`, 버퍼 0분. active 회차 ready/scheduled/open/in_progress, 명상·상담·기관 구분 없이 검사. 맞닿는 시간은 충돌 아님. 취소·완료·숨김·템플릿 제외.
- DB 기존 일정과 요청 내부 후보끼리를 모두 검사. 변경 대상 기존 행은 제외하고 최종 후보끼리 비교한다. 신규 host를 기준으로 한다.
- SQL 범위 조회와 `(host_id,scheduled_at)` 인덱스. 시작 전부터 길게 이어지는 기존 회차도 누락하지 않도록 종료 시각 조건을 사용한다.
- 응답: 후보 키·충돌 종류(host/place/member)·시간·상대 회차/부모 메타. 호출자가 볼 수 없는 상담의 이름·내담자·제목·ID는 제거하고 ‘다른 일정’만 제공한다.
- 장소는 같은 센터·주소 문자열일 때만 정보성 경고. 회원 충돌은 접근 가능한 범위만, 상담은 같은 상담사 일정만. 회원 API에 타인 충돌 목록을 반환하지 않는다.
- force는 경고 확인 의미이며 검사 생략이 아니다. 최신 충돌 집합이 preview와 달라지면 재확인 409. 열기·시작도 동일 확인 절차. EXCLUDE 제약은 도입하지 않는다.

## 7. 최소 멤버십·클래스 코드·알림

### 7.1 최소 멤버십

- 회원 초대/코드 가입 → class_members active 1행 + 합류 시점 이후 ready/scheduled 정규 회차 expected. 재요청 중복 없음. 이미 열린 회차는 기존 입장 경로에서 해당 회원의 출석 행을 멱등 보장한다.
- 과거 회차 expected를 만들지 않는다. 새 rolling/정규 회차 생성 시 active 회원 전원 expected. 보강은 지정 회원만 생성한다.
- report_included 기본 false, 연구 동의 복사 없음. D-05 고지 확인과 리포트 반영·연구 선택을 별개로 저장한다. client_counselor_links 자동 생성 없음.
- 최소 정원은 active 회원 수 기준 잠금 검증, 초과는 409. 클래스 대기열·자동 승격은 P4로 이월. 기존 회차 대기열과 섞지 않는다.
- 이메일/CSV는 클래스 단위 초대 요청을 기록하고 1통 발행한다. 비회원 장기 신원·멤버 병합은 만들지 않는다. 비회원은 입장 가능한 회차에서 기존 일회성 자격을 사용한다. 이메일 주소만으로 기존 사람·동의를 연결하지 않는다.
- 회원의 부모 일정 열람과 회차 입장/본문 열람을 구분한다. active 멤버는 일정 타임라인, 본인 참여자 행은 입장, 승인된 본인 리포트만 본문 허용.

### 7.2 코드

- `[0-9]{4}` 문자열·선행 0 보존, 클래스당 1개. 신규 명상 하위 세션의 access_code는 NULL, 공유 엔진 응답의 표시 코드는 부모에서 해석한다.
- 생성/재발급/단일 세션 생성 경로 전부 같은 발급 잠금을 사용해 활성 Class 코드와 아직 사용하는 Session 코드의 합집합에서 선택한다. 같은 부모에 기존 복사 코드가 있으면 같은 소유로 취급한다. 별도 클래스의 중복 점유 금지, 소진 503·전체 롤백.
- 코드로 부모를 찾고 회차를 선택한다. open/in_progress 한 건이면 진입, 여러 건이면 공개 가능한 일정 선택, 아직 열리지 않았으면 회원 가입 결과·다음 일정 안내. 미래 회차에 바로 진입시키지 않는다.
- 비회원은 아직 열린 회차가 없으면 다음 일정 안내만 제공한다. 장기 멤버십을 만들어 신원으로 쓰지 않는다.
- 종료·취소·보관·숨김·잘못된 코드는 동일 404, 시도 제한 재사용. 코드를 URL·로그·분석 이벤트에 넣지 않는다. 초대 메일 본문에만 넣는다.

- 카탈로그·선호 기본값·이메일 제목·인앱/푸시·FE 대상 해석을 같이 변경한다. 신규 이벤트 선호 초기값은 인앱 on, 이메일 off. 기존 리마인더 선호는 유지한다. 임박 푸시는 사용자 푸시 수신 설정을 따른다.
- 미정·수락 대기·needs_reassign은 회원에게 변경 확정 알림을 보내지 않는다. 재배정 확정/취소 확정 때만 발행한다.
- 리마인더 수신자는 active 멤버에서 해당 회차 excused/withdrawn을 제외. expected 행 유무만으로 누락하지 않는다. 비회원 리마인더는 P4. 실행 시 최신 시간·상태·멤버십·host 자격 재검사.
- 브로커/메일 실패는 예약·outbox 재처리로 복구. 저장 성공과 전달 성공을 분리한다. 이번 문서 작업에서 발송하지 않는다.

## 9. 시각·기능 수용 기준

- CH01 열린 회차 히어로·건수 탭·소프트 사이드바·클래스 행, CH02/03 탭·회차 행, CH06 설정·강사 패널, CH10~15 몰입형 단계, CH20 표/카드·시트, CH30 축소 상세를 시안에 맞춘다.
- SDD-215 summary의 픽셀 차이 중앙값 약 59%(14~86%)는 과거 기록이며 이번 재측정값이 아니다. DOM fit 통과만으로 시각 완료를 선언하지 않는다.
- 동일 Chromium·폰트·시계·합성 데이터·DPR 1에서 390×844 / 834×1194 / 1194×834 / 1280×720 원본·앱·diff·overlay를 리플레이한다. 상세 case는 verify 정본.
- 의미 차이로 승인된 작은 영역 외 공통 영역 픽셀 차이 비율 0.1% 이하(threshold 0.2), 정렬점 오차 2px 이하. 넘으면 원인을 수정하거나 사용자 검토 대상 차이로 남기며 자동 통과 처리하지 않는다.
- 히어로·사이드바·행 전체를 마스킹하지 않는다. 글자 12px 이상·터치 44×44px 이상·8px 간격 체계·텍스트 잘림/페이지 넘침 0. 목록/표/초대 목록 내부 스크롤만 허용한다.
- loading/error/empty/missing/no-band/long-content, 키보드·초점 복귀·모바일 안전 영역 포함. null은 데이터 없음, 실제 0만 0.
- 용어 사전 사용: 명상은 클래스·회차·지도사, 상담은 상담·상담사. 기존 영역별 금지어 가드 유지, 시안 ‘세션/오픈’은 회차/열기로 바꾸고 의도 차이에 기록한다.
- 실제 PG 4대 게이트(FK·8회 원자성·충돌 일괄·needs_reassign)와 D-05/D-28 권한 우회 검증이 통과해야 BE 출시 가능. 모의 API 리플레이는 실제 서버·기기 검증을 대신하지 않는다.
