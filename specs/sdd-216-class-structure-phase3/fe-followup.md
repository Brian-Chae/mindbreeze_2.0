# SDD-216 — 프론트엔드 후속 구현

- 담당: FE 전담 워커. 전용 브랜치 `sdd/216-fe-followup`.
- 변경 소유: `frontend/`, 이 문서. BE·배포·원본 verify 변경 없음.
- BE 실제 배포 미확인. 로컬 구현과 모의 API 테스트는 배포 검증과 구분한다.
- 전체 BE/FE 회귀를 실행하지 않는다. 변경별 focused Vitest와 최종 타입·빌드 1회.

| 작업 | 내용 | 구현 전 기대값 |

| F02 | 새 마법사 기본·일정·배정·초대 4단계 | 명상 생성은 `/classes`; 상담 생성 유지. 요일/정원/주소/날짜 검증, server preview만 사용 |
| F03 | 초안·재개·복제·충돌·완료 | 미정 공개 차단/초안 허용, 입력 변경 시 preview·충돌 동의 폐기, 저장 중 중복 호출 차단 |

## 상태

- F01~F03 진행 중. F04~F07 대기.
- V-54~65 및 CH10~15·CH20·CH04/06/30 기준. 원본 verify는 구현 전 게이트를 유지한다.

## 첫 구현 묶음

- F01 커밋 `adfacb71`: 편성 DTO/API·nullable host·현재 설정·revision/state_version·입력 검증·동일 요청 재시도 키.
- F02~F03: `/classes/new`를 새 4단계 마법사에 연결. 기존 `/counseling/new` 유지.
- `/classes/new?draft={id}` 초안 이어쓰기, `?copy={id}` 원래 규칙 복제·멤버 복사 기본 꺼짐.
- 4종 배정, 같은 센터 후보 선택, 회차별 override, 서버 preview, 충돌 fingerprint 확인, 초안/공개 저장, 이메일 전달 요청·요청 실패 재시도.
- 후보 API 실패 시 저장 차단. 입력 변경 시 preview·충돌 동의 폐기. 계정/경로 변경 시 이전 결과 폐기. 저장 중 ref 잠금으로 중복 호출 차단.
- 시안 CH11~14의 단계·색상·카드·보조 요약·행·모바일 구성을 반영. 실제 브라우저 시각 비교는 미검증.
- focused: 모델/API 6개, 마법사 5개(필수 입력·기능 불가·중복 클릭·미정 초안·충돌), 기존 데이터 17개 통과. 타입 검사 `tsc -p tsconfig.app.json --pretty false` 통과.
- 전체 FE/BE 회귀·실제 서버 호출·외부 이메일 발송 없음. 최종 통합 빌드는 감독자 실행.
- 후속: CH20 구현, 실제 요청 AbortSignal 전달, 화면별 브라우저 QA. 운영·고지·참관·CH30은 별도 FE 운영 워커 소유.

## CH20 및 저장 보완

- `ClassScheduleEditor({detail,sessions,onSaved})`: capability와 revision이 있는 관리 화면에서만 표시.
- 데스크톱 표/모바일 카드에 같은 편집 상태 사용. 완료·취소 행 선택 차단, 이 회차/선택/이후 회차 적용 시트.
- 일괄 수정·한 주 이동·취소를 서버 preview로 확인한 뒤 하나의 bulk 요청으로 저장. 모든 선택 회차 state_version과 클래스 revision 전달.
- 최신 충돌 응답 시 fingerprint 교체·동의 해제. 편집으로 돌아가기는 저장하지 않음. 수정 시트 닫기 시 원래 버튼 초점 복귀.
- 관리자 대행 사유를 실제 사용자 입력으로 받아 초안 수정/공개/초대·bulk에 전달. 이탈은 기존 useWizardLeaveGuard로 브라우저 뒤로가기 포함 처리.
- focused: 마법사 5개 + CH20 2개 = 7개, 1.32초 통과. 전체 회귀 없음.
- 정규/보강 추가·고지·참관·실브라우저 시각 비교는 이 묶음 완료 범위에 포함하지 않음.

## 정규·보강 회차 추가와 취소 신호

- CH20 아래 정규 회차·보강 추가. 보강 원본은 완료/취소 정규 회차만, 회원은 활성(완료 클래스는 수료 포함)이고 user_id가 있는 항목만 선택.
- 회원 행 id 대신 user_id를 member_ids로 전달. 원본 회차 id·revision·관리자 사유·operation_key를 함께 저장. 충돌 응답 뒤 확인한 fingerprint로 재시도.
- 후보·편성 preview·bulk preview는 AbortSignal을 공용 클라이언트에 전달. 화면 이탈 시 읽기 취소, 늦은 응답 폐기. 공용 client 구현은 별도 진입 워커가 담당.
- focused 4파일 16개 2.22초 통과. 보강 회원 미선택 차단·원 회차/user_id 전달·비회원 제외 포함.
- 실제 생성·보강·롤링·메일 서버 통합과 브라우저 비교는 미검증.

## 홈·생성 진입

- 대시보드 실제 class_id/counseling_relationship_id/area로 오늘 일정 칩과 부모 회차 링크 연결. 부모 누락·모순이면 유형명으로 추정하지 않고 기존 회차 경로 유지.
- 회원 홈 다음 일정에도 실제 영역 칩 표시.
- 클래스가 없는 계정의 새 생성은 서버 후보 API 성공으로 활성 여부 확인. 스위치 off·권한 없음·조회 실패이면 CTA 비활성. 클래스별 편집은 상세 capabilities.schedule 사용.
- CH01 열린 회차 히어로에 기존 이미지 자산·색상·여백 반영. 공통 사이드바와 전체 행의 시안 픽셀 일치는 아직 미검증.
- focused: 홈 경로 3개+기존 회원 화면 21개 = 24개 1.63초 통과; 생성 CTA 2개+기존 호스트 읽기 14개 = 16개 1.28초 통과.
- 초안·복제 및 마법사/CH20 로컬 구현은 완료된 기능 묶음이며, 실제 BE와 브라우저 통합·시안 전수 비교를 통과했다는 의미가 아니다.
