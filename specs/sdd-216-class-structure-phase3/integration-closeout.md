## E2E 계약 보완 — 구현 전 확인

- 사용자 “진행하자”로 PR 병합·develop 배포까지 승인받았다. 기존 머지 금지 범위는 이 통합 작업에 한해 해제한다.
- 기존 journeys/full-journey는 POST /sessions 명상 생성 사용. 편성 활성 시 session_service.create_session은 use_class_scheduling 409를 반환한다. 새 클래스 API로 테스트 준비를 전환한다.
- 기대값: 예약 클래스는 고정형 최소 2회·초대 회원·진행자·KST 일정 보존. 즉시 클래스는 1회차 open을 생성하므로 open 중복 호출 없이 start한다. 같은 상담사의 A/B 진행은 A 종료 후 B 생성으로 순서를 맞춘다. 생성 오류는 상태와 detail을 남긴다.
- 공통 테스트 준비 함수의 요청·응답·오류를 대역 테스트한 뒤 CI에서 실제 dev 흐름을 확인한다. 제품 충돌 검사를 해제하지 않는다.

- 제품 커밋 `7e34c056`의 BE CI도 22분 48초에 통과하여 FE·BE·PG 전체 성공을 확인했다. 이후 변경은 통합 문서와 E2E 준비 경로이며 제품 코드는 바꾸지 않는다.
- E2E 준비 함수 초점 테스트 3개 통과, 수정한 두 시나리오 파일 구문 검사 통과. 미진행 클래스는 부모 API로 숨기고, 완료 클래스는 보관해 원본 보존 정책을 따른다. 실제 dev E2E 결과는 후속 기록한다.
