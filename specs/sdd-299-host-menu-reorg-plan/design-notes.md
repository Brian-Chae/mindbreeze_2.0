## 디자인 결정
권장 A를 시각화했다. 네 독은 분석·채팅·미디어·설정 순서. 정원은 새 설정의 첫 구역에 두고 상단은 인원·시간만 표시한다. B는 plan.md 비교표에 있으며 별도 시안은 만들지 않았다.

기존 `design-1104/289-capacity-increase-sheet-v2.html`과 design-notes.md의 보라/자연 방향을 계승했다. 배경은 `designs/class-structure-redesign/assets/bg/background4.webp`를 HTML에 내장했다. 제품 이미지·기존 시안 원본을 바꾸지 않았다. `player-tokens.css`의 보라 #5F0080, 라벤더 #B373EF, 연보라 #D2AEFC, 민트 #01F0C8, 본문 #F7F4F0, 보조 #CFC6D6를 사용했다. 시트 배경은 불투명하게 하여 배경 글자가 비치지 않도록 했다. Pretendard 계열 및 시스템 폴백, 시트 24px·카드 16px 계열 반경을 유지했다.

390px에서 독 버튼 폭은 각 87px, 높이 64px, 아이콘 24px, 라벨 13px이다. 긴 시트는 내부 세로 스크롤하며 아래 기능은 스크롤 PNG로도 제공한다. 분석의 정렬·표 보기와 설정의 참여 안내·내 기기·나가기를 제거하지 않았다.

모든 인원·코드·대화는 합성 예시다. 기본은 정원 40/입장 40/대기 3. 고정 결과 프레임은 정원 45와 서버가 3명을 입장 처리했다고 가정한 표현이다. 동적으로 입력하는 폼에서는 처리 인원을 계산하지 않고 서버 응답 확인 대상으로 안내한다. 두 경우 모두 실제 입장 40을 임의로 올리지 않는다. 결과 프레임의 대기 3은 최신 목록 반영 전 예시이며 실제 구현은 새 대기 목록을 받아 갱신해야 한다.

## 시안 동작과 한계
- 네 메뉴 클릭은 갤러리의 해당 방식 기본 프레임으로 이동한다. 단일 실제 앱의 라우팅이 아니다.
- 분석 6개 지표 단일 선택, 정렬 선택, 토글, 채팅 받기 on/off에 따른 대화·입력 숨김을 제공한다.
- 정원 입력/스텝퍼/오류·관리자 사유·처리 잠금·합성 결과, 시트 닫기/재진입을 제공한다. 실제 네트워크 요청은 없다.
- 채팅 전송·초대·코드 복사·내 밴드·마커·영상 제어·나가기는 시각 예시이며 서비스/장치 동작이 아니다. 녹음 버튼도 라벨 예시만 바뀐다. 실제 녹음 상태 전이·오류 복구를 검증했다고 해석하면 안 된다.
- 대표 미디어 상태는 녹음 중이다. 녹음 시작·재개·권한 거절·무음 녹화 등 전체 조건별 UI는 analysis/plan의 보존 계약에 명시하고 이 갤러리에 모두 펼치지는 않았다.
- 여러 독립 시트를 비교하는 갤러리이므로 aria-modal·배경 inert·모달 포커스 트랩을 적용하지 않았다. 제품 적용은 PlayerSheet 기존 동작을 보존해야 한다. 닫기 버튼은 시트 본문과 함께 스크롤하며 Esc도 제공한다. 제품에서 긴 시트의 헤더 고정 여부는 후속 디자인 검증 대상이다.

- 이 워크트리의 소스만 입력으로 사용하고, 설치가 없는 의존성은 메인 체크아웃의 기존 node_modules를 읽었다. 제품 파일이나 의존성 설치물을 바꾸지 않았다. 출력 JS/CSS/HTML은 모두 design-1105의 299-v2 접두어 파일이다.
- Before는 현재 제품 컴포넌트의 합성 하니스다. 실제 서비스 로그인·운영 클래스·실제 카메라·장치 화면은 아니다. C01의 8명 픽스처와 기존 도구 시트를 사용한다. 하니스는 capacity props를 제공하지 않으므로 증원 기능의 운영 재현 근거로 쓰지 않는다.
- 전역 border-box와 body 여백 리셋을 외부 렌더 문서에 적용했다. 캡처용 주입은 제품 소스 수정이 아니다. 비교표의 Before/v1/v2는 데이터와 기능 분류가 서로 다르며, 같은 픽셀 상태의 회귀 비교가 아닌 시각 언어 비교다.

## 모션 메모
- 실제 시안: 시트 첫 표시 220ms ease-out / 아래 14px 이동, 컨트롤 상태 150ms, 처리 중 아이콘 회전. reduced-motion이면 정지한다.
- 독 전환은 내용과 선택 상태를 즉시 바꾸어 조작을 지연시키지 않는다.
- 닫기는 현재 시안에서 즉시 반영한다. 제품 적용 시 150ms opacity-out을 사용할 수 있으나 터치 차단이나 닫힘 지연은 만들지 않는다.
- 결과는 별도 카드로 전환한다. 제품 적용 시 150ms opacity-in 정도만 사용하고 숫자 카운트업·축하 모션은 넣지 않는다.

## 검증과 경계
- 19개 상태 페이지 캡처, 19개 상호작용 검증. JS 오류 0, 본문/시트 가로 넘침 0, 표시된 버튼의 44px 미만 높이 0.
- 오류 문구가 시트 스크롤 영역 안에 포함됨을 getBoundingClientRect로 확인. 제출 버튼도 844px 화면 안에 있다. 스크롤 전후 헤더 top 변화 0.
- 입력 오류 4종, 처리 잠금, 상단 정원 갱신, 실제 입장 불변, 결과 후 메뉴 왕복, 단일 지표 선택, 채팅 off, 관리자 사유, 오프라인 상한, 충돌 재입력, 카메라 토글·닫기/재진입을 확인했다.
- 신규 사용자용 HTML 4종과 렌더 본문의 금지 문구 검색 0건. Before 번들은 기존 제품 코드를 그대로 포함한 기준선으로, 기존 소스 문구를 변경하지 않았다.
- 주 HTML·비교 PNG·오프라인 비교 PNG는 HTTP 200 및 파일 내용 일치 확인.
- 기본 데이터는 입장 40/정원 40/대기 10이다. 결과 예시는 정원 50만 반영하고 대기 목록 10은 갱신 전으로 유지한다. 입장 처리 수를 임의로 추정하지 않는다.
- 시안은 합성 상태다. 실제 API·녹음·영상·밴드·초대·종료를 호출하지 않는다. 제품 테스트·운영 반영·네이티브 키보드·안전영역 기기 실측은 수행하지 않았다. env(safe-area-inset-*)는 적용했으나 데스크톱 캡처 값은 0이다.
- 대비는 기존 밝은 텍스트와 실제 앱 서피스를 유지하고 최종 PNG에서 읽기 상태를 점검했다. WCAG 전 항목 자동 인증이나 실기기 가독성 검증을 뜻하지 않는다.
