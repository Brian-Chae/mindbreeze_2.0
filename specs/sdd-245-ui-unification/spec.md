## 문제와 목표

공통 AppShell/ClientShell이 있어도 페이지의 contentPad 재정의, 중첩 최대 폭, 도메인 CSS, raw 버튼이 서로 다른 규칙을 만든다. 같은 메뉴를 이동했을 때 콘텐츠 시작선·제목 위치·조작 요소의 모양이 달라지는 것을 해소한다. 스타일 문자열이 다르다는 사실만으로 불일치라 단정하지 않고, 동일 용도의 요소를 같은 viewport에서 비교한다.

역할별 기준 홈은 회원 `/app`, 상담사 `/dashboard`, 기관관리자 `/dashboard/org`, 플랫폼 관리자 `/admin/orgs`다. 플랫폼 관리자에게 별도 대시보드를 만들지 않는다(`frontend/src/lib/auth-routing.ts:5`). 홈 자체도 모든 역할 간 완전히 같지 않으므로 관측값과 통일 제안값을 분리한다. 잘못된 대비·작은 터치 영역까지 복제하지 않는다.

## 범위

- 라우터 선언 94개와 `/app/*` 수동 분기 전체의 경로 인벤토리. 각 역할·390×844, 1440×900 표본에 정상/빈상태/리다이렉트/권한 분기/오류를 명시한다.
- 인증 후 일반 화면: 페이지 바깥/안쪽 좌우 여백, 콘텐츠 최대 폭과 정렬, 페이지 제목·섹션 제목, 섹션 간격.
- primary/secondary/ghost/icon 버튼의 크기·radius·padding·글꼴·normal/hover/focus/disabled, 카드·입력/select·탭·칩의 스타일 계약.
- 기존 디자인 토큰 원본을 정본으로 정리하고 공용 UI/페이지 래퍼를 도입한다. 셸 중복 여백을 제거하고 페이지군을 순차 이관한다.
- 공개 가입·안내·약관 화면은 공통 색/글꼴/컨트롤 토큰을 적용하되 본문 읽기 폭·독립 레이아웃은 용도별 예외로 명시한다. 별도 랜딩의 마케팅 타이포그래피를 앱 페이지 제목으로 덮어쓰지 않는다.
- 감사는 로컬 실제 앱 빌드 + 합성 GET fixture. 네트워크 가로채기(정해진 공개 폰트 CDN의 GET만 로컬 캐시 허용), WebSocket 차단, 인증 refresh mock 외 비GET 405. 사용자 클릭/제출·실서버 쓰기 없음. API 통합·실기기 검증을 주장하지 않는다.

## 비범위와 예외 판단

- 정보 구조, 메뉴, 화면 구성 순서, 문구, 데이터/API, 기능, 인증·권한, BLE/미디어, 수업 운영 로직은 변경하지 않는다. 종합점수 추가 금지.
- **명상 클래스 플레이어 몰입 화면은 통일 대상에서 제외하는 것을 추천한다.** `/sessions/:id/player`의 라이브 캔버스·영상·차트·오버레이·풀스크린 조작은 일반 페이지 여백과 버튼 규칙을 기계 적용하면 공간과 조작성을 훼손한다. 경로는 감사 목록과 회귀 캡처에 남기고 현 상태 보존 검사를 한다. 시안 `/design/*`도 제품 이관 대상이 아니다.
- 일반 클래스 목록·상세·예약·결과 리포트는 포함한다. 플레이어로 들어가기 전 대기/진입은 기존 공간 배치 유지, 공통 버튼·입력의 색/타이포만 검토하고 플레이어 CSS를 수정하지 않는다.
- 로그인은 진행 중인 `fix/mobile-login-header` 소유다. `LoginPage.tsx`, `ClientLoginPage.tsx` 및 해당 FIX 변경 파일은 수정 금지. 공통 토큰 변경의 간접 영향만 캡처하고 FIX 반영 뒤 재검증한다.
- 채팅 대화면, 문서/리포트 읽기 폭, 입력 폼 좁은 폭은 기능 목적이 있는 예외. 페이지 제목·외곽 시작선은 통일하되 내부 읽기 폭을 없애거나 채팅 패널을 재배치하지 않는다. 예외는 route/selector/속성/이유 단위로 관리한다.
- 이번 턴은 감사 도구·근거 및 spec/plan/verify만 작성. 제품 소스 구현, PR, 머지, 배포는 진행하지 않는다. SDD 완료로 표시하거나 summary를 사후 구현 기록처럼 만들지 않는다.

## 수용 기준

1. 감사 인벤토리의 모든 경로×역할×viewport에 캡처와 계산 스타일이 있거나 명시적인 차단/리다이렉트 사유가 있다. 오류 화면을 정상 페이지 측정으로 세지 않는다.
2. 승인된 일반 화면에서 frame의 좌우 시작선·padding·max-width, 동일 variant/size 컨트롤 수치가 정본과 0~1px 안에서 일치한다. 숫자 font-weight/색·shadow 문자열은 의미가 같은 정규화 값으로 정확히 일치한다.
3. 모바일 390px 수평 넘침 없음. 기존 정보량·상호작용·focus·disabled 의미를 유지한다. 아이콘 44px 이상, 기본 입력 48px 모바일 하한 유지.
4. 버튼 텍스트 대비 AA: 일반 텍스트 4.5:1, 큰 글자 3:1. 아이콘/컨트롤 경계 3:1. hover·focus 포함. disabled는 예외 근거를 별도 표기한다.
5. 기존 테스트 17개 실패의 이름·원인을 고정하고 신규 실패가 없어야 한다. 기존 실패를 숨기려고 삭제/skip하거나 assertion을 완화하지 않는다.
6. 홈과 대표 페이지 나란히 비교, 390/1440 전체 재측정 및 768/1024/1920 보조 폭 확인 후 독립 검증자가 승인한다.

## 결정 필요

1. **몰입 플레이어 제외 범위** — 추천: 라이브 플레이어·몰입 오버레이는 현 디자인을 보존하고 일반 페이지/결과 리포트만 통일. 이유: 화면 구성과 수업 조작성 유지.
2. **역할 간 홈 차이 처리** — 추천: 회원·상담사 홈의 20px 카드와 둥근 주 CTA를 앱 공통 방향으로 채택하고, 관리자 홈도 같은 토큰으로 이관. 관리자 홈의 16px 카드·42~42.5px CTA를 별도 정본으로 고착시키지 않는다. secondary·ghost·아이콘은 용도별 variant를 유지한다.
3. **좁은 읽기 폭 허용** — 추천: 설정/문서/리포트의 내부 읽기 폭과 채팅 분할 구조는 유지하고 외곽 frame/제목만 통일. 모든 화면 본문 폭을 1280px로 강제하지 않는다.
