# SDD-218 — 클래스 리포트 관리와 회원 변화 추이

- 상태: Stage ① Spec — 검토용 초안, 사용자 승인 전
- 작성일: 2026-10-20
- 브랜치: `sdd/218-class-structure-phase5`
- 선행: SDD-217(클래스 Phase 4) 통합 및 공통 계약 재확인
- 범위: 클래스 우선 출시의 Phase 5. 이후 Phase 8-A 출시 점검. 상담 Phase 6·7은 후속 업데이트.
- 안내: [착수 보고서](kickoff.md). 아래 요구와 API는 기존 기획을 정리한 제안이며 아직 구현 확정 계약이 아니다.

## 목적

지도사가 클래스 안에서 회차별 리포트의 생성·검토·발송 상태를 보고 일괄 처리하며, 회원은 본인의 출석과 회차별 변화 방향을 확인한다. 기존 회차 리포트와 생성 파이프라인을 재사용한다.

## 포함할 요구

### R1 클래스 리포트 운영
- 클래스 상세 리포트 탭: 회차별 생성·승인·발송 상태, 행을 펼쳐 건별 상태 확인.
- 생성 중·실패·미생성·검토 대기·부분 실패를 구분한다.
- 승인·재생성·메일 재발송의 선택 대상과 실행 결과를 제공한다. 결석을 빈 리포트나 0점으로 만들지 않는다.

### R2 일괄 작업의 신뢰성
- 승인/재생성/재발송은 비동기 접수(202)와 작업 결과 조회를 구분한다. 작업ID, 결과 조회 경로 및 DTO는 Plan/API 계약에서 확정한다.
- 대상 확정, 실행 시 재권한 검사, 건별 멱등성, 부분 실패, 안전한 재시도를 설계한다.
- 동일 요청과 중복 클릭/워커 재시도에도 승인·메일·알림·AI 비서 후속 효과가 중복되지 않아야 한다.
- 기존 단건 API와 `POST /reports/approve-all`의 응답·의미는 호환 유지한다.

### R3 승인 주체·감사·열람
- D-36 제안: 현재 진행 강사 + 현재 주강사 대행 승인, 실제 승인자/시각 기록. **승인 전 권한 확대 금지.**
- 센터 관리자·일반 보조 강사에게 일괄 승인권을 자동 부여하지 않는다.
- 현재 진행자 변경, 비활성/퇴사, 제거된 강사, 다른 클래스/기관 경계를 실행 시 검증한다.
- 승인 전 회원 비노출, 본인 승인 리포트만 열람, 이탈 후 본인 과거 리포트 열람과 217 canonical guest 정책을 보존한다.
- `approved_by_user_id`/`approved_at`은 이미 존재하므로 재사용한다. 과거 승인자를 추측해 backfill하지 않는다.

### R4 회원 변화 추이
- 회원 본인 출석·결석·보강·합류 전/이탈 중 구분, 측정 회차 수, 승인된 본인 리포트 링크.
- 각 회차 내부의 전반→후반 변화 방향을 나열하고 보강을 원회차와 연결한다. 회차 사이 건강 개선/악화를 추정하지 않는다.
- LINK BAND 미착용·데이터 유실·미동의·결석을 구분한다. 미측정을 0으로 대체하지 않는다.
- 회원 화면은 방향·서사를 우선한다. 기존 상세 기획의 ±델타 표기 충돌은 결정 필요이며 승인 전 숫자 델타를 추가하지 않는다.

### R5 지도사용 집계·자료 보호
- 회차별 출석 요약과 익명 방향 분포. 반영 가능한 유효 착용자 3명 미만은 분포 비노출.
- `report_included`, 제외 플래그, 연구/리포트 동의의 서로 다른 의미를 보존한다.
- 점수·종합점수·회원/강사 순위·타인 대비·강사 성과 비교를 만들지 않는다. `eeg.score`를 추이에 사용하지 않는다.
- 센터 관리자에게는 권한 범위 내 클래스 업무 건수만 제공한다. 원문·녹음·영상 열람 권한을 새로 넓히지 않는다.

### R6 기존 데이터·호환
- 기존 `session_id × participant_id × report type` 식별 및 FK를 보존한다.
- `content.eeg.change`는 기존 계산 자료가 충분할 때만 가산한다. 자료가 없으면 미산출로 표시하고 값을 만들지 않는다.
- 과거 자료 백필은 결정론 계산·건별 재시도·제외 재검사·중단/재개를 갖춘 별도 실행으로 설계한다. 준비 단계에서 운영 백필을 실행하지 않는다.
- 동의 기본값 복사는 217 계약을 재사용한다. 회차 override·명시 철회·이탈/보강 예외를 덮지 않는다.

## 제외
상담 Phase 6·7 구현, 클래스 마무리 리포트 신유형, 개인 장기 기준선, 새 EEG/STT/LLM 엔진, 전역 narrative cache 재설계, 점수/순위, 강사 비교, 회원 전환 및 비회원 상담, 운영 배포/백필 실행.

D-37 자동 승인 영역 분리는 Phase 5 포함 문구와 Phase 6 결정표가 충돌한다. 상담 동작을 이번 SDD에서 임의 변경하지 않으며, 공통 안전 분리만 포함할지 Spec 승인 전에 정한다.

### 시안 승인에서 확정된 UI 계약

- 리포트 상태는 6종으로 구분한다: 승인·발송 완료 / 검토 대기 / 생성 중 / 부분 실패 / 생성 실패 / 미생성. 색 외에 외곽선 형태로도 구분한다(색맹 대응).
- 일괄 작업 결과는 **재시도 가능한 실패**와 **정책상 처리 제외**(실행 중 동의 철회 등)를 분리해 표시한다. 처리 제외 건에는 재시도 수단을 노출하지 않는다.
- 회원 추이는 회차 **내부**의 전반→후반 변화만 서술한다. 회차 간 개선/악화로 읽히는 문구를 쓰지 않는다.
- 유효 착용 3명 미만 회차는 분포를 숨기고 그 사유를 안내한다.
| P5-02 | **해소.** 비동기 일괄 작업 계약 확정(2026-10-20). `POST /classes/{class_id}/report-jobs` 202 → `GET .../{job_id}` → `POST .../{job_id}/retry`. `state` ∈ succeeded / failed / excluded / pending 으로 **재시도 가능 실패와 정책상 처리 제외를 분리**. 기존 단건 승인과 `POST /reports/approve-all`의 응답·의미는 불변. 상세는 plan.md §2·§3. |
