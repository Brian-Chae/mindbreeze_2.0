## 1. 목적과 출시 순서

클래스 우선 출시의 Phase 4다. 지도사는 멤버의 합류·이탈·결석·보강을 관리하고 회원은 자신의 참여 상태와 지난 기록을 확인한다. 216에서 사용자가 발견한 진행 화면 결함 3건을 함께 해결한다.

순서: 216(Phase 3) → 217(Phase 4) → Phase 5 클래스 리포트 → 클래스 출시 점검(8-A). 상담 Phase 6·7은 출시 이후 업데이트다. 이 순서는 현재 대화에서 승인된 출시 조정이며, 기준 커밋의 오래된 전체 기획보다 우선한다. 상담 메뉴 공개 여부·운영 배포는 이 SDD에서 자동 결정하지 않는다.

입력: `docs/class-session-restructure/기획-상세-회원내클래스.md`, `기획-상세-상태머신권한.md`, `결정-필요.md`, `specs/sdd-216-class-structure-phase3/{spec,api-contract,next-sdd-handoff,integration-closeout}.md`. 과거 문서의 미구현 설명보다 기준 코드가 우선한다.

## 3. 기능 요구사항

### R1 멤버십·정원·대기열

- 상태는 기존 `invited/waitlisted/active/completed/left/removed/declined`를 유지한다. 초대는 현행 즉시 active 기본값이며 수락제는 신설하지 않는다.
- active → left(본인), active → removed(관리 권한 강사), waitlisted → left(본인 취소), left → active/waitlisted(재가입), removed → active/waitlisted(강사 명시 복구만). cancelled/archived 클래스 신규 가입 금지. completed 회원을 코드로 active로 되돌리지 않는다.
- 재가입은 같은 멤버 행을 사용한다. 합류 이전·이탈 중 과거 회차를 expected/absent로 생성하지 않는다. 과거 참가자 ID·EEG·리포트 FK를 보존한다.
- 정원이 찼거나 선행 대기자가 있으면 명시적 대기 신청으로 waitlisted를 생성한다. 기존 초대 API의 409를 조용히 바꾸지 않는다. 순번 FIFO, 취소 후 재대기는 끝 순번. 남은 한 자리 동시 요청에서도 1명만 활성화한다.
- 탈퇴/제외는 미래 expected/excused를 withdrawn으로 바꾸고 대기 승격·감사·알림 의도를 같은 트랜잭션에 기록한다. attended 및 종료된 과거 기록은 유지한다. 단, 유효 reserved/completed 보강의 원본인 excused는 원결석 이력으로 보존한다. 이 예외로 탈퇴·제외를 막지 않으며 멤버 상태와 entry_ver로 접근을 즉시 회수하고 대상 미래 보강행은 기존대로 철회한다. 클래스 제외와 한 회차 내보내기는 별개다.
- 현재 open/in_progress 회차에서도 입장 시 멤버 상태를 잠금 안에서 재검사한다. 제외/탈퇴와 입장이 경합하면 커밋 순서에 맞춰 최종 접근을 차단하고 기존 attended 이력은 유지한다. 현재 접속의 자격·WS·미디어 권한 회수는 기존 회수 경로를 재사용한다. excused의 직접 입장은 복귀와 동일하게 정원을 다시 검사한다.
- 클래스 정원과 회차 상한을 각각 검사한다. 정원 축소 시 기존 active 강등 금지. 이 스펙의 정원은 현행 유한 정수 계약을 유지하며 정기형 무제한 정원은 별도 후속이다.

### R2 출석과 현재 참여

- 체크인 설문 완료, 회차 출석, 현재 접속은 별도 상태다. 초대 행·joined_at·밴드 유무만으로 참여 중을 판정하지 않는다.
- 입장 성공은 entered_at 최초 기록과 attended 전이를 멱등 처리한다. 정상 종료 시 expected이며 실제 입장 근거가 없는 사람만 absent. 취소 회차는 absent 확정 제외; 진행 중 취소의 기존 attended는 유지한다.
- 시작 전 사전 결석은 excused, 복귀는 회차 정원 재검사 후 expected. 자기 absent 설정 금지. 강사의 사후 정정은 이전/이후·행위자·사유 감사 이력을 남긴다.
- 초기 조회·늦은 입장·새로고침·재접속에서 서버 스냅샷으로 복원하고 이후 이벤트를 적용한다. 오래된 이벤트가 새 스냅샷을 덮지 않도록 버전을 제공한다. 서버에 체크인 근거가 없으면 unknown으로 표현하며 ‘체크인 전’으로 단정하지 않는다.

### R3 보강

- 216 `class_write_service`의 보강 회차 생성과 개인 결석 보강 매칭을 분리한다. 취소 회차의 대체 편성은 유지하되 개인 결석을 임의로 만들거나 개인 보강 완료로 집계하지 않는다. 기존 생성 API도 새 매칭 검증을 우회할 수 없어야 한다. 현행 `member_ids`가 user ID를 받는 계약은 유지하고, 신규 명시적 member ID 필드는 T00에서 별도로 정의해 guest를 지원한다.
- 같은 클래스·같은 멤버의 absent/excused 회차만 원 결석으로 연결한다. 원 결석은 삭제하거나 참석으로 덮지 않는다.
- 별도 보강 회차와 기존 정규 회차 합류를 지원하되 원회차=대상회차 금지, 대상은 입장 전 회차여야 한다. 한 원결석의 유효 보강 예약은 1개, 완료도 중복 계산하지 않는다.
- `(session_id, member_id)` UNIQUE를 보존한다. 이미 대상 회차에 정규 출석 행이 있으면 중복 행을 만들거나 정규 참석을 보강으로 바꾸지 않고 충돌로 응답한다. 취소·철회된 보강은 감사 기록을 보존한 채 다른 대상에 재예약할 수 있다.
- 완료 고정형의 기존 completed 멤버도 216의 지정 보강을 이어갈 수 있다. 보강 때문에 클래스·멤버를 active로 되돌리지 않는다.
- 보강 완료는 대상 attended로 파생한다. 보강 예약/미예약/완료를 구분하고 회원에게 참석·결석·보강 횟수를 사실로 표시한다. 출석 점수·등급·순위는 만들지 않는다.

### R4 비회원 클래스·동의

- guest의 user_id=NULL을 동일인으로 취급하지 않는다. 회차 출석 생성·조회는 member_id 기준. 이름·이메일 일치만으로 자동 병합하지 않는다.
- 클래스와 member에 묶인 90일 슬라이딩 자격을 제안한다(기획 D-16). 토큰 검증에서 만료·entry_ver·멤버 상태·클래스 범위를 확인한다. 탈퇴/제외/로그아웃·병합 시 기존 자격을 회수한다. 회원 전환·이메일 복구는 범위 밖이다.
- 강사의 동일인 병합은 동일 클래스 guest끼리만, 근거 확인·미리보기·명시 확인·감사 필수. 참가자 ID와 리포트 FK를 보존한다. 같은 회차에 두 실제 입장/기록이 존재하면 409로 전체 롤백한다. 미래 미입장 expected 중복은 병합을 막지 않는다: 원 멤버를 removed로 보존하고 canonical member 매핑으로 신원을 연결하며, 중복 미래 행은 withdrawn 처리하고 하나만 유효하게 사용한다. 참가 행의 member_id를 일괄 덮어 UNIQUE를 깨지 않는다. 읽기·입장·집계·스크럽 모두 canonical 범위를 일관되게 적용하는 계약을 T00에서 고정한다.
- 병합 복구는 강사가 동일인을 확인한 뒤 살아남은 멤버에 연결되는 단회 교환 자격을 발급한다. 10분 만료·일회 사용·클래스 범위로 제한하고 교환 시 새 장기 자격을 발급한다(기술 제안). 이름/공개 코드만으로 기존 이력을 인계하지 않는다. guest 전용 최소 화면의 경로는 기존 라우트와 충돌하지 않게 `/class-members/:classId`로 신설한다.
- guest의 이탈 후 과거 기록 열람은 활동 자격과 분리된 본인 기록 읽기 자격으로 제공한다. 재입장·타인 데이터 접근은 불허하며 명시 로그아웃은 읽기 자격도 폐기한다. 기기 자격 상실은 같은 강사 확인 복구 절차를 사용한다.
- 개인정보 스크럽은 기획상 마지막 출석 회차 종료/멤버십 종료 중 늦은 기준 +90일. 활동 중 회원의 종료 기준 부재를 임의 날짜로 채우지 않는다. 멤버 원본과 출석 사본을 함께 처리하며 재노출·재발송을 막는다.
- 리포트 기본값은 false, 연구 기본값은 미동의. 회차별 고지는 유지한다. 기본값 변경은 아직 입장하지 않은 미래 회차에만 적용하고 회차별 명시 override와 종료 회차를 덮지 않는다.
- **연구 동의 O3 확정(2026-10-19 사용자 응답): 클래스 가입 시 1회 선택 → 이후 회차에 선택값 복사.** 신규 연구 동의의 선택값·고지 버전·선택 시각·원동의 식별자를 회차 증빙과 연결한다. 매 회차 연구 동의 재확인을 필수로 추가하지 않는다. 법무 확인 완료를 뜻하지 않는다. 기존 research_consents·report_scope·내보내기 의미는 유지한다.
- 클래스 기본값 변경과 연구 동의 철회는 별개다. 명시적 철회는 기존 철회/내보내기 제외 경로를 적용하며, 종료 스냅샷 불변을 이유로 철회 처리를 막지 않는다.
- 비회원 리마인더는 별도 명시 동의가 있을 때만. 코드 재발급은 기존 공유 코드 서비스로 수행하고 이전 코드의 신규 교환을 차단한다. 자격 회수는 entry_ver로 별도 처리한다.

### R5 화면·권한

- 회원은 참여 중/완료/이탈과 보강 대기 배지, 회차별 참석·결석·사전 결석·참여 전·취소 상태를 확인한다. 본인 나가기/대기 취소/사전 결석/보강 신청/동의 설정을 제공한다.
- 호스트 멤버 탭은 초대 기능을 보존하고 상태 필터·제외/복구·출석 정정·보강 제안·guest 병합/코드 재발급을 권한에 맞춰 제공한다.
- 이탈 이후에도 승인된 본인 과거 리포트만 열람 가능하다. 합류 전 회차는 일정 메타만, 타인 기록·미승인 리포트·다른 클래스·기관 정보는 노출하지 않는다. 관리자 권한을 216보다 확대하지 않는다.
- API는 권한·상태로 capability를 반환한다. 버튼 숨김만으로 보호하지 않는다. 모바일 390×844, 834×1194, 1194×834, 1280×720에서 검증한다. 기존 class-structure 시안을 재사용한다.
