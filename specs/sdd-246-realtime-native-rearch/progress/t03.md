## 설계 결정
- 직렬화: 회차별 `live_session_epoch` 행 `SELECT … FOR UPDATE`. 락을 쥔 뒤 ledger 재조회 → 동시 중복은 먼저 commit 한 1건만 실행, 나머지는 원 결과(duplicate).
- ledger·업무 전이·outbox·epoch.revision 증가는 한 트랜잭션/한 commit. handler 는 savepoint 안에서 실행 → 결정적 거절(CommandRejected)은 부분 변경(outbox 포함)을 되돌리고 거절 결과만 ledger 에 남김. 예기치 못한 예외는 전체 롤백·ledger 없음(같은 ID 재시도 가능).
- body_hash 는 command_id·expected_epoch·client_generation·protocol 을 제외(재시도 불변). 다른 hash 같은 ID → `idempotency_conflict`(http 409, committed=False).
- transient 거절(epoch_mismatch/session_not_found/unknown_kind/handler_not_registered)은 ledger 미기록.
- capture: 참가자당 active stream 1개(부분 유니크), 인계 시 이전 stream superseded + generation+1(참가자 행 락). lease 30s, offline 상한 10분, renew 는 현재 generation 만(fencing). 클라 시각 불신: reanchor 는 서버 probe 오차 resolver 가 값을 줄 때만 clock_uncertain=false.
- cutoff: `end_session_cutoff`(completed, close deadline 24h), `revoke_participant_capture`(expelled | consent_withdrawn). cutoff 는 최초 확정 우선. completed 는 종료 후 24h 내 capture.close 허용, 추방·철회는 revoked.
- `evaluate_ingest`: cutoff 이전 입증 구간만 accept, 오차 포함 걸치면 pending_time_review, 이후 reject, consent_withdrawn 은 이전 창도 reject, expelled 는 이전 창 보관(live fresh 불가).
