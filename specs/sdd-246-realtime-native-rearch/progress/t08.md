# T08 후속 — Doze 정지 진단 (Galaxy Note10, Android 12, One UI 4.1)

## 결론
- **정지 원인은 우리 코드(소켓·fsync·코어)가 아니라 삼성 Freecess(앱 cgroup freezer)**. 소켓/코어가 없는 **레거시 합성 경로(SyntheticSource 단독, native 소유 off)** 도 동일하게 얼음(A/B 모두).
- 증거(A, 레거시 합성, force-idle, 화면 꺼짐·비충전):
  - 시작 +25초까지 카운터 정상 증가(eeg 144→334), 이후 **eeg=334 고정** → unforce 후 재개(334→428).
  - `/proc/<pid>/cgroup` 의 `freezer:/` → **`freezer:/frozen`**, 스레드 상태 S→**D**(synthetic-band 포함 전 스레드).
  - logcat: `FreecessController: FZ : com.looxidlabs.mindbreeze2.dev(pid) reason: LEV` → `disable frozen app (…) wakelock.` (**프로세스 wakelock 도 무력화**) → unforce 시 `UFZ … reason: DeviceIdleOFF`/`enable frozen app wakelock`.
  - `dumpsys deviceidle whitelist` 에 dev 앱 없음(배터리 최적화 대상). 표준 AOSP `use_freezer=false` 이나 삼성 Freecess 가 별도 동작.
- B(앱을 실행→서비스 시작→BACK/HOME 후 force-idle)에서도 FZ(07:06:00)→UFZ(07:07:12) 동일 확인. 정지 약 15~30초 후 시작, unforce 까지 지속.
- 따라서 소켓 I/O 블로킹·Handler 타이머·wakelock 무시 가설 중 **"wakelock 무시 + 프로세스 freeze"** 가 해당. 소켓/코어 추가가 원인이라는 이전 가설은 기각(소켓 없는 경로도 동일).
- 이전 spike(5a800074) 결과와 불일치(60초 지속)는 **재현 못함**: 이전 시험은 Freecess 진입 전(앱 이탈 직후 debounce 구간)이었거나 화면/충전 상태 차이로 추정. spike 커밋 재빌드 비교는 하지 않았음(원인이 OS 레벨이라 코드 차이로 설명 불가 — 미검증 한계로 남김).

## 코드 수정
- 없음. 합성 소스는 같은 프로세스 내부 타이머라 프로세스 freeze 에 필연적으로 같이 멈추므로, 코드로 우회할 대상이 아님. 측정 경로는 이미 네트워크와 분리(LiveSession HandlerThread / 엔진은 BLE 콜백 스레드, 소켓 블로킹이 엔진을 막지 않음).
- 사실상 **freeze 되면 앱 전체(소켓·BLE 콜백 포함)가 멈춤** → 앱 내부 설계로는 방지 불가.

## 한계 / 실제 밴드에서 확인할 것
1. 실제 BLE notify 는 BT 스택(별도 프로세스)이 도착 시 앱 프로세스를 unfreeze 하는지가 핵심 — `FreecessController UFZ reason` 에 BLE/`broadcast` 가 찍히는지, freeze 중 `eegPackets` 증가 여부. 합성으로는 판정 불가(adb 외부 자극은 BLE 경로가 아니라 무의미).
2. BLE 가 깨워도 프로세스 freeze/unfreeze 반복이면 패킷 지연·버퍼 한계(밴드는 자체 저장 없음 → 장시간 freeze 구간 유실). 30분 화면 잠금 비충전 시험에서 gap 프레임 수·`msSinceLastNotification` 최대치 기록.
3. 비교군: ① 기본 설정 ② 배터리 "제한 없음"(최적화 제외) 설정 — Freecess 가 제외되는지 동일 시험.
4. 이 폰은 USB 충전(unplug 모사) 상태였음 → 실제 비충전 시험 필요.

## 배터리 예외 권고안 (설정 몰래 변경 금지)
- 상담사 실시간 표시가 목적이므로 **측정 시작 전 온보딩에서 사용자에게 안내**: 설정>앱>배터리>"제한 없음"(삼성: 절전 예외/"수면 중인 앱" 제외). 자동 변경 불가.

## 결정과 근거
- 배치 거절 재시도 범위: `not_ready`·`*_ingest_unavailable` 에 더해 **서버가 `retryable:true` 로 표시한 배치 오류(`db_unavailable`·`live_unavailable`)도 재시도**한다. 지시 문구(두 코드만)보다 넓다 — 일시 DB 장애에 60창을 영구 격리하면 live 가 근거 없이 비기 때문. 창별 `rejected` 는 예외 없이 격리.
- 비재시도 배치 거절(검증 실패·forbidden)은 보낸 창 전부를 격리(재전송 루프 방지). 한 창만 잘못돼도 배치 60창이 live 에서 빠진다(journal·archive 에는 남음).
- terminal/access_revoked 를 stream 종료로도 취급: 회차 종료·추방 후 창은 서버가 어차피 거절(`window_after_cutoff`)하므로 측정을 계속할 이유가 없다. 이벤트 순서에 기대지 않는다.
- renew 주기 10초 고정(lease 30초의 1/3). 서버 시계 차이 추정이 필요 없도록 상대 주기 사용.
- reanchor 시각쌍 = (EEG tick, 코어 창 시간축 µs = 벽시계앵커ms×1000 + 도착단조µs − 앵커단조µs).

## T06 에 요청 (웹 facade·안내 UI, `frontend/src/lib/native-measurement/`)
1. 측정 시작 전 `NativeMeasurement.getBatteryOptimization()` → `{batteryOptimization: "exempt"|"optimized"|"restricted"|"unknown", backgroundRestricted: boolean|null, vendorPolicy: "samsung_sleeping_apps"|null, settingsTargets: string[]}`. `optimized`/`restricted` 면 안내(삼성: 설정>앱>MIND BREEZE>배터리>"제한 없음", "수면 중인 앱"에서 제외).
2. 사용자가 누르면 `openBatteryOptimizationSettings({target?: "app_details"|"battery_optimization_list"})` → `{opened: boolean, target: string|null}`. 기본 app_details(앱 정보 화면). 자동 변경 없음.
3. 설정에서 돌아오면 상태가 바뀐 경우 이벤트 `batteryOptimizationChanged`(payload 는 1과 같은 형태). 계약 BridgeEvent 밖 이름이라 별도 리스너로 받는다.
4. `getMeasurementSnapshot()` 최상위(계약 `bridge` 객체 밖)에 `batteryOptimization`(1과 같은 객체)·`liveQuarantined`(격리 창 수) 진단 필드 추가.
5. 서버 cutoff 로 native 가 스스로 멈추면 `bridge.state`=BLOCKED + `blocked_reason` `owner_fenced`(superseded)/`consent_missing`(동의 철회)/`capture_lease_denied`(추방 등), 정상 종료(ended/closed)는 BLOCKED 없이 정지. 웹은 재시작 버튼을 숨기거나 사유를 안내.

## 남은 일·위험 (정직하게)
1. **outbox 창이 stream 에 묶여 있지 않다**: 프로세스 재시작 후 새 capture.start 가 다른 stream 을 주면 이전 stream 의 미확정 창이 새 stream_id·generation 으로 나간다(서버 sequence 공간 혼동). 재시작 후 같은 stream 을 이어받는 규칙(runtime.json streamId 재사용·renew) 또는 창별 stream 기록이 필요 — 미구현.
2. **재시작 재생 시 feature_hash 변화 가능성**: 복구 엔진이 새 벽시계 앵커로 창 시각을 다시 계산하면 같은 sequence 가 다른 hash → 서버 `feature_hash_conflict` → 격리. 실측 안 함.
3. `MetricOutbox` 압축(5000줄 초과) 후 acked 누계가 재시작 시 0부터 다시 센다(기존 결함, 표시용 카운터만 영향).
4. Doze/삼성 Freecess 정지(T08 후속)는 그대로 — 배터리 "제한 없음" 이 Freecess 를 피하는지 실제 밴드로 미검증. 안내 기능만 추가.
5. live:device 의 `battery_pct` 는 밴드 배터리를 아직 읽지 않아 항상 null.
6. 실서버 왕복은 합성 밴드·로컬 서버·USB 충전·화면 켜짐 조건. 화면 잠금·비충전·실제 BLE 아님.
7. 기기에 테스트 apk `com.looxidlabs.mindbreeze2.dev.test` 가 설치된 채로 남아 있음(삭제는 승인 후: `adb uninstall com.looxidlabs.mindbreeze2.dev.test`). 앱은 기본(export 없음) dev debug 빌드로 되돌려 둠.
