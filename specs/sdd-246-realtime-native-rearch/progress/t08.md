# T08 후속 — Doze 정지 진단 (Galaxy Note10, Android 12, One UI 4.1)

## 결론
- **정지 원인은 우리 코드(소켓·fsync·코어)가 아니라 삼성 Freecess(앱 cgroup freezer)**. 소켓/코어가 없는 **레거시 합성 경로(SyntheticSource 단독, native 소유 off)** 도 동일하게 얼음(A/B 모두).
- 증거(A, 레거시 합성, force-idle, 화면 꺼짐·비충전):
  - 시작 +25초까지 카운터 정상 증가(eeg 144→334), 이후 **eeg=334 고정** → unforce 후 재개(334→428).
  - `/proc/<pid>/cgroup` 의 `freezer:/` → **`freezer:/frozen`**, 스레드 상태 S→**D**(synthetic-band 포함 전 스레드).
  - logcat: `FreecessController: FZ : com.looxidlabs.mindbreeze2.dev(pid) reason: LEV` → `disable frozen app (…) wakelock.` (**프로세스 wakelock 도 무력화**) → unforce 시 `UFZ … reason: DeviceIdleOFF`/`enable frozen app wakelock`.
  - `dumpsys deviceidle whitelist` 에 dev 앱 없음(배터리 최적화 대상). 표준 AOSP `use_freezer=false` 이나 삼성 Freecess 가 별도 동작.
- B(앱을 실행→서비스 시작→BACK/HOME 후 force-idle)에서도 FZ(07:06:00)→UFZ(07:07:12) 동일 확인. 정지 약 15~30초 후 시작, unforce 까지 지속.
- 따라서 소켓 I/O 블로킹·Handler 타이머·wakelock 무시 가설 중 **"wakelock 무시 + 프로세스 freeze"** 가 해당. 소켓/코어 추가가 원인이라는 이전 가설은 기각(소켓 없는 경로도 동일).
- 이전 spike(5a800074) 결과와 불일치(60초 지속)는 **재현 못함**: 이전 시험은 Freecess 진입 전(앱 이탈 직후 debounce 구간)이었거나 화면/충전 상태 차이로 추정. spike 커밋 재빌드 비교는 하지 않았음(원인이 OS 레벨이라 코드 차이로 설명 불가 — 미검증 한계로 남김).

## 코드 수정
- 없음. 합성 소스는 같은 프로세스 내부 타이머라 프로세스 freeze 에 필연적으로 같이 멈추므로, 코드로 우회할 대상이 아님. 측정 경로는 이미 네트워크와 분리(LiveSession HandlerThread / 엔진은 BLE 콜백 스레드, 소켓 블로킹이 엔진을 막지 않음).
- 사실상 **freeze 되면 앱 전체(소켓·BLE 콜백 포함)가 멈춤** → 앱 내부 설계로는 방지 불가.

## 한계 / 실제 밴드에서 확인할 것
1. 실제 BLE notify 는 BT 스택(별도 프로세스)이 도착 시 앱 프로세스를 unfreeze 하는지가 핵심 — `FreecessController UFZ reason` 에 BLE/`broadcast` 가 찍히는지, freeze 중 `eegPackets` 증가 여부. 합성으로는 판정 불가(adb 외부 자극은 BLE 경로가 아니라 무의미).
2. BLE 가 깨워도 프로세스 freeze/unfreeze 반복이면 패킷 지연·버퍼 한계(밴드는 자체 저장 없음 → 장시간 freeze 구간 유실). 30분 화면 잠금 비충전 시험에서 gap 프레임 수·`msSinceLastNotification` 최대치 기록.
3. 비교군: ① 기본 설정 ② 배터리 "제한 없음"(최적화 제외) 설정 — Freecess 가 제외되는지 동일 시험.
4. 이 폰은 USB 충전(unplug 모사) 상태였음 → 실제 비충전 시험 필요.

## 배터리 예외 권고안 (설정 몰래 변경 금지)
- 상담사 실시간 표시가 목적이므로 **측정 시작 전 온보딩에서 사용자에게 안내**: 설정>앱>배터리>"제한 없음"(삼성: 절전 예외/"수면 중인 앱" 제외). 자동 변경 불가.
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`(직접 다이얼로그): Play 정책상 **핵심 기능이 최적화 때문에 불가능한 앱**에만 허용(건강·장치 연결 지속 등은 예시에 해당 가능하나 심사 사유 서술 필요). 거절 위험이 있으므로 우선안은 **`ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`(설정 화면으로 이동, 권한 선언 불필요)** + 안내 문구. 권한 선언은 실기기 시험에서 효과가 확인된 뒤 결정.
- 삼성 Freecess 는 AOSP 화이트리스트와 별개일 수 있어 위 3번 시험으로 효과 확인 후 권고 확정. 효과 없으면 "화면 잠금 중 측정 지속 불가/지연 허용" 을 제품 조건(G1)으로 재협의.
- UX: 측정 중 알림에 "화면 꺼짐 중 끊길 수 있음" 상태 표시, 재개 시 gap 을 명시(이미 코어 gap 프레임 처리).
