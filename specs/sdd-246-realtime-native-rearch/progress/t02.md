## 인터페이스

### C ABI (`include/measurement_core.h`, cbindgen 생성)
`mc_abi_version` · `mc_create(cfg_json)` · `mc_restore(cfg_json, ck)` · `mc_set_model(handle, params_json)` · `mc_push_packet(handle, PushPacketCall json)` · `mc_push_packet_raw(handle, sensor 0/1/2, bytes, arrival_us, wall_ms, anchor_mono_us)` · `mc_advance(handle, mono_us)` · `mc_checkpoint` · `mc_close`(FinalManifest, 핸들 해제) · `mc_destroy` · `mc_buffer_free`.
- 결과는 코어 소유 `McBuffer{data,len}` → 호출자가 `mc_buffer_free` 1회(null·이중 해제 안전). 입력은 호출 중에만 빌림, 상한 1MiB.
- 반환 `McStatus`: 0 ok · 1 invalid_handle · 2 buffer_too_small(예약) · 3 invalid_config · 4 checkpoint_corrupt · 5 panic_contained · 6 oom(예약) · 7 invalid_argument. 실패 시 `out`에 `{"code","message"}`(계약 CoreError; 7은 `invalid_config` 이름으로 투영).
- 모든 진입점 `catch_unwind` — panic이 FFI를 넘지 않음(`debug-hooks`의 `mc_debug_panic`으로 검증).

### WASM (`--features wasm`)
`new McCore(cfgJson)` · `McCore.restore(cfgJson, bytes)` · `set_model` · `push_packet(json)` · `push_packet_raw(sensor, Uint8Array, arrival_us, wall_ms, anchor_us)` · `advance` · `checkpoint` · `close` · `abiVersion()`. 호출 결과는 `{ok:true,value}` / `{ok:false,error}` 값(throw 아님), 생성·restore만 예외(메시지가 CoreError JSON). 시각 인자는 JS number(0..2^53 정수) 검사.

### 설정
계약 `CoreConfig`(unknown 필드 거절). v1은 rates 250/50/30, `anchor=last_sample_web_v1`, `acc_interval_profile=rounded_33333us_v1`만 허용 — 그 외는 `invalid_config`(profile 변경 전 조용한 downgrade 금지).

## 결정 반영 (감독 지시)
1. 나머지 바이트 패킷 → `invalid_remainder` + 원문 보존(`raw_preserved:true`). 기존 TS의 floor 부분 수용과 다름(계약 divergences.truncated).
2. 저품질 PPG 직후 SDNN·심박 튐은 TS 그대로 재현(개선 안 함).
3. anchor는 마지막 샘플 기준(현 웹), 원 tick은 `extended_ticks`로 항상 노출.

## 후속 (T01 정본 교체 반영, 1de11ca6 병합)

- 병합 806ba369 → 정본 expected = `expected/oracle`(실제 biquad). `expected/legacy_fallback` 은 비정본.
- Rust 기본 필터 `FilterImpl::Biquad` = biquadjs 1.1.0 ESM(`makeNotchFilter`/`makeBandpassFilter`, 직접형 I). node 로 같은 입력 8샘플을 돌려 notch·EEG bandpass·PPG bandpass 출력이 **비트 단위 동일**함을 확인.
- 패리티 테스트 교체: `golden_oracle` 4건 = (정본 oracle × biquad) EEG·PPG + (legacy_fallback × LegacyFallback) EEG·PPG. 정본 EEG+표시값 17,220건 max abs **2.13e-14**, PPG/HRV/호흡 47,228건 max abs **9.09e-13**, 불일치 0.
- 신규 `golden_acc_gf04` 4건: ACC 1491창 5,964값 **max abs 0**(burst 구간 motion>0 102창 포함), GF04 HRV 게이트 16건(70값, 0 오차) + SDNN 분모 N=100 정확, PPG 퇴화 입력(flat·zeros·nan_in_middle·noise) 40값 불일치 0.
- 퇴화 입력 재현을 위해 고친 JS 의미 차이(결함도 TS 그대로 재현 — 감독 결정): ① `Math.min/max` 는 NaN 전파(Rust `f64::min/max` 는 무시) → `js_min/js_max` ② `sort((a,b)=>a-b)` 의 NaN 비교=0 → panic 하는 `partial_cmp().unwrap()` 제거, `js_sort_numeric`(안정 병합). NaN 포함 입력의 정렬 순서는 V8 TimSort 와 비트 일치 보증 안 함(정상 입력은 동일).
- 위 "남은 위험" 1번(필터 경로 불일치)·2번(ACC 미비교)은 **해소**. 나머지 위험은 유지.

## 남은 위험 / 한계 (정직하게)
1. **필터 구현 경로 불일치 가능성(중요)**: `biquadjs`는 `main`이 export 없는 IIFE라 vitest/node에서 named import가 풀리지 않아 TS가 **fallback 필터**(단순 1극 HP/LP, 이동평균)로 떨어진다. T01 expected는 이 경로로 생성됨 → Rust는 `FilterImpl::LegacyFallback`으로 패리티를 증명했다. 브라우저 번들(`module` 필드)에서 쓰는 진짜 biquad(`FilterImpl::Biquad`, 제품 기본)는 계수를 TS와 비트 단위로 대조했지만 **EEG/PPG 전체 결과에 대한 골든 expected는 아직 없다**. 실제 웹이 어느 필터로 도는지 확인하고, 필요하면 T01이 biquad 경로 expected를 추가해야 G1/N07 완결.
2. **ACC 패리티 미비교**: oracle `acc.json`의 `activity/movement`가 1491건 전부 null(ACC 콜백 미발화). Rust ACC(`intensity→motion`)는 구현만 되어 있고 oracle 대조는 없다.
3. **cadence 차이**: 제품 기본 `SampleClock`(250/50/30 샘플마다, 헤더 tick을 샘플 격자로 정규화)은 batch 불변을 위한 의도된 설계이며 TS의 패킷/도착시각 throttle과 다르다. oracle 패리티는 `LegacyPacket` 모드로 증명했고, 두 모드의 DSP 코드는 같다. SampleClock 출력이 웹 출력과 시점이 달라질 수 있어 T06/T11이 표시 시점 차이를 확인해야 한다.
4. 실기기 미검증: Android `.so`·iOS `.a`는 **빌드·심볼 확인까지**. 기기/시뮬레이터 실행, 메모리·CPU budget(plan T02 마지막 항목)은 미측정. iOS arm64·Android arm64 수치 일치는 같은 libm 순수 Rust 구현이라 기대되나 실행 증거 없음.
5. 실측 골든(G1) 미충족 — 합성 입력만. 호흡 gate는 합성 RSA 0.25Hz에서만 확인.
6. 문자열 해시 `feature_hash`/`raw_sha256`는 코어 자체 정의(프레임 JSON·패킷 체인 SHA-256)이며 contract `stage_hashes`(canonical JSON)와는 별개다. T11 독립 checker와 정의를 맞춰야 한다.
7. 프레임 `contact`가 `unknown`→`contact/leadoff`로 샘플 단위 마지막 값만 반영(구간 비율 아님).
8. 크로스 링커 경로는 `ANDROID_NDK_BIN` 기본값에 이 머신 경로가 박혀 있음 — T12 CI에서 환경변수로 덮어쓸 것. `wasm-bindgen-cli` 0.2.129를 개발 머신에 설치(lockfile의 wasm-bindgen과 일치해야 함).
9. 해시 상수 `GRID_TOL_US=10ms`(프레임 격자 비교 허용폭)는 헤더 tick 양자화로 batch마다 달라지는 경계를 막기 위한 값이다. 10ms 이내 분석창 경계 차이는 같은 프레임으로 본다.
