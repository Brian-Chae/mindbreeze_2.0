# T12b — 서버 보정 (브랜치 `sdd/246-t12b-server-fix`, 기반 `sdd/246-final`)

로컬 커밋만. push·머지·배포·메일·dev 접속 0. 수정 범위: backend/**, contracts/**.

## 변경
1. **미래 창**: `freshness_of` — 창 종료가 서버시각보다 2초(`FUTURE_TOLERANCE_MS`) 넘게 미래면 `time_uncertain`. 2초 이내 시계 오차는 fresh 유지.
2. **session.end ACK**: 호스트 자기 명령이 `auth_revision` 을 올려 `ScopeStale` → 이전에는 `retryable/scope_stale` 로 응답(회차는 이미 종료). 이제 호스트/시스템 actor 는 현재 revision 으로 cursor 를 재읽어 **committed `applied` ACK 즉시** 반환, `RunOutcome.auth_revision` 으로 WS 연결 상태도 갱신. 멤버는 기존대로 retryable. commit 후 부수효과(종료 후 STT/리포트)는 ScopeStale/projection 지연 경로에서도 **한 번 실행**(기존엔 이 경로에서 누락 → 종료 후 파이프라인 미발행 위험이었음).
3. **계약 문구**: `metric.schema.json` window_start_us/window_end_us, `command.schema.json` capture.reanchor.monotonic_us 에 "같은 시간축(코어 창 시간축, μs)" 명시. `capture.renew` 설명에 lease 유지 필수(30초, 10초 주기) 명시. 서버 환산(`_window_server_times` = anchor_server_at + (window_us − reanchor.monotonic_us))이 그 기준임을 시험으로 고정.
4. **v2 pin 전 경로**: 기존에는 `POST /sessions` 라우터 한 곳만 pin → 클래스 회차 생성(`create_sessions`: 신규·재개·보충·롤링), 복제(`duplicate`), 즉석 클래스(시작 즉시 open) 가 v1 로 남던 결함. `pin_new_run_if_enabled`(session_live_legacy, 같은 트랜잭션·commit 없음)를 `create_sessions`·`create_session`·`_clone_session_config`(템플릿 제외)에 연결. 라우터는 멱등 호출 유지. 플래그 off 면 no-op.
5. **리포트**: v2 저장 행이 `play_group_id=stream_id`, focus 등 non-null 이며 `compute_class_stats` 가 예외 없이 읽음을 시험.
