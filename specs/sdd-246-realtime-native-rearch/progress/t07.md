## 다른 Task 에 요청

1. **T01/T05**: 서버 `device.changed` payload(`stream_id`,`generation`,`status`,`clock_uncertain`,`cutoff_code`)가 T01 event 스키마(DeviceEntity)와 불일치. native 는 서버 payload 기준으로 stream 채택. `capture.start` ACK 에도 stream_id 가 없어 device 이벤트로만 받는다 — ACK 결과에 stream_id 포함 권장.
2. **T01**: bridge 스키마에 확장 메서드 `setNativeOwnership`·`registerCredential`·`setJSBandOwnership` 반영.
3. **T06**: 로그인/토큰 갱신 시 `registerCredential` 로 native 에 인계해 핸들을 받아 `startMeasurement` 에 전달. JS bluetooth-le 사용 시 `setJSBandOwnership`.
4. **T05/T09**: `live:metric` 응답은 `{acks:[...]}` 가정. sink 연결 전 `*_ingest_unavailable`(retryable) 이면 pending 유지.
5. **T12**: Rust 코어 xcframework 빌드를 CI 선행 단계로. `EXCLUDED_ARCHS[sdk=iphonesimulator*]=x86_64`(코어는 arm64 sim 만).
6. **T09**: raw/feature 아카이브는 현재 journal 파일 단위 1개이고 `monotonic_range` 미채움 — cutoff 이후 사후전송 판정에 구간 필요.

## 위험·한계

1. 실기기·실제 밴드·TestFlight 미검증. 시뮬레이터는 BLE 가 없어 CoreBluetooth 실동작·willRestoreState 실제 발동·잠금 30분 소켓 유지는 **증거 없음**(G1 미충족).
2. 합성 서버는 T05 서버가 아니라 wire 형태만 흉내 낸다. 실제 T05 서버 통합 시험 미실시.
3. `clock_uncertainty_ms` 300000 고정, `capture.reanchor`/`clock_probe`/`capture.renew` 미구현 → 서버가 fresh 로 취급하지 않을 수 있음. 후속 필수.
4. 코어 모델은 legacy_cohort/b0 고정. 수업 시작 model pin(`mc_set_model`) 미연결.
5. archive 는 stop 후 journal 단위 업로드뿐 — 수집 중 주기 청크/분할 복구, 80% 용량 경보 미구현.
6. `live:terminal` 수신 시 자동 seal 미연결.
7. 단일 `currentHandle` 전역(다계정 동시 불가), 로그아웃 시 wipe 경로 미노출.
