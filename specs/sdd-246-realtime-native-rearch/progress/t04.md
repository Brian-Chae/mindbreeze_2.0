## 설계 결정
- **정본=DB outbox**, Redis=projection. projector 는 Redis `applied_revision`(watermark) 바로 다음 revision 만 적용(Lua `gap` 검사). `project(event)` 는 어떤 event 가 들어와도(역순·중복) DB 에서 watermark 이후를 순서대로 다시 읽어 적용.
- **exactly-once**: Lua 가 `dedupe:<event_id>`(24h) + `rev <= applied` 로 중복 무해화. Redis 적용 → DB `processed_at` 표기 순서라 그 사이 crash 해도 재처리가 seq 를 이중 증가시키지 않는다.
- **fence**: `projector-lock`(TTL 10s, renew 3s) + 단조 증가 fence 카운터. Lua 가 fence 불일치를 `stale_fence` 로 거부 → 과거 projector 쓰기 불가. fence 카운터는 rebuild 가 지우지 않는다.
- **domain cursor**: `(audience, domain)` 별 `seq` INCR. stream ID = `<seq>-0` 이라 replay 가 `XRANGE (cursor-0 +` 한 번. 로그 절단/cursor 앞섬/epoch 불일치 → `ReplayUnavailable`(새 snapshot).
- **entity 버전**: state hash 값 `{"v":version,"d":dto}`/tombstone `{"v","x":1}`. 낮은 버전은 state 를 덮지 못함(stream 에는 남음). singleton domain(session/audio/aggregate/policy)은 entity 키 `_`.
- **snapshot 원자성**: state + through + epoch + auth_revision 을 단일 Lua(no-writes)로 읽음. projector 쓰기도 단일 Lua 라 중간 상태가 보이지 않음. scope: host=host+public, member=public+본인 member. 타 member audience 요청은 `ScopeViolation`.
- **auth scope**: `Scope.auth_revision` 보다 Redis auth_revision 이 크면 `ScopeStale`(권한회수 후 재인가 요구). projection 시 DB `auth_revision` 을 meta 로 전파.
- **재구축**: meta 없음 + projection 이력 있음 → 회차 행 락 아래 `epoch+1` 원자 증가, outbox 접기(`_fold`)로 state/seq 복원, 재구축 락으로 단일 rebuild, 복원 중 `status=building`/meta 없음 → snapshot 은 `LiveNotReady`(READY 금지). `snapshot_ready` 는 미projection outbox 까지 drain 한 뒤 공개. 보정: metric `freshness=stale`, 만료된 signal tombstone, `connected=false`(재join 전 unknown).
- **TTL**: 활성 중 meta/state/seq/events 는 만료 없음(dedupe 만 24h). session `status in (completed,cancelled)` event 가 projection 되면 `meta.status=terminal` + 회차 키 전부 24h TTL(이미 TTL 있는 키는 연장 안 함).
- **OOM/장애 fail-closed**: 쓰기 Lua 는 `#!lua`(OOM 시 시작 전 거부, 부분 적용 없음), 읽기 Lua 는 `flags=no-writes`. 모든 Redis 예외 → `LiveRedisUnavailable(reason)`. 메모리 폴백 없음, OOM 시 outbox `processed_at` 미표기, 복구 후 이어서 적용.

## 위험 / 후속
1. **cluster 비호환 주의**: Lua 가 파생 키를 `base` 로 만들어 KEYS 선언을 엄밀히 따르지 않는다(hash tag 는 동일). 단일 노드/Sentinel 전제. cluster 이전 시 검증 필요.
2. **세션 event kind 가정**: 종료 판정은 `session` domain payload 의 `status in (completed, cancelled)`. T05 가 session 업무 전이 handler 에서 이 payload 를 emit 해야 TTL 이 걸린다.
3. **tombstone 규칙**: event_type 이 `.removed`/`.expired` 로 끝나면 삭제. 계약 fixture 와 일치하지만 T05 가 새 kind 를 추가하면 규칙 확인 필요.
4. **재구축 시 presence/aggregate**: 접속 lease 는 이 Task 범위 밖(`conn:<instance>` 미구현 — T05 transport). `connected` 는 재구축 시 false 로 복원.
5. **metric/device 는 scalar outbox 경유 가정**: T09 가 metric 을 outbox 로 쌓아야 재구축 복원 대상이 된다. 현재 T03 outbox 에 metric emit 경로 없음.
6. **dedupe 기본 24h 키 수**: event 당 1키. 대회차 고빈도 metric(1Hz×20명)은 키 증가 → T11 용량 시험에서 hash 묶음으로 바꿀지 판단 필요.
7. 이 환경의 Redis 는 `noeviction`. 운영 AOF/복제는 운영 게이트(미검증).
8. 소유권 밖 변경 요청: 없음 (T03 progress 의 dev_data_reset/deletion_sweep 패치는 T03 에서 이미 반영됨).
