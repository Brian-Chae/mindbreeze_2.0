# SDD-022 — MB 2.0 리포트 시스템 UX/기획 리뷰

> 역할: UX/리포트 기획 리뷰어  
> 근거: `00-research-brief.md`, F8/F9 기능명세, SDD-008, `ReportDetailPage`/`report_task` 현황  
> 범위: 설계 문서만 (코드 수정 없음)

## 리포트 시스템 기획

### 한 줄 정의
MB 2.0 리포트는 **상담 도메인 산출물(AI 요약·마커·승인·발송)** 위에, LINK BAND 착용 시에만 **하루밴드 7지표·품질 게이트·시계열**을 얹는 **이중 레이어 문서**다. 뇌파가 없으면 상담 리포트는 정상 동작하고, 뇌파 섹션만 숨긴다.

### 제품 레이어 (권고 아키텍처)

| 레이어 | 역할 | 출처 | UX 책임 |
|--------|------|------|---------|
| L1 세션 맥락 | 세션명·유형·일시·참여자 | Session | 커버 메타 |
| L2 상담 콘텐츠 | 요약·인사이트·마커·상담사 메모 | SessionRecord / AI | 핵심 본문, 승인 대상 |
| L3 EEG 분석 | 7지표 점수·품질·졸음·종합 | 하루밴드 `metrics.py` 계열 | 지표 카드·품질 배지 |
| L4 EEG 시계열 | 다운샘플 타임라인 | feature 시계열 / analytics | 라인차트 |
| L5 추이·비교 | 주간/월간·세션 간 | 하루밴드 `analytics.py` 계열 | 트렌드/비교 탭(후행) |
| L6 거버넌스 | type·편집·승인·열람 | MB 2.0 Report | 상담사 게이트 |

하루밴드 리포트는 L3~L5에 강하고 L2·L6가 약하다. 1.0 GuestComplete는 L6를 전화번호로 우회한다. MB 2.0은 **L2+L6를 본체**, **L3~L5를 opt-in 확장**으로 둔다.

### 생성 파이프라인 (UX 관점)

```text
세션 완료
  ├─ (항상) AI 요약·기록지 → Report draft (counselor / client)
  └─ (밴드 착용·EEG 품질 통과 시) 비동기 EEG 산출 → content.eeg_* 병합
상담사: 초안 검토·편집 → 승인
내담자: approved client 리포트만 노출 (인앱 + 알림)
```

- **분리 생성 금지 권고**: counselor/client를 완전 별도 파이프라인으로 두면 EEG 재계산·톤 불일치가 난다. **공통 EEG 스냅샷 1회 산출 → type별 뷰 템플릿 매핑**이 UX·비용 모두 낫다.
- **승인 전 내담자 노출 금지**: F8.3 §18 유지. EEG가 늦게 붙어도 내담자 화면은 `sent_at` 이전엔 “준비 중/상담사 확인 중”만.

### 세션 유형별 톤

| 세션 유형 | 리포트 프레이밍 | EEG 강조 |
|-----------|-----------------|----------|
| 임상/최면 1:1 | “상담 기록 + (선택)뇌파 참고” | 상담 맥락 보조, 의료 해석 금지 |
| 명상 수업 | “수업 참여 결과 + 명상 지표” | 7지표·이완 중심, 클래스 평균 비교는 MVP 후행 |
| 게스트 체험 | 계정 연결 후 자동 리포트 (아래 통합 방향) | 품질 게이트 엄격 고지 |

## 지표/화면 구성

### 하루밴드 7지표 → MB 표시 매핑

| # | 하루밴드 지표 | 내담자용 라벨(권고) | 상담사용 라벨 | 비고 |
|---|---------------|---------------------|---------------|------|
| 1 | `focus_index_stability_score` | 집중 안정 | Focus stability | 순간 focus ≠ 안정성 |
| 2 | `total_neural_activity_score` | 뇌 활동량 | Neural activity | 높음=좋음 오해 주의 |
| 3 | `cognitive_load_stability_score` | 인지 부하 안정 | Cognitive load stability | |
| 4 | `stress_score` | 스트레스 | Stress | 낮을수록 긍정적 톤 |
| 5 | `hemispheric_balance_score` | 좌우 균형 | Hemispheric balance | 상담사에만 상세 수치 권장 |
| 6 | `emotional_stability_score` | 정서 안정 | Emotional stability | |
| 7 | `relaxation_score` | **두뇌휴식도** | Relaxation | 1.0 브랜드명 계승 |

**두뇌휴식도 매핑 결정(권고)**  
1.0 `avgEfficiency`/두뇌휴식도 ≡ 내담자 대면 브랜드명. 기술 소스오브트루스는 `relaxation_score`(하루밴드). `meditationLevel`/`relaxationIndex`는 **실시간 모니터링 게이지**용으로 두고, **리포트 확정 점수는 세션 종료 후 정규화·품질 게이트 통과본**만 쓴다. 실시간 게이지와 리포트 점수가 어긋날 수 있음을 상담사 UI에 한 줄 고지.

**종합점수**  
하루밴드 `weighted_total`(가중치 재정규화)을 Cover `score`로 사용. AI 요약 점수와 혼용 금지 — Cover에는 **EEG 종합** 또는 **상담 품질 스코어** 중 하나만, 병기 시 라벨을 분리한다.

### 화면 IA (단일 세션 상세)

기존 `ReportDetailPage` 골격을 유지하되 섹션 계약을 명확화한다.

```text
1. Cover
   - type/session_type 뱃지, 세션명, 일시
   - (EEG valid/degraded) 종합점수 | (insufficient/invalid/미착용) 점수 숨김 + 사유 칩
2. 상담 본문
   - counselor: summary + markers + counselor_notes(+ 전사 발췌 링크)
   - client: greeting/summary + insights(카드)
3. EEG 품질 배너 (착용 시에만)
   - valid | degraded | invalid | insufficient | not_measured
4. 지표 카드 그리드 (7)
   - 점수 / null → "산출 불가" (0 위장 금지)
   - drowsiness_flag 시 상단 경고
5. 뇌파 타임라인
   - 기본 3채널: concentration / relaxation / stress (기존 Recharts 계약 유지)
   - 상담사 토글(선택): 7지표 중 2~3개 overlay (인지부하·정서안정 등)
6. (상담사 전용, 후행) 세션 비교 진입 / 트렌드 딥링크
7. 액션
   - counselor: 편집 · 승인 및 발송 · PDF(스텁→MVP3)
   - client: 읽음 처리 · 공유(정책 후)
```

### 트렌드 / 비교 (별 화면, 세션 리포트에 몰아넣지 않음)

| 뷰 | 주 사용자 | 내용 | 우선순위 |
|----|-----------|------|----------|
| 세션 리포트 | 양쪽 | 해당 세션 스냅샷 | P0 |
| 트렌드 | 내담자·상담사 | 주간/월간 7지표 스파크 | P1 (analytics 이식 후) |
| 세션 비교 | 상담사 | A vs B / 최근 N회 | P1 |
| 클래스 평균 대비 | 명상 수업 | 개인 vs 수업 익명 평균 | P2 |

세션 상세에 트렌드 전체를 넣으면 스크롤이 폭발하고 “이번 상담 결과” 초점이 흐려진다. **세션 리포트 = 스냅샷, 트렌드 = 별 탭(내담자 홈/프로필·상담사 내담자 상세)** 가 맞다.

### content 스키마 정합 (UX 블로커)

현황: UI는 `summary` / `insights[]:string` / `markers[{label,value}]` / `eeg_summary` / `eeg_timeline`을 기대하고, `report_task` 스텁은 `headline`·`sections`·`eeg.available` 등 다른 형태다.  
**기획 결정**: 프론트 기대를 **공식 content 계약**으로 고정하고 생성기를 맞춘다. EEG는 아래 형태를 권고한다.

```json
{
  "eeg": {
    "status": "valid|degraded|invalid|insufficient|not_measured",
    "reliability": 0.0,
    "drowsiness_flag": false,
    "score": 72,
    "metrics": {
      "focus_index_stability_score": 80,
      "relaxation_score": 75,
      "...": null
    },
    "summary_labels": { "relaxation_score": "두뇌휴식도" },
    "timeline": [
      { "t": 0, "concentration": 0.6, "relaxation": 0.7, "stress": 0.3 }
    ],
    "normalization_version": "…"
  }
}
```

UI는 `eeg_summary`/`eeg_timeline` 평탄화 어댑터를 두거나, 상세 페이지가 `content.eeg`를 직접 읽도록 통일한다. **둘 중 하나를 스펙으로 못 박아야** 빈 섹션 UX가 사라진다.

## 상담사/내담자 구분

### 정보 비대칭 원칙
상담사는 **해석 가능한 밀도**, 내담자는 **이해·안심·행동 힌트**. 같은 EEG 숫자를 그대로 복붙하지 않는다.

| 요소 | 상담사용 | 내담자용 |
|------|----------|----------|
| 진입 | `/reports/:id`, 승인 전 초안 열람 | `/app/reports/:id`, **승인 후만** |
| Cover 점수 | EEG 종합 + reliability 수치 | 점수 또는 “오늘의 두뇌휴식” 카피, reliability는 “측정 신뢰도 보통/높음” 정도 |
| 7지표 | 전체 + null 사유 + 정규화 버전(작게) | 상위 3~4 + 나머지 “더보기”(기본 접힘) |
| 타임라인 | 3채널 + (옵션) 전문 overlay, 마커 타임코드 연동 | 3채널만, Y축 0–100 단순화 |
| 마커/전사 | 노출·편집 | 미노출(또는 상담사가 고른 하이라이트만) |
| 인사이트 | AI 초안 + 메모 필드 | 개인화 카드만 |
| 품질 게이트 | insufficient면 “리포트 EEG 제외 권고” CTA | “이번 세션은 뇌파 참고를 생략했어요” |
| 비교/트렌드 | 내담자 타임라인 대비 비교 | 본인 추이만 |
| 비의료 고지 | 상단 1회 | 상시 푸터 |

### 승인 UX
1. EEG 병합 전에도 상담 초안 승인 가능하되, **“뇌파 분석 대기 중 — 승인 시 뇌파 없이 발송”** 확인 모달.
2. EEG가 나중에 도착하면 **재승인 또는 ‘뇌파 보충본 발송’** 플래그 필요(기획 누락 시 내담자가 구버전만 봄).
3. degraded는 기본 포함 + 배지, invalid/insufficient는 EEG 섹션 제거가 기본.

### 읽음·발송
기존 `sent_at` / `is_read` 유지. 내담자 홈 “최근 리포트 2건”은 **승인된 client 리포트만**.

## 1.0/하루밴드 통합 방향

### 세 시스템의 본질

| 시스템 | 트리거 | 산출 | 전달 | 약점 |
|--------|--------|------|------|------|
| **1.0 GuestComplete** | 게스트 종료 → 전화번호 신청 | 두뇌휴식도 등 레거시 | SMS/연락 대기형 | 계정 비연동, 상담 도메인 없음, 프라이버시·운영 비용 |
| **하루밴드** | 세션 close 워커 자동 | 7지표+품질+트렌드/비교 | 앱 내 즉시 | 상담 요약·승인·내담자 톤 없음 |
| **MB 2.0 Report** | generate + 승인 | AI 콘텐츠 + (미연동)EEG 자리 | 인앱·이메일 게이트 | EEG 파이프라인·스키마 공백 |

### 통합 결정 (권고)

**방향: MB 2.0 Report를 단일 전달면으로 고정하고, 하루밴드를 EEG 엔진으로, 1.0 GuestComplete는 폐기·축소한다.**

1. **엔진**: 하루밴드 `metrics.py`의 7지표·정규화 상수·null 보존·품질 게이트·weighted_total을 MB EEG 분석의 소스로 채택. 실시간 3게이지(집중/이완/스트레스)는 모니터링용, 리포트는 종료 후 확정본.
2. **전달면**: 기존 `Report.type` counselor|client + 승인 게이트 유지. 하루밴드식 “종료 즉시 전원 공개”는 MB 상담 윤리에 맞지 않음.
3. **1.0 GuestComplete**:
   - **정식 상담/수업 참여자**: 계정·세션 참가 → 자동 초안 → 상담사 승인 → 인앱 리포트. 전화번호 신청 UX **도입 금지**.
   - **비회원 게스트 체험(필요 시)**: 결과 미리보기(품질 통과 시에만 요약 카드) + “저장하려면 가입” CTA. 전화번호 수집은 마케팅/운영 예외로만, 리포트 본문 전달 경로로는 쓰지 않음.
4. **브랜드**: 내담자 카피의 “두뇌휴식도”는 유지하되, 산출식은 하루밴드 `relaxation_score`로 단일화. 1.0 efficiency 공식 병행 금지(이중 점수 사고).
5. **스키마**: haru feature JSON → MB `EEGRecord.analysisResult` / Report `content.eeg` 어댑터 한 곳에서만 변환.

### 하지 말아야 할 통합
- 하루밴드 UI를 통째로 임베드해 상담 리포트와 경쟁시키는 것.
- 1.0 전화 신청과 2.0 승인을 병렬 운영해 같은 세션에 두 리포트가 나가는 것.
- 품질 게이트를 무시하고 0점으로 채워 “예쁜 레이더 차트”를 만드는 것.

## 최종 권고안

### UX/기획 포인트 (12)

1. **이중 레이어**: 상담 콘텐츠 필수, EEG는 opt-in 확장 — 미착용 시 섹션 제거(빈 차트 금지).
2. **content 계약 단일화**: UI 기대 필드와 생성 스텁 불일치를 SDD-022에서 먼저 해소. 빈 리포트는 구현 버그가 아니라 기획 미결이다.
3. **7지표 카드 + 3채널 타임라인**: 카드=확정 점수, 타임라인=진행 곡선. 역할을 섞지 말 것.
4. **두뇌휴식도 = `relaxation_score`**: 브랜드명만 1.0, 수식은 하루밴드. 실시간 게이지와 리포트 점수 괴리 고지.
5. **null 보존 UX**: “0점” 대신 “산출 불가/데이터 부족”. falsy 버그를 제품 카피로 재현하지 말 것.
6. **품질 게이트 4상태(+미측정)**: valid·degraded·invalid·insufficient·not_measured별 노출 규칙 고정.
7. **정보 비대칭**: 상담사 전체·내담자 상위 지표 + 쉬운 라벨. 반구 균형 등 오해 소지 지표는 접힘/상담사 우선.
8. **승인 게이트 + EEG 지연**: 대기 중 발송 확인, 보충본 재승인 플로우를 명시.
9. **트렌드/비교는 세션 상세 밖**: 스냅샷 리포트 초점 유지, analytics는 P1 별도 IA.
10. **GuestComplete 폐기(전달 경로)**: 계정 기반 자동 산출 + 승인. 전화 신청은 리포트 채널에서 제외.
11. **비의료·해석 한계 카피**: 상담/명상 모두 푸터 고지. “진단/치료” 문구 금지.
12. **세션 유형 템플릿**: 1:1은 상담 본문 비중↑, 명상은 지표·두뇌휴식 비중↑ — 동일 컴포넌트에 variant.

### MVP 컷 (권고)

| Phase | 범위 |

### 수락 기준(기획)

- [ ] LINK BAND 미착용 세션에서 뇌파 섹션이 DOM에 나타나지 않는다.
- [ ] insufficient/invalid에서 종합점수·레이더가 0으로 채워지지 않는다.
- [ ] 내담자는 `sent_at` 이전 client 리포트를 목록/상세에서 볼 수 없다.
- [ ] 내담자 Cover/본문에 “두뇌휴식도”가 보이면 값은 `relaxation_score`와 동일 소스다.
- [ ] 상담사와 내담자 상세의 EEG 밀도(노출 지표 수)가 다르다.
- [ ] 1.0식 전화번호 리포트 신청 플로우가 MB 2.0 정식 경로에 없다.

### 한 줄 결론
**하루밴드는 숫자를 만들고, MB 2.0은 사람과 승인을 만든다.** 리포트 UX는 그 경계를 화면 구조로 고정하는 일이며, 1.0 GuestComplete는 전달 채널에서 내려야 한다.
