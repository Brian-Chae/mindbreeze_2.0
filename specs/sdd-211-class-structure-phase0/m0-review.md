# M0 질의 리뷰 기록 (SDD-211 M1 · M0-1)

- 대상: `m0-prequery.sql` 44문장(B0·A1~A11·A4a~d·A5 변형·C2~C4·C6-Q1~Q11), `m0-prequery.py` 러너. 질의 실행은 하지 않았다(M2·M3 는 Brian 승인 단계).
- 최종본 sha256: `m0-prequery.sql` = `43095d4efad2af5212e4017f962b9c197ddde4c9ddf730ba530944379df3714c`, `m0-prequery.py` = `9e235b65d3e10cdc39c70f35df06ddb98cf08317d7ad86889899a47ed51d58f3`. 서버로 복사한 파일의 sha256(러너가 `# sha256=…` 첫 줄로 출력)와 일치함을 실행 때 대조한다(R7).
- 리뷰어: 작성 워커(BE-2)와 별개로 띄운 독립 에이전트(general-purpose, 2026-10-18). 리뷰 시점의 SQL sha256 은 `fa08f70f…` 였고, 지적 4건을 반영한 뒤 최종본으로 정적 검사·테스트를 다시 돌렸다(최종본 자체를 리뷰어가 재열람한 것은 아님).

## 체크리스트 R0~R10 (조사 07 §1.7)

| ID | 결과 | 근거 |
|---|---|---|
| R0 빈 PG 에서 EXPLAIN | 통과 | 로컬 임시 PG 16.13(alembic head 적용, 실데이터 없음)에서 44/44 `EXPLAIN 통과`(A4d 포함), 전 질의 실행도 오류 0. CI 에서는 `tests/pg/test_m0_prequery_pg.py`(backend-pg-smoke)가 같은 검증을 한다 — CI 실증은 I1 |
| R1 SELECT 시작·리터럴 금지 문자 | 통과 | 러너 파서가 44문장 전부 검증(리터럴의 `;`·`--`·`%`·`$`, E'…', U&'…', 큰따옴표 식별자, 블록 주석 거부) |
| R2 금지어 | 통과 | 금지어 정규식 0건 + 함수 호출 허용 목록(19개)만 사용. 독립 리뷰어 지적(금지어 목록은 우회 가능)을 허용 목록으로 보강 |
| R3 바깥 SELECT 목록 금지 컬럼 | 통과 | 리뷰어 수작업 대조 위반 0건 + `test_바깥_SELECT_목록에_금지_컬럼이_그대로_나가지_않는다`(괄호 깊이 0 절 분해) |
| R4 금지 컬럼 사용 형태 | 통과 | custom_type_name 은 A4a 의 `count(DISTINCT …)`·A4b 의 CASE 범주·A4c 서브쿼리·A4d 로만 사용(테스트로 고정). title 은 `left(title,4)='E2E-'` 불리언, org_code 는 `='E2E001'` 불리언 |
| R5 행 수 상한 | 통과(해석 명시) | 모든 질의가 집계. 이론상 최대는 A1·C3 의 192행이라 설계의 100 대신 러너 상한을 250 으로 둠. 리뷰어가 지적한 C2b·C2c 의 무제한 행은 날짜 창(10-10~10-24, 10-17~10-19)으로 고정. A4d·A8 은 `LIMIT 100` |
| R6 A4d 기본 제외·입회 | 부분(실행 시 확인) | 러너가 `--include-labels` 없이는 A4d 를 건너뜀. 실행 요청자가 platform_admin 임을 M3 기록에 남기는 것은 실행 단계 |
| R7 sha256 | 기록 완료 / 대조는 실행 시 | 위 해시. 서버 복사본 대조는 M3 |
| R8 배포·E2E 비실행 확인 | 미확인(실행 시) | `gh run list` 는 M3 직전에 확인 |
| R9 출력 파일 위치·권한·삭제 | 부분 | 라벨 파일은 러너가 0600·`O_EXCL` 로 생성, DB 연결 성공 뒤에만 생성(실패 시 빈 파일 없음). 일반 출력 리다이렉트는 `umask 077` 후 실행(사용법에 명시), `.gitignore` 에 `out-*` 추가. 서버 임시 파일 삭제는 M3 |
| R10 리뷰어·일시 | 기록 | 위 리뷰어·일시 |

## 독립 리뷰 지적과 처리

| 지적 | 처리 |
|---|---|
| 금지어 정규식은 denylist 라 `pg_notify`·`pg_stat_file`·`query_to_xml` 등을 통과 | 함수 허용 목록(allowlist)으로 전환 + denylist 보강. 실제 방어선은 READ ONLY 트랜잭션이라는 점 유지 |
| `E'…'`·큰따옴표 식별자를 분리기가 처리하지 못함 | 거부 규칙 추가(테스트 포함) |
| 라벨 분리가 qid==A4d 로만 판단 — 다른 qid 로 custom_type_name 을 내보내면 이메일·UUID 정규식만 걸림 | **러너에는 적용하지 않음.** 방어는 (a) 파일이 리뷰·sha256 고정되고 (b) `test_custom_type_name_은_A4d_밖에서_개수_집계_또는_고정_범주로만_나간다` 가 질의 파일을 정적으로 검사. 러너가 SQL 의미를 해석하는 것은 과함 — 파일이 바뀌면 sha 가 달라져 R7 에서 걸림 |
| C2b·C2c 행 수 무제한 | 날짜 창으로 고정 |
| 일반 출력 파일 권한은 umask 의존, `.gitignore` 부재 | 사용법에 `umask 077`, 폴더 `.gitignore` 추가 |
| 라벨 파일을 DB 연결 전에 열어 실패 시 빈 파일 | 연결 성공 뒤에 열도록 변경(테스트 포함) |
