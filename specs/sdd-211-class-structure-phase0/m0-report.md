## 7. P2 스키마 덤프 vs 빈 DB 체인 diff (PG-5, 1회 보고)

dev 스키마 덤프(`baseline_e036a0000051.sql`)와 빈 PG16 에 `alembic upgrade head` 로 만든 스키마를 `pg_dump --schema-only --no-owner --no-privileges --no-comments` 로 비교했다. 동일하지 않다 — **dev 에만 있는 차이 약 6개 객체 계열**(코드 체인이 만든 스키마와의 드리프트):

| 대상 | 덤프(dev) | 체인(빈 DB) |
|---|---|---|
| `careers`·`qualifications` | `id` 기본값 `gen_random_uuid()`, 일부 컬럼 nullable·길이·추가 컬럼(`description`, `credential_*`, `expires_at`, `is_verified` 등) | 체인에는 없음/다름, `user_id` 인덱스 존재, FK `ON DELETE CASCADE` 없음 |
| `chat_messages` | `read_by jsonb`, `recipient_count` NULL 허용 | `read_by character varying(36)[]`, `NOT NULL` |
| `users.auth_provider` | NULL 허용 | `NOT NULL` |
| `chat_rooms` | FK `host_id → users` 없음 | 체인에 있음 |
| 인덱스 | `ix_careers_user_id`·`ix_qualifications_user_id` 없음 | 체인에 있음 |

시사점: 복원본(dev 스키마)에서 `upgrade head` 는 현 head 에서 no-op 이라 문제없지만, Phase 1 의 M1 이후 델타가 이 드리프트 테이블(특히 `users`)을 건드릴 때는 dev 스키마 기준으로 별도 검증이 필요하다. 드리프트 정리는 Phase 0 범위 밖(후속).
