# SDD-047 — LLM 서사 캐시 (방향 패턴 시그니처)

> 리포트 서사를 LLM으로 매번 생성하면 비용·지연이 부담된다.
> 몸/마음 지표의 방향성(↑/↓/→)을 시그니처로 압축해, 같은 패턴은 기존 서사를 캐시 재사용한다.
> 캐시 미스일 때만 LLM 호출 + 저장. LLM 실패 시 규칙 폴백.

## 1. 배경

- SDD-045에서 리포트 서사를 LLM(Deepseek→Gemini)으로 생성, 실패 시 규칙 폴백.
- 매 리포트 생성마다 LLM 호출 → 비용·지연 누적.
- LLM 입력은 6개 지표의 전반-후반 변화량 → 방향성(↑/↓/→)으로 압축 가능.

## 2. 캐시 설계

### 시그니처 (결정론적 키)
- 6개 지표(호흡수·심박수·HRV·집중도·이완도·감정안정도) 각 방향성 → 6자리 시그니처
- 예: 호흡↓ 심박↓ HRV↑ 집중↑ 이완↑ 감정↑ → "↓↓↑↑↑↑"
- 유한 조합(3⁶=729), 실제 발생 패턴은 소수로 수렴

### 캐시 계층
| 계층 | 동작 |
|------|------|
| L1 캐시 히트 | 시그니처로 `narrative_cache` 조회 → 기존 서사 반환 (LLM 스킵) |
| L2 LLM 생성 | 캐시 미스 시에만 Deepseek→Gemini 호출 → 서사 저장 |
| L3 규칙 폴백 | LLM 실패 시 규칙 기반 템플릿 |

## 3. 구현 범위 (BE codex)

### T1. narrative_cache 테이블
- `signature`(PK, string 6자리) → `narrative`(JSON: journey/body/mind/closing) + created_at
- Alembic 마이그레이션

### T2. 시그니처 계산 + 캐시 조회
- `_call_narrative_llm` 진입 시:
  1. metrics_summary에서 6지표 방향성 계산 → 시그니처
  2. `narrative_cache`에서 시그니처 조회 → 히트 시 반환 (LLM 스킵)
  3. 미스 시 LLM 호출 → 결과 저장 → 반환
- 규칙 폴백(fallback_narrative) 결과도 캐시 저장 가능 (LLM 비용 없이 캐시 축적)

### T3. 캐시 만료/무효화
- 표준 모델 갱신 등으로 정규화 기준이 바뀌면 캐시 무효화 필요
- 간단히: 시그니처는 방향성 기반이라 정규화 변화에 둔감하지만, 필요 시 clear API

## 4. 주의
- 시그니처는 방향성만 기반 (변화율 수치 미포함) → 같은 방향 = 같은 서사 (문장에 구체 수치는 변화량 카드가 별도 표시하므로 문제 없음)
- LLM 결과 저장 시 signature 키로 upsert

## 5. 완료 기준
- 캐시 히트 시 LLM 호출 0건
- 같은 방향 패턴 → 같은 서사 재사용
- BE pytest 통과
