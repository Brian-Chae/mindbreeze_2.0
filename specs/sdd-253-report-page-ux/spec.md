## 1. 문제와 목표

모바일 카드의 읽기 흐름은 유지한다. 데스크톱은 리포트 문서의 속성을 나열하는 화면에서, 필요한 일을 찾아 처리하는 화면으로 바꾼다.

대표가 제공한 현재 화면 관찰: 필터 4줄, 그룹마다 반복되는 표 헤더, 11개 컬럼으로 인한 칩·보기 링크의 세로 줄바꿈, 회차 제목·날짜 중복, 생년월일의 상시 노출, 두 종류 문서가 별도 행으로 분산, 의미가 드러나지 않는 NEW, 검토 대기와 주요 행동의 낮은 가시성.

이 관찰을 현재 코드와 대조했다. 캡처는 운영 데이터가 아닌 현재 워크트리 소스 + 합성 API이다. 대표 스크린샷 원본은 이번 세션에 첨부되지 않았으므로 픽셀 단위 동일 재현이라고 주장하지 않는다.

목표:

- 상담사는 첫 화면에서 검토 대상 수·실패 수와 다음 행동을 구분한다.
- 회원·회차로 찾고, 같은 회차의 회원용·상담사용을 같은 맥락에서 연다.
- 회원은 새로 도착한 리포트를 먼저 열고, 지난 승인 기록을 찾아 나란히 읽는다.
- 승인, 회원 공개, 메일 전달, 읽음 상태를 서로 다른 사실로 표시한다.
- 데스크톱 1440px에서 필터 컨트롤은 한 줄, 본문 최대폭 1200px, 상태·CTA는 한 줄로 읽힌다.
- 명상·웰니스는 서사와 변화량만 사용한다. 종합점수·순위·좋음/나쁨·치료·진단 효능 표현을 추가하지 않는다.

## 3. 역할별 사용자 작업과 주 CTA

- 상담사: 계층 목록에서 **검토 시작** → 회원용 검토·코멘트 저장/미리보기 → **승인하고 발송** → 다음 대상. 승인 완료와 발송 결과는 독립 상태로 표시한다. 실패 후 보조 행동은 **다시 발송**이다.
- 기관관리자: 허용된 기관 범위에서 상담사와 동일한 **검토 시작 → 승인하고 발송** 흐름. 서버 capability로 승인 가능 여부를 판단한다. 코멘트 편집 권한은 기존 정책을 유지하며 승인 권한에서 자동 파생하지 않는다. 승인자 성명·역할·승인 시각을 표시한다.
- 회원: 목록 **새 리포트 열기**(없으면 최신 승인 리포트 열기), 상세 **지난 리포트와 함께 보기**. 이전 기록이 없으면 안내와 목록 복귀. PDF는 준비된 경우만 보조 행동이다.
- 생성 실패는 **실패 확인**, 안전한 재생성 계약이 확보된 대상만 재시도한다. 메일 발송 실패와 생성 실패는 혼용하지 않는다.

## 4. 개선 정보 구조와 화면 규격

### 4.1 데스크톱 목록

- 기본 계층은 **클래스 > 회차(담당 상담사) > 회원 > 리포트**. 초기 시안은 펼침 상태이며 클래스·회차를 접고 펼칠 수 있다. 사용자가 계층을 잃는 평면 회차 목록으로 바꾸지 않는다.
- 클래스 행: 클래스명·회차 수·회원용 검토 대기 수. 회차 행: 일시·담당 상담사·참여 인원·대기 수. 회원 행: 마스킹 없는 성명·성별·만 나이, 행 내부에 회원용/상담사용 상태와 CTA를 둔다. 생년월일은 표시하지 않는다. 만 나이는 생년월일과 서비스 기준일(Asia/Seoul)로 계산하며 미상 값은 ‘미확인’으로 표시한다.
- 1:1 상담도 클래스/상담 묶음 > 회차 > 회원 1명 계층을 유지한다. 클래스가 없는 기존 상담은 별도 논리적 ‘개인 상담’ 묶음으로 표현하며 실제 클래스 식별자를 합성하지 않는다.
- 클래스 상담사용은 회차 전체 공통 자료다. 회원 행에서는 ‘상담사용 · 회차 공통’ 참조 링크로 표시하고 리포트를 회원마다 복제하거나 승인 대기 수에 중복 집계하지 않는다. 1:1은 실제 문서 소유관계대로 연결한다. 존재하지 않는 문서는 만들지 않는다.
- 검색(성명·식별번호·클래스·회차)과 검토 필요 등 상태 필터는 일치 회원의 **클래스·회차 경로를 함께** 반환하고 자동 펼친다. 다른 회원은 숨기며 ‘필터 일치 N명 / 전체 참여 N명’, 일치 대기/전체 대기를 구분한다. 회차 공통 문서 일치 시 회차와 접근 가능한 회원 맥락을 명시한다.
- 본문 최대폭 1200px, 1440px에서 좌우 120px. 데스크톱 한 줄 검색·필터, 한 번의 컬럼 헤더, 회원/회원용/상담사용의 안정된 열 정렬. 들여쓰기는 단계당 16px 수준으로 제한하고 문서 상태·CTA·성별·나이는 줄바꿈 금지. 제목만 최대 두 줄, 세로 글자·가로 넘침 금지. 1200px 뷰포트에서도 확인한다.
- 페이지 경계는 클래스 경로를 포함한 완전한 회차 단위이며 회원·문서가 페이지 사이로 갈라지지 않는다. 클래스가 여러 페이지에 걸치면 클래스 경로와 ‘이어지는 회차’를 표시한다. 문서 레코드 total을 회차·회원 수로 재해석하지 않는다.
- 상단 요약은 전체 권한 범위, 탭 집계는 필터 범위를 명시한다. 생성 실패·검토 필요·생성 중·승인 완료와 발송 상태는 구분한다. 운영 설정·샘플·기존 일괄 승인은 보조 메뉴이며 자동 승인 정책은 유지한다.

### 4.2 데스크톱 검토 분할 보기

- 1200px 안에서 왼쪽 320px 계층 대기 목록, 오른쪽 나머지 읽기·편집 영역. 선택 회원의 클래스 > 회차·담당 상담사 > 성명·성별·나이 경로를 유지한다. 직접 URL과 딥링크·목록 필터·스크롤 복원을 보존한다. 모바일은 기존 전체화면 상세를 유지한다.
- 현재 선택한 회원용 report_id만 승인한다. 클래스 상담사용 참고는 승인 대상이 아니다. 상담사·기관관리자 모두 승인 capability를 서버에서 받는다.
- 코멘트는 선택이며 편집 capability가 있을 때만 수정한다. 미저장 입력은 저장·미리보기 후 진행하고 저장 실패 시 보존한다. 빈 내용은 명시적으로 확인한다. 최종 주 CTA는 **승인하고 발송** 하나이며 별도 최초 ‘메일 보내기’ 단계는 두지 않는다.
- 클릭 시 승인을 확정하고 발송 작업을 멱등 예약한다. 승인 성공 후 발송 실패는 승인을 되돌리지 않는다. 승인자·역할·시각과 ‘발송 대기 / 발송 성공(전송 확인) / 발송 실패 / 확인 불가’를 독립 표시한다. 실패 시 **다시 발송** 보조 행동, 진행 중 중복 클릭 방지. 재발송은 승인자·승인 시각을 덮어쓰지 않는다.
- 발송 성공은 메일 제공자 인계/전송 확인 기준이며 수신함 도착·열람을 뜻하지 않는다. 주소 미등록·수신 미신청은 발송 불가 사유를 보여주고 버튼을 비활성화한다. 승인만 필요한 예외 처리 계약은 Plan에서 명확히 하며 성공으로 위장하지 않는다.

### 4.3 회원 데스크톱 목록·상세

- 목록은 새 리포트 요약+한 줄 필터+4컬럼 표(회차, 상담사, 읽음 상태, 열기). 같은 클래스·회차의 승인된 본인 회원용만 열며 상담사용·다른 참여자 정보는 보이지 않는다.
- NEW → **아직 읽지 않음**, 본문 열람 후 읽음. 상담사 업무 대기에는 이 배지를 쓰지 않는다. 전체 읽음은 보조 메뉴.
- 승인 전은 `준비 중` 또는 `상담사 확인 중`으로 안내하고 본문·지표·코멘트 초안·원문 오류를 노출하지 않는다. 오래 걸릴 때는 지연 안내만 추가한다.
- 상세는 왼쪽 목차(210px) + 오른쪽 서사 본문. 오늘의 이야기 → 몸·마음의 변화 → 상담사 코멘트 → 지난 기록. 문서 폭 전체에 문장을 길게 늘이지 않는다.
- 변화량은 같은 회차의 전반/후반, 또는 같은 클래스·호환 측정 조건의 본인 승인 자료만 사용한다. 기준·단위·비교 기간·자료 유무를 명시하고 결측은 0으로 바꾸지 않는다. 다른 조건은 수치 비교 없이 두 서사를 나란히 읽는다.
- 1회 기록, 미착용, 측정 부족, 일부 누락에서는 비교 불가 이유를 표시한다. 점수·순위·좋고 나쁨·증상 개선을 생성하지 않는다. 밴드 없이도 참여 기록·코멘트·서사 중심 리포트가 존재할 수 있다.
- 토큰 링크 열람은 현재 단일 문서 권한을 유지하며 지난 리포트 탐색을 제공하지 않는다. 만료 시 최신 메일 링크 안내. 샘플은 지속적인 `예시 데이터` 표기.

### 4.4 용어와 상태

- `타입` → **리포트 구성** 또는 **문서 종류**: 회원용/상담사용. API의 client/counselor는 그대로 유지한다. 비회원도 받는 일반 사용자용은 **비회원 참여자용**, 회원 화면은 **내 리포트**로 표시한다. 시안은 회원 사례라 회원용을 쓴다.
- `구분` → **참여자 유형**: 회원/비회원. 업무에 필요한 경우 보조줄만.
- `세션유형` → **활동**: 명상/상담/기타. 구체적 임상·최면 분류는 필터·상세에서 확인한다.
- `검토중` → **검토 필요**(업무 대기), `분석중` → **생성 중**, `실패` → **생성 실패**, `승인됨` → **승인 완료**. 회원에게는 준비 중/상담사 확인 중/열람 가능 문맥으로 바꾼다.
- `생성 상태` 독립 컬럼은 제거하되 실제 모델은 분리 유지한다. partial+error면 실패 확인, partial이지만 usable이면 일부 자료만 생성과 누락 사유, 생성 중이면 단계·지연을 상세에서 확인한다. 미측정 자체를 실패로 분류하지 않는다.
- `보기` → **검토하기 / 실패 확인 / 진행 보기 / 열기**. 재시도는 실패 확인 안에서 안전성·권한 확인 후 제공한다.

### 4.5 모바일·접근성·기타 상태

- 현재 카드·전체화면 상세·하단 내비게이션을 유지한다. 390px에서는 필터를 작은 여러 줄로 허용하고 상세 필터는 접어둔다. 데스크톱 표를 축소해서 넣지 않는다.
- 공통 용어·성명 원문/성별/만 나이·계층·상태별 행동을 맞춘다. 카드 전체 클릭과 명시 버튼이 중복 포커스를 만들지 않도록 구현한다.
- 권한 범위 안 목록은 성명 원문·성별·만 나이를 표시하며 생년월일은 숨긴다. 이메일은 마스킹 예외지만 목록 상시 노출은 하지 않는다. 상세에서 개인정보 펼침이 필요하면 기존 정책·권한을 따른다. 화면 숨김만으로 민감한 API 응답 문제가 해결되는 것은 아니므로 projection도 검토한다.
- 첫 이용 빈 상태는 상담사 클래스 보기/회원 나의 클래스 보기. 검색 빈 상태는 필터 초기화, 목록 네트워크 실패는 다시 불러오기, 생성 중은 진행 보기, 생성 실패는 대상·재시도, 권한 없음은 읽기 전용/담당자 확인.
- 44px 이상 터치 영역, 키보드 포커스, 표 scope, 상태 텍스트, 저장·승인 피드백의 live region, 모달 focus trap·닫기 후 복귀를 유지한다. 색으로만 상태를 구분하지 않는다.

## 5. 구현 경계·서버 변경 필요 여부

이번에는 어떤 구현도 하지 않는다. 다음 단계의 범위를 정확히 나누기 위한 계약 요구사항이다.

프론트에서 가능한 표현 변경:

- 폭·필터 배치·계층·컬럼 축소·용어·상태별 버튼·보조 메뉴 우선순위, 기존 상세 컴포넌트의 읽기 구조.
- 기존 코멘트 PATCH → 승인 POST → 재조회 순서를 보존한 단계 UI. 기관관리자 승인은 서버 권한 확장 후 연결한다.

서버 지원이 필요한 완성 범위:

1. **계층 조회 읽기 API**: 클래스 > 회차(담당자) > 회원 > 문서, 완전한 회차 단위 페이지네이션, 전 범위 검색·상태 필터·정렬·집계, 일치 경로 반환. class_id 없는 상담의 논리적 묶음 키를 실제 클래스 ID와 구별한다. 문서별 report_id/type/status/approval_required와 회차 공통 여부를 제공한다. 기관·소유권 projection을 적용한다. 성명·성별·계산된 만 나이만 제공하며 목록에 생년월일을 추가하지 않는다.
2. **권한**: 활성 기관관리자가 허용 기관·귀속 범위에서 승인하도록 서버 검증을 확장한다. can_view/can_edit_comment/can_approve/can_retry 및 사유를 제공한다. 타 기관·회원·비활성 계정 접근은 거부한다. 코멘트 편집과 승인은 별도 capability다.
3. **승인 감사**: approved_by_user_id, 승인 당시 성명/역할의 감사 스냅샷, approved_at 및 승인 이벤트를 영속 저장한다. 자동 승인·기존 승인자는 ‘자동 승인’/‘기존 기록 · 승인자 미확인’으로 구분하고 추정하지 않는다. 재승인·중복 요청·재발송으로 최초 승인 이력을 덮어쓰지 않는다.
4. **승인·발송 통합 명령**: 승인 후 발송 예약을 하나의 사용자 행동으로 연결한다. 기존 승인 API의 의미를 바꾸지 않는 별도 명령 계약을 Plan에서 정의한다. 멱등 키/고유 작업, 트랜잭션 outbox 또는 동등한 내구적 예약, 재시도 시 승인 중복·오발송 방지를 포함한다. 기존 최초 승인 자동 예약과 이중 예약되지 않아야 한다. 자동 승인 기본 정책과 미측정 예외는 유지한다.
5. **발송 상태**: approval과 분리된 delivery_status(pending/sending/sent/failed/not_requested/unavailable), 마지막 시도 시각·실패 사유 코드·시도 수 및 재발송 이력을 저장한다. sent_at은 기존 의미 그대로 두고 발송 성공 근거로 재사용하지 않는다. 워커/브로커 중단, 예약 실패, success/sent=false도 실패·확인 불가로 구분한다. 실패 대상 재발송은 별도 보조 행동이다.
6. **회원 기록 읽기**: 승인된 본인 회원용만 나란히 읽는다. 토큰 단일 문서 권한은 확장하지 않는다. 수치 비교는 후속이다. 생성 재시도는 작업 식별·멱등성·기존 승인 결과 보존 계약을 확보한 범위만 활성화한다.

**앱 심사 중 호환**: 기존 엔드포인트·필드·status/type/total/sent_at의 의미와 기본 동작은 유지한다. 기존 응답은 optional 필드 추가만 허용하며 새 계층 조회/통합 명령은 별도 경로로 확장한다. 구 앱이 새 필드를 무시해도 현재 승인·열람이 동작해야 한다. 기존 승인 enum에 발송 상태를 섞지 않는다. 구 앱 회귀와 신·구 앱 중복 발송 방지를 검증한다.

**DB 마이그레이션 필요: 예.** 승인 주체·역할/시각 감사와 내구적 발송 작업/시도 이력을 위한 nullable 필드·감사/발송 테이블·고유 제약 확장을 계획한다. 정확한 테이블 재사용 여부는 Plan에서 모델 확인 후 확정한다. 기존 기록은 unknown을 허용하고 이력·배달 결과를 합성 backfill하지 않는다. 추가형 마이그레이션과 구 앱/서버 호환 순서를 설계하며 이번에는 migration 작성·실행·DB 쓰기를 하지 않는다.

## 6. 대표 결정
