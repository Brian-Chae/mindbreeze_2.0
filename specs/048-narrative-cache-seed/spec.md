# SDD-048 — 서사 캐시 pre-seeding + 주기적 업데이트

> SDD-047(시그니처 캐시)의 후속. 초기에 규칙 기반으로 캐시를 채워놓고(비용 0),
> 주기적으로 일부 항목만 LLM으로 업그레이드해 문장 품질을 점진적으로 올린다.
> LLM 비용·지연을 구조적으로 분산한다.

## 1. 배경

- SDD-047에서 방향 패턴 시그니처 기반 캐시 구현 (캐시 미스 시 LLM).
- 첫 세션은 캐시 미스 → LLM 호출 → 비용·지연.
- 사용자 제안: 초기 캐시를 미리 채우고, 주기적으로 일부를 업데이트.

## 2. 설계

### ① 초기 pre-seeding (규칙 기반, 비용 0)
- 규칙 기반 템플릿(`fallback_narrative`)으로 **대표 방향 패턴(또는 전부)을 미리 캐시에 채움**
- 배포 시 자동 실행 또는 관리자 명령
- 이러면 첫 세션부터 캐시 히트 (LLM 호출 0)

### ② 주기적 일부 업그레이드 (LLM, 비용 분산)
- Celery beat 주기 태스크: 캐시 항목 중 일부(예: 매회 N개)를 LLM으로 재생성해 품질 업그레이드
- 규칙 기반으로 채워진 항목(source='rule')을 우선 업그레이드
- 한 번에 전체를 돌리지 않고 분산 → 비용 폭탄 방지

### ③ 온디맨드 LLM (캐시 미스)
- pre-seeding에 없는 패턴 → 즉시 LLM + 저장 (기존 SDD-047 동작)

## 3. 구현 범위 (BE codex)

### T1. pre-seeding
- 대표 패턴(예: 실제 빈도 높은 상위 N개, 또는 전체 3⁶=729)에 대해 규칙 기반 서사 생성 → 캐시 저장
- `source` 컬럼 추가 (rule/llm) — 규칙 기반으로 채운 항목 표시

### T2. 주기적 업그레이드
- Celery beat 태스크: source='rule' 항목을 일부씩 LLM으로 재생성 → source='llm'로 갱신
- 매회 업그레이드 개수 제한 (비용 제어)

## 4. 완료 기준
- 초기 pre-seeding 후 첫 세션부터 캐시 히트 (LLM 0건)
- 주기적 업그레이드로 규칙 기반 항목이 LLM 품질로 점진 전환
- BE pytest 통과
