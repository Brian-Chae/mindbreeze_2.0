# SDD-212 — 리포트 생성 큐 분리·동시성·적체 모니터링·종료 일괄 몰림 완화 (Spec)

- 상태: Stage ① Spec — Brian go/no-go 대기 (구현 금지)
- 출처: SDD-211 plan §13.1(신규 요구) · §14.1(후속 항목)
- 태그: [SDD] / 번호: 212 (`specs/.sdd-counter` 211 → 212)

## 1. 문제

- 세션 종료 시 `음성 변환(STT) → 요약 → 리포트 생성`이 하나의 비동기 사슬로 큐에 쌓임.
  - `backend/app/services/audio_service.py:204-230`, `backend/app/tasks/report_task.py:704-737`
- 이미 비동기라 "종료 버튼이 느려지는" 문제는 없음. 문제는 **종료가 한꺼번에 몰릴 때 뒤쪽 처리 순서**.
- 현재 구조의 약점 (조사 결과, 상세는 plan §1):
  1. 작업 일꾼(워커)이 1종류뿐이고 큐도 1개(기본 큐). 오래 걸리는 음성 변환(최대 30분)과 짧은 리포트 생성이 같은 줄·같은 일꾼 슬롯을 공유 → 음성 변환 몇 건이 일꾼을 점유하면 리포트가 줄 뒤로 밀림
  2. 동시 처리 수·우선순위·대기열 상한이 어디에도 지정돼 있지 않음 (일꾼 수 = 서버 CPU 수에 암묵 의존)
  3. 대기열 길이·대기 시간을 보는 지표/경보가 없음. 지금은 "리포트가 안 나온다"는 문의로만 알 수 있음
  4. 대기가 길어지면 **기존 안전장치가 오히려 피해를 키움**: 30분 넘게 대기한 건을 "멈춘 것"으로 보고 실패 처리하거나 같은 사슬을 중복 발행(plan §1.4)
  5. 외부 AI(Gemini) 호출은 음성 변환·요약·상담사 코멘트 초안·AI 비서가 같은 키/같은 한도를 공유. 몰림 시 한도 초과(429) 가능성
- 회원 영향: SDD-211(U1=B)로 회원은 승인 전 리포트를 `리뷰 중`으로 봄. 적체되면 `리뷰 중` 기간이 길어지는데 **생성 지연인지 상담사 확인 대기인지 구분되지 않음**.

## 2. 목표

- G1. 짧은 작업(요약·리포트 생성)이 긴 작업(음성 변환·영상 병합) 뒤에서 굶지 않도록 줄을 분리
- G2. 줄마다 동시 처리 수 상한을 명시해, 몰려도 서버·외부 AI 한도를 넘지 않게 함
- G3. 적체(대기 건수·가장 오래 기다린 시간)를 숫자로 보고, 임계 초과 시 운영자에게 알림
- G4. 대기가 길어져도 정상 건이 실패 처리·중복 발행되지 않게 안전장치의 기준 시각을 보정
- G5. 몰림 시에도 순서가 예측 가능하도록 처리 순서 정책 확정 (결정 D-2)
- G6. 적체 상태를 회원 `리뷰 중` 안내와 연결 (결정 D-1)
- G7. 기존 동작 무회귀: 리포트 내용·승인 흐름·알림·API 응답 계약 불변 (적체 안내 가산 필드 제외)

## 3. 비목표

- 리포트 내용·AI 프롬프트·요약 품질 변경 없음
- 메시지 중개기(Celery/Redis) 교체·신규 도입 없음 (현 스택 안에서 해결)
- 서버 대수 증설·오토스케일링 자체는 범위 밖 (필요 시 별도 인프라 항목으로 제안만)
- 이메일·푸시 발송 큐(이미 별도) 변경 없음
- 영상 병합·EEG 원본 정리 등 리포트 외 작업의 성능 개선 없음 (줄 분리 대상 지정만)
- 외부 AI 공급자 교체·모델 변경 없음 (`docs/AI_STACK_DECISION.md` 유지)
- 개발 서버·DB·AWS 실제 변경은 구현 단계에서 별도 승인 후 (본 단계는 문서만)

## 5. SDD-211 `리뷰 중` 문구와의 연결

- 현재(SDD-211): `frontend/src/lib/report-review-copy.ts:1-30` — 배지 `리뷰 중`, 상세 안내 `리뷰 중이에요. 확인이 끝나면 알려드릴게요.` / 서버 가산 필드 `in_review` (`backend/app/schemas/report.py:89`)
- 연결 방식(D-1=B 선택 시): 서버가 "생성 지연 중" 여부를 가산 필드로 내려주고, 화면은 그때만 보조 문구 1줄 추가
  - 기본 문구·배지는 변경 없음 (용어 가드 유지)
  - 지연 판정 기준은 D-3 목표 시간의 초과 여부 (plan §4에서 확정)
- 적체와 무관한 `리뷰 중`(상담사 확인 대기)에는 보조 문구를 붙이지 않음
- 회원에게 내부 용어(큐·워커·적체 등) 노출 금지

## 6. 수락 기준 요약 (상세는 verify.md)

- 음성 변환이 일꾼을 모두 점유한 상태에서도 리포트 생성이 시작된다 (줄 분리)
- 동시 N개 세션 종료 시 줄별 동시 처리 수가 상한을 넘지 않는다
- 대기 건수·최장 대기 시간이 지표로 조회되고, 임계 초과 시 경보가 발생한다
- 큐 대기 30분 초과 건이 실패 처리·중복 사슬 발행되지 않는다
- 기존 리포트 API 응답 계약·승인 흐름 무변경 (골든 스냅샷 + 가산 필드만 허용)
- 롤백: 설정 한 곳을 되돌려 단일 줄 구성으로 복귀 가능

## 7. 위험

- 줄을 나누면 배포 시 일꾼 서비스 구성 변경이 필요 → 코드 배포 순서(일꾼 먼저, 라우팅 나중) 어기면 작업이 소비되지 않고 쌓임 (plan §7)
- 외부 AI 한도는 줄 분리만으로 해결되지 않음 (동시 호출 수 제한은 줄별 동시 처리 수로 간접 통제)
- 단일 서버(t4g.medium, `deploy/aws/t10-ec2.sh:12`) 자원 한계 — 동시 처리 수를 올리는 데 상한 존재
