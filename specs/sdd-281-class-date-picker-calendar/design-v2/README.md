## 결정 요약

- D-1만 유지. 단일 날짜 필드 → 768px 미만 Bottom Sheet, 그 이상 326px 팝오버.
- 오늘 2026-11-03 고정. 오늘 셀은 라벤더 링과 하단 점, 선택일은 보라 채움, 지난 날짜는 흐림·비활성. 오늘이 선택일이어도 링은 유지한다.
- 모바일은 하단 핸들, 제목·닫기, 월 이동, 요일·날짜, 하단 오늘 이동 순서다. 기존 WizardSheet의 딤 rgba(12,6,20,.55), 배경 rgba(24,12,36,.97), 상단 24px 라운드를 따른다. 달력은 7열 44px 최소 타깃을 위해 좌우 16px, 짧은 화면은 간격 6px로 조정한다.
- 날짜 탭 즉시 반영·닫기. 배경·핸들 아래 드래그·ESC·X·브라우저 뒤로가기는 취소. 좌우 스와이프·월 버튼·PageUp/Down으로 월 이동한다. 오늘로 이동은 달력 위치만 되돌린다.
- 열릴 때 배경 폼·이전/다음 바를 inert 처리하고 스크롤 잠금. 시트가 하단 바를 덮으며 별도 바 재배치 없이 모달 완료/취소 후 원상 복귀한다.
- dialog 이름·aria-modal, 선택 날짜로 포커스 이동, Tab 순환, 방향키, 날짜 한글 라벨, 닫힌 뒤 필드 포커스 복귀를 시안에 포함했다.

## 즉시 선택 vs 확인 버튼

| 방식 | 닫힌 필드에서 탭 수 | 오탭 복구 | 시작 시각과 일관성 |
|---|---:|---|---|
| 즉시 선택 — 추천 | 같은 달 2회 / 다음 달 3회 | 다시 열어 날짜 변경. 취소 경로는 값 유지 | 모바일 시·분 select의 즉시 반영, 데스크톱 분 선택 후 닫기와 유사 |
| 확인 버튼 | 같은 달 3회 / 다음 달 4회 | 임시 선택을 검토·취소 가능 | 별도 확정 단계 추가 |

단일 날짜이며 선택값이 필드에 즉시 보이므로 즉시 선택을 추천한다. 확인 방식은 비교 설명만 제공하며 실제 시안 동작은 즉시 선택이다. 모바일 시작 시각은 현재 **시·분 네이티브 select 두 개**이며 앱 자체 시각 시트가 아니다. OS가 표시하는 선택기의 모양을 앱 시트로 가정하지 않았다.

## 데스크톱 폭 보정

326px 유지: 카드 640px의 필드 약186px에 7×44px 날짜를 담는 것은 불가능하다.

1. **채택**: 날짜 필드 우측에 팝오버 우측 정렬하고 화면 가장자리 8px 보정. 시작 시각과 동일한 16px 라운드·보라 테두리·그림자·배경을 사용한다. 날짜/시각 필드도 56px·15px·700·16px 동일하다.
2. 대안: 필드 중앙 정렬 + 상단 작은 화살표 꼬리. 연결점은 명확하지만 가장자리 보정 시 꼬리 위치도 따로 움직여야 해 제외했다.

## 구현 계획 초안 — 제품 구현 미착수

1. `frontend/src/pages/classes/wizard-visual-components.tsx`: WizardDateTime의 date 분기를 StartDatePicker로 연결. YYYY-MM-DD·min/max·onChange 계약 유지.
2. `frontend/src/components/class/flow/host/start-date-picker.tsx`: 순수 날짜 계산, 월 격자, 선택/오늘/비활성, 데스크톱 위치 보정과 모바일 모달 분리. 기존 StartTimePicker의 반응형 기준과 토큰 사용.
3. `frontend/src/pages/classes/class-scheduling.css`: 날짜 필드·팝오버·모바일 시트 전용 규칙. 85dvh·safe-area·모션 감소 설정, 짧은 화면 간격을 적용한다.
4. WizardSheet 재사용 우선. 현재 제공하는 title/body/footer·포커스 복귀·ESC·Tab 순환을 공유하되 핸들·드래그·뒤로가기·배경 inert·스크롤 잠금은 기존 시트에 아직 없어 별도 설계가 필요하다. 다른 시트 회귀를 막도록 선택적 옵션 또는 공용 모달 기반 확장을 검토한다.
5. 시험: 날짜 월말/윤년/min/max, 월 스와이프와 클릭 경합, 모든 닫기와 취소 값 보존, 포커스·읽기 순서, 3종 모바일 크기의 6주 달, 데스크톱 가장자리, 실제 Safari/Chrome·Android 뒤로가기·VoiceOver/TalkBack.

## 검증과 한계

- 실행: `node specs/sdd-281-class-date-picker-calendar/design-v2/verify-design.cjs`. 결과 `validation.json`, 화면 `shots/` 참조. 앱 빌드 없이 정적 HTML을 Chrome headless로 검증한다.
- 2026년 11월과 8월은 일요일 시작 기준 모두 5주다. 6주 달은 미래 선택 가능한 2027년 5월로 검증한다.
- 안전영역은 `max(12px, env(safe-area-inset-bottom,0px))`로 반영한다. headless 기본 inset은 0이므로 실제 노치 기기의 inset·OS 제스처·키보드·스크린리더 음성은 미확인이다.
- 하단 바를 덮는 모달 정책과 배경 잠금은 시안에서 확인한다. 앱 라우터와 브라우저 히스토리 통합은 제품 구현 시 추가 검증한다.
- 애니메이션·pointer 기반 드래그/스와이프는 정적 시안 수준. 실기기 스크롤과 제스처 경합은 별도 확인 필요.
- v1 및 제품 소스는 보존. push·PR·배포·메일·삭제·prod 접근·앱 빌드 없음.

## 남은 결정

추가 결정 질문 없음. 대표의 D-1/모바일 시트 방향 내에서 즉시 선택·우측 정렬을 시안 작성자의 제안으로 채택했다. 제품 구현 승인은 이번 시안 작업에 포함하지 않는다.

### 최종 실측

- 모바일 6개 조합(3개 viewport × 5주/6주 달)과 데스크톱 1개: 모두 통과. 모바일 시트 5주 444px / 6주 488px, 390×600에서도 85dvh=510px 이하.
- 날짜 셀 최소 46.56×44px(360px 화면), 390px에서는 50.84×44px. 잘린 셀·내부 스크롤·가로 넘침 모두 0.
- 닫기 5종과 브라우저 뒤로가기, 좌우 월 스와이프, 포커스 진입/복귀, 오늘·선택·비활성 구분 통과. 독립 재확인으로 방향키→Enter 선택, PageDown 월 이동, Tab 모달 내부 순환도 통과.
- PNG 직접 확인: 오늘 링·점, 24일 선택 채움, 1~2일 비활성, 6주 달 하단 행과 하단 버튼에 잘림·겹침 없음. 시각 select 비교는 OS 팝업 캡처가 아닌 현재 필드 재현임을 이미지에 표시했다.
