**추천: D-1.** 11/24 선택을 스테퍼 21회에서 2회로 줄이고, 모바일에서도 오늘·선택·지난 날짜를 같은 색과 위치로 보여 준다. D-2는 목표 날짜 선택의 탭 수가 같으며 패널이 52px 더 높다. D-3은 모바일 달력 구현을 줄이지만 제품 톤과 조작 비용을 일정하게 제어할 수 없다.

D-2 칩은 '오늘 / 내일 / 다음 주 같은 요일'로 고정했다. 기준은 현재 선택값이 아니라 **오늘**이다. 날짜를 반복해서 읽지 않아도 되는 가까운 날짜 세 가지를 담았다. 11/3 기준 각각 11/3·11/4·11/10을 선택하고 즉시 닫는다. 오늘→3주 뒤를 다음 주 칩 세 번으로 이동하는 동작은 제공하지 않는다. 같은 달의 직접 선택도 2회라서 이번 과제의 대표 목표에서 추가 절감은 없다.

탭 수는 닫힌 필드부터 실제 포인터 클릭으로 검증했다. 11/24는 필드 열기→24일 2회, 12/1은 필드 열기→다음 달→1일 3회다. 취소·포커스 이동은 탭 수에 포함하지 않았다. OS 선택기 내부는 자동화 값 주입과 실제 조작을 구별하며 모바일 D-3 수치를 추정하지 않는다.

## 화면·동작 근거

- `frontend/src/pages/classes/class-scheduling.css:6`~47: 브랜드 #5F0080, 보라 #B373EF/#D2AEFC, 텍스트 #F7F4F0/#CFC6D6, sheet rgba(24,12,36,.78), 테두리 rgba(255,255,255,.14), 반경 24/16px, 폰트 스택, 카드 폭 640px.
- 같은 파일 `:108`~109 카드 padding 16/24px, `:149`~151 스테퍼 높이56px와44px 버튼, `:270`~274 데스크톱3열·모바일2열과 예약알림 span을 재현했다. 높이는 바깥 박스56px로 맞췄다.
- 같은 파일 `:400`~416: 시작 시각 C-3의 56px·15px·700·16px 필드, #24132f 팝업, 보라 테두리, 0 16px 48px rgba(0,0,0,.5) 그림자, 선택색·18px 날짜 글꼴을 채택했다.
- `frontend/src/pages/classes/wizard-visual-components.tsx:15`~35: 날짜는 YYYY-MM-DD 문자열, 표시는 M/D(요일), min/max 전달. `class-scheduling-wizard.tsx:303`: 시작 날짜에는 min=koreanToday()만 전달하고 max는 없다. 따라서 **이 화면의 날짜 상한은 없음**으로 재현했다. 서버가 무제한을 보장한다고 주장하지 않는다.
- `frontend/src/lib/class/class-wizard.ts:80` MAX_DAY_OFFSET=13은 별도 dayOffset 흐름(`:302`)의 스테퍼 한계다. 이 recurrence_rule.start_date 선택기의 상한으로 사용하지 않는다.
- `class-scheduling-wizard.tsx:111` rule은 전달된 필드만 합치고 rows를 비운다. `:303` 날짜 변경은 start_date만 전달하며 weekdays를 자동 변경하지 않는다. 시안에서도 선택된 화요일은 다른 요일 날짜를 골라도 **현행 유지**한다. 날짜와 반복 요일 정합 규칙을 새로 만들지 않는다.
- 공휴일 표시·자동 제외·차단은 넣지 않았다. 기존 '공휴일은 자동으로 건너뛰지 않아요'를 유지했다.
- `frontend/public/images/background4.webp`를 인라인 내장. 실제 캡처 `specs/sdd-279-class-start-time-picker/shots-fix/1440-open.png`, `390-select.png`를 직접 열어 비교했다. 카드640px·컨트롤56px·색·라운드와 모바일2열은 소스를 따른다. 279의 과거 디자인 v2에 있던 1010px 카드·88px 컨트롤은 실제 구현과 달라 따르지 않았다.
- 실제 C-3는 시각 팝업이 카드 경계에서 잘리는 캡처다. 이번 날짜 팝업은 body 직계 fixed 레이어로 카드 overflow 밖에 두고 화면8px 여백에서 위치를 보정했다. 열림·날짜 선택·밖 클릭·Esc·모바일 닫기를 지원한다. 팝업을 닫으면 값 선택·Esc·닫기에서 날짜 필드로 포커스가 돌아온다. 밖 클릭은 클릭 대상의 포커스를 유지한다.
- 시작 시각은 비교용으로 C-3 외형과 오전/오후·시/분 목록을 재현했다. 전체 시각 선택 로직·예약알림·스테퍼 등은 이번 날짜 시안의 상호작용 범위가 아니며 앱 기능 검증이 아니다. 아이콘은 외부 의존 없는 문자 대체라 원본 Lucide와 픽셀 단위 동일하지 않다. 폰트 파일은 내장하지 않아 시스템별 차이가 있다.

## 측정과 요구 충돌

`node specs/sdd-281-class-date-picker-calendar/design/verify-design.cjs`로 재현한다. Chrome headless + Playwright 사용, 앱 빌드는 실행하지 않는다. 상세 측정은 [validation.json](validation.json), 탭·칩·외부닫기·이미지 내장 확인은 [supplemental-validation.json](supplemental-validation.json)에 저장했다.

| 검사항목 | 결과 |
|---|---|
| 해상도 | 3안 × 1440×900 / 1280×900 / 1024×900 / 390×844 / 390×600 = 15조건 |
| 데스크톱 3열 라벨 y | 차이 0px |
| 세 컨트롤 높이 | 모두56px, 차이0px |
| 날짜·시각 필드 높이/글자/라운드 | 56px / 15px / 16px 동일 (모바일 시각은 현행 select 기준) |
| 라벨→컨트롤 간격 | 8px |
| 가로 넘침 | 0px |
| 조작 타깃 | 가시 버튼·입력 최소44px; 팝업 날짜44px 이상 |
| 팝업과 필드 폭 | 데스크톱326px / 약186px(약1.753배), 모바일 시트390px / 필드156px |
| 카드·화면 가장자리 | 카드 overflow:hidden·필드 하단/오른쪽 배치에서 화면 내 표시 및 hit-test 확인 |
| 날짜·키보드 | 지난 날짜 비활성, 11/24 선택, 방향키·Enter, Esc 복귀, PageUp/Down, 월말→월초, 연말, 평년2/28·윤년2/29 확인 |
| 모바일 동일 y | 현행2열 재배치로 소요 시간은 다음 행. 세 라벨 동일 y는 적용 불가; 동일 간격·높이로 검사 |

**요구 충돌을 숨기지 않는다.** 현재 카드640px에서 24px 패딩·16px 열 간격을 빼면 필드는 약186px다. 요일7열 × 터치44px + 패딩16px + 테두리2px = 최소326px이므로 '필드와 같은 팝업 폭'은 충족하지 못한다. 작은 터치 타깃 대신 **달력만326px로 확장**했다. 필드까지326px로 넓히려면 카드최소1060px(326×3+32+48+2)이 필요해 실제 화면640px 재현과 충돌한다. 대표 결정 전 제품 구현에 확정 반영하지 않는다.

숫자 조작의 독립 검증은 별도 검증 에이전트가 Chrome headless에서 수행했다. 초기 검토에서 ARIA row 누락·D-3 중복 접근성 노출을 지적하여 시안에 수정했다. 이후 구현자 측 15조건 회귀 검사와 최종 PNG 직접 확인을 수행했다. 최종 독립 재검증 6조건(3안 × 1440×900/390×600)에서 JavaScript 오류0·가로 넘침0, ARIA row 구조 정상, D-3 네이티브 단일 포커스·값 반영을 확인했다.
