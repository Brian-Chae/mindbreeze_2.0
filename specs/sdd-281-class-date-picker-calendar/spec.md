# SDD-281 — 클래스 시작 날짜 캘린더 팝업 선택

- 상태: Stage ① Spec · 디자인 3안 검토 대기, 제품 구현 전
- 브랜치: `sdd/281-class-date-picker-calendar`
- 작성일: 2026-11-03

## 문제

클래스 만들기 2단계 '언제 진행할까요?'의 시작 날짜가 하루씩 움직이는 −/+ 스테퍼다. 오늘에서 3주 뒤 날짜를 고를 때21회 조작이 필요하고 월 단위 날짜 관계를 보기 어렵다. 옆 시작 시각은 SDD-279 C-3 단일 필드 팝업으로 바뀌어 날짜 입력 경험과 다르다.

## 목표

날짜 필드를 누르면 캘린더가 열려 시작 날짜를 직접 고른다. C-3의 필드 높이56px·글자15px·라운드16px·보라 선택색·팝업 배경/그림자를 유지한다. 지난 날짜를 비활성화하고 오늘과 선택 날짜를 구분한다. 모바일390px·낮은600px 화면에서도 선택할 수 있어야 한다. 오늘→3주 뒤를 두 번의 조작으로 선택하는 데스크톱·커스텀 모바일 시안을 제시한다.

- 오늘2026-11-03 고정, 월 이동·날짜 선택·밖 클릭·닫기·키보드 동작.

- 지정 공유 폴더에 복사, 지정 문구의 로컬 문서 커밋.

## 유지할 계약과 현행 동작

값은 YYYY-MM-DD 문자열이고 표시는 M/D(요일)이다. `class-scheduling-wizard.tsx:303`의 min=koreanToday()를 따른다. 이 호출은 max를 전달하지 않는다. `class-wizard.ts:80`의 MAX_DAY_OFFSET=13은 별도 흐름에만 적용되므로 여기로 옮기지 않는다. 날짜 변경은 `:111` rule과 `:303` 호출에 따라 반복 weekdays를 자동 변경하지 않는다. 공휴일 표시·자동 제외는 추가하지 않는다. 백엔드 최대 범위·검증은 이번 디자인 작업에서 확인하지 않았다.

## 요구 충돌과 디자인 선택

현행640px 카드의 같은 폭3열은 약186px다. 7열44px 날짜 타깃을 가진 달력은 최소326px이므로 필드와 같은 폭이 불가능하다. 세 열·카드는 원형대로 보존하고 달력만326px로 넓히는 절충을 시안에 담았다. 모바일은 현행2열이며 세 라벨을 모두 같은 y에 두지 않는다. 이 두 조건은 검증 결과에서 예외로 명시한다.

## 범위 밖

제품 `frontend/src` 변경, 실제 API·서버 계약 변경, 날짜/요일 정책 신설, 앱 빌드, 푸시·PR·배포·메일·삭제·운영 접속. 구현 plan/verify/summary를 사후 작성하지 않는다. 제품 구현은 방향 결정과 구현 전 Verify 게이트 후 별도 진행한다.
