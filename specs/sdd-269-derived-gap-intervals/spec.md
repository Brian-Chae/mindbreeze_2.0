# SDD-269 — 저장 데이터 기반 결측 구간 계산·표시

- 상태: Stage ① Spec
- 브랜치: `sdd/269-derived-gap-intervals`
- 작성일: 2026-11-01

## 1. 문제
네이티브(앱) 경로로 측정한 회차는 `biosignal_gap_events` 가 0건이다(SDD-270 이 앱 쪽을 고친다). 그래서 데이터센터·리포트가 "신호가 끊긴 구간"을 말할 정식 근거가 없다. 그러나 서버가 이미 가진 데이터에 흔적이 남는다.
- 분석 데이터 창(`eeg_feature_windows`): 품질 0, window_index 결번, `device_timestamp_ms` 간격 이상
- 측정 기록 파일(`eeg_raw_chunks`, eeg): 재연결마다 segment 분할 → segment 사이 시간 간격
밴드는 자체 저장소가 없어 끊긴 구간 데이터는 복구 불가. **빈 구간을 정확히 설명할 뿐 데이터를 지어내지 않는다.**

## 2. 범위
- 포함: 파생 결측 구간 순수 함수 + 서비스, 기존 `gaps` 응답에 병합(source 구분), 구간 요약 API, 데이터센터 파형 표시, 회차 상세 중립 문구.
- 제외: 앱/네이티브 수정(SDD-270), DB 스키마 변경·마이그레이션(없음), 원인 단정, 점수화.

## 3. 파생 규칙 (확정)
시간 기준은 기기 시각(ms). 한 참여자의 한 회차 안에서 `play_group_id`(없으면 NULL 하나의 그룹)별로 창을 `window_index` 순 정렬해 계산한다.

| # | 규칙 | 구간 [시작, 끝) |
|---|---|---|
| R1 | 품질 0 연속 창(`signal_quality = 0` 또는 `quality = 'invalid'`) | 첫 창 시각 ~ 마지막 창 시각 + 1000ms |
| R2 | window_index 결번(같은 그룹, 인접 창의 index 차 > 1) | 이전 창 시각 + 1000ms ~ 다음 창 시각 |
| R3 | `device_timestamp_ms` 간격 > 1500ms (같은 그룹 인접 창) | 이전 창 시각 + 1000ms ~ 다음 창 시각 |
| R4 | 측정 기록 파일(eeg) segment 사이 간격: 시간순으로 정렬한 chunk 의 `max(end_ms)` 와 다음 chunk `start_ms` 의 차 > 1500ms | 이전 end_ms ~ 다음 start_ms |

- R2 와 R3 은 같은 구멍을 중복해서 잡는 경우가 많다 → 아래 병합이 흡수한다.
- 병합: 시간이 겹치거나 맞닿은(≤ 0ms) 구간은 하나로 합친다. 합친 구간의 `reasons` 는 합집합.
- **최소 길이 2000ms 미만 구간은 버린다**(측정 잡음·1초 창 경계 흔들림 방지). 병합 후 길이로 판정한다.
- 사유(`reason`)는 단정하지 않는다: R1 `signal_lost`, R2·R3·R4 `unknown`. 구간에 R1 이 섞이면 `signal_lost`, 아니면 `unknown`.
- 기존 `biosignal_gap_events`(기록된 구간)가 있으면 그대로 두고 `source='recorded'`, 파생은 `source='derived'`. 기록 구간과 겹치는 파생 구간은 기록 구간으로 흡수(중복 표기 없음): 겹치는 부분은 recorded 가 우선, 겹치지 않는 파생 잔여 구간은 그대로 남는다.
- 본 규칙은 저장 데이터가 없으면 아무 것도 만들지 않는다(빈 목록). 창 1개 이하이면 R1~R3 없음.

## 4. API (가산 변경만)
1. `GapRange` 에 선택 필드 `source: 'recorded' | 'derived' = 'recorded'` 추가. 파형 응답의 `gaps` 에 파생 구간 병합(요청 구간과 겹치는 것만). 기존 필드·의미 불변.
2. 신규 `GET /data-center/measurements/{session_id}/{participant_id}/gaps` → `{ gaps: GapRange[], count, total_seconds }` (파생+기록 병합, 시작 상대 µs 기준).
- 시간 원점(실측 확정, dev fbb7ee46): 분석 데이터 창 `device_timestamp_ms` = **절대 epoch ms**, 측정 기록 파일 `start_ms/end_ms` = **세션 상대 ms**(파형 x축과 같은 기준, 최소 -55). 절대 시각 앵커가 없어 **각 소스의 첫 시각을 같은 0 으로 두는 근사**를 쓴다: 창 시각 → `device_ms - 첫 창 시각 + 첫 측정 기록 파일 start_ms`. 측정 기록 파일이 없으면 첫 창이 0.
- 오차 상한: 파형 x축 위치 오차 = (첫 창 시각과 첫 측정 기록 파일 시작의 실제 차이) ≈ 첫 분석 창이 만들어지기까지의 지연(수 초 이내로 추정, 실측 미확정). 창 기반 구간이 이 값만큼 평행 이동될 수 있다.
- 영향 없는 것: 구간의 **길이(초)·횟수·합계**는 각 소스 안의 차이로만 계산해 원점 오차와 무관하다(요약 정확). 같은 끊김을 창·파일 양쪽이 가리키면 근사 위치가 겹쳐 하나로 병합되며, 어긋나 겹치지 않으면 두 구간으로 보일 수 있다(알려진 한계).

## 5. 화면
- 데이터센터 파형: 기존 "결측 구간" 블록이 파생 구간도 보인다. 줄 문구: `12.0–23.7초 · 11.7초 결측`, 파생은 `(저장 데이터로 계산)` 덧붙임. 선으로 잇지 않는 기존 동작 유지.
- 회차 상세(데이터센터 측정 상세): "측정 중 신호가 끊긴 구간 N회, 합계 N초" 중립 문구. 없으면 표시하지 않는다.
- 금지 표현: 점수·종합점수·좋음·나쁨·완료·보증. 내부 용어(feature/원시/EEG/PPG/ACC) 화면 노출 금지 → "분석 데이터", "측정 기록 파일", "뇌파/맥박/움직임".

## 6. 수용 기준
- 실측 회차 모양 fixture(품질 0 85~87/90~95/97~99, 101→102 간격 11.73초)에서 기대 구간이 계산된다.
- 앱 재빌드 없이 기존 회차에 적용된다(스키마·클라이언트 변경 없음).
- 대용량(40명×600창)에서 쿼리 수·응답시간이 상한 이내(verify V-P).
