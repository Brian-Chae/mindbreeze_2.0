상태: Brian이 본 세션에서 구현 범위 및 Stage ③ Verify를 승인함. 승인된 구현 지시서 `/tmp/wrc-react-brief.md`에 따라 진행.

## 목적과 기준

`design/waiting-room-checkin/index.html`을 React에 이식한다. 회원의 중복 대기 흐름을 없애고 상담사가 각 회원의 준비 상태를 확인하도록 한다. 목업의 다크 퍼플(#12081C, #5F0080, #dcb5ee), 단계 연결선, 완료 체크, 카드와 3개 뱃지를 따른다. 기존 사용자 제공 목업·이미지는 보존한다.

## 회원 화면

- ClassWaitingRoom에 “잠시 후 시작합니다” hero, 참여 이름, ①설문 ②링크밴드 ③기기 테스트 탭, N/3 완료 및 자동 입장 안내를 배치한다.
- 설문은 PreCheckinPanel의 SAM 2축·전달 말·submitCheckin 인증 분기를 유지한다. 저장 성공 또는 명시적 건너뛰기 시 완료하고 다음 단계로 이동한다. 저장 실패는 완료가 아니다.
- 밴드는 WaitingRoomBandCheck와 useBand singleton을 유지한다. `/linkband-detail-1.png`와 01 전원·02 착용·03 연결 안내를 추가한다. 연결 성공 또는 미사용 선택 시 완료하고 다음 단계로 이동한다.
- 기기는 자동 마이크 확인·레벨미터, 선택 카메라 미리보기, 스피커 테스트음을 유지한다. 확인 완료 또는 건너뛰기 선택으로 단계 완료를 기록한다. 권한 오류는 안내하되 입장을 막지 않는다.
- 완료 상태는 준비 절차를 마쳤다는 의미다. 밴드 연결 해제 등 실제 기기 상태와 구분한다. 미사용을 실제 연결로 표시하지 않는다.
- 탭 이동으로 설문 입력, 완료 상태, BLE 연결이 초기화되지 않도록 한다. 숨겨진 탭은 키보드 초점 대상에서 제외한다.
- 입장은 이름만 필수다. 단계 미완료라도 입장 가능하며, 대기 중 상담사가 시작하면 이름이 유효한 참가자는 MemberSessionScene으로 자동 전환한다.
- lobby/waiting의 중복 렌더를 단일 대기 컴포넌트로 합친다. MemberWaitingScene의 welcome/guide/wait 단계는 제거한다. 대기 중 presence·BGM·Wake Lock을 유지하고 라이브 전환 시 미리보기 자원을 정리한다.

## 상담사 화면

- ClassPlayerPage의 open 상태에서 “준비 현황” 패널을 표시한다.
- 전체는 현재 presence로 확인된 대기 회원 M명, 완료 인원 N은 세 단계가 모두 완료인 회원으로 정의한다. 예약 명부 전체를 대기 인원으로 오인하지 않는다.
- 이름, 설문/링크밴드/기기 ✓ 또는 ○, n/3을 표시한다. 미완 행은 배경과 좌측 점으로 강조한다. 0명에서는 0/0과 빈 상태를 표시한다.
- 기존 체크인 요약·전달 말 및 세션 중 보존 기능을 유지한다.
- “미완 N명 리마인드”는 해당 세션 미완 참가자에게 대기실 내 안내를 전달한다. 목업의 가짜 전송 성공 표시는 이식하지 않는다. 미완 0명·연결 불가·전송 중에는 비활성화하고 서버 수락과 실패를 구분한다.

## 필요한 최소 데이터 확장

현행 waiting_room 이벤트는 nickname/checkin만 전달한다. 다른 브라우저의 밴드·기기·건너뛰기 상태를 UI만으로 알 수 없으므로 선택적 `readiness` 필드를 추가하고 서버에서 검증 후 호스트 룸으로 전달한다.

```ts
interface WaitingRoomReadiness {
  surveyDone: boolean;
  bandDone: boolean;
  deviceDone: boolean;
}
```

기존 이벤트명·필드·체크인 REST 계약은 그대로 유지한다. readiness가 없는 구버전 클라이언트는 체크인 존재 시 설문만 완료로 간주하고 밴드·기기는 미확인으로 표시한다. 상태 변경 즉시 전송, 15초 heartbeat·재연결 복원, 45초 TTL과 leave 처리를 보존한다.

리마인드는 호스트 권한을 확인하는 별도 WS 요청과 해당 세션 참가자 본인 룸 알림으로 구현한다. 다른 세션이나 참가자에게 체크인 정보를 공개하지 않는다. 이메일·문자·푸시·DB 마이그레이션은 포함하지 않는다. 이는 실제 동작을 위한 제안 범위이며 Verify 승인 대상이다.
