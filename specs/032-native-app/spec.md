# SDD-032 — 네이티브 하이브리드 앱 (웹뷰 기반) — 후순위

> **나중에 진행.** 웹 검증 완료 후 착수. **하이브리드 앱(웹뷰) 형태.**
> 네이티브는 블루투스·기본 신호취득·앱 푸시만 담당, 나머지(UI·신호처리·지표 추출)는 웹뷰(동일 JS 로직).

## 1. 배경·목표

웹 블루투스(Web Bluetooth API)는 Chrome/Edge만 지원하고, iOS(Safari)에서 미지원이라
iOS 사용자가 LINK BAND를 연결할 수 없다. **하이브리드 앱(웹뷰)**으로 해결한다. 목표:

1. iOS/Android 앱에서 LINK BAND BLE 연결 (네이티브: CoreBluetooth/BluetoothGATT — 안정적, 재연결 포함)
2. 신호처리·지표 추출은 **웹뷰(웹 JS)에서 처리** — SDD-030의 순수 TS 로직을 그대로 재사용
3. 사용자(내담자) 명상·대기 화면을 웹뷰로 표시 (웹 UX와 동일)
4. 앱 푸시(네이티브) — 수업 알림 등

## 2. 구조 — 하이브리드(웹뷰) 분담

| 계층 | 담당 | 기술 |
|------|------|------|
| **네이티브** | BLE 연결 + raw 신호취득 | LINK BAND SDK(iOS/Android) |
| **네이티브** | 앱 푸시 | FCM/APNs |
| **웹뷰** | 신호처리·지표 추출 | 웹 JS (SDD-030 순수 TS 로직) |
| **웹뷰** | UI (대기/명상/완료 화면) | 기존 React 웹 |

- 네이티브가 BLE raw를 수신 → 웹뷰 JS로 브리지 전달 → 웹뷰에서 신호처리·지표 계산
- 웹뷰는 기존 `frontend/`와 동일한 신호처리 로직(`lib/eeg/`)을 사용 — 지표 결과 일치 보장

## 3. 프레임워크

| 옵션 | 평가 |
|------|------|
| **Capacitor** (권장) | 웹(React) 코드를 그대로 패키징 + 네이티브 BLE/푸시는 플러그인. 웹뷰 재사용 최대 |
| React Native(WebView) | RN 셸 + react-native-webview. 네이티브 모듈 작성 필요 |
| 순수 네이티브 + WebView | 개발 비용 높음, 웹 코드 분리 |

권고: **Capacitor** — 웹 코드(React) 재사용 + 커스텀 네이티브 플러그인(BLE raw 브리지)으로
"네이티브 BLE + 웹뷰 신호처리" 하이브리드 구조를 가장 적게 구현한다.

## 4. 구현 범위
1. Capacitor 프로젝트 생성 (기존 `frontend/` 웹 코드 기반)
2. 네이티브 BLE 플러그인 — LINK BAND SDK(iOS/Android) 연동, raw 스트림을 웹뷰 JS로 브리지
3. 앱 푸시 플러그인 — FCM/APNs
4. 웹뷰 신호처리 — 기존 `lib/eeg/` 로직 재사용 (수정 없이 동일 동작)
5. 사용자 화면: 대기/명상/완료 화면 (웹뷰, 기존 React 컴포넌트 재사용)

## 5. 검증 기준
- iOS(iPhone)에서 LINK BAND 연결 안정적 (웹 블루투스 대비 개선)
- 웹뷰 신호처리 지표가 웹 브라우저와 **동일** (순수 TS 로직 재사용)
- 상담사 화면(웹)에서 앱 사용자 데이터가 동일하게 표시
- 앱 푸시 수신 정상

## 6. 의존·후속
- 선행: SDD-030 (신호처리 로직 — 웹뷰에서 재사용)
- 후속: SDD-033 (듀얼 모드 통합)
