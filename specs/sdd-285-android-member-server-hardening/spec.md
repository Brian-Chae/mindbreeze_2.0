# SDD-285 — 안드로이드 회원 경로 검증 및 서버 안정화 (11/11 행사 대비)

- 상태: Stage ① Spec — 대표 go/no-go 대기 (대표 지시 의도 확인됨, 11/4)
- 브랜치: `sdd/285-android-member-server-hardening`
- 작성일: 2026-11-04
- 기한: **11/11(수) 행사 전**. 안드로이드는 Play 스토어 게시본(vc47)으로 진행하므로 앱 수정이 필요하면 **금요일(11/6) 전 업데이트 심사 1회**에 맞춘다.
- 관련: SDD-282(유실 원인·복구), SDD-283(부하), SDD-284(iOS)

## 1. 배경

11/4 행사에서 안드로이드는 권한 설정 문제로 다수가 준비한 태블릿으로 **회원가입 없이 코드로 입장(비회원)** 해 데이터가 거의 남지 않았다. Play vc47은 11/4 16:29 게시됨(앱 권한 흐름 개선 기대).
회원으로 정상 완주한 6명(전원 Android)이 있었지만, **회원이고 밴드가 연결됐는데도 분석 데이터가 저장되지 않은 케이스**가 있다(분석 표 0건·원시 업로드 있음·기대량 보고 있음: 4명, SDD-282 F3/H1′).
11/11 행사는 **전원 회원가입 → 모든 동의 완료 → 대기 상태에서 밴드 연결 완료 → 클래스 진행**으로 운영한다.

## 2. 해결할 문제

1. **(최우선) 회원 + 동의 완료 + 밴드 연결 + 네트워크 안정이었는데 데이터가 저장되지 않은 케이스의 원인을 파악한다.**
   - 11/4 회원 24명 전수에서 이 조건을 만족한 사람 중 실패한 사람이 있는지 확인(건수·접두사만). 있다면 왜 저장이 안 됐는지.
2. 안드로이드 회원 경로가 위 이상 조건에서 성공 6명과 같은 결과를 보장하는지 검증한다. **문제가 없다면 안드로이드 앱은 수정하지 않고** 서버 안정화만 진행. 앱 수정이 필요하면 금요일 전 업데이트 심사 1회로 가져간다.
3. 서버 안정화: 실시간 방송 오류 반복(`log_truncated`), 입장 시 정원 계산, `eeg-raw/presign` 403 재시도 폭주, 로깅 부재(`[ingest-batch]`), 플랫폼·빌드 기록 부재.

## 3. 범위

### 포함
- 11/4 회원 24명의 조건별 분류(동의·밴드 연결·대기열·재입장·플랫폼)와 실패 사례 원인 규명
- 4명(`de8312`, `6a2172`, `518675`, `ac1a78`)의 H1′(소켓 끊김으로 귀속 전 창 미전송) 검증: 앱 코드(`MetricOutbox.pendingBatch`, 복구 스위퍼), 서버 `capture.start/renew/reanchor` 흐름
- 서버측 안정화 항목 설계·구현(SDD 승인 후): 방송 오류 반복 차단, 로깅 설정, 플랫폼 기록, 정원 계산
- dev 환경 재현: 소켓 끊김 + 귀속 전 창 시나리오로 4명과 같은 상태가 만들어지는지

### 제외
- 운영 DB 쓰기 (복구 12,540행 재적재는 SDD-282 plan 단계 0에서 별도 승인 후 수행)
- iOS (SDD-284)
- 비회원 코드 입장 개선 (이번 행사는 회원가입 필수 운영)

## 4. 성공 기준

- 11/4 회원 24명 중 "동의 완료+밴드 연결+대기열 아님"인 사람 전원의 성공/실패가 분류돼 있고, 실패 사례마다 원인이 확정/가설/모름으로 표시돼 있다.
- 안드로이드 앱 수정 필요 여부가 **근거와 함께 결론** 나 있다.
- dev에서 40명 동시 회원 경로(가입→동의→대기→밴드 연결→클래스) 시나리오가 데이터 99% 이상 저장으로 통과한다(부하 시험 자산 재사용 가능 여부 확인).

## 5. 제약

- 운영 DB 읽기 전용(SSM `i-0487c67fb0db7dcba`). 쓰기·재시작·배포·푸시·메일은 대표 지시 후.
- 개인정보는 건수·접두사만. 비밀값 출력 금지.
- 운영 배포는 11/6(목) 이전까지, **행사 전날 밤까지만 배포**하고 행사 당일 배포 금지.
- 금지 표현(점수·종합점수·좋음·나쁨·완료·보증·100% 단정)은 신규 화면에 쓰지 않는다.
