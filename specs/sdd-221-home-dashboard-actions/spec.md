## 1. 목적

상담사 홈(`/dashboard`)의 요약 수치가 실제와 맞고, 눈에 보이는 안내 문구와 카드가 누르면 이동하도록 고친다.

## 2. 증상과 확인된 원인

| # | 증상 (Brian 보고) | 코드 조사로 확인된 사실 |
|---|---|---|
| 1 | 검토 대기·진행 중·오늘 예정 수치가 맞지 않는 것 같음 | **기준 불일치**: ① `진행 중` 타일은 서버 `in_progress_classes`(`dashboard_service.py:15` `_IN_PROGRESS=("in_progress",)`)인데, 같은 화면의 `진행 중 · 예정` 목록과 상단 카드는 `in_progress`+`open` 을 진행 중으로 본다. 오픈(대기) 클래스가 있으면 타일과 목록이 어긋난다. ② `검토 대기` 는 서버가 **상담 세션 포함 전체**를 합산(`:138`)해 목록(상담 제외)과 어긋날 수 있다. ③ `오늘 예정` 은 프론트가 로컬 날짜로 계산하며 **오늘 이미 끝난 회차도 포함**(취소만 제외). ④ 서버는 `host_id == 본인` 회차만 집계하므로 **팀 강사로만 참여한 회차는 빠진다** (dev 실데이터로 확인 필요) |

## 3. 범위

### 3.1 수치 정합 (증상 1)
- 요약 타일 수치는 **같은 화면 목록과 같은 기준**으로 계산한다.
  - `진행 중` = 진행 중 + 오픈(대기). 목록·상단 카드와 동일 집합.
  - `검토 대기` = 화면에 보이는(상담 제외) 클래스의 `pending_review_count` 합.
  - `오늘 예정` = 오늘 일정 중 **아직 끝나지 않은**(취소·완료 제외) 회차.
- 서버 합산(`pending_review_count` 등)은 기본적으로 건드리지 않는다. dev 실데이터 재현에서 **팀 강사 회차 누락(원인 ④)** 이 확인되면 `dashboard_service.py` 에 한해 서버 수정을 포함한다(Brian 사전 승인 범위: "백엔드 수정 가능").
- 같은 기준을 `OrgDashboardPage` 의 동일 타일에도 적용하는지는 plan 에서 확인한다.

### 3.2 타일을 버튼으로 (증상 2)
타일 전체를 링크로 만들고 키보드로도 동작하게 한다.

| 타일 | 이동 |
|---|---|
| 진행 중 | 진행 중인 회차가 1개면 그 입장 화면, 여러 개면 `진행 중` 필터가 걸린 클래스 목록 |
| 검토 대기 | `/reports?status=pending` (기존 쿼리 지원) |
| 오늘 예정 | 클래스 목록의 오늘 일정 |
| 총 참여자 | `/clients` |

- 값이 0이어도 이동은 가능하다. 단, `입장하기 →` 는 진행 중이 0이면 문구를 `클래스 목록 →` 로 바꿔 거짓 안내를 하지 않는다.

### 3.3 카드 전체 클릭 (증상 3)
- `ClassCard`(내 클래스)와 `일정` 행 전체를 링크 영역으로 만든다.
- 카드 안의 `입장`, `코드 복사`, `기록 보기` 같은 **내부 버튼은 기존 동작을 유지**하고 카드 이동으로 번지지 않게 한다.
- 접근성: 카드 전체가 하나의 링크로 읽히고 포커스 링이 보인다.

### 3.4 새 알림 클릭 (증상 4)
- 알림 행을 눌러 `resolveNotificationTarget(extra, role)` 경로로 이동하고, 이동 직전에 읽음 처리한다.
- 이동 대상이 없는 알림(공지 등)은 읽음 처리만 하고 이동하지 않으며 눌림 피드백은 유지한다.
- 상담 알림은 SDD-219 규칙대로 클래스 홈으로 대체된다.

### 3.5 회원 홈 데스크톱 레이아웃 정리 (Brian 추가 요청 2026-10-20)
증상: 데스크톱에서 컴포넌트가 삐뚤빼뚤하고 정렬이 안 맞아 한눈에 파악하기 어렵다.
확인된 원인(코드):
- 폭 기준이 둘이다. `member-structure-home-page` 의 `.mc-stack`(최대 1040px) 안에 `ClientHomePage` 가 최대 1200px 2단 격자를 다시 만든다.
- `내 클래스` 카드가 2열 격자라 개수가 홀수면 빈칸이 생기고 카드 높이도 들쭉날쭉하다.
- 요약 타일·이번 주 클래스·알림 등이 서로 다른 격자·카드 스타일(`mc-card` 와 Tailwind 카드)을 써서 모서리·여백·제목 크기가 다르다.
목표:
- 데스크톱에서 **하나의 폭·하나의 격자**로 정렬한다(히어로 전폭 → 아래 좌 주 영역/우 요약 레일).
- `내 클래스` 는 카드를 **가로 스크롤 줄(고정 카드 폭, 스크롤 스냅)** 로 보여 개수와 무관하게 정렬되고 한눈에 훑을 수 있게 한다. 카드 높이는 같게 맞춘다.
- 요약 타일(다음 클래스까지·새 리포트·이번 주·완료)은 한 줄 또는 2×2 로 높이를 맞춘 격자에 둔다.
- 섹션 제목·카드 모서리·여백·카드 그림자 스타일을 하나로 통일한다.
- 태블릿·모바일(767px 이하)의 기존 동작은 유지한다. 가로 스크롤 줄은 키보드(포커스 이동)와 터치 스와이프로 모두 동작한다.
- 이 작업은 **디자인 시안 HTML 로 먼저 방향을 확인**한 뒤 구현한다(시각 작업은 시안 반복 후 확정 원칙).
- 기능·데이터·라우팅은 바꾸지 않는다(표시 배치만).
