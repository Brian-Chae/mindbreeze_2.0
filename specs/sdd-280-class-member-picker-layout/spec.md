## 범위와 승인 상태
이번 산출물은 원인 조사와 정적 디자인 시안이다. 앱 구현은 시안 선택 후 별도 승인한다. Stage ④~⑥ 진행·수정 적용을 의미하지 않는다.

## 코드 근거와 원인
- 실제 해당 경로는 `frontend/src/pages/classes/class-scheduling-wizard.tsx:280-285`이다. host 하위 마법사가 아니라 `cs-wizard` 페이지가 회원 선택기를 사용한다.
- `frontend/src/components/class/structure/class-member-picker.tsx:56-68`: 목록은 일반 흐름의 div이며 `max-h-60 overflow-y-auto`가 있다. 회원 행은 absolute가 아니다.
- `frontend/src/pages/classes/class-scheduling.css:312`: 페이지 CSS가 목록에 `flex:1;min-height:320px`를 부여한다.
- 같은 파일 `:325`는 `max-height:none`으로 공통 선택기의 높이 상한을 해제한다. 320px 최소 높이는 좁은 카드에서 줄어들 수 없다.
- 같은 파일 `:154-155,268-269`: 부모 열과 카드는 `flex:1;min-height:0`으로 제한된 화면 높이에 맞춰 줄어든다. 자식 목록의 최소 높이와 검색·안내·선택 요약·간격·탭·대행 사유의 합이 부모보다 커지면 목록이 카드 밖으로 넘는다. 목록에 overflow:auto가 있어도 부모 바깥 침범은 해결되지 않는다.
- 같은 파일 `:344-349`: `display:contents`와 order가 검색·요약·목록을 동일 flex 흐름에 노출한다. 대행 사유 자체가 absolute인 구조는 아니다.
- 같은 파일 `:336`: 외부 스크롤 보정이 `.fl-body:not(.w-fill)`에만 적용돼 마지막 단계 `.w-fill`에는 적용되지 않는다. `:320`의 저높이 보정은 640px 이하에서만 적용된다.

## 영향 범위와 이력
센터 관리자 한정이 아니다. `class-scheduling-wizard.tsx:254`의 role 분기는 대행 사유 표시만 제어하고, `:282`의 회원 목록 구조는 공통이다. 관리자는 사유 입력 높이 때문에 더 빨리 침범한다. 실제 사용자별 재현은 미확인이다.

`git blame`상 목록 상한 해제는 `dd0194d03`(2026-10-19 14:58), display:contents/order는 `e0438b7d0`(15:01), 외부 스크롤 제외는 `07fe6640a`(14:59)에 도입됐다. 이는 회귀 후보를 좁힌 코드 이력이며 운영에서 처음 발생한 시점 확정은 아니다.

## 재현·디자인
`design/before.html`은 현재 코드의 높이 충돌을 축약한 합성 재현이다. 실제 React DOM·Tailwind 전체·계정 API 재현은 아니다. 정확한 원본 스크린샷은 브리프의 서술로만 제공됐다. 디자인 후보와 측정 결과는 `design/README.md`, `design/validation.json` 참조.

브라우저 측정 결과: 합성 before는 두 역할·두 화면에서 카드/푸터 침범, 관리자에서 사유 겹침을 재현했다. 목록 자체 스크롤은 가능해 신고된 스크롤 불가 현상의 정확한 조건은 미확정이다. 따라서 높이 충돌은 코드·합성 측정 근거가 있지만 실제 운영 증상 전체의 원인 확정으로 확대하지 않는다.
