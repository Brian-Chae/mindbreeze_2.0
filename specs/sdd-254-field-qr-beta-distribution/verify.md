# SDD-254 Verify — 구현 전 QA 체크리스트

> Stage ③ (구현 전 작성·사후 수정 금지, 추가는 별도 절로). 검증자는 구현자와 분리. 모든 항목은 **증거(스크린샷·로그·명령 출력)** 를 summary.md 에 첨부.

## G. 배포 게이트
- [ ] V-G1 원신호 합격: iOS 30~60분, Android 30~60분 각각 — 화면 잠금 1회·네트워크 1분 단절 포함, 원시 수신률 ≥ 99%, 세션 종료 상태 `complete` (서버 기록 대조).
- [ ] V-G2 운영 서버에 develop 묶음 선반영 완료, alembic head 1개, `a253b0c1d2e3` 적용 확인(`scripts`/헤드 점검).
- [ ] V-G3 빌드에 운영 API 주소 존재, dev 주소·역할 시뮬레이션 흔적 0건.
- [ ] V-G4 배포 빌드의 커밋 SHA 가 합격 시험 빌드와 동일.

## S. 서명·버전 (Android)
- [ ] V-S1 `apksigner verify --print-certs` 로 배포 APK 인증서 SHA-256 기록.
- [ ] V-S2 Play Console 의 **앱 서명 키 인증서 지문**과 V-S1 값이 일치(방식 B). 불일치면 spec §5 A안 경고를 랜딩에 노출하고 대표에게 보고.
- [ ] V-S3 패키지명 `com.looxidlabs.mindbreeze2`(dev 접미사 `.dev` 아님), versionCode > Play 최대값(23 이상 증가), versionName 표기 일치.
- [ ] V-S4 같은 서명의 이전 APK 위에 새 APK 덮어쓰기 설치 성공(데이터 유지).
- [ ] V-S5 (가능 시) Play 내부 테스트 설치본 → 베타 APK 덮어쓰기 가능 여부 기록.

## A. Android 설치 시나리오(실기기, 제조사 다른 ≥3대: 예 삼성·픽셀·샤오미/기타)
- [ ] V-A1 QR → `/beta` → "Android" 분기, 버전·SHA 표시.
- [ ] V-A2 "출처를 알 수 없는 앱 허용" 안내 그림이 실제 화면과 일치(브라우저 Chrome·삼성 인터넷 각각).
- [ ] V-A3 다운로드 헤더(`Content-Type`·`Content-Disposition`), LTE 에서 다운로드 시간 측정, 100MB 초과 시 경고 화면 없음.
- [ ] V-A4 Play 프로텍트 경고 문구·"그래도 설치" 동작 기록.
- [ ] V-A5 설치 후 로그인(내담자 계정)·마이크/블루투스 권한 요청·클래스 입장 동작.
- [ ] V-A6 SHA-256 이 랜딩 표기와 일치.

## I. iOS 시나리오(실기기 ≥3대, OS 버전 혼합)

- [ ] V-I2 TestFlight 앱 미설치 상태에서 설치 안내 흐름, 설치 후 "테스트 시작" 성공.

## L. 랜딩·QR
- [ ] V-L1 데스크톱 접속 시 "폰으로 스캔" 안내, iPad/태블릿 분기 정책 확인.
- [ ] V-L2 `beta.json` 링크 교체 후 **QR 동일**로 새 링크 노출, 캐시 지연 ≤ 정의값.
- [ ] V-L3 QR 인쇄물(A4, 실제 크기)이 서로 다른 폰 카메라 3종으로 1초 내 인식(밝기 낮은 환경 포함).
- [ ] V-L4 가용성: 모바일 3G/LTE 에서 랜딩 로딩 ≤ 3초 목표.
- [ ] V-L5 접근성: 큰 글씨 설정, 대비, 키보드/스크린리더 기본 점검.
