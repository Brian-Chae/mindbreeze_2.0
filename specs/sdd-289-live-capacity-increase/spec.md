# SDD-289 — 행사 중 상담사 화면에서 정원 증원 (예: 40명→50명)

- 상태: Stage ① Spec — 대표 지시로 착수 (11/4)
- 브랜치: `sdd/289-live-capacity-increase`
- 작성일: 2026-11-04
- 관련: SDD-282(11/4 정원 초과·대기열), SDD-286(비회원 입구 숨김)

## 1. 배경

행사에 예상보다 많은 사람이 올 수 있다(중복 참여가 아니라 실제 인원 증가). 정원이 40명인데 50명이 오면 초과분이 대기열로 밀려 입장하지 못한다. 11/4에도 정원 50에서 대기열 12행이 생겼다.
**상담사가 수업 직전·진행 중에 상담사 화면에서 정원을 늘려(예: 40→50) 대기 중인 회원을 즉시 입장시킬 수 있어야 한다.**

## 2. 이미 있는 것 (코드 확인, 11/4)

- 서버 `session_service.update_session`(`session_service.py:~978`)은 `max_participants`를 바꾸면 **대기열을 순번대로 자동 승격**(`_promote_waitlist_all`)하고 승격 알림을 보낸다. 종료·취소 회차만 막는다.
- 단, 반복 클래스에 속한 회차는 `_require_legacy_mutation`이 409 `use_class_scheduling_api`로 막는다. 11/11 회차는 클래스(편성) 소속이라 **이 경로로는 증원이 안 될 수 있다.**
- 클래스 설정 패널의 정원 입력은 `min=2, max=오프라인 100/온라인 50`이다(`class-settings-panel.tsx`). 이것이 클래스 전체 정원인지 회차별 정원인지, **진행 중 회차에 즉시 반영되는지는 확인되지 않았다.**
- 회원 입장 정원 판정은 `class_attendance_service.check_capacity`, `class_membership_service`(`class_capacity`·`session_capacity` 409), `session_service._has_capacity`로 흩어져 있다.

## 3. 해결할 문제

1. **진행 중이거나 시작 직전인 회차의 정원을 상담사 화면에서 늘릴 수 있는 경로가 실제로 있는가.** 없으면 만든다.
2. 늘리는 즉시 대기열 회원이 **자동으로 입장 가능**해지고, 대기 화면의 회원 화면이 갱신되는가(소켓·폴링).
3. 정원이 늘 때 서버 부하·실시간 방송이 문제를 일으키지 않는가(SDD-283 연계).
4. 늘리기만 허용하고 줄이기는 입장 중 인원보다 작게 못 하게 막는가(안전장치).

## 4. 범위

### 포함
- 현재 상담사 화면(클래스 상세·라이브 화면·설정 패널)에서 정원을 바꾸는 경로 전수 확인과 한계 정리
- 진행 중 회차 정원 증원 API·화면 설계(회차 단위, 클래스 전체 정원과의 관계 포함)
- 증원 후 대기열 승격·알림·상담사 화면 인원 표시 갱신
- 권한(상담사/기관관리자), 감사 기록, 최대 허용치(온라인 50 제한 등)와 오프라인 한도

### 제외
- 운영 DB 쓰기·배포·푸시·메일 발송, 앱 빌드
- 비회원 동일인 연장 처리(별도 후속)

## 5. 성공 기준 (verify.md에서 구체화)

- 상담사가 라이브/대기 상태에서 정원을 40→50으로 늘리면 대기열 10명이 순번대로 입장 가능 상태가 되고 회원 화면에 반영된다.
- 줄이기는 현재 입장 인원 미만으로 불가. 종료·취소 회차는 불가.
- 반복 클래스 소속 회차에서도 동작한다.
- 정원 변경 이력이 남는다.

## 6. 제약

- 운영 DB 읽기 전용, 쓰기·배포·푸시·메일 금지. 개인정보는 건수만. 금지 표현(점수·종합점수·좋음·나쁨·완료·보증·100% 단정) 신규 화면에 금지.
- 일정은 대표가 챙긴다. 이 SDD는 원인·설계·검증 기준에 집중한다.

## 7. 대표 결정 필요

1. 최대 허용 정원(현재 오프라인 100, 온라인 50) 유지 여부
2. 정원 증가 시 대기자 알림(푸시) 발송 여부
