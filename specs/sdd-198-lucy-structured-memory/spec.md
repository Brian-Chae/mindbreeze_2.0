# [SDD-198] 루시 장기기억 구조화 — 사실·선호·관계·감정 트렌드

## Goal
루시가 내담자와의 대화에서 "이서·이준이 자녀" 같은 사실·선호·관계·감정 트렌드를 구조화된 기억으로 축적하고, 응답 시 정확히 인출해 "기억하는 동반자"가 되게 한다(투표 1위 A3).

## Context
- 현재 루시 기억(SDD-194)은 체크인 요약(문장 덩어리, 최대 100개)을 프롬프트에 통으로 넣는 방식 → 정확한 사실 인출이 약함
- 기존 `AgentProfileItem`(수면/스트레스/감정/대처/관계)은 상담사 전용 "관찰 항목"이라 성격이 다름
- 루시가 "지난번에 아이들 얘기하셨죠, 이서랑 준이" 처럼 정확한 사실을 끌어내려면 키-밸류 구조화 기억이 필요

## Scope

### ✅ In-scope
- 새 테이블 `AgentMemoryItem` — 내담자별 구조화 기억 (category·key·value·evidence)
- 카테고리: `fact`(사실) / `preference`(선호) / `relation`(관계) / `emotion_trend`(감정 트렌드)
- 체크인 마무리(close) 시 LLM JSON 추출 → upsert (키별 최신 유지)
- 루시 응답 시 `client_context` 에 구조화 기억 로드 → `context_to_text` "■ 기억" 블록

### ❌ Out-of-scope
- 상담사 열람 UI (기존 프로파일·요약 경로 유지)
- 기억 삭제/편집 UI (내담자·상담사 수동 관리)

## Acceptance Criteria
- [ ] 체크인 마무리 시 대화에서 사실·선호·관계·감정 트렌드가 구조화 추출되어 저장
- [ ] 같은 키(예: "자녀")는 최신 값으로 갱신(중복 없음)
- [ ] 루시 응답 프롬프트에 구조화 기억이 포함
- [ ] 진단·점수·민감 정보는 기억에 저장되지 않음(agent_guard 통과분만)
- [ ] `pytest` 관련 테스트 통과

## Dependencies
- SDD-188/191(체크인), SDD-194(기억), SDD-193(감정 대화)

## Risks
- LLM 추출이 과도하게 개인정보를 저장 → agent_guard 통과 + 민감 카테고리 제한
- 기억이 프롬프트에 과다 → 키별 최신 1건 + 상한 제한
