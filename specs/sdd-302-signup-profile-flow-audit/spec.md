## 문제와 목표
1. 로그인 이동은 누락 필드가 아니라 `onboarding_completed`에 종속된다. 값이 false로 남으면 재로그인 때 같은 온보딩으로 이동한다.
2. Google은 별도 1페이지, Apple은 일반 4단계, 초대 Google은 일반 4단계 경로다. 요구 입력과 진행 조건이 경로별로 다르다.
3. Google 화면은 가입에서 이미 저장한 생일을 다시 빈 칸으로 시작한다. 일반 온보딩 전화 필수는 가입 화면의 전화 선택과 충돌한다.
4. 사진 배경·흰 카드·다크 폼·52px 버튼·공용 48/44px 버튼이 혼재한다. 회원 홈과 가입을 하나의 서비스로 인식하기 어렵다.
5. 선택 프로필 안내의 ‘나중에 하기’와 ‘다시 보지 않기’를 서버에 저장하고, 필수 가입 요건·권한·측정 동의와 분리한다.

## 요구사항
- R1: 회원은 필수 가입 요건 확인 후 선택 프로필 때문에 홈 진입이 차단되지 않는다.
- R2: ‘나중에 하기’는 즉시 홈 이동. 자동 모달 재노출 없음. 30일 후 홈의 비차단 안내를 최대 1회만 허용하는 기본안.
- R3: ‘프로필 입력 안내 다시 보지 않기’는 계정 단위 영구 숨김. 재설치·다기기에서도 유지. 설정에서 직접 해제할 수 있다.
- R4: 가입 당시 생일/이름 등 저장값을 먼저 불러오고, 동일 값을 다시 요구하지 않는다.
- R5: 약관·개인정보·민감정보는 현행 신규 가입 필수 정책을 유지한다. EEG·연구 동의는 선택이며, EEG 수집 시 별도 동의 검사 유지.
- R6: 이메일 코드 필수·소셜 코드 불필요라는 SDD-249 대표 결정을 이번 기획에서 임의로 변경하지 않는다. 비로그인 코드 입장은 폐쇄 방침을 따른다.
- R7: 화면은 회원 홈의 크림 배경·밝은 카드·보라 CTA, 공용 입력·버튼 규격으로 정리한다. 390px·768px에서 비교한다.
- R8: 이름은 표시 식별에 사용, 생일은 현행 가입 연령 판정에 사용한다. 선택 항목 완화는 기능별 null 검증 후 적용한다.
