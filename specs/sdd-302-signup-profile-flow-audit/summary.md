# SDD-302 — 회원 가입·필수정보·선택 프로필 개선 결과

## 결과
승인된 v4 클래스 화면 디자인을 회원 가입·소셜 확인·필수정보 보완·선택 프로필에 적용했다. 이름·성별·생년월일과 신규 필수동의가 가입 조건이며 전화는 선택, 회원 주소는 제외했다. 필수정보가 있으면 기존 온보딩 완료 플래그와 무관하게 홈으로 이동한다. 선택 프로필 보류 후 자동 재안내하지 않으며 설정에서 수동 입력한다.

## 구현과 리뷰
- 이메일 OTP→정보·동의 2단계, Google/Apple 확인→홈. 기존 소셜 재로그인에 신규 가입 정보를 요구하지 않는다.
- 서버의 실제 저장값으로 누락 필드를 판정하고 GET 본인 정보로 캐시를 갱신한다. 이미 저장된 생일을 재검증·재전송하지 않는다.
- 선택 전화 저장·삭제·보류 및 실패별 재시도, 초대 토큰 보존, 교차 탭 로그아웃 경합을 수정했다.
- 온보딩 공통 저장은 User 부모행 잠금과 세션 캐시 갱신으로 직렬화한다. 최초 진행행 생성 및 JSON 덮어쓰기 경합을 실제 임시 PostgreSQL에서 재현 후 해결했다.
- 백엔드·프런트엔드 독립 리뷰 후 Important 4건을 수정하고 재리뷰에서 해소를 확인했다.

## 검증 증거
- 백엔드 관련 13파일 165 passed. 후속 전화·동시성 보완 뒤 관련 회귀 86 passed. PostgreSQL 동시성 RED 2건→GREEN.
- 프런트엔드 관련 12파일 68 passed, 타입·변경 ESLint·빌드 통과.
- `runtime/browser-check.cjs`: 제품 React 소스에 합성 API를 연결. 390px·768px 화면 12개, 가로 넘침 0, 페이지 오류 0. 이메일 OTP→가입, 소셜 가입, 누락 성별만 보완, 선택전화 보류→홈 재진입 총 8개 흐름 통과.
- 캡처에서 자연배경·다크시트·연보라 CTA·Google 로고를 확인. 코치 연결 배너 대비도 수정했다.
- 감독 최종 재실행 및 전체 테스트·PR CI·dev 배포 결과는 완료 후 아래에 추가한다.

## 범위와 한계
실 OAuth 제공자 인증, 실기기 네이티브, 실제 메일 발송, EEG 장치, 운영 DB는 시험하지 않았다. 브라우저 가입은 합성 응답을 사용했으며 실계정을 만들지 않았다. Apple 버튼 노출은 iOS 조건에 따른다. 기존 전체 테스트의 실패는 관련 회귀 성공과 분리해서 기록한다. 운영 배포는 수행하지 않는다.
