# Plan — 서비스 LF/HF 과대 산출 원인 분석과 수정안 (코드 수정 전 단계)

브랜치 `fix/lfhf-overestimate-audit` (RMSSD 수정 PR #303 브랜치 위). 이 문서는 분석·계획만 담는다. 제품 코드는 수정하지 않았다.

## 1. 문제
하네스(원시 PPG 53명, 지표 산출 가능 49~50명, 사람별 중앙 → 전체 중앙):
| 구분 | LF/HF 중앙 | 재계산과 ρ |
|---|---|---|
| RMSSD 수정 전 | 0.99 | 0.30 |
| RMSSD 수정 후 | 2.50 | 0.64 |
| 원시 재계산(5분 창) | 1.11 | – |

수정 전 0.99가 재계산에 가까웠던 것은 우연이다(ρ 0.30). 수정 전 RR 지터가 HF 대역에 잡음 전력을 더해 비율을 낮췄고, 지터를 없애자 아래 결함이 드러났다(추정: 지터 효과는 직접 분리 실험을 하지 않았다).

|---|---|---|

| Hann 단독 | 5.20 | 0.52 |
| cubic 단독 | 1.74 | 0.65 |
| **평균 제거 단독 (= 선형 detrend 단독)** | **1.50** | **0.90** |

## 4. 원인 판정
- **주원인 (확정, 하네스로 재현): Welch 입력에서 평균(DC)을 제거하지 않음.** RR 평균 ~0.9s가 Hamming 창의 사이드로브·제로패딩 누설로 LF(0.04~0.15Hz)에 유입 → LF 과대. 평균 제거만으로 중앙 2.37→1.50, ρ 0.66→0.90. 위치: `AnalysisMetricsService.ts:756~765`(resample 직후 `computeWelchPeriodogram` 호출, 평균/추세 제거 없음), Rust `hrv.rs` `freq_domain`(동일 호출) / `welch`(:263).
- **부차 (확정): 선형 보간.** 선형 보간은 HF에서 sinc² 형태로 감쇠(저역통과)하여 HF를 낮춘다. detrend 후 선형→cubic 으로 1.50→1.06. 재계산 쪽이 cubic이라 같은 기준이 된다.
- **무관 확인:** NaN 꼬리(영향 +0.01), HF 확장 hack(발동 0), Hann/Hamming 선택(Hann은 오히려 악화되어 현 Hamming 유지), 창 길이(120박 vs 300박은 비율 영향 작음: 1.06 vs 1.09).
- **관찰(별건, 수정 범위 밖):** EMA 첫 시드가 평활 전 값이라 첫 틱 값이 큰 아웃라이어(사람별 첫 틱 중앙 약 700)일 수 있고, 저장 윈도우에는 이 초기값이 섞인다. 산출 시작 후 약 20초 동안의 값이 불안정 → 저장 시계열 통계는 중앙값(견고) 기준으로 읽을 것.

## 5. 표준 판정
- 대역 0.04~0.15 / 0.15~0.4Hz, 단기 5분 기록 기준 정의는 Task Force of ESC/NASPE 1996 (Circulation 93:1043)에 따른다 — 서비스와 재계산 모두 동일(내가 아는 규정 내용이며 이번 세션에서 원문을 다시 열어 확인하지는 못했다. 구현 전 원문 대조 필요).
- 평균/추세 제거는 Task Force 1996가 알고리즘을 규정하는 부분이 아니라 Welch/FFT 스펙트럼 추정의 일반 전처리(주파수 누설 방지)다. "서비스가 DC를 그대로 넣는 것은 비표준 오류"이며, 재계산 쪽(detrend+cubic)이 일반적 관행에 가깝다. cubic vs 선형 보간은 표준이 정하지 않는 선택지라 재계산과 맞추는 근거는 "하네스 일치도"뿐이다.
- 서비스는 1~2분(120박) 창이라 Task Force의 "LF는 최소 약 2분(≥ LF 하한 0.04Hz의 주기 25초 × 몇 주기)" 권고에 걸쳐 있어 낮은 해상도가 있다. LF/HF 절대값은 추이용 표기를 병행하는 것이 안전.

## 6. 최소 수정안 (TS·Rust 동시, 같은 형태)
1. **평균 제거(필수)**: `calculateFrequencyDomainMetrics`/호흡수 경로 공통, `resampleRRIntervals` 결과에서 선형 detrend(재계산과 동일) 후 `computeWelchPeriodogram`. `calculateRespiratoryRate`(:556~)도 같은 입력이라 동시에 적용(호흡 지배주파수 추정은 DC 누설에 덜 민감하나 일관성 위해). → 위치: 새 private `detrendLinear(y)` 추가(TS), Rust `detrend_linear`.
2. **cubic 보간(권장)**: `interpolateLinear` 대신 박동 중점 시각(`t_i + RR_i/2`)에 RR 값을 놓고 자연 3차 스플라인으로 4Hz 재표본. 마지막 구간 NaN 문제(`interpolateLinear` :848~872의 `yOriginal` 길이 불일치)가 함께 사라진다.
3. **정리(저위험)**: HF 확장 hack(:783~794) 제거 또는 단위 정정 — 이번 데이터에서 발동 0이므로 값은 불변. 제거를 기본으로 한다.
4. 변경 안 함: Hamming, 창 120박, EMA α, 대역, 게이트 25%.
5. **저장값**: 대표 결정대로 `backend/scripts/recompute_ppg_hrv.py` 제자리 덮어쓰기에 합류. 재산출 엔진(Rust example)이 `lf_power/hf_power/lf_hf_ratio`를 이미 덮어쓰므로 **도구 변경 없음**, 수정된 엔진으로 재빌드만 하면 된다(버전별 사본·컬럼 없음). 단 현재 실행 순서상 RMSSD 재산출 apply 전에 이 수정이 같은 PR/배포에 들어가야 한 번에 덮어쓴다 → **RMSSD PR #303과 같은 릴리즈로 묶을 것** (분리하면 두 번 덮어씀).
6. 부수: WASM 재생성, 네이티브 앱 재빌드 필요(RMSSD 때와 같음). 골든 oracle(`expected/oracle`, `legacy_fallback`, gf04)·`frontend/tests/fixtures/sdd273/native-*.json` 재생성.
