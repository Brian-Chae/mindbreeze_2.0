- 범위: plan.md 단계 0·1(조사·복구)과 단계 2 하위 SDD가 각자 가져갈 공통 게이트

## A. 조사 단계(단계 0) 완료 조건
- [ ] A1. 리포트 재생성 호출 경로와 `reports`의 `generation_status`/`approved_*`/`delivery_status` 처리 규칙이 문서화됨
- [ ] A2. 로컬 테스트 DB에서 feature 파일 샘플 → `eeg_feature_windows` 변환 결과가 정상 경로(`store_batch`)와 컬럼 값 동일(핵심 지표 컬럼 전부 비교)
- [ ] A3. `log_truncated` 시작/종료 시각의 서비스 재시작·재구축 이력이 확인되거나 "확인 불가"로 명시됨
- [ ] A4. handoff의 모름 6건이 각각 확정/가설/모름 중 하나로 재분류됨

## B. 복구(단계 1) 사전 게이트 — 하나라도 미충족이면 실행 금지
- [ ] B1. 대표의 **건별 서면 승인**(대상 4명, 행 수 12,540, 리포트 처리 방식)

- [ ] B4. 롤백 쿼리 작성·로컬 시험 완료(`ingest_path='recovery_sdd282'` 표식 행만 삭제)
- [ ] B5. 쓰기 계정/권한, 실행 시각, 실행자 기록. 개인정보는 건수·접두사만 출력

## C. 복구 사후 검증
- [ ] C1. 4명 `eeg_feature_windows` 행 수가 파일 행 수(2,820 / 4,200 / 2,580 / 2,940)와 일치, 합계 12,540
- [ ] C2. 재실행해도 행이 늘지 않음(멱등)
- [ ] C3. 다른 참가자·회차 행 수가 실행 전후 동일(전체 27,416행 + 12,540 = 39,956)
- [ ] C4. 리포트 재생성 후 4명 본문이 빈 리포트(343자) 아님, 신뢰도/구간 표기가 "부분 구간"을 숨기지 않음
- [ ] C5. 리포트에 종합점수·점수 환원 표현 없음(서사+변화량), 금지 표현(점수·종합점수·좋음·나쁨·완료·보증·100% 단정) 없음
- [ ] C6. 메일·알림이 발송되지 않았음(발송은 대표 별도 승인)

## D. 하위 SDD 공통 게이트 (각 SDD verify.md에 상속)
- [ ] D1. **재현 테스트 먼저(RED)**: 이번 사례를 로컬/테스트에서 재현하는 실패 테스트가 구현 전에 존재
  - 귀속 전 창 구제: stream 없이 쌓인 창 + `capture.start` ACK 유실 → 전송되지 않는 현상 재현 → 수정 후 전송 확인(Android `FeatureUploaderTest`/`ScopeSweeperTest`, 백엔드 `test_features_batch_pg`)
  - 비회원 재입장: 입장 자격 없는 재입장 → 같은 `guest_client_id`로 행 재사용, 정원 카운트 미증가
  - 403 사유 코드: 대기열/동의 거부 각각 다른 코드, 클라이언트가 재시도 폭주하지 않음
  - 로깅: 기본 설정에서 `[ingest-batch]` INFO가 출력됨
- [ ] D2. 기존 정상 경로 비회귀: 정상 6명 유형(회원·밴드 연결·renew 정상)의 저장/리포트 결과가 변경 전과 동일
- [ ] D3. `LINK BAND` 미착용 경로 비회귀(밴드 없는 입장·상담·요약·리포트 정상)
- [ ] D4. 실제 동작 확인: 빌드/타입 통과만으로 보고하지 않고 화면·API 응답·생성 CSS/데이터로 확인, dev 서브도메인에서 확인 후 보고
- [ ] D5. 배포는 대표 승인 후(dev는 develop 푸시, 운영은 main 별도 승인), 운영 쓰기·삭제는 건별 승인
