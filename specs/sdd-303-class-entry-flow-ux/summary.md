# SDD-303 — 통합 동의 구현·검증 결과

2026-11-05. Astra가 구현하고 root와 별도 검토자가 독립 검증했다. 로컬 구현과 검증 완료, 사용자 최종 리뷰·배포는 미수행이다.

## 결과

- 승인된 v3 디자인으로 전체 동의 → 필수 → 선택 항목의 계층을 통일했다. 전체 선택/해제, 일부 선택 표시, 흰색 미선택 체크박스, 개별 선택과 상세 고지를 제공한다.
- 기존 동의 API로 조회·저장한다. 유효한 서버 동의/거절을 복원하고 부분 저장 실패 시 선택을 유지해 재시도한다. 모든 저장 완료 전에는 밴드 단계로 진행하지 않는다.
- 자격 없는 첫 방문은 녹음 동의로 자격을 내부 확보한 뒤 실제 회차 고지와 기존 선택을 보여 주고 같은 화면에서 한 번 더 확인한다. 실제 정보를 모르는 상태에서 명상 고지 확인 증빙이나 기본 false를 저장하지 않는다.
- EEG 미동의는 밴드 연결 UI 없이 기존 준비 단계로 이동한다. 미연결 상태의 선택 변경·이전 이동을 검증했고, 이미 밴드 준비를 거친 경우의 EEG 변경은 잠가 기존 연결 소유권을 보존한다.
- 코드 입력 화면, 입장 확인·설문·기기 점검·준비 요약·대기·시작 및 연결 코어는 유지한다. 최초 기획의 전체 단계 축소를 구현 완료했다고 주장하지 않는다.

## 발견하고 수정한 문제

첫 입장의 기존 선택 복원 누락, 실제 회차 고지 없는 확인 증빙 저장, EEG 거절 후 이전 버튼 루프, 저장 오류 문장 잘림, 종료 상태가 동의 조회 오류에 가려지는 문제, 비초대 복구, 미선택/저장된 연구 거절 구분, 미연결 EEG 재선택, 미개방 대기 후 이전 선택 상태가 서버 true를 덮어쓰는 문제를 수정했다. RED 기록과 최종 GREEN은 `report.md`에 연결했다.

## 기준 실패와 검증 한계

- 연결 코어 회귀는 변경 전후 모두 8파일 101개 assertion 통과지만, SDD-293 테스트 callback의 기존 `releaseRef.current(...).catch` TypeError 1건으로 exit 1이다. 전체 통과로 표기하지 않는다. `final-core-regression.log`.
- 전체 suite baseline은 기존 nav-labels-characterization 5실패와 종료되지 않는 실행으로 중단했다. 전체 suite 완료·통과 주장은 하지 않는다. `baseline-suite.log`.
- 빌드는 기존 번들 크기·정적/동적 import 혼용 경고를 출력한다. 새 동의 모듈 타입·빌드 오류는 없다.
- 실제 LINK BAND, iOS/Android 권한, 웹→네이티브 인계와 운영 API/DB 저장은 실기기·통합 환경에서 검증하지 않았다. 소스 불변과 모의 테스트가 실기기 성공을 입증하지는 않는다.
- 기존 여러 endpoint를 순차 저장하므로 원자적 롤백은 제공하지 않는다. 부분 성공·이탈 후에는 서버 기록을 다시 읽으며 이미 받은 요청이 취소됐다고 표시하지 않는다.
- 커밋·푸시·PR·배포·메일·삭제는 수행하지 않았다. dev 배포 여부는 결과를 사용자에게 제시한 뒤 저장소 승인 규칙에 따라 확인한다.
