# SDD-303 — 동의 화면 v3 시안

2026-11-05 · Astra 재설계 · 제품 구현 전 검토용

## 변경 범위

- 새 시안: `303-v3-preview.html?state=first`
- v2를 복사한 뒤 `first` 동의 화면과 동의 화면에만 적용되는 스타일을 수정했다.
- 코드 입력 화면을 포함한 다른 화면의 HTML 분기·동작 및 공용 스타일은 보존했다. v2 파일은 덮어쓰지 않았다.
- 제품 코드·빌드·커밋·푸시·배포는 수행하지 않았다.

## 디자인 결정

### 한 가지 선택 방식

전체 동의와 네 개의 개별 항목을 모두 같은 크기의 체크박스로 통일했다. 뇌파와 리포트에 있던 양자택일 버튼/라디오를 제거해, 사용자는 모든 행에서 같은 방식으로 선택한다. 행 전체를 누를 수 있고 키보드 Tab·Space로도 조작할 수 있다.

### 전체 → 필수 → 선택 순서

하나의 반투명 카드 안에서 전체 동의를 가장 먼저 보여 준다. 굵은 제목과 여백으로 상위 항목임을 표현하고, 얇은 구분선 아래에 필수 1개와 선택 3개를 배치한다. 체크박스는 하나의 세로축에 맞췄다. 필수/선택 표기는 각 제목 옆 같은 위치 규칙으로 표시한다.

기존 클래스의 자연 배경, `rgba(24,12,36,.78)` 카드, 흰 글자, 24px 모서리와 `#5F0080` pill CTA를 사용한다. 별도 보라색 전체 동의 박스나 항목별 선택 버튼은 추가하지 않았다.

### 선택하지 않았을 때의 결과

뇌파 수집 아래에는 “선택하지 않으면 밴드 없이 참여해요.”, 리포트 아래에는 “선택하지 않으면 리포트에 반영하지 않아요.”를 직접 표시했다. 카드 아래에서도 선택 동의 없이 참여할 수 있음을 안내한다. 필수 동의만 선택하면 하단 “동의하고 계속하기”가 활성화된다.

## 시안 동작

- 초기 상태: 다섯 체크박스 모두 미선택, 계속 버튼 비활성화.
- 전체 동의: 필수 1개와 선택 3개를 한 번에 선택/해제한다.
- 개별 선택: 전체 동의가 선택 완료/부분 선택(`indeterminate`)/미선택으로 동기화된다.
- 진행 조건: 개인정보·녹음 필수 동의만 검사한다. 선택 동의는 진행 조건이 아니다.
- 뇌파 수집 미선택: 밴드 연결 화면을 거치지 않고 `none` 상태로 진행한다.
- 리포트 반영 미선택: 시안 선택값을 `report:false`로 저장한다.
- 저장 범위: 브라우저 `sessionStorage`의 `303-v3-consent`에만 저장한다. 실제 API·동의 원장·리포트 반영 처리는 연결하지 않았다.
- 테스트용 기존 ID `allconsent`, `required`, `eeg`, `research`, `reportyes`, `save`를 유지했다.

## 제작자 확인과 검증 범위

- JavaScript 구문 검사 통과.
- 동의 화면에 체크박스 5개, 라디오 0개 확인.
- 코드 입력 분기와 `band` 이후 모든 분기의 원문이 v2와 동일함을 비교했다.
- 독립 검증자가 390×844, 768×1024, 390×667에서 브라우저 상호작용·레이아웃을 검사했다. 세 뷰포트 모두 체크박스 5개/라디오 0개, 전체·개별 동기화, 필수만 선택 후 진행, 밴드 유무 분기, 하단 CTA 노출, 가로 넘침 없음, 스크립트 오류 없음 확인. 근거: `303-v3-check.json`.
- 코드 입력 화면은 세 뷰포트 모두 v2와 디코딩 픽셀이 동일하다. PNG 인코딩 바이트 차이는 렌더링 차이로 취급하지 않았다.
- 제작자도 390×844 미선택/전체 선택, 768×1024 및 390×667의 실제 캡처를 열어 체크박스 정렬·위계·텍스트·CTA를 확인했다.
- 위 결과는 정적 HTML 시안의 검증이며 제품 API·BLE·앱 동작이나 실제 동의 저장 완료를 뜻하지 않는다.
