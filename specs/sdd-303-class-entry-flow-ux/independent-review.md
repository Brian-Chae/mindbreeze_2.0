# SDD-303 — 독립 검토 기록

구현자는 Astra, 검토자는 별도 consent_safety_review 에이전트와 root다. root는 제품 코드를 수정하지 않고 실제 React 화면·요청·보호 파일 및 테스트를 확인한다.

## 1차 코드 검토

1. **높음 — 자격 없는 첫 동의 화면의 기존 선택 복원 누락.** 녹음만 미동의인 회원의 기존 연구·리포트 true가 false로 표시되어 덮어써질 수 있었다.
2. **높음 — 첫 동의 화면의 실제 회차별 고지 누락.** 회차 정보가 없는 상태에서 온라인 기본 안내를 사용하고 명상 열람 고지를 생략한 뒤 실제 명상 고지 확인 증빙을 전송할 수 있었다.
3. **중간 — 밴드 미사용 시 이전 버튼 제자리 복귀.** c를 무조건 next하는 우회 처리 때문에 e/d에서 이전을 눌러도 다시 같은 단계로 돌아왔다.

구현자에게 세 항목 모두 전달했다. 해결 방향은 첫 자격 확보 뒤 실제 회차 정보와 기존 동의를 같은 화면에 복원하여 재확인하고, 밴드 미사용 시 이전 유효 단계로 이동하는 것이다. 연결 코어·상태 머신은 변경하지 않는다.

## root 독립 실행 증거

- 실제 React 합성 API: 전체 동의 후 기존 설문·밴드 연결 버튼 도달, 부분 저장 오류·재시도, 필수만 동의 후 밴드 없이 준비 요약, 상세 안내 시트 확인.
- 화면 390×844, 390×667, 768×1024. 저장 오류가 하단에 잘려 보이던 문제를 발견해 구현자가 오류 focus·스크롤을 보강했다.
- 코드 입력 실제 화면 390×844, 768×1024는 변경 전후 decoded pixel 차이 0.
- 보호 파일 1,300개 해시 동일, EntryPage native hold 호출 및 BandStepContainer JSX 원문 동일.
- 연결 회귀 최종 실행: 8파일 101개 assertion 통과, 변경 전과 같은 SDD-293 fixture의 unhandled TypeError 1건으로 exit 1. 전체 통과로 보고하지 않는다.

## 최종 검토

1차 세 항목 수정 후 재검토했다. 종료/취소 우선 처리, 비초대 복구, 밴드 미진입 false→true 재선택과 연결 후 잠금도 확인했다. 기존 설문·연결·기기·대기 테스트의 보존 assertion 부당삭제는 발견하지 못했다.

최종 리뷰에서 미개방(notyet) 경유 후 `pendingConsentTouched`가 남아 요약→a 재진입의 서버 true를 false로 덮어쓰는 결함을 추가 발견했다. 구현자가 RED로 재현하고 성공 시 values와 touched를 함께 초기화했다. 별도 검토자가 해당 수정과 403→409→재입장→전체 동의→요약→a 복귀 테스트를 다시 읽고 마지막 차단사항 해소를 확인했다.

root가 최종 22개 통합 동의 테스트를 직접 재실행해 통과(exit 0)했고, 구현자 최종 회귀 8파일 105개 통과 로그를 확인했다. 최종 웹 빌드·타입 검사 exit 0, 보호 파일 검사 통과. 추가 차단 결함은 발견하지 못했다. 실기기·운영 통합 검증은 수행하지 않았다.
