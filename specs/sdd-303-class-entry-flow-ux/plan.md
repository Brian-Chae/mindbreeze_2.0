# SDD-303 — 단계 분석과 개선 계획

## 조사 기준
2026-11-05 로컬 코드 읽기. 아래 경로는 모두 `frontend/src/` 기준. 실행 환경·운영 배포와 일치 여부는 미검증이다. 법률 해석이 아니라 브리프에 주어진 동의 보존 요구를 설계 제약으로 사용한다.

**집계 단위**: 화면은 코드 화면부터 대기실까지 사용자에게 보이는 논리 화면(질문별 화면 포함), 시트는 별도 표시한다. 수업 진행 화면은 종점으로 별도 +1이며 아래 합계에는 넣지 않는다. 탭은 전진 버튼·선택지 누르기만 센다. 숫자 4자리 타이핑, 로그인, OS 팝업·기기 선택, 임의 뒤로가기·재시도는 제외한다. 제외한 권한 동작은 P로 따로 더한다. 화면 안의 연결 중/접촉 상태 변경은 새 화면이 아니다.

## 수량: 현재 → A안 목표
기준은 로그인·열린 회차가 1개인 클래스 코드·가입 확인 표시·녹음 동의가 이미 유효·EEG 동의가 유효·리포트는 included를 선택·상태 질문은 첫 화면에서 건너뛰기·권한 재시도 없음. 즉 가입 1 + 입장 확인 1 + 리포트 선택/계속 2 + 질문 스킵 1 + 밴드 연결/설명/다음 3 + 온라인 다음 1 + 요약 1. 밴드 없음은 밴드 화면에서 스킵 1로 계산한다.

| 조건 | 현재 화면 / 시트 / 탭 | A안 목표 화면 / 시트 / 탭 |
|---|---|---|
| 오프라인·밴드 새 연결 | 8 / 1 / 9+P | 4 / 0 / 3+P (새 리포트 선택 1+저장 1, 연결 1) |
| 온라인·밴드 새 연결 | 9 / 1 / 10+P | 4 / 0 / 3+P (마이크/영상 선택은 대기실 내 별도) |
| 오프라인·밴드 미사용 선택 | 8 / 0 / 7 | 4 / 0 / 3 (리포트 선택 1+저장 1, 밴드 없이 1) |
| 온라인·밴드 미사용 선택 | 9 / 0 / 8 | 4 / 0 / 3 |
| 오프라인·회차가 bandMode=none | 7 / 0 / 6 | 3 / 0 / 2 |
| 온라인·회차가 bandMode=none | 8 / 0 / 7 | 3 / 0 / 2 |
| 이미 같은 회차 모든 선택 유효·밴드 새 연결 | 현재 위 행과 같음(화면 재마운트 기준) | 3 / 0 / 1+P |
| 같은 회차 재입장·유효 동의·연결/hold 유지 또는 미사용 기록 | 현재 마법사 재방문, 연결상태에 따라 밴드 1탭으로 감소 | 2 / 0 / 0 (코드 → 대기실) |

A안의 자동 가입은 **이미 가입한 회원만** 기본 가정. 신규 가입이면 의사 확인 화면/탭 +1, 열린 회차가 여러 개면 회차 선택 화면/탭 +1. 코드 대신 목록/링크로 들어오면 코드 화면 −1; 목록 선택 행동은 +1탭, 링크 전달/푸시 OS 동작은 별도이다. 현재 클래스 코드에서 초대 녹음 gate가 추가되면 +1화면/+2탭(체크·제출), EEG 미동의→동의면 +1화면/+1탭, 리포트 제외→연결이면 +1시트/+1탭. 회차 코드는 가입 화면 대신 정보 화면(+동의 체크 1탭)이며 실제 프로필 검증 결과에 따라 추가 입력 가능. 질문을 모두 응답하면 현재 +3화면/+3탭. A안 첫 동의는 같은 한 화면에서 미결 항목 K개 선택에 K탭 + 저장 1탭이며 미리 체크하지 않는다. 따라서 ‘첫 사용도 무조건 3탭’은 아님.

앱/웹의 제품 흐름 수는 같으나 OS 권한 수 P는 다르며 실측 전이다. 이미 연결된 밴드는 현재 connect/설명 2탭 없이 다음 1탭만 남는다. EEG 거절이면 현재 c 안에서 스킵되므로 연결 화면/권한 시트가 없다. 준비 중 시작/정원 대기/미개방은 위 정상 경로 숫자에 섞지 않는다.

## A/B 비교와 자동 진행 계약
| 항목 | A 분리된 짧은 흐름 | B 통합 준비 화면 |
|---|---|---|
| 주 행동 | 선택 저장 → 밴드 연결 | 입장하기가 저장·권한·연결까지 수행 |
| 장점 | 실패 원인이 분명하고 현장 설명이 짧음 | 페이지 이동 감소 |
| 비용 | 유효 동의 조회와 대기실 통합 필요 | UI 복잡·비동기 저장 뒤 OS 제스처 연결 위험 |
| 판단 | 행사 후 목표로 제안 | 이번 기획에서는 보류 |

자동 진행 조건: 계정 로그인/입장 자격·정원·회차 서버 상태 확인 → 해당 범위의 유효 동의 조회 → 미결 선택만 표시 → 연결됨과 접촉 확인 후 c 이탈 및 hold 인계 → 대기. 이미 거절한 EEG는 밴드 없음으로 진행하고 대기실 ‘설정 바꾸기’에서만 다시 선택. 이전 연결은 기기 ID와 소유권 확인 없이 재사용하지 않는다. 접촉 미확인은 계속 점검/밴드 없이 입장 제공, 자동 정상 처리 금지. 서버 동의 조회 실패는 재시도와 밴드 없이 참여 경로를 제공하되 필수 녹음 동의가 미확정이면 수집·입장을 진행하지 않는다.

취소: 코드 화면으로 돌아가기, 밴드 검색 취소, 대기실 나가기를 제공. 비동기 요청의 늦은 응답으로 되돌아간 화면을 다시 넘기지 않도록 요청 세대/Abort 처리. 중복 저장·가입은 멱등 처리. 로컬 기록만으로 동의를 인정하지 않는다.

## 40명 행사 및 적용 시기
현장 안내: ‘로그인한 뒤 코드 네 자리를 넣어 주세요. 필요한 선택을 확인하고, 밴드가 있으면 연결하고 없으면 밴드 없이 입장을 눌러 주세요. 대기실에서는 코치가 시작할 때까지 기다리시면 됩니다.’ 이는 A안 안내이며 현행 행사에 그대로 사용하지 않는다. 현행에서는 권한 안내 확인과 마지막 ‘입장 대기’가 추가로 필요하다.

행사 전 저위험 후보: EEG 선택 버튼을 ‘선택 저장하고 계속’으로 바꾸어 연결 의미 중복을 해소; PermissionGuide 설명을 밴드 화면에 인라인 배치하여 설명 시트의 확인 1탭만 제거(공용 컴포넌트 전체 삭제 아님); 과도한 ‘2분’ 단정을 없애고 버튼 문구를 실제 도착점에 맞춘다. 이 후보만으로 **9→8, 10→9탭**, 화면 수는 그대로이며 P는 유지된다. 제품 구현·배포는 이번 범위 밖이다.

행사 후: 입장 확인/준비 요약 제거, 질문·기기 점검의 대기실 이동, 서버 선택 복원, 신규/기존 가입 분리, 밴드 자동 진행, 리포트 재질문 제거. 상태 머신·readiness·설문 수집 시점·hold와 맞물려 저위험 변경으로 취급하지 않는다. 11/11 로그인 정책 연결은 별도 선행 과제이며 미반영 시 운영 준비를 주장하지 않는다.

실제 구현 전 verify.md에 위 케이스와 네이티브 adoptBand→startMeasurement 인계, 나가기 release, 권한 팝업 실측 P, 40명 네트워크 재접속을 명시한다. 이번은 기획이므로 구현 전 검증 문서를 사후 증빙처럼 만들지 않는다.

온라인 권한 요청은 대기실의 ‘마이크·영상 사용’ 한 행동에서 필요한 권한만 요청하고 이미 허용된 권한은 재요청하지 않는 목표로 설계한다. OS가 분리해서 표시하는 창은 합칠 수 없으므로 앱 설명 중복만 제거한다. 기본 꺼짐·거절 후 수업 참여·나중에 켜기 경로를 유지하며 P는 플랫폼별 실측한다.

## 구현 승인 이후 적용 기준
사용자 승인으로 동의 화면 통합 및 동의 orchestration 변경까지 구현한다. 현재 상세 태스크는 `implementation-plan.md`, 구현 전 시험 기준은 `verify.md`를 따른다. 위 문서의 전체 단계 축소는 기획 목표이며 이번 통합 동의 구현의 성과 수치로 사용하지 않는다. 연결 코어·코드 입력 화면 불변을 최우선으로 유지한다.
