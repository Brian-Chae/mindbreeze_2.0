# SDD-323 — Stage ③ Verify: 구현 전 QA 체크리스트

- 구현 전 게이트. 기준: `spec.md` §9 + `plan.md` §1~2. 구현자와 검증자는 분리한다.
- 판정 표기: 기대 결과가 어긋나면 FAIL. 모든 API 시나리오는 **직접 HTTP 호출**로 검증(화면 숨김으로 대체 금지)하고, 거절 시 **DB 불변**을 함께 확인한다.
- 테스트 계정: 대표 `P`, 일반 관리자 `A`, 코치 `C`, 타 기관 관리자 `X`, 플랫폼 관리자 `S`. 메일은 발송 대역(mock)만 사용 — 실제 발송 금지.

## V-LIST. 목록 응답 보강 (A1)

- `is_primary_admin`, `membership_status`, `account_status`, `is_self`, `class_count`, `last_activity_at`, `allowed_actions`, `blocked_reasons` 존재.
- `allowed_actions` ↔ 서버 실제 판정 교차검증: 모든 (요청자 역할 × 대상 유형) 조합에서, `allowed_actions` 에 있는 행동은 성공/보호 409 외 403 이 없고, 없는 행동은 403 또는 409.
- 정지/재활성은 어떤 요청자에도 `allowed_actions` 에 없음.
- `class_count`/`last_activity_at`: 해당 기관 값만(다기관 코치로 기관 간 값이 다름을 확인). 활동 없음 → null.
- 쿼리 수: 구성원 50명 목록 호출 시 SQL 쿼리 수가 인원 수와 무관(N+1 없음, 측정치를 summary 에 기록).
- 활성 코치·관리자·초대 대기를 합산한 숫자가 응답 어디에도 없음.
