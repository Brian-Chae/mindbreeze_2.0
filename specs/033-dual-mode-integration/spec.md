# SDD-033 — 듀얼 모드 통합 (웹 + 네이티브 앱) — 후순위

> **나중에 진행.** 네이티브 앱(SDD-032) 착수 시점에 진행한다.
> 지금은 SDD-031의 웹 호출 테스트로 서버측 신호처리를 검증한다.

> 웹(프론트 처리)과 앱(FeatureWorker 서버 처리)을 단일 1초 feature 계약으로 통합.

## 1. 배경·목표

SDD-030(웹 지표), SDD-031(FeatureWorker), SDD-032(네이티브 앱)로 각 모드가 완성된 뒤,
두 모드를 통합해 **신호처리 위치만 다르고 사용자·상담사 UX는 동일**하게 만든다.

## 2. 통합 원칙

```
웹 모드:  브라우저 BLE → 프론트 신호처리 → 1초 feature
앱 모드:  앱 BLE → raw → FeatureWorker → 1초 feature
                └────────────┬────────────┘
                   동일한 1초 feature 계약
                             ↓
          백엔드 FastAPI (ingestion·집계·리포트·WS broadcast)
                             ↓
          사용자 + 상담사 화면 (모드 무관 동일)
```

## 3. 통합 범위
1. **단일 feature 계약**: 웹/앱 모두 동일한 1초 feature 포맷(EEGFeatureWindow)으로 백엔드에 전달
2. **모드 선택**: 웹은 자동(브라우저 BLE 감지), 앱은 기본 logic_server
3. **백엔드**: ingestion·집계·리포트는 모드 무관 동일 (이미 SDD-022~028에서 구축)
4. **WS/실시간**: 앱 사용자 데이터도 웹과 동일하게 WS로 상담사에게 전달

## 4. 검증 기준
- 웹과 앱에서 동일 raw 입력 → 동일 지표 산출 (교차 검증)
- 상담사 화면에서 웹/앱 사용자 구분 없이 동일하게 표시
- iOS에서 앱 → FeatureWorker → 백엔드 → 상담사 화면 E2E 동작

## 5. 의존
- 선행: SDD-030 + SDD-031 + SDD-032
