### 1-2. 서사 부재 진단

| # | 문제 | 근거 |
|---|---|---|
| B1 | **"무엇을 하면 되나"가 없다.** 사유 라벨(`raw_failed` → "서버가 받지 않음")은 상태 설명이지 행동이 아님. 코치 화면에는 CTA 가 0개 | `REASON_LABEL`, 표 내부에 버튼 없음 |
| B2 | **숫자가 서사 앞**. "수신 확인 30 · 업로드 중 1 · 확인 필요 2 · 미수신 5" 는 사용자가 직접 해석해야 하는 나열 | `Counts` |
| B3 | **총량 대비 정보 미사용**. 현행 화면은 "수신 N창"만 있고 분모가 없다(SDD-261 §3 의 `expected=null`). SDD-264 로 분모가 생기면 "얼마나 왔나"를 한 문장으로 말할 수 있다 | contract §2 `expected` |
| B4 | **회차 간 우선순위 없음**. 확인 필요 회차 1개와 정상 29개가 같은 비중. 상단 카드가 "확인 필요 회차 N개"만 말하고 어느 회차인지 말하지 않음 | `totals.attentionSessions` |
| B5 | 코치·기관관리자·회원이 같은 상태명(확인 필요/업로드 중…)을 쓰지만 **할 수 있는 행동이 다름**(§2 참조) | 역할별 CTA 부재 |

### 1-3. 유지할 것 (자산)

- 서버 수신 기준 어휘·`basis` 표기, 상태 5종(`needs_attention/uploading/received_unreconciled/no_data/excluded`)과 reasons, ETag 폴링 훅(`useUploadOverview`, `useUploadStatus`), 보라 토큰(`#5B1A8A`, `#F3E9F8`, `#FAF7FC`)·`rounded-2xl` 카드·테이블 구조.
- 본 재설계는 **데이터 소스를 바꾸지 않고 표현 계층을 바꾼다**. 서버 상태 이름은 그대로 두고, FE 에서 "서사 모델"(§2)로 한 번 더 번역한다.

- 위험: 서사 문구가 원인을 단정하는 방향으로 드리프트(§2-5 점검표 + 단위 테스트로 고정). 표 선호 사용자 불만.

### 안 B — "문제 먼저 + 표 유지" (표 기본 + 서사 한 줄 + 접기) ⭐ 추천

**핵심 아이디어**: 표·검색·필터·그룹핑 원칙은 유지하되 **행당 정보를 3열로 줄이고**, 모든 행 위에 서사 한 줄을 둔다. 문제 행만 펼쳐 이름·사유·조치를 노출하고 정상은 접는다. 안 A 보다 변경이 작고 안 C 보다 명확하다.

```

┌ 한 줄 요약 ───────────────────────────────────────────────┐

[검색 ________]  [상태 ▾] [기간 ▾] [그룹 ▾]    ← 클래스 필터는 "필터 ▾" 안

**회차 상세 와이어**
```

| 장점 | 단점 |
|---|---|
| 대표 원칙(표+검색·필터·그룹핑) 유지 + 길이 대폭 감소 | 안 A 대비 서사의 극적 효과는 작음 |
| 기존 컴포넌트(`UploadStatusTable`, `UploadOverviewScreen`, `Detail`) 대부분 재사용 | "그 외 접힘" 때문에 정상 회차 확인에 클릭 1회 추가 |

- 난이도: **낮음~중**. API: 10건 페이지네이션 필요(§4-2). 상세 API 불변(264 필드 추가분만).
- 위험: 접힘 기본값에서 코치가 정상 회차를 놓칠 수 있음 → 접힘 헤더에 "8개 · 모두 수신 확인" 요약 문구로 완화.

### 안 C — "스토리 타임라인 + 시트" (시간순 서사, 상세는 하단 시트)

**핵심 아이디어**: 목록을 표가 아니라 **시간순 타임라인**(회차 = 하루의 한 사건)으로 보이고, 회차 상세는 별도 페이지 대신 **하단 시트/오른쪽 패널**에서 연다. 가장 모바일 친화.

**코치 목록 와이어 (390px)**
```
데이터 현황                    ● 3초 전  [Ⅱ]
오늘
 ● 14:00 아침 호흡 3회차
   │ 40명 중 37명 수신, 3명 확인 필요
   │ [확인하기]
 ○ 10:00 점심 명상 1회차
   │ 40명 모두 수신
어제
 ○ 16:00 …  "38/40명 수신 · 2명 수신 기록 없음"
 …(10개)
        [ 이전 회차 더 보기 ]
```
- 데스크톱: 좌측 타임라인(10개) + 우측 선택 회차 상세 패널(2분할). 표는 상세 패널 안에만.
- [확인하기] → **하단 시트**(모바일)/우측 패널(데스크톱): 이야기 헤더 + 확인 필요 참여자 목록 + CTA, "전체 40명 보기" 로 기존 표 풀 뷰로 이동.

**회원 화면**: 같은 타임라인 문법. 내 회차 10개가 날짜별 점으로, 점 색/아이콘이 상태. 탭하면 시트에 내 이야기 + 조치.

**10건 페이지네이션**: 날짜 그룹 단위 무한 스크롤 대신 "이전 회차 더 보기" 버튼(10개 단위). 안 A·B 와 같은 API.
**서사 노출**: 타임라인 각 점이 한 문장 이야기. 시간 흐름 자체가 서사(어제 vs 오늘).

| 장점 | 단점 |
|---|---|
| 모바일에서 가장 짧고 직관적, "무슨 일이 있었나" 시간순 | 표·정렬·그룹핑 원칙 후퇴(검색·필터는 시트 밖 상단 바 1줄로 최소화) |
| 시트로 상세 이동 비용 없음 | 신규 UI 패턴(타임라인·시트·2분할) → 구현·QA·접근성 비용 최대 |
| 회원/코치 일관 | 같은 날 다회차·다클래스 코치에게는 클래스 구분이 약함 |

- 난이도: **높음**. API: 10건 페이지네이션 필요(+ 날짜 그룹용 `started_at` 은 기존 필드).
- 위험: 시트 + 폴링 상태 동기화, 앱 WebView 뒤로가기 처리, 상세 라우트 딥링크(`/classes/:id/sessions/:sid/upload-status`)와의 공존.

### 4-2. 10건 페이지네이션 API 필요 여부

| 항목 | 판단 |
|---|---|
| 현행 `GET /upload-status/overview` | `limit`(최대 50)·`since`·`status` 있음. **`offset/cursor` 없음**, `truncated` 만 제공 |
| 클라이언트에서 `slice(0,10)` | 가능하나 서버는 50개 요약 계산(응답·SQL 비용 동일) → 권장 안 함 |
| 필요 변경 | `limit=10` + **`cursor`**(정렬 키: `in_progress` 우선 → 유효시각 desc → id; 마지막 항목의 키를 base64 로) 또는 단순 `offset`. 응답 `next_cursor`(없으면 null), `total_candidates` 유지 |
| 재현성 | 폴링으로 목록이 바뀔 때 offset 은 행이 밀림 → **cursor 권장**. "더 보기"로 누적한 목록은 재폴링 시 이미 로드한 페이지 수만큼 합쳐 갱신(첫 페이지만 폴링, 나머지는 새로고침 시) |
| ETag/304 | 페이지(cursor)별 ETag. 첫 페이지만 3초 폴링, 이후 페이지는 정적(60초 또는 수동) |
| 회원 목록 | 현행은 클래스 N개 × 회차 목록을 FE 가 합침. `pickCandidateSessions` 후 FE `slice(0,10)` + "더 보기" 로 충분(회원 개별 회차 수는 적음). 서버 변경 불필요 |
| 마이그레이션 | 없음 |

### 4-3. 공통 컴포넌트 · 데이터 요구 (3안 공통)

| 항목 | 내용 |
|---|---|
| `narrative.ts` (신규, `lib/upload-status/`) | 입력: 회차 요약 or 참여자 DTO + 시점 + 역할 + (264) 총량 → 출력: `{headline, evidence[], cta[], tone}`. 템플릿 고정(P8), 금지어 검사 단위 테스트(§2-5) |
| `StoryLine` | headline + 근거 한 줄 컴포넌트. 회차 행/참여자 행/회원 카드가 공유 |
| `CtaRow` | 역할별 CTA: [앱 재접속 안내 복사] [새로고침] [담당 코치 확인] 등. 서버 호출 없음 |
| `Collapse` | "그 외 N개 · 모두 수신 확인" 접힘 헤더(요약 문구 필수) |
| `LoadMore` | 10개 단위 "더 보기" + `10/32개` 표기 |
| 필터 접힘 | 검색만 상시, 나머지는 "필터 ▾" |
| 264 매핑(가정) | 회차: 참여자 `M/N`; 참여자: feature `Y/X`, raw `Q/P` + "분모 확인 여부" 플래그. 분모 미확인이면 `X/P/N` 자리에 "예상 수 미확인"(0/0 금지) |
| BE | overview 에 `cursor`/`next_cursor` 추가. 선택: 회차 항목에 "문제 참여자 상위 3명(이름 마스킹 규칙은 기존 상세와 동일)·사유" 요약(없으면 카드 클릭 시 상세 로드로 후퇴) |
| 접근성 | 서사 헤드라인은 `role="status"`, 접힘은 `aria-expanded`, 색 외 아이콘+텍스트 병행(현행 규칙 유지) |
| 테스트 | narrative 매핑표(§2-3 S1~S16) 단위 테스트, 금지어 정규식, 10건→더 보기 시나리오, 390px 가로 넘침 없음, 폴링 시 문장 구조 불변 |
