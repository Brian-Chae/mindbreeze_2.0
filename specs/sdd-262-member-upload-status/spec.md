# SDD-262 — 회원 "내 데이터 저장 현황" 설정 정식 메뉴

- 상태: Stage ① Spec (구현 전 확정)
- 브랜치: `sdd/262-member-upload-status` / 작성일: 2026-11-01
- 범위: FE 중심. **서버 변경 없음**(아래 근거)

## 1. 왜
현장 회원이 "내 데이터가 서버에 잘 올라갔나"를 스스로 확인한다. 코치·관리자용 SDD-261 화면은 회원이 열 수 없고, 회원은 본인 것만 봐야 한다.

## 2. 결정
| 항목 | 결정 | 근거 |
|---|---|---|
| 메뉴 위치 | 회원 설정(`SettingsContent`)에 정식 `Group`(제목 "내 데이터 저장 현황", 아이콘 DatabaseZap/CloudUpload) 추가. client 전용 → 그룹 7→8 | 기존 그룹 카드 패턴 |
| 코치·기관관리자 | **미노출**. 이미 SDD-261 `데이터 저장·업로드 현황`(전 참여자 표)이 있고, 본인 데이터 용도는 코치에게 의미가 없음(코치는 참여자가 아님) | 가장 단순 |
| 라우트 | `/app/profile/upload-status` (RoleGuard client, ClientShell → 하단 탭 유지). App.tsx 에서 `/app/*` 앞에 등록(상담사 미연결 회원도 접근) | `/app/classes` 선례 |
| 회차 목록 | 기존 `GET /classes`(본인 멤버십 클래스) + `GET /classes/{id}/sessions`(본인 출석 `attendance` 포함)로 구성. `attendance != null` 이고 상태가 진행중·완료인 회차만, 최근순 | 신규 API 불필요 |
| 데이터 소스 | `GET /sessions/{sid}/features/summary` + `GET /sessions/{sid}/biosignal-raw/summary` (JWT 본인, `_summary_target`). 타인 participant_id 는 보내지 않음 → 서버가 본인 행만 확정, 비참가자 403 | SDD-260 contract §2·§3 |
| 폴링 | 진행중 회차만 5초 폴링(summary 엔드포인트는 ETag 없음 → 훅 재사용 불가, 얇은 전용 훅). 숨김탭·오프라인 중지, 복귀 시 즉시 1회. 완료 회차는 1회 조회 + 새로고침 버튼 | |

## 3. 화면
- 회차 선택(클래스명 · N회차 · 일시), 선택 시 카드: 상태 배지(텍스트+아이콘+색), feature 수신 창 수, 원시 EEG/PPG/ACC 청크(업로드/대기/실패), 마지막 수신 시각, 안내 문구.
- 상태(서버 수신 기준): `확인 필요`(실패>0) / `업로드 중`(대기>0) / `수신 확인`(수신>0·대기·실패 0, "전체 대조 미확인") / `수신 기록 없음`(둘 다 0 — 밴드 미착용이면 정상. 미착용≠미수신, summary 로는 둘을 구분 못 하므로 단정하지 않음).
- 기대 수를 모르므로 "수신 N창"으로만 표기. 완료·보증·100%·점수·좋음/나쁨·종합점수 문구 금지. 마이크 OFF 등 opt-out 은 누락이 아니라는 안내를 넣는다.
- 오류: 403/404 → 이전 수치 제거 + 안내, 오프라인 카드, 5xx → 재시도 안내.
- 모바일 390px 우선(1열 카드), 데스크톱 `max-w-2xl` 반응형.

## 4. 비범위
상담(counseling) 회차, 코치용 표, 서버 API 변경, 푸시·배포.
