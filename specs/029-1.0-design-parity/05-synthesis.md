# 05 — 1.0 디자인 패리티 종합 기획

> Orca orchestration(codex×2 + cursor×1) + Supervisor 직접 보강. 01/02/03/04 문서 종합.

## 실행 요약

1.0(mind-breeze-app)의 클래스 대기·진행·호스트 화면 디자인을 2.0 웹에 "동일한 화면"으로 반응형 포팅하는 기획 완료. **색상은 이미 정합**(2.0 `mb-tokens.css`에 1.0 보라색 팔레트 존재), 남은 것은 **타이포·컴포넌트·asset·반응형**이다.

## 핵심 디자인 갭 (1.0 정본 vs 2.0 현재)

| 영역 | 1.0 정본 | 2.0 현재 | 조치 |
|------|----------|----------|------|
| 명상 배경 | **검정 풀블리드 + 자연 이미지 페이드**(background1~10, 20s/1s 교차) | 보라 그라데이션 카드(#2D1045→#5F0080) | 검정 + FadingImageBackground 이식 (webp 최적화 완료) |
| 두뇌휴식도 | **130px 초대형** 흰색 | 60~72px | `clamp(64px,10vw,130px)` |
| "AI 분석중" | BlinkingText 70px 깜빡임 | 없음 | CSS keyframes 재현 |
| 뇌파 차트 | 회색 둥근 막대 바차트 | cyan sparkline | SVG 바차트 재현 |
| LeadOff | 풀스크린 모달 + SensorTracker | 인라인 문구 | 모달 승격 |
| 호스트 화면 | 흰 배경 + 평평한 회색 테이블 + 보라 버튼 | 둥근 카드형 | 평평한 표 + DashboardBox 수평 카드 |
| 완료 화면 | 연보라(#F5EDFC) + 리포트 샘플 마퀴 + 전화 신청 | 흰 카드 + 홈 링크 | #F5EDFC + 마퀴 |

## 핵심 설계 결정

1. **색상**: mb-tokens.css 재사용 (추가 정의 금지). 명상/대기 = 검정(#000) + 흰 텍스트, 호스트 = 흰 배경 + 회색(#F2F3F8), 완료 = 연보라(#F5EDFC).
2. **타이포**: 1.0 고정 px → 웹 `clamp()`. 초대형 130px/70px는 반응형으로 모바일에서 과대하지 않게.
3. **자연 이미지**: background1~10.jpg → webp 최적화 완료(89% 절감, 총 1.6MB), `frontend/public/images/`에 배치. 20초 간격 + 1초 CSS transition 교차 페이드.
4. **상태 머신 유지**: 디자인 패리티는 표현층만. 폴링/WS/BLE 로직(SDD-021~026)은 변경 없음.

## 결정 필요 (Brian)

1. **게스트 리포트 전화 신청** — 1.0 Complete의 핵심 CTA인데 2.0 백엔드에 SMS/report-request API 없음. (A) API 선행 (B) UI+대기 카피 (C) 로그인 사용자만 리포트함, 게스트는 감사만.
2. **배터리 임계** — 1.0 카드 `<25` vs 셀 `<=25` vs 2.0 `<20`. 통일값 결정.
3. **종료 버튼 색** — 1.0은 시작=진보라(#5F0080), 종료=연보라(#D2AEFC). "둘 다 primary" 원하면 별도 결정.
4. **초대형 130px** — 모바일에서도 고정인지, clamp 하한(64px)인지.

## 한 줄 결론

1.0 명상 화면의 완성도는 **검정 화면 위 자연 이미지가 20초마다 조용히 교차 페이드되고, 그 위에 130px 두뇌휴식도가 떠 있는 것**에서 나왔다. 2.0은 이미 색상 토큰이 정합돼 있으므로, 자연 이미지(webp 최적화 완료)·초대형 타이포·깜빡임·평평한 호스트 테이블만 재현하면 1.0과 동일한 화면이 반응형으로 완성된다.
