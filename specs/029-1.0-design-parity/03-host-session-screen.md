작성일: 2026-09-08. 범위: 호스트 세션과 클래스 목록의 화면 기획만. 구현·API 변경·실행 테스트는 수행하지 않았다. 아래 **원본 사실**은 현재 로컬 소스, **포팅안**은 제안이며 승인된 구현 명세를 의미하지 않는다.

근거 경로의 `1.0/src/`는 `/Volumes/Looxid SSD/looxid/repository/mind-breeze-app/src/`, `2.0/frontend/`는 `/Volumes/Looxid SSD/looxid/repository/mindbreeze_2.0/frontend/`를 뜻한다. 줄 번호는 작성일 기준이다.

## 세션코드 배너 + 진행시간

**원본 사실**

- 제목은 `세션코드: ${code}`이고 오른쪽에 클래스 정보·시작/종료 버튼이 있다. 시작 전에는 뒤로가기가 보인다. 본문은 상단 24px 여백 → 안내 배너 → 12px → DashboardBox → 12px → 테이블 순서다. 근거: `1.0/src/screens/SessionScreen/index.tsx:153–245`.
- 대기 문구는 “아직 수업이 시작되지 않았어요. 수강생에게 세션코드(XXX)를 알려주세요.”, 진행 문구는 “수업을 시작했어요. 진행시간: ”다. 문구와 Timer는 `#5E4FFF`, 16px/24px, weight 600이며 우측에 “화면 새로고침”이 있다. 근거: `SessionScreen/index.tsx:199–213`, `1.0/src/components/Texts.tsx:21–29`.
- 화면 기본 배경은 흰색이다. 배너는 `RadiusContainer` 기본인 `#F2F3F8`, padding 16px, radius 12px이며 그림자·테두리를 지정하지 않는다. 근거: `1.0/src/components/ScreenWrapper.tsx:36–38,79`, `1.0/src/components/Containers.tsx:119–134`.
- Timer는 시작시각과 현재시각의 차이를 1초마다 계산하고 음수를 0으로 보정한다. `00분 00초` 형식이며 60분 이상도 분 누적으로 표시한다. 근거: `1.0/src/screens/GuestMeditationScreen/Timer.tsx:14–44`.

**2.0 차이와 포팅안**

현행은 제목·예정 소요시간·상태 카드 다음에 시작 전 전용 배너를 보여주며, 배너는 연보라 배경·큰 코드·코드 복사로 구성된다. 진행 중에는 배너가 사라지고 호스트 BLE 카드가 요약보다 먼저 나온다. 근거: `2.0/frontend/src/pages/sessions/SessionLivePage.tsx:457–543`, `2.0/frontend/src/components/session/SessionCodeBanner.tsx:24–40`.

1. 호스트 본문을 흰색으로 하고 원본 순서를 복원한다. 상단 제목 `세션코드: XXX`를 시작 후에도 유지하고, 안내 배너를 대기·진행 모두 표시한다. 2.0의 제목·소요시간·참여 정원 등은 클래스 정보 안에 배치한다. 내부 `run` 식별자는 기본 운영 화면에 노출하지 않는다.
2. 진행시간은 서버 `SessionDto.started_at`을 기준으로 한다. 현재 녹음용 `recordingStartedAt`과 `startedAtMs`는 별개다. 녹음 시작 여부에 따라 수업 시간이 초기화되면 안 된다. 근거: `2.0/frontend/src/lib/api/session.ts:26–49`, `SessionLivePage.tsx:307–353`.
3. `ready/scheduled`는 원본 대기 문구, `in_progress`는 원본 진행 문구, `paused`는 “수업이 일시정지되었어요. 경과시간: ”로 제안한다. 일시정지 동안에도 경과시간은 계속 계산한다. 이는 순수 수업시간이 아닌 시작 후 경과시간이며, 일시정지 차감 기능은 별도 계약이 필요하다. 완료는 `ended_at - started_at`을 고정 표시하고 취소는 “취소된 클래스입니다”로 표시한다. 시작시각 누락은 `진행시간 확인 중`으로 표시하며 임의 현재시각을 시작점으로 삼지 않는다.
4. 코드가 없으면 `세션코드 확인 중`과 재조회 동작을 제공한다. 코드 대신 세션 ID를 노출하거나 복사를 활성화하지 않는다. 코드 복사는 제목 옆 보조 동작으로 유지하고 결과를 짧게 알린다. 원본의 새로고침은 세션과 모니터링 데이터를 재조회하며 진행 중 중복 클릭을 막는다.
5. 데스크톱은 코드 제목·도구를 한 줄, 안내문·Timer·새로고침을 한 줄로 둔다. 좁은 화면에서는 제목 → 버튼 묶음 → 안내문과 Timer → 새로고침 순으로 줄바꿈한다. 원본의 본문 `maxWidth: 65%`는 모바일에 적용하지 않는다.

**반응형 공통 제안**: 페이지 폭 1024px 이상은 데스크톱, 640–1023px은 태블릿, 640px 미만은 모바일로 구분한다. 본문 가용폭 부족 시 페이지 폭과 관계없이 좁은 배치를 적용한다. 데스크톱 본문 padding 20px, 모바일 16px, 최대폭은 현행 1280px을 기준으로 시각 검증한다. 간격·크기 제안은 React Native 원본의 실제 기기 스크린샷 측정값이 아니다.

## DashboardBox 4종

**원본 사실**

`DashboardBox`는 큰 KPI 숫자를 아래에 두는 카드가 아니다. 같은 줄의 왼쪽 제목과 오른쪽 `N명`이 모두 16px/24px, weight 600인 낮은 직사각형이다. 기본 배경 `#F2F3F8`, radius 12px, padding 16px이고 4개 사이 간격은 12px이다. 경고 카드의 count가 1 이상이면 배경 전체 `#F2212133`, 제목·숫자 모두 `#F22121B2`로 변한다. 참여자 카드는 인원이 많아도 경고색으로 바뀌지 않는다. 근거: `1.0/src/screens/SessionScreen/DashboardBox.tsx:13–31`, `SessionScreen/index.tsx:217–242`.

순서와 집계:

1. **참여자**: 원본 `sessionLogs.length`; 2.0에서는 대기명단을 제외한 실제 입장자의 동일한 표시 집합을 카드·테이블·시작 가능 여부에 함께 사용한다. 필터를 걸어도 총수는 변하지 않는다.
2. **접촉불량**: 원본 `SENSOR_FAILURE`; 2.0의 `device_status === 'lead_off'`에 대응한다. SQI 저하는 접촉불량으로 집계하지 않는다.
3. **기기연결 실패**: 원본 `CONNECTION_FAILURE`; 2.0에서는 밴드 사용자의 명시적 연결 실패·전송 중단을 집계한다. 밴드 미사용은 제외한다. 명시적 미사용 정보가 없는 상태를 곧바로 장애로 단정하지 않는다.
4. **밴드 배터리 부족**: 원본 화면 철자는 “밴드 베터리 부족”이고 집계는 `<25%`다. 문서의 제안 표기는 오타를 교정한 “밴드 배터리 부족”이다. 현행 2.0은 `<20%`여서 임계값 결정이 필요하다. 근거: `SessionScreen/index.tsx:237–240`, `2.0/frontend/src/pages/sessions/SessionLivePage.tsx:92–103`.

**포팅안**

- 현행 `SessionMonitorSummary`의 흰 배경·16px radius·위 라벨/아래 24px 숫자를 원본의 수평 16px 텍스트 카드로 바꾼다. 경고 0명은 중립색, 경고 1명 이상은 카드 전체 빨강을 적용한다. 근거: `2.0/frontend/src/components/session/SessionMonitorSummary.tsx:16–47`.
- 데스크톱은 4열, 태블릿과 일반 모바일은 2열, 360px 미만 또는 확대 시 제목과 숫자가 겹치면 1열로 전환한다. 카드 내 제목은 줄바꿈 가능, `N명`은 줄바꿈 금지다. 높이는 텍스트에 맞춰 늘린다.
- 기존 클릭 필터는 유지한다. 선택은 보라색 외곽선과 `aria-pressed`로 표현하며 경고 배경을 덮지 않는다. 같은 카드를 다시 누르면 해제한다. 시작 전에도 4종을 보여주어 원본처럼 입장 준비 상태를 확인한다.
- 로딩 중에는 수치를 `—`, 확정된 빈 목록은 `0명`으로 구분한다. 오류를 0명으로 위장하지 않고 재시도 안내를 별도로 보여준다.

## 모니터링 테이블 (컬럼·행강조·반응형)

**원본 컬럼과 2.0 매핑**

기본 컬럼은 아래 8개를 이 순서대로 유지한다. 원본 정의는 `1.0/src/screens/SessionScreen/index.tsx:61–129`, 셀 기본 정렬·여백은 `1.0/src/components/Table.tsx:42–67,114–127`에 있다.

1. **자리번호** — 원본 `seatNumber`. 중앙 정렬, flex 1. 현행 `SessionLiveMetric`과 `SessionParticipant`에 대응 필드가 없다. 서버 계약 확정 전 `—`로 표시하고 배열 인덱스를 실제 자리번호처럼 표시하지 않는다.
2. **이름** — 원본 `user.realname`, 2.0 `display_name`. 왼쪽 정렬, flex 2. 이름 누락 시 현행 게스트/참가자 대체문구를 유지하고 이메일을 기본 표시명으로 쓰는 fallback은 검토한다.
3. **접촉상태** — flex 1. 원본 정상 “접촉됨”, 실패 “접촉안됨”, 기타 `-`. 2.0 `ok/lead_off`를 이 문구에 대응시키고 `unknown`은 “미확인”, `unsupported`는 “미지원”으로 명시한다. 연결 실패를 접촉불량이라고 표시하지 않는다.
4. **기기연결** — flex 1. 원본 “연결됨/연결끊김/-”. 2.0의 `band_connected`, `device_status`, `last_eeg_at`을 조합한다. 연결은 유지되나 EEG가 중단된 경우 “전송중단”, 명시적 밴드 미사용은 “미사용”으로 구분한다.
5. **배터리** — flex 1. 값 뒤 `%`, null은 `-`. 원본은 `<=25%`일 때 글자만 빨강으로 표시한다. 배터리 저하만으로 행 전체를 빨강 처리하지 않는다.
6. **평균 두뇌휴식도** — flex 1.5. 2.0 `avg_efficiency`, 정수 반올림과 `%`. 원본은 truthy 판정으로 평균 0을 `-`로 표시하지만 2.0에서는 실제 0은 `0%`, null만 `-`로 구분한다.
7. **현재 두뇌휴식도** — flex 1.5. 2.0 `current_efficiency`. 원본은 `CLEAR`이고 샘플이 있어야 표시한다. 포팅은 정상 접촉·연결·유효한 최신 측정이 확인될 때만 표시하고 접촉불량/무응답/미확인에서는 `-`로 처리한다. 정상 여부를 SQI만으로 추정하지 않는다.
8. **데이터 업로드 현황** — flex 1.6. 원본은 업로드 성공률이 아니라 `updatedAt` 이후 경과 표시다. 2.0의 `upload_status`는 완료/전송 중/지연/실패/대기라는 별개 계약이다. 현재 확보 가능한 상태 문구를 본문에 유지하고, 실제 업로드 갱신시각이 제공되면 `N초 경과`를 추가한다. `last_eeg_at`을 업로드 완료시각으로 치환하지 않는다.

현행 타입 근거: `2.0/frontend/src/lib/api/session.ts:11–24,114–135`. 원본 접촉·연결 라벨: `1.0/src/classes/SessionLog.ts:43–77`. 업로드 경과 표시: `1.0/src/components/TimeSince.tsx:13–29`. 현행 테이블은 자리번호가 없고 “신호” 컬럼이 추가되어 있다: `2.0/frontend/src/components/session/SessionMonitorTable.tsx:139–150`.

**시각 규칙**

- 흰 화면 위에 테이블을 직접 놓고 헤더는 `#F2F3F8`, 일반 행은 흰색과 `#F2F3F8` 교차색이다. 현행 20px 둥근 테두리 카드로 감싼 외형을 원본의 평평한 표 형태로 바꾼다. 굵은 외곽선·그림자를 추가하지 않는다.
- 글자는 원본처럼 14px/22px, weight 500, 기본 `#1F1F1F`. 헤더도 같은 크기·무게이며 이름 외에는 중앙 정렬한다. 원본 행 좌우 padding 16px, 상하 8px, 기본 높이 38px을 참고하되 긴 이름·두 줄 헤더는 자연스럽게 늘린다. 근거: `Table.tsx:43–46,104–116`, `Texts.tsx:15–18`.
- 원본 빨간 행 조건은 연결 실패 OR 접촉불량 OR 마지막 `updatedAt` 이후 **60초 초과**다. 이 조건이 교차색보다 우선한다. 근거: `SessionScreen/index.tsx:251–260`.
- 2.0은 `last_eeg_at` **10초 초과**로 stale을 판정하며 현행 행 강조는 `leadOff || stale`여서 명시적 단절만 있는 행과 집계가 다를 수 있다. 포팅에서는 행·카드·필터의 장애 판정을 공통 규칙으로 맞춘다. 근거: `2.0/frontend/src/lib/session-live/signal-status.ts:15–16,86–96`, `SessionMonitorTable.tsx:43–57,73–85`.
- 포팅 제안은 기존 10초 EEG 전송중단 판정을 유지하면서 원본 빨간색을 적용한다. 60초 업로드/응답 지연은 해당 시각 계약 확보 후 별도로 표시한다. 두 시각의 의미를 합치지 않는다. 색 외에도 “접촉안됨/연결끊김/전송중단” 원인 텍스트를 제공한다.
- 원본의 `#F2212133`는 배경 20% alpha이고 `#F22121B2`는 글자 약 70% alpha다. 행 전체 opacity를 낮추지 않는다. 웹 대비 검사 결과 보정이 필요하면 원본과의 차이를 명시하고 승인한다.

**반응형 제안**

- 데스크톱: 8열 테이블, 이름을 제외한 원본 폭 비율을 유지한다. 본문 가용폭이 부족하면 테이블 최소폭 960px을 초기값으로 두고 테이블 영역 안에서만 수평 스크롤한다. 960px은 제안값으로 한글 헤더와 실제 데이터를 통해 조정한다.
- 태블릿: 같은 8열과 가로 스크롤. 자리번호·이름 열을 고정하고 고정 셀에도 해당 행 배경을 적용한다. 고정 영역이 나머지 열을 가리지 않는지 확인한다.
- 모바일 기본: 참가자별 카드 1열. 상단 `자리번호 · 이름`, 아래 접촉상태/기기연결/배터리, 다음 평균·현재 두뇌휴식도, 마지막 업로드현황 순서다. 모든 필드를 레이블과 함께 표시하고 테이블과 같은 상태·경고색을 적용한다. 카드 padding 16px, 간격 12px, radius 12px으로 제안한다.
- 모바일 대안: “표로 보기”를 선택하면 동일한 8열 수평 스크롤 표를 제공한다. 기본 카드와 표를 동시에 노출하지 않으며 전환해도 필터·참가자 식별·값은 동일하다. 가로 스크롤 안내와 키보드로 접근 가능한 스크롤 영역 이름을 제공한다.
- 현행 추가 “신호” 정보는 기본 8열 밖의 참가자 상세/펼침 영역으로 이동한다. 접촉과 SQI가 별개라는 2.0 계약은 유지한다. hover만으로 접근하는 설명은 사용하지 않는다.
- 원본 롱프레스의 자리·이름 수정은 웹에서는 명시적 “참가자 정보” 동작으로 연결한다. 저장은 자리번호·수정권한 API가 확인된 후 구현하며 지금 문서로 변경 기능이 존재한다고 가정하지 않는다. 원본 근거: `SessionScreen/index.tsx:262–265,292–340`.
- 목록 로딩·빈 목록 문구는 각각 “참석한 인원 목록을 불러오는 중입니다.”와 “참석한 인원이 없습니다.”를 유지한다. 필터 결과 없음은 별도 문구로 구별한다. 재조회 중 기존 데이터는 유지하고 갱신 중 상태를 표시한다.
- 시간 경과만으로도 stale 상태가 바뀌어야 한다. 현재 행 `memo`와 요약 `useMemo` 구조에서 새 이벤트가 없는 상태의 10초 경계 통과를 검증하고, 시간 갱신을 위해 데이터 행 전체를 불필요하게 복제하지 않는다. 근거: `SessionMonitorTable.tsx:68–75`, `SessionLivePage.tsx:420–421`.

## 시작/종료 버튼

**원본 사실**

- 시작은 primary `#5F0080` 배경 / `#EFEFEF` 글자, 종료와 클래스 정보는 secondary `#D2AEFC` 배경 / `#5F0080` 글자다. disabled는 `#DDDEE7` 배경 / `#A2A3AD` 글자다. 일반 버튼 119×44px, 작은 버튼 80×44px, radius 12px, 글자 16px/24px·500이다. 근거: `1.0/src/components/Buttons.tsx:49–74,99–128`.
- 시작은 소켓 연결 안 됨 또는 참가자 0명이면 비활성화된다. 종료는 연결 안 됨이면 비활성화되고 버튼 문구는 두 경우 모두 “연결중...”이다. 종료 클릭 시 “정말 종료할까요?” 확인창을 열고 “클래스가 종료되면 사용자들도 모두 종료됩니다. 정말 종료할까요?”를 안내한다. 근거: `SessionScreen/index.tsx:174–191,276–289`.

**포팅안**

1. 데스크톱은 제목 오른쪽에 클래스 정보 → 시작/종료 순서, 모바일은 제목 아래 2열 동일 폭 버튼으로 둔다. 좁은 폭이나 확대 시 1열로 전환한다. 기본 높이 44px 이상, 긴 처리 문구는 너비를 늘리거나 줄바꿈한다.
2. 원본 동일성이 우선인 권고안은 **시작은 진보라 primary, 종료는 연보라 secondary**다. 요청의 “시작/종료 보라색 primary”를 두 버튼 모두 진보라로 해석할 경우 원본과 달라지는 결정이므로 별도 승인 항목에 둔다.
3. 현행 2.0 시작 조건은 대기 상태 + 대기명단 제외 참가자 1명 이상 + 전환 중 아님이며, 종료는 즉시 실행 후 기록 화면으로 이동한다. 이를 보존하면서 종료 확인창을 앞에 추가한다. 근거: `2.0/frontend/src/pages/sessions/SessionLivePage.tsx:294–304,332–348,415–453`.
4. 2.0은 REST fallback을 사용하므로 WS 미연결만으로 시작/종료를 막는 1.0 조건을 그대로 가져오지 않는다. 서버 통신 불가·권한 없음·요청 진행 중을 구분하고 사유를 버튼 가까이에 텍스트로 표시한다. 밴드 미연결은 시작 금지 사유가 아니다.
5. 처리 중 `시작 중.../종료 중...`, 중복 요청 금지, 실패 시 오류·재시도 제공. 취소 버튼은 종료를 실행하지 않으며 완료·취소 상태에는 시작 버튼을 재노출하지 않는다. 원본의 disabled 색을 명시적으로 적용해 단순 opacity 50%와 구별한다.
6. 클래스 정보 모달은 읽기 전용 세션코드, 클래스 이름, 설명(200자), 저장/닫기 동작을 계획한다. 원본은 저장 시 Lecture를 수정한다. 2.0의 session `title/notes` 수정과 동일한 데이터 범위인지 확인해야 한다. 데스크톱 최대폭 640px, 모바일 좌우 여백 16px·화면 높이 내 스크롤로 제안한다. 원본 근거: `1.0/src/screens/SessionScreen/LectureUpdateModal.tsx:33–41,45–98`; 2.0 후보 계약: `frontend/src/lib/api/session.ts:73–85`.

## 클래스 목록

**소스 기준 정정**: 요청의 “1.0 LectureScreen 카드 목록”과 달리 지정된 실제 소스는 `Table`이다. 생성일(yy.MM.dd) / 세션코드 / 클래스명(flex 3, 왼쪽 정렬) / 편집 / 입장 5열이며 편집은 secondary, 입장은 primary 작은 버튼이다. 상단은 프로필 설정, “클래스 목록”, 보관된 클래스, 클래스 추가로 구성된다. 근거: `1.0/src/screens/LectureScreen/index.tsx:25–65,84–117`.

2.0은 `세션 관리` 안에 즉시 클래스 카드와 캘린더·타임라인이 함께 있고, 기본 `SessionCard` 클릭은 세션 상세로 이동한다. 원본의 입장과 다르다. 근거: `2.0/frontend/src/pages/sessions/SessionListPage.tsx:575–612,628–675`, `2.0/frontend/src/components/session/SessionCard.tsx:100–111`.

**권고 포팅안**

- 호스트 클래스 목록을 현재 예약 캘린더와 구별된 목록 보기로 구성한다. 데스크톱은 원본 5열 표, 모바일은 같은 정보를 가진 1열 카드로 전환한다. “카드 목록”을 모든 폭에 적용하면 원본 동일성이 깨지므로 모바일 적응으로 한정한다. 기존 예약 관리의 제거는 이 기획 범위가 아니다.
- 데스크톱은 원본과 같은 흰 바탕, `#F2F3F8` 헤더·교차행, 14px 본문, 생성일/세션코드/클래스명/편집/입장 순서를 유지한다. 헤더까지 간격 24px. 태블릿은 클래스명 열을 유연하게 늘리고 필요하면 표 안에서 가로 스크롤한다.
- 모바일 카드는 흰 바탕·옅은 경계·radius 12px·padding 16px, 제목 → 생성일·세션코드 → 편집/입장 2열 버튼 순서로 제안한다. 클래스명을 두 줄까지 기본 표시하고 전체 제목을 확인할 수 있게 한다. 색상 배지·그림자가 핵심 정보보다 먼저 보이지 않게 한다.
- 생성일은 `created_at`, 코드 `access_code`, 클래스명 `title`로 매핑한다. 예약일 `scheduled_at`을 생성일에 넣지 않는다. 코드 없는 예약은 “코드 없음”, 입장할 수 없는 완료·취소 항목은 상태와 기록/상세 보기로 구분한다.
- 입장 CTA는 호스트 세션 콘솔로 이동하며 클래스 시작 요청을 자동 실행하지 않는다. 원본처럼 편집과 입장을 별도 동작으로 둔다. 호스트 역할 및 해당 세션 접근권한은 2.0의 기존 검사와 연결한다.
- 상단 “클래스 추가”는 현행 즉시 클래스 생성 흐름과 연결하는 안이다. “보관된 클래스”는 완료 세션과 같은 개념인지 확인하기 전 완료 목록으로 대체하지 않는다. 프로필 설정은 기존 프로필 경로로 연결 가능 여부를 확인한다.
- 로딩 “클래스 목록을 불러오는 중입니다.”, 빈 상태 “생성된 클래스가 없습니다.”, 실패 시 재시도. 원본 로딩 오타 “클랙스”는 교정한다. 원본 100개 요청을 그대로 제한으로 두지 않고 2.0 목록 API의 total·페이지 계약 확인 후 목록 누락 없이 탐색하도록 한다.

## 리스크/결정 포인트

1. **동일성 기준**: 코드에 근거한 스타일·문구·구조는 확보했지만 원본 실행 스크린샷과 렌더링 비교는 하지 않았다. 본 문서는 픽셀 동일성 검증 완료 보고가 아니다. 흰 화면, 회색 배너·교차 표, 보라 버튼을 기본으로 하고 새 반응형 규칙을 별도 검증한다.
2. **요청과 원본 차이**: 데스크톱 클래스 목록은 표 유지, 모바일만 카드 권고. 종료는 연보라 secondary 권고. 모든 화면 카드화 또는 종료 primary 통일은 별도 디자인 선택이다.
3. **배터리 임계**: 1.0 카드 `<25`와 셀 `<=25`가 서로 다르고 2.0은 `<20`이다. 권고는 카드·셀·필터를 모두 `<=25`로 통일하되 이는 명시적인 1.0 동작 수정으로 승인받는다. 미승인 상태에서 숫자 정책을 바꾸지 않는다. 0/20/24/25/26/null을 검증 사례로 남긴다.
4. **무응답 시간의 의미**: 1.0 updatedAt 60초와 2.0 last_eeg_at 10초를 같은 필드로 취급할 수 없다. 기존 EEG 판정은 유지하고 업로드 경과를 위한 시각 계약을 별도로 정한다. 원본과 완전히 같은 업로드 표시는 이 계약 확보 전에는 불가능하다.
5. **미사용·미확인·실패**: 밴드 선택 사용을 유지한다. 과거 연결·사용 여부를 알 수 없는 경우 무조건 실패로 집계하지 않는다. 마지막 샘플 null은 정상 접촉이나 전송 성공의 증거가 아니다. 상태별 정의는 카드·필터·행에 함께 반영한다.
6. **자리번호·참가자 정보**: 자리번호 필드와 저장 경로는 현재 조사한 FE 타입에 없다. 임의 번호 생성 금지. 원본 롱프레스 수정과 2.0 권한 계약은 구현 전 확인해야 한다.
7. **Lecture와 Session/Run**: 1.0 클래스 템플릿 편집·재입장·보관 의미와 2.0 회차 세션 수정은 일대일 대응이 보장되지 않는다. 클래스 정보의 저장 대상, 종료 후 이동(1.0 목록 / 2.0 기록), 보관 기능은 서비스 담당자가 결정한다. 권고 종료 목적지는 2.0 기록 화면 유지다.
8. **추가 기능 배치**: 호스트 BLE 설정은 핵심 표 아래 보조 영역, 녹음/화상/마커는 기존 접기 영역으로 둔다. 원본과 달라진 2.0 기능을 제거하거나 녹음 동의 흐름을 생략하지 않는다.
9. **표시 성능·접근성**: 320/375/768/1024/1440px, 200% 확대, 긴 이름, 참가자 0/1/30/100명에서 필드 누락·페이지 가로 넘침·버튼 겹침을 확인한다. 10초/60초 경계는 새 이벤트 없는 상태에서도 확인한다. 키보드 포커스, 모바일 터치, 경고 텍스트, 색 대비를 검증하고 Timer 매초 갱신을 스크린리더가 계속 읽지 않게 한다.
10. **착수 게이트**: 본 문서는 디자인 기획 산출물 하나다. SDD의 spec/plan/verify/summary 완료나 구현 승인으로 대체하지 않는다. 실제 구현 전 정책 결정과 Verify 승인을 받은 뒤 대기·진행·일시정지·종료·오류·미사용·접촉불량·전송중단 사례를 테스트한다.

검토 범위: 지정 1.0 5개 소스(SessionScreen, DashboardBox, LectureUpdateModal, Table, LectureScreen), 관련 공통 토큰·Timer·상태 모델, 2.0 세션 화면·목록·카드·배너·요약·테이블·프런트엔드 타입·상태 유틸을 읽어 비교했다. 코드 변경, 빌드, 브라우저 실행, 서버 계약 검증은 하지 않았다.
