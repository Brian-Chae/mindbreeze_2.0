# [SDD-015] Verify — 구현 전 QA 체크리스트

> Stage ③. 구현 전에 아래 시나리오를 확정하고, 구현 후 각 항목을 실제로 검증한다.

## 1. 기관 등록 (system_admin)

- [ ] platform_admin이 기관명 입력 → 기관 생성 + 6자리 기관 코드(org_code) 자동 발급
- [ ] 발급된 기관 코드가 기관 상세/목록에 표시됨
- [ ] 기관 코드 중복 없음 (unique)

## 2. 상담사 가입 (기관 코드 필수)

- [ ] 상담사 가입 시 기관 코드 입력 → 유효하면 가입 완료 + org_id 연결
- [ ] 잘못된 기관 코드 → 가입 거부 (400/404)
- [ ] 기관 코드 없이 상담사 가입 시도 → 거부

## 3. 클래스 생성·시작 (일정 없이)

- [ ] 상담사가 클래스 생성 (제목/유형/그룹여부) → scheduled_at 없이 생성 가능
- [ ] 생성 시 6자리 클래스 코드(access_code) 자동 발급
- [ ] "시작" → status ready → in_progress, started_at 기록
- [ ] "종료" → status completed, ended_at 기록

## 4. 참여 (가입/게스트 + 클래스 코드)

- [ ] 로그인 내담자: 클래스 코드 입력 → 해당 클래스 참여
- [ ] 게스트: 클래스 코드 + 이름만으로 참여 (회원가입 불필요)
- [ ] 잘못된 클래스 코드 → 404

## 5. AI 기록·리포트 (2.0 유지)

- [ ] 클래스 진행 시 음성 녹음 → STT → 요약 파이프라인 기존 동작 유지
- [ ] 클래스 종료 후 AI 요약·기록지 생성
- [ ] 리포트 생성·조회 기존 동작 유지

## 6. 대시보드

- [ ] 상담사: 본인이 진행한 클래스 목록 + 기록/리포트 조회
- [ ] 기관(org_admin): 소속 상담사 전체 + 모든 클래스 기록 + 통계(총 클래스/참여자/상담사별)

## 7. 회귀

- [ ] 기존 백엔드 테스트 106 passed 유지
- [ ] 프론트 tsc 0 error, build 성공
- [ ] 기존 세션/기록/리포트 API 깨지지 않음

## 8. 간소화 (숨김)

- [ ] 자격증명·어드민·채팅·영상통화·캘린더·셀프트레이닝이 프론트 메뉴에서 숨겨짐
- [ ] 숨김은 라우트/메뉴 숨김이지 코드·DB 삭제가 아님
