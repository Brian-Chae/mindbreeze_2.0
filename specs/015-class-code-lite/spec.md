# [SDD-015] 클래스 코드 라이트 모델 — 기관·상담사·내담자 3계층 + 즉석 클래스

## 1. 배경 (왜)

MIND BREEZE 2.0이 과도하게 커졌다. 유저가 실제로 만족하는 것은 1.0의 명상 클래스 중심 기능이다.
기존 2.0 코드를 **기반으로 축소·재구성**해 "클래스 코드로 바로 접속"하는 라이트 모델로 간소화한다.
AI 기록·리포트는 2.0 수준을 그대로 유지한다.

## 2. 역할 모델 (4계층)

| 역할 | 설명 | 핵심 권한 |
|------|------|-----------|
| **system_admin** | 플랫폼 관리자 | 기관 등록·관리 (간단하게) |
| **org** (기관) | 상담사가 소속된 기관 | 소속 상담사·클래스 기록 전체 조회 + 기관 통계 |
| **counselor** (상담사) | 클래스를 진행하는 지도자 | 기관 코드로 가입, 클래스 생성·진행, 본인 클래스 데이터 |
| **client** (내담자) | 참여자 | 가입 또는 게스트, 클래스 코드로 참여 |

## 3. 가입·접속 플로우

```
[system_admin] 기관 등록 → 기관명 입력 → 기관 코드(6자리) 자동 발급
[counselor]    가입 시 기관 코드 입력 → (기관 코드 유효하면) 가입 승인
[client]       가입(이메일/구글) 또는 게스트 → 클래스 코드 입력 → 참여
[guest]        회원가입 없이 클래스 코드 + 이름만으로 즉시 참여
```

- **상담사 가입 = 기관 코드 필수**. 등록된 기관 코드와 일치해야 가입 가능.
- **내담자는 게스트 허용**. 코드만 알면 이름 입력 후 바로 입장.

## 4. 클래스 모델 (일정 등록 없이 즉석 시작)

핵심 변경: **예약/일정(scheduled_at) 없이, 상담사가 "시작"을 누르면 클래스가 시작**된다.

```
[counselor] "클래스 만들기" → 제목·유형(명상/상담)·그룹여부 입력 → 6자리 클래스 코드 발급
            → 참여자에게 코드 공유 → 참여자 입장 확인 → "시작" 버튼 → 진행중
            → "종료" → AI 기록·리포트 자동 생성
```

- `Session.scheduled_at` → **nullable** 로 변경 (즉석 클래스는 일정 없음)
- `Session.access_code` (6자리, unique) 추가 — 생성 시 자동 발급
- 상태: `ready`(대기) → `in_progress`(진행중) → `completed`(완료) / `cancelled`(취소)

## 5. AI 기록·리포트 (2.0 유지)

| 기능 | 유지 여부 |
|------|-----------|
| 음성 녹음 → STT → 화자분리 → AI 요약 → 기록지 (SDD-013) | ✅ 유지 |
| 리포트 (상담사용/내담자용) (SDD-014) | ✅ 유지 |
| LINK BAND 뇌파 모니터링 (선택) | ✅ 유지 |

LiveKit 영상통화는 **숨김** (대면/오프라인 클래스 중심).

## 6. 대시보드

### 6.1 상담사 대시보드
- **자신이 진행한 클래스 목록** 위주
- 클래스별 기록(AI 요약)·리포트·참여자 목록

### 6.2 기관 대시보드
- 소속 상담사 전체 목록
- 기관 내 모든 클래스 기록 열람
- **기관 통계**: 총 클래스 수, 총 참여자 수, 상담사별 실적, 기간별 추이

## 7. 간소화 (숨김/비활성화 — 코드 삭제·DB 롤백 없음)

| 기능 | 조치 |
|------|------|
| 상담사 다단계 온보딩 (상담센터/경력/자격) | 최소화 (기관 코드 + 이름/전문분야만) |
| 상담사 자격증명(credential) | 숨김 |
| 어드민 검토큐(admin) | 숨김 |
| 실시간 채팅(chat) | 숨김 |
| LiveKit 영상통화 | 숨김 |
| 캘린더·모바일 시간표 고도화 | 숨김 |
| 알림 고도화 | 최소화 |
| 셀프트레이닝 (MVP3) | 숨김 |

## 8. 데이터 모델 변경 요약

| 대상 | 변경 |
|------|------|
| `Session` | `access_code`(String(6), unique) 추가, `scheduled_at` nullable로 변경, `started_at`/`ended_at` 추가 |
| `Organization` | 기관 코드(org_code) 필드 추가 (기존 org 모델 활용) |
| `User` | role에 `system_admin`/`org` 구분 반영 (기존 role 체계 활용) |

## 9. 검증 기준

1. system_admin이 기관 등록 → 기관 코드 발급
2. 상담사가 기관 코드로 가입 (잘못된 코드는 거부)
3. 상담사가 클래스 생성 → 6자리 코드 발급 → "시작" → 진행중
4. 내담자(가입/게스트)가 클래스 코드로 참여
5. 클래스 종료 → AI 기록·리포트 생성 (2.0 수준)
6. 상담사 대시보드: 본인 클래스 목록/기록/리포트
7. 기관 대시보드: 소속 상담사 + 클래스 + 통계
8. 백엔드 테스트 회귀 없음 (기존 106 passed 유지)
