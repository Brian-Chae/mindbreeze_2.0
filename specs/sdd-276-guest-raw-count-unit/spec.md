# SDD-276 — 비회원 측정 기록 파일 도착량 계산 단위 불일치 수정

- 상태: Stage ① Spec
- 브랜치: `sdd/276-guest-raw-count-unit`
- 작성일: 2026-11-02
- 범위: 웹(JS 번들)만. backend·네이티브 변경 없음.

## 문제
비회원 한 명이 "측정 기록 파일 일부 도착(맥박·움직임)" 으로 남는다. 분석 데이터는 모두 도착했는데 폰 보고 기대량(eeg 198 / ppg 759 / acc 37)과 서버 `eeg_raw_chunks` 행(632 / 673 / 32)이 어긋난다. 서버 행의 시간 범위는 연속이라 데이터 누락이 아니라 **세는 단위 불일치**다.

## 원인 (코드로 확정한 것 / 못 한 것)
| 신호 | 원인 | 확정 |
|---|---|---|
| eeg 보고 < 서버 | 웹 측정은 v2 청크(`capture-session`)와 별개로 레거시 v1 1초 청크(`useBand` → `useEegRawUpload`)도 같은 `eeg_raw_chunks` 에 올린다. 서버 `_raw_stats` 는 `signal_type` 만 세므로 v1 행도 eeg 로 센다. 폰 `computeWebRawTotals` 는 v2(sealed+receipt)만 센다. 632 − 198 = 434 행이 v1 1초 청크일 것으로 추정(v1 은 stream 당 chunk_index 0..N 연속, 보고된 distinct 451 과 모순 없음) | 코드 경로 확정, 운영 행 구성은 DB 접근 불가로 미확인(추정) |
| ppg·acc 보고 > 서버 | `computeWebRawTotals` 가 sealed 목록을 읽은 뒤 receipts 를 따로 읽는다. 그 사이 업로드가 끝난 청크가 양쪽에 잡혀 이중 계산되고, 보고는 최댓값 병합(`mergeReport`)이라 한 번 부풀면 내려가지 않는다. 재현 테스트로 이중 계산 확인 | 재현 확인. 운영 크기(86/5)가 이 경쟁만으로 나왔는지는 미확인 |

## 목표
1. 폰 보고 기대량 = 서버가 세는 단위(올라가 행이 된 청크 수)와 일치.
2. 이미 끝난 회차는 소급하지 않는다. 서버·계약·판정 로직·네이티브 불변.
3. 새 문구·금지 표현(점수·좋음/나쁨·완료·100% 단정) 없음.

## 비목표
- 서버 `upload_progress_service` 변경, 레거시 v1 경로 제거(데이터 보존 우선).
